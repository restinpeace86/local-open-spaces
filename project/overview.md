# local-open-spaces 프로젝트 개요 (Overview)

> **SSOT 안내 (Decision 008):** 서비스 모토·UI 구조·데이터 정책의 최상위 기준 문서는 `docs/spec.md`이다. 본 문서는 그 방향을 프로젝트 배경/목적 관점에서 풀어 설명하며, 세부 정책이 서로 다르면 `docs/spec.md`가 우선한다.

## 1. 프로젝트명

`local-open-spaces` — 아이·가족을 위한 가성비 놀거리 큐레이션 서비스
(기존 "내 동네 열린 공간 & 시한성 이벤트 큐레이션"에서 Decision 008에 따라 확장 재정의됨)

---

## 2. 프로젝트 정의

`local-open-spaces`는 단순한 관광지 목록이나 단순 정보 검색 서비스가 아니다.

사용자가 현재 위치(또는 지정 위치)를 기준으로 **오늘/이번 주말, 아이·가족과 가성비 있게(0원~1만 원) 즐길 수 있는 놀거리**를 탐색·큐레이션할 수 있도록 지원하는 **위치 기반 놀거리 큐레이션 플랫폼**이다. 무료/공공 열린 공간(쉼터, 공원, 도서관 등)과 시한성 행사(지역 축제, 공연, 체험 프로그램)를 핵심 축으로 하되, 타임커머스 핫딜·제휴 특가 정보까지 포괄한다.

본 서비스의 핵심은 복잡한 가입 절차 없이, "오늘/이번 주말 아이·가족과 가성비 있게 뭐 하고 놀지?"라는 일상적인 궁금증을 직관적인 큐레이션 경험으로 해결하는 것이다. 사전 예약 마감건은 제외하고, 오늘/주말 당일 즉시 방문 가능한 정보를 우선 추천한다.

---

## 3. 프로젝트 목적

`local-open-spaces`는 사용자가 위치 기반으로 동네 놀거리 소식을 쉽게 이해하고, 가성비 있는 공간·행사·핫딜을 찾아 방문할 수 있는 플랫폼 구축을 목표로 한다.

이를 위해 다음 탐색 흐름을 제공한다 (`docs/spec.md` 2 UI/UX 구조 기준).

하단 5탭 내비게이션 진입 ([카테고리] / [내주변(지도)] / [홈, 디폴트] / [찜] / [마이])
→ 홈: 위치 선택기 + 통합 검색바 → 서브탭(홈/특가·핫딜/무료·공공) → 비주얼 캐러셀 → 5대 카테고리 Quick 그리드 → 큐레이션 피드(0원의 행복/오늘만 이 가격)
→ 내주변(지도): GPS/수동 위치 기반 반경 탐색, 지역별 카테고리 그리드, 월별 시한성 이벤트 캘린더
→ 상세 정보 모달 (기간, 운영 시간, 카카오맵 길찾기, 카카오톡 공유)
→ 찜 / 맞춤 관심 지역·카테고리 알림 수신

---

## 4. 해결하려는 문제

현재 공공 데이터 및 행사장 정보는 각 지자체, 기관, 포털 사이트에 파편화되어 있다.

사용자는 우리 동네에 어떤 열린 공간이 있는지, 이번 주말에 어떤 시한성 행사가 열리는지 통합해서 알기 어렵다.

`local-open-spaces`는 다음 문제를 해결한다:
- 공공 데이터 API가 분산되어 있어 한눈에 파편화된 소식을 보기 어려움
- 현재 내 위치에서 몇 미터(m) 떨어져 있는지 직관적 거리 및 반경 파악이 어려움
- PC 모니터와 스마트폰 모바일 화면 간의 UX 불일치로 인한 탐색 불편
- 일시적으로 열리는 시한성 이벤트(축제/공연)의 마감 임박 여부를 놓치는 문제
- 예산이 정해진(0원~1만 원) 아이·가족 나들이 계획 시, 무료/가성비 정보와 유료/고가 정보가 뒤섞여 있어 걸러보기 어려운 문제 (Decision 008)

---

## 5. 핵심 사용자 및 멀티 디바이스 환경

### 사용자
자신의 현재 위치나 특정 동네 주변의 열린 공간과 시한성 이벤트를 찾고 싶은 사용자.

예:
- 주말에 아이/가족과 함께 갈 동네 공원, 쉼터, 무료 행사장을 찾는 사용자
- 퇴근 후 주변 도서관, 열린 강좌, 무료 공연을 찾는 사용자
- 모바일 스마트폰으로 이동 중 길찾기를 이용하거나 PC 큰 화면으로 주말 나들이를 계획하는 사용자

### 멀티 디바이스 환경 (PC & 모바일 필수 지원)
- **Mobile (`< 768px`):** 풀사이즈 지도 + 하단 바텀시트(Bottom Sheet) 인터페이스
- **Desktop (`>= 768px`):** 좌측 목록/캘린더 패널 + 우측 넓은 지도 뷰 (2단 Split View)

## 6. 서비스 핵심 방향 및 데이터 파이프라인

`local-open-spaces`는 Supabase PostGIS 위치 데이터를 기반으로 동작하며, 데이터 수집은 **80% 안정적인 공식/공공 API + 20% 보완 크롤링/제휴 API(커머스 핫딜 포함)** 구조로 확장한다 (Decision 008, `docs/spec.md` 3.1).
- **메인 수집 (80% / Stable):** 기존 7대 공공 API(도시공원/체육시설/문화기반시설/서울예약/서울문화행사/TourAPI/서울야외팝업, `project/data_sources.md` 참고) + 산림청, 네이버 Local API, 쿠팡 파트너스/네이버 쇼핑 API (신규, 미착수)
- **보완 수집 (20% / Dynamic):** 마트 문화센터 1일 특강, 지자체 광장 행사 게시판 등 크롤링/스크래핑 (신규, 미착수)
- **Fail-Safe Skip 규칙:** 크롤링/스크래핑 모듈 오류 시 전체 파이프라인을 중단하지 않고 해당 모듈만 Skip(경고 로그) 후 정상 API 데이터로 DB 동기화를 완료한다.

핵심 구조:

공공/제휴 API 수집 및 PostGIS 정제 (Fail-Safe Skip 적용)
↓
AI 태깅(5대 카테고리 매핑 + Parental Checkpoint 뱃지, `spec/data/ai-rule.md`)
↓
위치 반경(Radius) 계산 및 지도 마커 피벗
↓
시한성 이벤트 & 공간 카테고리 큐레이션 (사전 예약 마감건 제외, 오늘/주말 우선)
↓
상세 길찾기 / 카톡 공유 / 웹 푸시 알림

모든 위치 데이터는 위도/경도(WGS84) 공간 좌표를 기반으로 인덱싱되며, 독립적인 공간 및 이벤트 단위로 관리된다.

## 7. 제로 코스트(Zero-Cost) 최적화 아키텍처 원칙

초기 MVP 운영 비용을 zero(0원) 또는 최소화하기 위해 다음 플랫폼과 무료 티어를 적극 활용한다:
- **Hosting & Deployment:** Vercel (Hobby Free Tier)
- **Database & Spatial Backend:** Supabase PostGIS (Free Tier - 500MB DB / 50K MAU)
- **Map & Geocoding SDK:** Kakao Maps API (일일 300,000건 무료 호출)
- **Data Collection Pipeline:** GitHub Actions Scheduled Workflows (무료 CI/CD 인프라 기반 자동 수집 및 DB 동기화)

---

## 8. 현재 개발 목표 (MVP Scope)

초기 목표는 무겁고 복잡한 커뮤니티 플랫폼이 아닌, **가장 빠르고 명확한 위치 기반 가성비 놀거리 탐색 서비스**를 제공하는 것이다.

**구현 완료 (Phase 1):**
- Kakao Map SDK 연동 (GPS 위치 및 사용자 지정 위치 피벗)
- PostGIS 기반 반경(1km/5km/10km, 조건부 20km/30km) 내 동네 공간 & 시한성 이벤트 탐색 (Main View)
- 지역별 도감 그리드 뷰 (Region View) / 월별 시한성 이벤트 캘린더 뷰 (Calendar View)
- 공간/이벤트 상세 정보 모달 및 카카오맵 길찾기 연동
- 검색바(Debounce)/카테고리·Quick 필터/Parental Checkpoint 뱃지
- 광역 맞춤 알림 UI + LocalStorage 알림함 (`spec/notification/notification-settings.md`)
- Mobile / Desktop 반응형 UI, GitHub Actions 기반 제로 코스트 공공 API 동기화 파이프라인

**신규 확장 목표 — 미착수 (Decision 008, `docs/spec.md` 기준):**
- 하단 5탭 고정 내비게이션([카테고리]-[내주변]-[홈]-[찜]-[마이])으로 전면 개편 (현재는 상단 3탭: 지도/도감/캘린더)
- 홈 화면: 위치 선택기 + 서브탭(홈/특가·핫딜/무료·공공) + 비주얼 캐러셀 + 5대 카테고리 Quick 그리드 + 큐레이션 피드
- 쿠팡 파트너스/네이버 쇼핑 등 커머스 핫딜 API 연동
- 요금 오탐 방지 OCR/Fallback 룰(`spec/data/ai-rule.md` 5.2-7)
- 찜(즐겨찾기) 기능 — 현재 Decision 003에 따라 Feature Flag로 비노출 상태

## 9. 유연한 개발 및 노출 제어 원칙 (Feature Toggling)

확장 가능성과 유연성을 위해 서비스 로직 및 기능 코드는 우선적으로 선제 개발할 수 있다.
단, 초기 서비스의 복잡도를 낮추기 위해 미오픈 기능은 **화면 비활성화(Feature Flag / Disabled UI) 처리**를 거쳐 단계적으로 노출한다:
- 필요에 따라 확장 기능(소셜 기능, 고급 필터 등)의 모듈/코드 구현 허용
- 미승인/미오픈 기능은 UI상에서 숨김 또는 비활성화(Disabled) 상태로 제어
- 실제 화면 노출 전환은 Spec 및 기획 업데이트 후 활성화

---

## 10. 핵심 원칙

`local-open-spaces`는 다음 원칙을 따른다:
- 제로 코스트(Zero-Cost) 인프라 최적화
- 위치 기반 가성비 놀거리 큐레이션 중심 (아이·가족 우선, Decision 008)
- PC 및 모바일 반응형 UX 무결성
- 공공 데이터 정제 및 PostGIS 정확성
- 사용자 가치 우선
- 유연한 코드 구현 및 스펙 기반 UI 제어
