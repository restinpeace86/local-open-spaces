# [스팟 매칭 검색: OR 매칭으로 무관한 결과가 섞이던 문제 수정]

## 구현 대상
사용자 지적(2026-09-16): "안나오네 이거 검색조건이 &가 아니고 OR야 오키드
키즈카페 할경우 이것만 나오는게 아니고 키즈카페 모두다 나오는거같아"

## 구현 일시
2026-09-16

## 원인 확인
`/v1/products/tna/search`를 `keyword: "오키드 키즈카페"`로 직접 재현 호출한
결과, 정확한 매칭("[김포] 오키드 키즈카페")은 실제로 결과 안에 있었지만
`totalCount: 46`이나 되는 무관한 다른 지역 "키즈카페" 상품(남양주/구미/포항/
부천/동탄 등)과 뒤섞여 나왔다 — 마이리얼트립 검색이 키워드를 공백 기준
토큰으로 쪼개 OR로 매칭하는 것을 실측으로 확인했다(개선사항1 도시 필터
버그를 고칠 때 확인했던 것과 같은 API 특성).

## 왜 이번엔 클라이언트에서 걸러도 되는지 (도시 필터 사례와 다른 점)
직전에 고친 "도시" 필드는 완전한 위치 필터가 아니라는 걸 인지하고도 문자열
필터를 추가하지 않았다 — 진짜 관련 있는 상품이 제목에 도시명을 안 쓸 수도
있어서였다. 반면 이번 `SpotMyRealTripLinkEditor`는 "이 스팟과 정확히 일치하는
**특정 상호명**의 상품을 찾는" 것이 유일한 목적이라, 검색어(스팟명)의 모든
토큰이 상품명에 그대로 있는지 확인하는 건 추측이 아니라 정확한 상호 일치
확인 그 자체다 — 그래서 이번엔 안전하게 적용했다.

## 변경 사항
### `src/lib/admin/myrealtrip-search.ts`
`filterSearchItemsByAllKeywordTokens(items, keyword)` 신규 순수 함수: 검색어를
공백으로 토큰화해, 상품명에 모든 토큰을 포함하는 결과만 남긴다. 전부 걸러져
0건이 되면(표현 차이로 토큰이 정확히 안 맞을 수 있음) 원본 목록을 그대로
돌려줘 관리자가 직접 훑어볼 수 있게 한다 — 아무것도 안 보여주는 것보다 낫다
(제5장 제11조).

### `src/components/admin/spot-myrealtrip-link-editor.tsx`
검색 시 `size`를 10 → 50으로 늘리고(정확한 매칭이 OR 결과 뒤쪽 페이지로 밀릴
수 있어 한 번에 넉넉히 받아옴), 받아온 결과에 위 필터를 적용해 화면에는 실제
일치 후보만(또는 전부 안 맞으면 전체를) 보여준다.

일반 탐색용 `MyRealTripSearchPanel`에는 이 필터를 적용하지 않았다 — 그쪽은
카테고리/도시로 폭넓게 둘러보는 게 목적이라 강제로 좁히면 오히려 발견해야
할 상품을 놓칠 수 있다(도시 필터 사례와 동일한 이유).

## 검증
- `npx tsc --noEmit`, `npm run test`(전체 1838개, 신규 3개 포함), `npm run build`
  모두 통과.
- 실측 재현 데이터("[김포] 오키드 키즈카페" + 남양주/구미/포항 등 무관한 결과
  46건)를 그대로 축소한 단위 테스트로 필터가 정확히 1건("[김포] 오키드
  키즈카페")만 남기는 것을 확인.
