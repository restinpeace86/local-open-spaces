# [공공키즈카페/서울형키즈카페 — 동네 우선(진짜 거리순) 정렬]

## 구현 대상
사용자 지시(2026-09-20): "동네 우선 정렬이 맞는거 같아" — 오늘 만든 서울형키즈카페
알림 기능에 이어, 공공키즈카페/서울형키즈카페 화면에서 사용자 위치 기준으로
가까운 순서대로 보여주는 기능.

## 실측 확인 — 기존 구조 재사용
`src/lib/home/get-home-feed.ts`의 `getCategoryMinFeed`(모든 중분류 드릴다운
화면이 공유하는 함수)는 이미 좌표 기반 거리 계산(`sortByDistanceIfKnown`)을
갖고 있었지만, 최종 단계에서 `selectRegionFirst`(자치구 텍스트 일치 우선순위,
`regionTier`)가 그 순서를 다시 덮어쓰고 있었다 — 거리순은 각 자치구 우선순위
그룹 "안에서만" 유지될 뿐, 전체 결과에서는 자치구 일치 여부가 실제 거리보다
우선했다.

공공키즈카페/서울형키즈카페는 서울 전역에 145건 안팎만 있는 희소 카테고리라
(직전 조사에서 실측), 이 우선순위 역전이 특히 두드러진다 — "같은 구 안이지만
15km 떨어진 곳"이 "이웃 구지만 200m 거리인 곳"보다 먼저 뜨는 문제가 실제로
생길 수 있다.

프론트엔드(useUserLocation → region.lat/lng)와 API 라우트
(`/api/home/category-feed`)는 이미 좌표를 끝까지 전달하고 있어 — 새로 배선할
것 없이, `getCategoryMinFeed` 내부의 최종 정렬 단계만 고치면 됐다(제5장 제4조
기존 구조 우선).

## 설계 결정 — 범위를 키즈카페 2종으로 한정
전체 중분류 화면에 일괄 적용하지 않고 `공공키즈카페`/`서울형키즈카페` 두
중분류에만 적용했다 — 사용자가 이번 세션 내내 "여러 중분류를 한꺼번에 벌리지
말고 키즈카페 하나를 끝까지 완성하자"는 방향을 명시했고, 다른 중분류(문화/축제
등)는 건수가 많아 기존 자치구 우선순위가 여전히 합리적인 1차 필터라 검증 없이
동작을 바꾸지 않았다(제3장 제5조 추측 금지 — 검증되지 않은 화면까지 임의로
확장하지 않음).

## 코드 변경
`src/lib/home/get-home-feed.ts`:
- `DISTANCE_FIRST_CATEGORY_MINS`(신규 상수, `{'공공키즈카페', '서울형키즈카페'}`)
  — 기존 `SPACE_ID_GROUP_CATEGORY_MINS`(캠핑장 전용 그룹핑)와 동일한 "카테고리별
  옵트인 Set" 관례.
- `getCategoryMinFeed`의 마지막 반환문: 이 두 중분류이고 `region.lat`/`lng`가
  모두 있으면 `selectRegionFirst`(자치구 우선순위 재정렬)를 건너뛰고
  `sortByDistanceIfKnown`이 이미 계산해 둔 진짜 거리순 배열을 그대로
  `offset`/`limit`으로 자른다. 좌표가 없거나 다른 중분류면 기존 동작(자치구
  우선순위) 그대로.
