# [버그 수정] AI 챗봇 예산 옵션 무료/유료/상관없음 3단계로 단순화

## 구현 일시
2026-09-03

## 배경
전날(2026-09-02) "예산 1만원 이하가 인당인지 가족 전체인지 모호하다"는 지적에 라벨
문구만 "1인 기준"으로 고쳤었는데, 사용자가 "그전에 원천 데이터에 금액 필드가 있는지
파싱 못 하냐"고 재질문 — 라벨 수정 이전에 실제 데이터 가용성부터 다시 조사했다.

## 조사 내용 (원천 데이터 실측)
- **이벤트(events)**: 서울시 문화행사 원천(`seoul_public_culture`)에 `USE_FEE` 텍스트
  필드 존재. 전체 19,040건 중 8,820건(46%)에 실제 금액 텍스트("10,000원", "전석
  20,000원", "R석 2만원 S석 1만5천원" 등) — 파싱 가능하나 자유서식이라 정규식 처리 필요.
- **스팟(open_spaces)**: `CULTURE_FACILITY` 소스에만 `ENTR_FEE` 텍스트 필드 존재.
  전체 142,109건 중 **1,080건(0.76%)뿐** — 공원/놀이터/수영장/캠핑장/키즈카페/체험마을
  등 나머지 소스는 원천 데이터 자체에 금액 필드가 없음(GO_CAMPING은 자유서식 설명문에
  가격이 섞여 있지만 기준인원 초과요금/퇴실지연요금 등과 뒤섞여 있어 "기본 요금"을
  신뢰성 있게 추출할 근거가 없음).
- **결정적 문제**: AI 챗봇은 `get_nearby_spaces_and_events` RPC를 `p_item_type: 'SPACE'`
  로만 호출해 이벤트는 애초에 검색 대상이 아니다 — 이벤트 쪽 46% 데이터를 파싱해도
  챗봇 예산 필터에는 반영될 수 없다. 스팟 쪽은 파싱해도 전체의 0.76%만 커버돼 "1만원
  이하/2~3만원 이하" 필터는 사실상 항상 무의미했다(기존에 이미 "가짜 정밀도"였음을
  인지하고 있었으나, 이번에 정확한 커버리지 숫자로 재확인).

## 사용자 결정
위 조사 결과를 제시하고 세 가지 선택지(① 단순화만 / ② 가격 파싱 파이프라인 구축
/ ③ 단순화 후 나중에 파싱 추가)를 물어, **① 무료/유료/상관없음 3단계로 단순화**를
선택받았다.

## 구현 내용
- `Budget` 타입: `'FREE' | 'UNDER_10K' | 'UNDER_30K' | 'ANY'` → `'FREE' | 'PAID' |
  'ANY'`.
- `matchesBudget`: `PAID`는 `is_free === false`로 정확히 필터링(FREE와 대칭 —
  `is_free`가 null/unknown인 항목은 무료/유료 어느 쪽에도 포함하지 않음, 정직한 처리).
- `BUDGET_OPTIONS`: "완전 무료"/"유료"/"상관없어요" 3개로 축소.
- 세분화 옵션(1만원 이하/2~3만원 이하)과 그 라벨 수정 이력은 폐기 — 실제로 걸러낼
  수 없는 옵션을 화면에 남겨두지 않는다(제3장 제5조 추측 금지).

## 검증
### 코드 검증
`npx tsc --noEmit`/`npm run test`(96파일 964건 — PAID/ANY 신규 테스트 2건 포함)/
`npm run build` 통과.

### 실측 검증
dev 서버 curl로 `budget: "PAID"` 검색이 정상 응답하며 실제로 유료 스팟만 반환됨을
확인.

## 특이 사항
- 이번 결정으로 "가격 파싱 파이프라인 구축"(② 옵션)은 명시적으로 보류됐다 — 나중에
  스팟 커버리지가 늘어나거나(예: 다른 소스에 요금 필드가 새로 생기는 경우) 이벤트도
  챗봇 검색 대상에 포함하게 되면 재검토할 만하다.
