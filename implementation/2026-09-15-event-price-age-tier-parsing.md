# [개선사항 6 보완] 연령별 가격 구간 파싱

## 구현 대상
[개선사항 6] 완료 후 사용자 보완 지시: "최종 연령 기준은 유저화면 노출 목적이
아니라 연령에 따른 가격 세팅때문 — 성인 15,000원 / 36개월 미만 무료 / 아동
5,000원처럼 금액이 연령별로 나뉘어 있다면, 그 연령 기준(아동이 몇 세부터 몇
세까지인지 등)도 함께 파싱되어야 한다."

## 구현 일시
2026-09-15

## 원인 재확인
기존 구현(`extractAgeText`)은 텍스트 전체에서 연령 힌트 키워드 하나만 찾아 그
주변 문맥을 보여줬다 — "가격이 여러 개일 때 어느 라벨에 어느 금액이 붙는지"라는
매칭 관계 자체는 전혀 보존하지 못했다. `priceText`도 전체 텍스트에서 "가격
후보 하나"만 뽑아 문자열로 반환해, "성인 15,000원 / 아동 5,000원"처럼 여러
구간이 있으면 그중 하나만(또는 뭉뚱그려) 보였다.

## 변경 사항
### `src/lib/admin/event-price-candidates.ts`
- `PriceAgeTier` 타입 신규: `{ label, priceWon, isFree }`. label은 원문에 실제로
  쓰인 표현을 그대로 보존한다("아동"/"36개월 미만"/"미취학" 등) — "아동"이라는
  범주어의 실제 나이 경계(몇 세부터 몇 세까지)는 소스 텍스트가 명시적으로 정의해
  주지 않는 한 서비스마다 다르고 확인할 근거가 없어(제3장 제5조 추측 금지) 임의로
  지어내 채우지 않는다. 대신 원문에 "36개월 미만"처럼 숫자가 이미 포함된 라벨은
  그 숫자 자체가 곧 나이 기준이 되어 별도 변환 없이 그대로 유용하다.
- `parsePriceAgeTiers(text)`: 신규 순수 함수.
  - 1순위: `/` 또는 줄바꿈으로 구간이 명확히 나뉜 형식 — 각 구간을 "라벨+금액"
    또는 "라벨+무료"로 파싱. 첫 구간 맨 앞에 붙는 "이용료:"/"요금:" 같은 섹션
    제목은 `parse-price-from-text.ts`의 기존 라벨 키워드를 재사용해 걷어낸다
    (제5장 제4조 — 새 키워드를 지어내지 않음).
  - 2순위(구분자가 전혀 없을 때만): 짧은 한글 라벨(최대 12자) 뒤에 금액이 바로
    붙는 경우, 그리고 "36개월 미만 무료"처럼 명시적 나이 숫자+방향 표현이 붙은
    무료 구간만 인정한다(오탐지 방지 — "무료 주차 가능" 같은 무관한 "무료" 언급을
    구간으로 오인하지 않도록 라벨에 나이 숫자가 있을 때만 허용).
  - 같은 라벨이 중복되면 처음 것만 채택.
- `PriceCandidate.priceTiers?: PriceAgeTier[]` 필드 추가(4개 소스 빌더 모두에서
  계산). optional로 둔 이유: `event_price_verifications.candidates`에 이미 저장된
  과거 스냅샷(이 필드 도입 이전)에는 없을 수 있어, UI가 방어적으로 처리한다.

### `src/components/admin/event-price-curation-modal.tsx`
소스 카드에 `priceText` 바로 아래 구조화된 구간 목록("· 성인: 15,000원", "· 36개월
미만: 무료", "· 아동: 5,000원")을 추가했다 — 관리자가 최종 확정 폼(최종 연령 기준/
최종 가격 텍스트)을 채울 때 "이 가격이 어느 대상에 적용되는지"를 한눈에 참고할 수
있다. 요청 원문대로 유저 화면에는 노출하지 않는다(관리자 검증 화면 전용).

## 실측 중 발견해 수정한 버그
1. 구분자가 전혀 없는 문자열("성인15,000원 아동5,000원")에서 1순위(구간 매칭)를
   그대로 시도하면 정규식이 문자열 전체를 하나의 구간으로 보고 "성인15,000원
   아동"을 통째로 라벨로 잘못 묶었다 — 구분자가 실제로 있었을 때만(`segments.length
   > 1`) 1순위를 쓰고, 없으면 처음부터 2순위(전역 패턴)로 가도록 분기를 고쳤다.
2. 2순위 전역 패턴의 라벨 문자 클래스에 숫자를 포함시켰더니, 라벨과 금액 사이에
   공백이 없는 경우("성인15,000원") 탐욕적 매칭이 금액의 앞자리 숫자를 라벨로
   삼켜("성인1" + "5,000원") 잘못 분리됐다 — 라벨은 한글로만 제한했다(숫자가
   필요한 나이 경계형 라벨은 무료 구간 전용 패턴이 별도로 담당).

## 검증
- `npx tsc --noEmit`, `npm run test`(전체 1778개, 신규 12개 포함), `npm run build`
  모두 통과.
- 사용자가 든 예시("성인 15000원 36개월 미만 무료 아동 5000원")를 단위 테스트로
  정확히 재현해 라벨-금액 매칭이 올바르게 분리됨을 확인.
- `/api/admin/events/price-candidates` 실제 운영 데이터 호출로 `priceTiers` 필드가
  응답 전 구간(소스1~4)에 정상적으로 실려 오는 것을 확인(해당 이벤트는 연령별
  가격이 아니라 단일 가격이라 실제 다중 구간 사례로는 검증하지 못했으나, 파이프라인
  자체가 깨지지 않고 정상 동작함은 확인했다 — 다중 구간 파싱 정확성은 위 단위
  테스트로 별도 확인).
