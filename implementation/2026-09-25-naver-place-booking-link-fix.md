# 네이버 예약 자동 생성 버튼 링크를 /booking 경로로 정확화

## 구현 대상
사용자 지시(2026-09-25): 네이버 아이디 1084365162 예시로 "가격표" 정보가
스팟큐레이션 쪽 가격 파싱에 실제로 반영되는지 확인 요청 + 네이버 아이디
1683390650 예시로, 예약 뱃지가 있는 스팟 중 실제로는 "예약"이 아니라
"예매"(티켓 구매)가 맞는 곳들이 있다는 제보. 논의 끝에 사용자가 직접
확인한 사실: "확인해보니깐 /ticket이어도 /booking으로 쳤을때 redirect
해주더라.. 예약가능이나 예약필수일 경우에만 /booking으로 하면 아마
/ticket으로 redirect해줄꺼같아" — 네이버 플레이스가 예매전용 업체도
`/booking` 경로 접근 시 실제 예매 페이지(`/ticket`)로 자동 리다이렉트해
준다는 것을 사용자가 직접 검증했다. 따라서 우리 쪽에서 예약형/예매형을
따로 판별할 필요 없이, 항상 `/booking`으로 링크하면 네이버가 알아서
맞는 페이지로 보내준다.

## 확인한 사실 (가격표 파싱, Q1)
운영 배포된 `/api/admin/spot-curations/naver-crawl`에 실제로 해당 URL을
넣어 테스트한 결과, `menuText`가 사용자가 제시한 가격표와 정확히 일치했다
(예: "🛀대인목욕,사우나(중학교1학년이상) 12,000원" 등 5줄 전부 일치).
기존 `PlaceMenuItem:` 스캔이 업종("메뉴" vs "가격표" 라벨)과 무관하게
동일하게 동작함을 실측으로 확인 — 코드 변경 없음(이미 정상 동작 중이었음).

## 변경 사항
`src/components/map/detail-modal.tsx`의 `buildNaverPlaceUrl()`:
- 기존: `https://map.naver.com/p/entry/place/{id}` (범용 진입 링크)
- 변경: `https://pcmap.place.naver.com/place/{id}/booking`
- 예약 관련 뱃지(예약 가능/예약 필수)가 있고 `naver_booking_url`을 관리자가
  따로 입력하지 않은 스팟에서 자동 생성되는 "🟢 네이버 예약" 버튼의 링크만
  바뀐다 — 라벨/노출 조건/폴백 순서는 그대로다.

## 검증
`npx tsc --noEmit` / `npm run test`(202개 파일 2,341개) / `npm run build`
모두 통과. `detail-modal.test.tsx`의 기존 자동 생성 버튼 테스트를 새 URL
형식으로 갱신.

## 특이 사항
- `/ticket`이 `/booking`으로의 접근을 리다이렉트해준다는 사실은 사용자가
  직접 네이버 플레이스에서 확인한 것으로, 이 세션에서 별도로 재검증하지는
  못했다(이 개발 환경의 네이버 직접 접근이 "과도한 접근" 429로 막혀 있어
  라이브 재확인이 불가능했음 — 배포된 우리 자체 크롤러 API는 Vercel IP를
  타서 정상 동작했다). 사용자 본인의 실측 확인을 그대로 신뢰해 반영했다.
