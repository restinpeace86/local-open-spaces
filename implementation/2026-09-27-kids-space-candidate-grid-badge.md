# open_spaces 그리드에 "키즈 공간 후보 검토" 뱃지 표시

## 구현 대상
사용자 지시(2026-09-27, 채팅으로 보고한 후보 분석 후속): "여기에 대하여
따로 뭐 반영하지말고.. 너가 후보라고 해놓은거는.. 관리자화면의
open_spaces쪽에 그리드 row쪽에 좀 표시 해줄수 있어? 출처 옆에라던가..
표시해놓으면 내가 그거보고 한번 확인해보게".

## 배경
직전에 채팅으로만 보고했던 category_min별 키워드 후보 분석(전체 XXX건 중
XX건)에 대해, 사용자가 아래 3가지를 확정했다:
1. 체육시설은 수영장 외에는 전부 후보 제외
2. 주택단지는 전부 제외 (아파트 단지 내부 시설명이 대량 오검출)
3. 학교는 전부 제외
4. 공원은 "어린이/유아" 키워드가 전국 공통 소규모 놀이터 명명 관례
   ("OOO어린이공원", "OO공원 어린이놀이시설/놀이터")에 대량으로 걸려
   실측(10,052→723건)으로 확인했다 — "생태/체험/모험/동화/과학관/상상/
   키즈/장난감" 테마 키워드로만 좁힌다.

이번 지시는 위 규칙으로 category_min/service_category_id 등 실제 분류
데이터를 바꾸라는 게 아니라(제3장 제5조 추측 금지 — 사람이 최종 확인해야
함), 관리자가 그리드에서 눈으로 훑으며 확인할 표본을 눈에 띄게 표시만
해달라는 것이다.

## 변경 사항
- `src/lib/admin/kids-space-candidate.ts`(신규): `isKidsSpaceReviewCandidate
  (name, categoryMin)` 순수 함수 — 위 4가지 규칙을 그대로 코드화.
  - 주택단지/학교/키즈카페/놀이방식당/놀이방찜질방·스파 → 항상 제외
  - 체육시설 중 수영장 외 중분류(테니스장/골프장/풋살장 등 14종) → 항상 제외
  - category_min === '공원' → 테마 키워드(생태/체험/모험/동화/과학관/상상/
    키즈/장난감)만 적용
  - 그 외 → 기존 포함 키워드(어린이/유아/키즈/장난감/과학관/상상/생태/체험/
    모험/동화) AND NOT 제외 키워드(어린이집/유치원/지역아동센터/방과후교실/
    돌봄센터/경로당)
- `src/components/admin/data-grid-client.tsx`: open_spaces 탭 그리드 행의
  "출처" 셀 옆에, 위 함수가 true를 반환하면 작은 주황색 "후보" 뱃지를 표시.
  events 탭에는 표시하지 않는다(이번 분석은 open_spaces 전용).

## 검증
- `src/lib/admin/kids-space-candidate.test.ts`(신규 9개): 4가지 확정 규칙과
  경계 케이스(공원의 "어린이공원"/일반 이름 대비 테마 키워드, category_min
  null 폴백 등) 전부 검증.
- `src/components/admin/data-grid-client.test.tsx`(신규 4개): 뱃지가 실제
  그리드 행에 렌더링되는지, 제외 대상엔 안 뜨는지, events 탭엔 안 뜨는지 확인.
- `npx tsc --noEmit` / `npm run test`(205개 파일 2,391개) / `npm run build`
  모두 통과.

## 특이 사항
- 이 뱃지는 순수 표시 전용이다 — category_min, service_category_id 등
  실제 DB 값은 이번 변경으로 전혀 바뀌지 않는다. 최종 판단(후보를 실제로
  키즈/놀이시설로 재분류할지)은 관리자가 그리드에서 직접 확인 후 결정한다.
- 채팅 분석 당시 만들었던 임시 스크립트(`scripts/_tmp-full-sql.mjs`)는
  이번에도 공원 이름 샘플 조회에 재사용했다가 다시 삭제했다 — 커밋 대상이
  아니다.
