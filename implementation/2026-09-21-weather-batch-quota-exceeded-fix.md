# [기상청 날씨 배치 — 일일 API 할당량 초과로 인한 반복 실패 조치]

## 구현 대상
사용자 제보(2026-09-21): "지금 기상청 데이터 가져오는게 3시간마다인데 계속
fail 뜨는거 같아 내 gmail로 fail 계속 오고있어."

## 원인 조사
`node scripts/ingest/adapters/kma-weather-adapter.mjs`를 로컬에서 직접
재실행해 실제 에러를 재현했다:
```
KMA getVilageFcst(...) 호출 실패 (HTTP 429): {
  "cmmMsgHeader": {
    "errMsg": "LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR",
    "returnAuthMsg": "일일 서비스 요청제한 횟수 초과 에러"
  }
}
```
실제 규모를 측정한 결과: 전국 EXACT 좌표 스팟 **140,757건**을 5km 격자로
묶어도 고유 격자가 **3,946개**. 3시간마다(하루 8회) 격자당 API를 1회씩
호출하므로 **하루 약 31,568건**의 기상청 단기예보 API 호출이 필요했다 —
이 계정(`PUBLIC_DATA_API_KEY`, TourAPI 등과 공유하는 통합 인증키)의 승인된
일일 한도를 크게 초과해, 그날 한도 소진 이후의 모든 실행이 100% 실패하고
있었다. `withRetry`의 재시도 판별 로직(`isRetryableError`)은 이미 이런 종류의
영구적 오류(429 할당량 초과)를 재시도 대상에서 제외하도록 잘 설계돼 있어서
불필요한 재시도로 할당량을 추가로 낭비하고 있지는 않았다 — 순수하게 "필요한
호출량 > 승인된 한도" 구조적 문제였다.

## 사용자 결정
"즉시 메일 스팸을 멈추고 싶은지 vs 근본 해결부터 정할지" 질문에 "하루 6시간
배치로 해서 8회에서 4회로 줄이자 00시 06시 12시 18시"로 확정. 기상청 단기예보
발표 시각은 02/05/08/11/14/17/20/23시(KST) 8개뿐(고정 발표 주기라 임의
시각 선택 불가)이라, 그중 사용자가 말한 00/06/12/18시에 가장 가까운(각
1시간 차이) **05/11/17/23시(KST)**를 선택했다.

## 변경 사항
`.github/workflows/ingest-weather.yml`:
- Cron을 `47 2,5,8,11,14,17,20,23 * * *`(하루 8회)에서 `47 2,8,14,20 * * *`
  (하루 4회)로 변경.
- **주의**: 원래 8개 값 전체는 KST 오프셋(9시간)이 발표 주기(3시간)의 배수라
  KST로 읽든 UTC로 읽든 같은 집합이 나오는 우연한 대칭이 있었지만, 이번에
  고른 4개 값 부분집합은 그 대칭이 깨진다 — 실제로 KST 05:47/11:47/17:47/
  23:47은 UTC로 20:47(전날)/02:47/08:47/14:47이 된다(Node Date로 직접 계산
  검증). 그래서 cron에는 UTC 값(2,8,14,20)을 명시적으로 넣었다 — KST 값을
  그대로 옮겨 적으면 완전히 다른 시각에 실행되는 조용한 버그가 됐을 것이다.
- 워크플로 이름/주석을 6시간 주기로 갱신.

## 검증
- `npx tsc --noEmit` / `npm run test`(192개 파일 2224개, 회귀 없음 확인) /
  `npm run build` 모두 통과(이 변경은 순수 GitHub Actions YAML이라 애플리케이션
  코드 영향은 없음).
- 실측: 새 cron 문자열을 js-yaml로 직접 파싱해 `47 2,8,14,20 * * *`가 정확히
  반영됐음을 확인. KST↔UTC 변환은 Node `Date` 객체로 4개 값 모두 직접 계산
  검증(암산에 의존하지 않음).

## ⚠️ 잔여 위험 — 이번 조치로 완전히 해결되지 않을 수 있음
하루 4회로 줄여도 필요한 호출량은 여전히 약 **15,784건/일**(3,946격자×4회)
이다. 이는 공공데이터포털의 일반적인 미승인 개발계정 한도(보통 1,000~10,000
건/일)를 여전히 넘을 수 있다 — 이번 변경은 사용자가 명시적으로 지시한 "즉시
완화" 조치이고, 완전한 해결에는 다음 중 하나가 추가로 필요할 수 있다:
1. **공공데이터포털에서 이 API(기상청 단기예보 조회서비스, VilageFcstInfoService_2.0)
   의 트래픽 한도 증량을 신청**(외부 조치, 계정 소유자만 가능 — 코드로 해결 불가).
2. 그래도 부족하면 배치 범위를 추가로 줄이는 것(빈도를 더 낮추거나, 전국
   140,757개 스팟 전체가 아니라 일부 지역/카테고리로 좁히는 것)을 검토해야
   하는데, 이는 "어떤 스팟에 날씨를 안 보여줘도 되는지"를 정하는 제품 판단이라
   임의로 결정하지 않았다 — 4회 실행 후에도 여전히 할당량 초과가 발생하면
   다시 알려주시면 그때 함께 정하면 된다.
