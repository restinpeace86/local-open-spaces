# [스팟픽(/nearby) 카테고리 필터 토글 시 지도 클러스터 숫자 누적 버그 긴급 수정]

## 사용자 제보
"어린이놀이시설(야외)를 누르면 숫자가 증가하는데, 해제했다가 다시 누르면 숫자가 계속
누적된다 — 해제하면 초기화되거나 차감돼야 한다."

## 원인 — 직전 커밋(Step 55)의 "카테고리 필터 성능 개선"이 유발한 회귀
Step 55에서 카테고리 필터 토글 시 지도 반응이 느리다는 제보에 대응해, `KakaoMapView`의
마커 렌더링 방식을 "매번 전체 마커 파괴 후 재생성"에서 "item.id 기준으로 diff해서 바뀐
만큼만 추가/제거"하는 방식으로 바꿨다. 이 변경이 실제로는 마커 중복 등록(리크) 버그를
유발했다.

**실측(Playwright, 실제 카카오맵 SDK)으로 재현 및 확인**: 클러스터 버블 숫자(반경 내
마커 개수 합)를 필터 선택→해제→선택→해제로 4회 반복하며 추적한 결과:
```
초기(미선택): [62, 31, 33, 16, 23, 9, 12, 12, 2]
1회 선택 후: [62, 31, 33, 16, 24, 9, 12, 12, 2]   (+1 정도, 거의 그대로 — 필터가 제대로 안 걸림)
2회 해제 후: [95, 58, 60, 32, 47, 25, 28, 25, 6]  (거의 1.5배로 증가!)
3회 선택 후: [95, 58, 60, 32, 48, 25, 28, 25, 6]
4회 해제 후: [124, 86, 87, 49, 71, 41, 45, 38, 11] (계속 증가)
```
즉 `MarkerClusterer.removeMarker(marker, true)`로 제거했다고 표시한 마커가 클러스터러
내부에서 실제로는 완전히 빠지지 않고, 해당 항목이 다시 필터에 포함될 때 새 마커 객체가
추가로 등록되어 같은 항목이 두 번, 세 번... 계속 중복 집계되는 것으로 확인했다(원인은
카카오 SDK 자체의 `removeMarker` 동작이 이 프로젝트가 가정한 것과 다르거나, addMarkers로
일괄 등록된 마커에 대해 removeMarker가 완전히 반영되지 않는 것으로 추정 — 정확한 SDK
내부 동작까지는 확인하지 않았고, 이 API 조합 자체를 쓰지 않는 방향으로 대응했다).

## 조치 — 성능 최적화 되돌리기
`src/components/map/kakao-map-view.tsx`를 Step 54 시점의 검증된 방식으로 되돌렸다:
필터가 바뀔 때마다 `clustererRef.current.clear()` + 개별 `marker.setMap(null)`로 전체
마커를 파괴한 뒤, `items` 전체를 순회하며 마커를 다시 생성해 `addMarkers()`로 일괄
등록한다. Step 55에서 추가했던 `markersByIdRef`/`itemsByIdRef`/`groupsByPositionRef`
(diff 전용 상태)와 `kakao.d.ts`의 `removeMarker`/`redraw` 타입 선언,
`tests/e2e/support/mocks.ts`의 대응 스텁을 모두 제거했다. 겹친 마커 클릭 시 목록을
보여주는 기능(Step 54, `onSelectGroup`)은 그대로 유지된다 — 이 기능은 diff 방식과
무관하게 항상 올바르게 동작했다.

**데이터 정합성을 성능보다 우선**했다: 필터 토글 시 최대 200개 마커를 재생성하는 비용
(실측 30~120ms, Step 55 기록 참고)은 감수 가능한 수준이지만, 지도에 실제 없는 항목이
중복 집계되는 것은 사용자에게 잘못된 정보를 보여주는 심각한 결함이라 롤백을 우선했다.

## 검증
- **버그 재현 후 수정 확인(Playwright 실측)**: 동일한 선택→해제 반복 시나리오에서
  수정 후에는 선택 시 [10, 7, 6](필터링된 소수), 해제 시 [62, 31, 33, 16, 23, 9, 12,
  12, 2](최초와 완전히 동일)로 4회 반복 내내 정확히 재현되며 전혀 누적되지 않음을 확인.
- `npx tsc --noEmit` 통과
- `npm run test`(56파일 562건) 통과
- `npm run build` 통과

## 특이 사항
- 성능 최적화 자체(카테고리 필터 토글 시 마커 재생성 비용)는 이번에 다시 원상복구했으므로
  Step 55에서 제기됐던 "느리다"는 체감은 재발할 수 있다. 이 부분을 다시 개선하려면
  카카오 클러스터러의 `removeMarker`/`addMarker` 개별 API의 정확한 동작을 별도로 충분히
  검증한 뒤(이번처럼 실측 없이 API 존재만 믿고 적용하지 않도록) 재시도해야 한다 — 이번
  세션에서는 안정성을 우선해 되돌리는 것으로 마무리한다.
