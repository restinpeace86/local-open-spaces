# 관리자 화면 데이터 테이블 스크롤 최적화 — 세로/가로 스크롤 축 분리

## 구현 대상
사용자 지시: "어 최적화해줘" — 직전 모바일 점검 보고에서 언급한 "테이블이 부모의
`overflow-auto`(세로+가로 동시)에 얹혀 동작해 대각선 스와이프 시 다소 부자연스럽다"는
지점을 실제로 개선.

## 구현 일시
2026-09-05

## 변경 사항
`src/components/admin/data-grid-client.tsx`(open_spaces/events/raw_ingest_data 공유
테이블), `src/components/admin/curated-items-panel.tsx`(제휴 상품 테이블) 둘 다
동일한 구조였다 — 테이블 전체를 감싸는 컨테이너 하나(`overflow-auto`)가 세로(페이지)
스크롤과 가로(넓은 테이블) 스크롤을 동시에 담당하고 있었다. 표준 반응형 테이블
패턴으로 분리했다:
- 바깥 컨테이너: `overflow-auto` → `overflow-y-auto`(세로 스크롤 전담).
- `<table>`을 `<div className="overflow-x-auto">`로 새로 감싸(가로 스크롤 전담),
  이 안에서만 테이블이 넓을 때 가로로 스크롤된다.
- 페이지네이션 푸터는 이 가로 스크롤 래퍼 바깥에 그대로 둬(원래도 바깥이었음) 항상
  화면에 붙박이로 보이게 유지했다(가로로 스크롤해서 찾을 필요 없음).

## 특이 사항
- **`data-grid-client.tsx`의 테이블 헤더는 `sticky top-0`이다** — 가로 스크롤
  래퍼를 중간에 끼워 넣어도 스티키 헤더가 계속 정상 동작하는지가 이번 변경의
  핵심 리스크였다. 이 래퍼(`overflow-x-auto`, 높이 제약 없음 — 내용물 높이 그대로
  자라남)는 실제로는 세로 방향으로 전혀 스크롤되지 않으므로(제약된 높이가 없어
  넘칠 일이 없음), 브라우저의 실제 렌더링에서는 진짜 세로 스크롤 컨테이너인 바깥
  `overflow-y-auto`를 기준으로 스티키가 계속 동작한다 — 이 프로젝트 밖에서도
  "overflow-x-auto로 감싼 테이블 + 스티키 헤더"는 매우 흔히 쓰이는 검증된 패턴이다.
  다만 이 환경에는 실제 브라우저로 시각 확인할 도구가 없어(jsdom은 실제 레이아웃/
  스크롤을 시뮬레이션하지 않음), 스티키 동작 자체를 자동 테스트로 재확인하지는
  못했다 — 실제 화면에서 스크롤해보고 헤더가 계속 붙어 있는지 한 번 확인해주시면
  좋겠다(문제가 있으면 바로 되돌릴 수 있는 작은 변경이다).
- `curated-items-panel.tsx`는 스티키 헤더가 없어 이 리스크 자체가 없다.
