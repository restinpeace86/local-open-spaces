## 1. "글이 잘려서 얼마 안 보인다" — 실측 재확인

전체 본문 보기 기능(2026-09-05) 자체는 정상 동작했다 — 사용자가 붙여넣은
텍스트로 실제 URL(`https://blog.naver.com/lkk4268135/224401608956`)의 본문을
직접 재추출해보니, **본문 전체(1,317자)가 정확히 추출됐고, 그 첫머리가 사용자가
화면에서 본 문구와 정확히 일치**했다:

```
대구월성동맛집 신월성맛집 월배맛집 월성동돼지갈비 대구진천동맛집 호박터숯불촌
신월성점 #호박터숯불촌 #호박터숯불촌신월성점 #대구월성동맛집 #신월성맛집
#월배맛집 #월성동돼지갈비 #대구진천동맛집 오늘은 동네에 최근에 오픈한 호박터숯불촌
신월성점 다녀온 후기 전합니다 💕🍀 ... (총 1,317자)
```

즉 백엔드는 정상이었고, 문제는 화면 쪽에 있었다 — `BlogReferenceViewer`의 본문
표시 영역이 `max-h-64 overflow-y-auto`로 **자기 안에 별도의 작은 스크롤을**
갖고 있었는데, 이 영역 자체가 이미 스크롤되는 모달/워크벤치 안에 중첩돼 있어
"스크롤 안의 또 다른 스크롤"이 됐다 — 사용자는 이 작은 박스가 그 안에서 또
스크롤된다는 걸 알아채지 못해 처음 몇 줄(정확히 짧은 요약 스니펫과 겹치는
분량)만 보고 "잘렸다"고 느낀 것이었다.

### 수정
`src/components/admin/blog-reference-viewer.tsx`: 본문 표시 div에서 `max-h-64
overflow-y-auto`를 제거했다 — 이제 본문 길이만큼 자연스럽게 늘어나고, 부모
(모달의 `max-h-[90vh] overflow-y-auto` 또는 워크벤치의 `flex-1 min-h-0
overflow-y-auto`)의 스크롤 하나로만 전체를 이어서 볼 수 있다.

## 2. 큐레이션 메모 입력란 추가

### 재사용(제5장 제4조) — 새 컬럼을 만들지 않음
새 DB 컬럼을 추가하지 않고, 이미 `spot_curations` 테이블에 있고
`SpotCurationsPanel`(키즈친화 식당 큐레이션 폼)이 이미 "큐레이션 메모(선택)"라는
라벨로 쓰고 있던 `curation_note`(text, nullable) 컬럼을 그대로 재사용했다 —
`/api/admin/spot-curations` GET/POST/PATCH는 이미 이 필드를 지원하고 있어
백엔드 변경이 전혀 필요 없었다.

### 변경 사항
- `src/lib/admin/use-spot-curation-form.ts`: `SpotCurationItem`에
  `curation_note` 추가, `curationNote` 상태 추가(기존 큐레이션 조회 시 프리필),
  저장 payload에 `curation_note: curationNote.trim() || null` 포함.
- `src/components/admin/curation-badge-form.tsx`: "큐레이션 메모(선택)"
  textarea 추가(`rows={3}`, `resize-y` — 기존 `SpotCurationsPanel`의 "영업시간
  (텍스트 붙여넣기)" textarea와 동일한 스타일 관례). placeholder에 사용자가
  예시로 든 해시태그 형식을 그대로 넣어 어떤 용도인지 바로 알 수 있게 했다.
- `BlogCurationModal`/`MobileCurationWorkbench`: `curationNote`/
  `onCurationNoteChange`를 훅에서 폼으로 그대로 전달.

## 특이 사항
- 메모 입력란의 정확한 용도(검색 키워드 보강용인지, 순수 참고 메모인지)는
  지시문에 명시되지 않았다 — 다만 이미 이 프로젝트에 "큐레이션 메모(선택)"라는
  동일 목적(자유 텍스트 참고 메모)의 필드가 존재해 그걸 그대로 재사용하는 것이
  가장 근거 있는 선택이라고 판단했다(추측 대신 기존 구조 재사용, 제3장 제5조·
  제5장 제4조). 저장만 될 뿐 화면 어디에도 자동으로 노출/활용되지는 않는다 —
  필요하면 이후 검색 refinement 등에 활용하는 기능을 별도로 요청하면 된다.
