# [버그 제보] 어드민 스팟 큐레이션 등록 화면 — 검색 선택/영업시간·메뉴 파싱

## 구현 일시
2026-09-02

## 배경
관리자가 실제로 화면을 쓰다가 카카오톡/메시지로 남긴 사용성 제보 3건을 그대로 재현·
진단해 고쳤다.

## 진단 및 조치

### 1. "스팟 검색 결과를 클릭해도 반영이 안 되네"
- Playwright로 실제 클릭 플로우를 재현한 결과, **선택 로직 자체(state)는 정상 동작**
  했다 — 클릭하면 `selectedSpot`이 정확히 설정되고 검색창이 사라지는 것을 확인했다.
  다만 두 가지 실제 문제를 발견해 고쳤다:
  1. **검색 API가 콜드 스타트 시 최대 5초 가까이 걸릴 수 있음**(실측: 1.2~5초 변동,
     웜 상태에서는 250~330ms) — 이 사이 사용자가 "검색 중" 상태를 인지하지 못하고
     클릭해도 반응이 없다고 느낄 여지가 컸다. "검색 중..." 문구를 회색 잔글씨에서
     파란색 강조 문구("🔍 검색 중이에요, 잠시만 기다려주세요...")로 바꿔 눈에 띄게 했다.
  2. **선택 후 UI가 검색창을 완전히 다른 모양(회색 카드)으로 바꿔버려** "이름이
     입력란에 채워졌다"는 느낌이 들지 않았다 — 검색 입력란과 동일한 테두리 스타일의
     읽기전용 필드 형태(✅ 체크 아이콘 포함)로 바꿔, 선택된 이름이 실제로 "채워졌다"는
     것을 시각적으로 분명히 했다.
  - 추가로 AbortController를 도입해 새 검색이 시작되면 이전 요청을 확실히 취소하도록
    방어를 강화했다(느린 응답이 뒤섞일 가능성을 원천 차단 — 실제 원인으로 확정하지는
    못했지만 재발 방지 차원의 보강).

### 2. "영업시간 자동 파싱 시 브레이크타임/라스트오더가 안 채워짐" — 근본 원인 확정, 수정
- 제보 원문("매일 / 11:00 - 21:00 / 15:00 - 17:00 브레이크타임 / 20:30 라스트오더")을
  그대로 넣어 재현한 결과, **시간이 키워드보다 앞에 오는 표기**("15:00 - 17:00
  브레이크타임", "20:30 라스트오더")에서 파싱이 실패함을 확인했다.
- **근본 원인**: 기존 `extractLabeledRange`/`extractLabeledTime`은 "키워드 위치부터
  뒤쪽 텍스트만" 검색해, 키워드보다 *앞*에 있는 시간을 아예 못 봤다(키워드 뒤에는
  더 이상 시간이 없으니 매칭 실패).
- **수정**: 줄 단위로 키워드가 포함된 줄을 찾고, 그 줄 안에서 키워드와 *가장 가까운*
  시간(범위)을 채택하도록 바꿨다 — 키워드가 시간보다 앞이든 뒤든, 같은 줄에 다른
  숫자가 여러 개 섞여 있든(예: 메인 시간+브레이크+라스트오더가 한 줄에 있는 기존
  지원 형식) 모두 정확히 근접한 값을 고른다. 기존 6개 테스트(키워드가 시간보다
  앞에 오는 형식) 전부 그대로 통과함을 확인했다.

### 3. "메뉴 복붙 파싱이 안 됨(형식이 다를 수도)" — 근본 원인 확정, 신규 형식 지원 추가
- 제보 원문(메뉴판을 그대로 긁어온 "이름" / (빈 줄) / "가격" / (빈 줄) / "설명" 반복
  형식)을 그대로 넣어 재현한 결과, 단 한 줄도 파싱되지 않음을 확인했다.
- **근본 원인**: 기존 파서는 "이름 가격원"이 한 줄에 함께 있는 형식만 인식했는데,
  제보된 형식은 이름/가격/설명이 전부 별도 줄로 나뉘어 있었다 — 이런 배달앱/홈페이지
  메뉴판 복사-붙여넣기 결과가 실제로 매우 흔한 모양이다.
- **수정**: 가격만 단독으로 있는 줄("12,000원")을 새로 인식해, 그 직전에 본 텍스트
  줄을 이름으로 확정하는 방식을 추가했다. 이름 → 가격 → 설명 순서가 항상 유지되는
  구조라(설명은 항상 가격 *다음*에 옴), 가격을 찾을 때마다 이름 후보를 비워두면
  설명 줄이 다음 이름 자리를 잘못 차지하는 일이 없다. `menu_items` 스키마가
  `{name, price}`만 저장하도록 이미 확정돼 있어(`2026-09-01-create-spot-curations-
  table.sql`) 설명은 의도적으로 버린다(스키마를 임의로 바꾸지 않음). 기존 4개 테스트
  (단일 줄 형식) 전부 그대로 통과함을 확인했다.
- **부가 개선**(제보: "영업시간/메뉴 텍스트 붙여넣기 화면이 좀 작다"): 영업시간
  textarea를 2줄→5줄, 메뉴 textarea를 3줄→8줄로 늘리고 `resize-y`를 허용해 붙여넣은
  내용을 스크롤 없이 더 잘 확인할 수 있게 했다. 메뉴 라벨/플레이스홀더도 새로 지원하는
  두 형식을 모두 안내하도록 갱신했다.

## 검증

### 코드 검증
`npx tsc --noEmit`/`npm run test`(88파일 894건 — 파서 5건 신규)/`npm run build` 통과.

### 실측 검증(실제 브라우저, 실제 관리자 화면, 사용자 제보 원문 그대로)
- Playwright로 실제 화면에서 검색→클릭 선택 플로우 재현(선택 state는 정상 동작함을
  최초 확인).
- Playwright로 제보된 영업시간 원문을 실제 textarea에 붙여넣고 "⚡ 자동 파싱" 클릭 →
  오픈 11:00/마감 21:00/브레이크 15:00~17:00/라스트오더 20:30 전부 정확히 필드에
  채워짐을 실제 입력값으로 직접 확인.
- Playwright로 제보된 메뉴 원문(17줄, 3개 항목)을 실제 textarea에 붙여넣고 자동
  파싱 클릭 → "하노이 쌀국수·12,000원/하노이 고급쌀국수·14,000원/수제 넴(짜조)·
  8,000원" 3건이 정확히 목록에 표시됨을 확인, 스크린샷으로 최종 화면 확인.

## 특이 사항
- 검색 클릭-선택 자체는 원인을 확정하지 못했다 — 코드상 로직은 정상이었고, 콜드
  스타트 지연/시각적 피드백 부족이 유력한 원인으로 추정돼 그 부분을 개선했다. 개선
  후에도 재현되면 정확한 재현 절차(브라우저, 검색어 글자 수, 클릭까지 걸린 시간 등)
  를 추가로 확인해야 한다.
