## 1) 스크롤 버그 수정
원인은 2026-09-22에 고친 온보딩 화면 스크롤 버그와 완전히 동일했다 —
루트 레이아웃(`src/app/layout.tsx`)의 `body`가 `h-dvh flex flex-col
overflow-hidden`인데, `src/app/hq/layout.tsx`는 `min-h-dvh`만 쓰고
있어 내부에 독립 스크롤 컨테이너가 없었다. 그래서 파트너가 늘고 예약이
쌓일수록 body의 고정 높이 안에서 아래쪽 내용이 그냥 잘렸다(스크롤 자체가
안 먹는 게 아니라, 스크롤할 대상 자체가 `overflow-hidden`에 갇혀 있었음).
`min-h-dvh` → `flex-1 overflow-y-auto`로 변경(`my-page-view.tsx`/온보딩
화면과 동일한 기존 셸 패턴, 제5장 제4조).

## 2) 대시보드를 파트너별 요약 목록 + 드릴다운으로 재구성
기존에는 `/hq` 한 화면에 모든 파트너의 예약 표 전체를 다 펼쳐놨다 — 스크롤
버그와 별개로도, 파트너 수/예약 수가 늘어날수록 한 화면에 정보가 과도하게
쌓여 탐색이 어려워지는 구조였다. 사용자 지시대로 목록/요약 형태로 단순화:
- `src/app/hq/page.tsx`: 파트너 목록 + 파트너별 예약 건수만 보여주는 요약
  목록으로 재작성. 각 항목은 `/hq/partners/[id]`로 링크. 집계는 기존 관례대로
  (monthly/page.tsx와 동일하게, 제5장 제4조) SQL GROUP BY 대신 JS에서
  처리하되, `bookings`에서 `partner_id`만 select해 이전보다 페이로드를
  줄였다(예약 상세 컬럼은 이제 상세 페이지에서만 필요).
- 신규 `src/app/hq/partners/[id]/page.tsx`: 기존 `/hq`에 있던 "파트너명 +
  예약 표 전체(HqBookingRow 재사용)"를 그대로 옮긴 상세 화면. 존재하지 않는
  파트너 id면 `notFound()`.
- 두 페이지 모두 `export const dynamic = 'force-dynamic'` 유지(2026-09-22에
  발견한 정적 프리렌더링 버그 재발 방지).
- `middleware.ts`의 `/hq/*` 가드(이메일 화이트리스트)는 경로 프리픽스 기준이라
  새 하위 경로에도 코드 변경 없이 그대로 적용된다.
