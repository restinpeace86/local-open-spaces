# 중복 스팟 검수 — 병합 예정 멤버의 원본 중분류가 다르면 경고 표시

## 구현 대상
사용자 지시(실측 사례): "화성에코팜테마파크 오토캠핑장(캠핑장, 경기도
화성시..) / 화성에코팜 테마파크 어린이체험관(키즈카페, 경기 화성시..) —
이거 원본 중분류가 다른데? 둘다 노출중분류가 캠핑장인가? 노출중분류가
캠핑장인것만 중복스팟 검수 및 매핑에 나와야하는거 아닌가? 내가 지금
캠핑장/피크닉장 기준으로 중복체크중인데"

## 구현 일시
2026-09-09

## 원인 진단 — 코드 버그가 아니라 데이터 매핑 실수였다
실측 확인 결과 두 스팟 모두 실제로 `service_category_id`가 "캠핑장 /
피크닉장"으로 매핑돼 있었다(직접 SQL로 확인). 즉 "노출중분류가 캠핑장인
것만 나와야 하는데 다른 게 섞였다"는 스캔 로직의 오류가 아니라 — **스캔은
정확히 자기 필터대로 동작**하고 있었고, "화성에코팜 테마파크 어린이체험관"
(실제로는 키즈카페 성격 시설)이 애초에 캠핑장 노출 중분류로 잘못 매핑돼
있었던 것이 근본 원인이다(같은 주소의 5개 시설 중 이 2건만 캠핑장으로
매핑돼 있고 나머지 3건은 미매핑 상태 — 언젠가 관리자가 수동/대량 매핑
과정에서 실수로 함께 포함시킨 것으로 보인다). 게다가 [[2026-09-09-address-
normalization-and-consumer-count-fix]](Step 88)의 주소 정규화 개선으로
"경기도"/"경기" 표기 차이가 없어지면서, 원래도 매핑이 틀렸던 이 두 건이
주소까지 일치해 그룹으로 묶이며 비로소 눈에 띄게 됐다.

이 특정 행의 매핑을 직접 고치지는 않았다 — 어떤 노출 중분류가 맞는지는
관리자가 직접 판단할 사안이라(제5장 제3조 임의 판단 금지), 기존
`ServiceCategoryEditor`(raw-data-modal.tsx)로 언제든 바로잡을 수 있다.

## 변경 사항
`src/components/admin/spot-dedup-panel.tsx` — `GroupDetailModal`에
경고를 추가했다: 병합 예정(체크된) 멤버들의 원본 중분류(`category_min`)가
서로 다르면 "⚠️ 병합 예정인 항목들의 원본 중분류가 서로 다릅니다(캠핑장 /
키즈카페). 정말 같은 장소인지 확인해주세요"를 보여준다. **막지는 않는다**
— 서로 다른 공공데이터 출처가 같은 개념을 "야영장"/"캠핑장"처럼 다르게
표기하는 정상적인 경우도 있어(예: [[2026-09-09-childcare-support-center-
moved-to-etc]] 이전 세션에서 이미 이런 표기 차이 사례를 여러 번 확인했다),
임의로 차단하면 제3장 제5조 추측 금지에 어긋난다 — 대신 관리자가 눈으로
바로 알아채고 체크박스로 뺄지 그대로 병합할지 판단할 수 있게 한다.
