# /admin/data-grid 모바일 — 필터 영역이 화면 90% 차지, 결과 목록이 한 건만 보임

## 구현 대상
사용자 지시: "모바일화면에서 /admin/data-grid 관리자 화면 봤을때 open_spaces쪽에
일단 보면 중분류나 등록일등의 조건이 화면영역의 90% 차지하고 있어.. 조회하기
누르면 하단에 검색된 데이터 나오는데 이 영역이 너무 작아서 목록 리스트 한건정도
밖에 안보여 영역자체가 너무 작어 모바일에서 그래서 뭘 확인하기가 어려워"

## 구현 일시
2026-09-06

## 원인
`AdminDataGridClient`(`src/components/admin/data-grid-client.tsx`)의 필터 바
(검색창 + 표준 중분류 계층 필터 + 노출 중분류 미지정 체크박스 + 등록일 단축/
달력 필터 + 조회하기 버튼)를 감싸는 컨테이너가 `shrink-0`로 높이 상한 없이
렌더링되고 있었다. 데스크톱 폭에서는 각 버튼/체크박스가 한두 줄에 다 들어가
문제가 없었지만, 모바일 좁은 폭에서는 같은 항목들이 `flex-wrap`으로 훨씬 많은
줄로 줄바꿈되어 이 블록 자체의 높이가 크게 늘어난다. 결과 목록 영역은 이
필터 블록의 형제 요소로 `flex-1 min-h-0 overflow-y-auto`(2026-09-05에 이미
적용된 스크롤 수정)를 쓰고 있어 자체적으로는 정상 작동하지만, `flex-col`
레이아웃 특성상 앞의 `shrink-0` 필터 블록이 커질수록 뒤의 `flex-1` 결과
영역이 차지할 수 있는 실제 공간이 줄어든다 — 필터 블록이 뷰포트의 90%를
차지하면 결과 목록에는 10%(리스트 한 줄 정도)만 남는 것이 정확한 원인이었다.

## 변경 사항
`src/components/admin/data-grid-client.tsx`: 필터 바 컨테이너에
`max-h-[45vh] overflow-y-auto`를 추가했다. 필터 내용이 아무리 길어져도(상세
필터까지 펼친 경우 포함) 이 블록 자체가 뷰포트 높이의 45%를 넘지 않고 내부
스크롤로 처리되며, 결과 목록(flex-1)은 항상 나머지 절반 이상의 공간을
확보한다.

## 검증
- `npx tsc --noEmit` 통과.
- `npm run test`: 신규 1건("필터 바에 최대 높이 제한과 자체 스크롤이 있어
  결과 목록 영역을 밀어내지 않는다" — 검색창의 부모 요소에 `max-h-[45vh]`,
  `overflow-y-auto`, `shrink-0` 클래스가 모두 있는지 확인) 포함 115개 파일 /
  1230개 테스트 전체 통과.
- `npm run build` 통과.

## 특이 사항
- 이 위(대시보드 요약 위젯 + 탭 목록)의 별도 `shrink-0` 헤더 블록은 사용자가
  지목한 "중분류나 등록일등의 조건" 영역이 아니라서 1차 수정 범위에는
  포함하지 않았다 — 하지만 사용자가 "여전히 90% 차지"라고 재확인해 2차
  수정(아래 [[2026-09-06-admin-mobile-filter-bar-percent-fix]])에서 이 판단을
  뒤집었다.
- 데스크톱에서는 필터 내용이 보통 45vh를 넘지 않아 시각적 변화가 없고,
  넘더라도 필터 영역만 자체 스크롤되는 것은 모바일/데스크톱 모두에 안전한
  동작이라 반응형 분기(`md:` 등) 없이 공통 적용했다.

## 2026-09-06 후속 — 1차 수정으로 부족했음 (사용자 재확인)
사용자 재확인: "아니 똑같은거 같은데.. 모바일에서 했을때 여전히 거의 안보여
검색조건쪽이 90% 차지하고 있고..." — 1차 수정(`max-h-[45vh]`)이 배포된
상태였음을 CSS 번들 직접 확인으로 검증했으나(운영 CSS에
`.max-h-\[45vh\]{max-height:45vh}` 규칙이 실제로 존재), 그럼에도 효과가
부족했다. 자세한 원인 재분석과 2차 수정 내용은
[[2026-09-06-admin-mobile-filter-bar-percent-fix]] 참고.
