# [예약 오픈 알림 — "여기저기" 서울형키즈카페 오분류 정정]

## 구현 대상
사용자가 "여기저기 서울형키즈카페" 공식 30개소 명단을 제시(2026-09-20)하며
"여기서 일단 MINCLASSNM이 서울형키즈카페인 것들이 여기저기 서울형키즈카페이긴
할 텐데"라고 확인을 요청 — 명단을 실제 서울시 API와 대조해 우리 DB 분류가
맞는지 검증하고 틀린 건 바로잡음.

## 구현 일시
2026-09-20

## 실측 확인
사용자가 제시한 30개소 명단을 라이브 서울시 API(tvYeyakCOllect,
MINCLASSNM='서울형키즈카페')와 정확 매칭한 결과:
- **30개소 중 실제로 지금 API에 존재하는 건 11곳뿐**이다. 나머지 19곳(강동구
  광나루한강공원, 강서구 마곡하늬공원, 광진구 뚝섬한강공원, 구로구 오류역광장
  등)은 이름을 아무리 느슨하게(공백 제거, 부분 포함) 매칭해도 API 어디에도
  없다 — **우리 파이프라인이 놓친 게 아니라 원천 데이터 자체에 아직 없다**
  (온라인 예약이 아직 게시되지 않은 것으로 보임).
- 11곳 중 9곳(제목이 순수 장소명, "키즈카페" 단어 없음 — 예: "마포구
  망원한강공원")은 이미 지난 시드에서 정확히 처리돼 있었다.
- 나머지 2곳은 제목에 "키즈카페"가 들어있어("서울형 키즈카페 시립
  서울식물원점", "서울형 키즈카페 양천구 오목공원점") 카테고리 정제 규칙
  엔진이 `공공키즈카페`("일반")로 잘못 분류했고, 그 결과 4월(화요일) 규칙이
  잘못 적용돼 있었다 — **이 2건이 실제 오류였다.**
- 즉 "제목에 키즈카페가 있는지"는 "여기저기"를 구분하는 신뢰할 수 있는
  신호가 아니었다(실제 반례로 확인) — 최종적으로는 사용자가 제공한 공식
  명단과의 정확한 이름 대조만이 신뢰할 수 있는 방법이었다.

## 코드 변경
`scripts/migrations/2026-09-20-fix-misclassified-yeogijeogi-kids-cafe.mjs`
(신규, 1회성): 위 2건(`external_id`로 정확히 지정 — 동일 제목의 legacy 중복
행(`SEOUL_RESERVATION_*` 접두)까지 잘못 건드리지 않도록)의 `category_min`을
`서울형키즈카페`로, `category_min_source`를 `MANUAL`로 정정하고,
`next_reservation_open_at`을 9월 공지문 규칙(강서구→월 10시, 양천구→월
12시)으로 재계산했다.

카테고리 재분류 배치(`scripts/ingest/lib/category-rules.mjs`)는 이미
`category_min_source`가 채워진 행은 다시 건드리지 않으므로(실측 확인 주석
그대로), `MANUAL`로 정정해두면 향후 일일 수집 배치가 다시 `공공키즈카페`로
되돌리지 않는다.

## 특이 사항
- 19개소는 여전히 우리 DB에 없다 — 서울시가 온라인 예약을 게시하면 일일
  수집 배치가 자동으로 새 행을 만들 것이고, 그 시점에 제목이 "키즈카페"를
  포함하면 다시 `공공키즈카페`로 잘못 분류될 위험이 있다. 근본적으로
  해결하려면 카테고리 정제 규칙 엔진 자체에 이 30개소 명단(또는 더 나은
  신호)을 반영해야 하는데, 이번 작업 범위는 "이미 들어와 있는 데이터 정정"
  까지였다 — 규칙 엔진 개선은 별도 지시가 있을 때 진행한다.
- 이 조사 과정에서 events 테이블에 `SEOUL_RESERVATION_*`/`SEOUL_YEYAK_*`
  접두가 다른 legacy 중복 행이 남아있는 것도 함께 확인했다(2026-08-27
  백필 스크립트가 처리하다 만 잔재로 추정) — 이번 작업 범위 밖이라 손대지
  않았다.
