# [UI/UX 개선 및 기능 수정 요청] 이벤트픽 챗봇 추가, 대/중분류 바텀 시트 개편, 스팟픽 레이아웃 통일 및 시설 제한 상향

## 구현 일시
2026-09-01

## 배경 — 항목 1의 실측으로 발견한 직전 작업의 오류
지시서 항목 1("이벤트픽 페이지 챗봇 FAB 노출 추가 — 현재 누락되어 있음")을 그대로
믿지 않고 먼저 현재 코드를 확인했다. 직전 "AI 맞춤 추천 챗봇 엔진" 작업에서 나는
"이벤트픽 = `/calendar`"로 잘못 판단해 그 화면에 FAB를 마운트했었다 — 실제로는
`bottom-tabs.tsx`가 명시적으로 `{ href: '/', label: '이벤트픽' }`(홈 화면)이라고
정의하고 있고, `/calendar`는 "도감/캘린더" 상단 서브탭으로 진입하는 완전히 별개의
보조 화면이다(Decision 008: 기존 뷰 재배치, 하단 탭 구조와 무관). 즉 지시서의 지적은
정확했고, 내 이전 작업의 실수였다 — 투명하게 정정한다.

## 구현 내용

### 1. 이벤트픽(`/`) 챗봇 FAB — 정정
- `CalendarView`(`/calendar`)에서 `AiChatFab`/`useUserLocation`을 제거했다(애초에
  이 화면은 "이벤트픽"이 아니었으므로 대상이 아니다).
- `HomeView`(`/`, 실제 "이벤트픽")에 `AiChatFab`을 마운트했다 — 이미 `useUserLocation()`
  을 사용 중이라 `center`를 그대로 재사용, 새 온보딩 흐름을 추가하지 않았다.

### 2. 이벤트픽 하단 '테마별 행사 영역' 숨김
- `<section aria-label="테마별 추천">`에 `hidden` 속성을 적용했다. 지시서가 "제거
  또는 주석 처리/hidden 적용" 중 하나를 명시적으로 선택할 수 있게 제시했고, 관련
  state(`selectedTheme`/`themeSpotItems`)와 지연 페칭 로직을 그대로 둔 채(섹션
  진입 자체가 막히므로 실제로 페칭이 발생하지도 않는다) 되돌리기 쉬운 `hidden`을
  선택했다(완전 삭제가 아님 — 제5장 제4조 기존 구조 우선/불필요한 재작업 방지).

### 3. 대분류/중분류 선택 UI 바텀시트 개편
- `MajorCategoryGrid`가 대분류 아이콘 그리드 바로 아래 인라인으로 펼치던 중분류
  칩 목록을, 기존 `AiRecommendSheet`/`EventBrowseSheet`와 동일한 오버레이+바텀시트
  패턴(배경 클릭/✕로 닫힘)으로 교체했다. 대분류 아이콘 클릭 시 로컬 상태
  `isSheetOpen`이 true가 되어 시트가 열리고, 중분류를 고르면 `onSelectMin` 호출 후
  자동으로 닫힌다(선택이 끝났으니 더 볼 것이 없음). 대분류 선택 상태 자체는 계속
  부모(HomeView)가 소유하는 controlled prop 그대로 두고, "시트가 열려 있는지"만
  이 컴포넌트 로컬 상태로 분리했다 — 대분류 선택 후의 카드 피드 조회/렌더링 로직은
  전혀 건드리지 않았다(지시서 범위가 "선택 UI"에 한정됨).

### 4. 스팟픽(`/nearby`) 상단 레이아웃을 이벤트픽과 통일
- `/nearby`의 모바일 플로팅 헤더(`LocationHeader`+`SearchBar`)를 `flex-col`(세로
  스택)에서, 이벤트픽의 `HomeHeader`(`docs/spec.md 2.1` "고정 헤더: [위치 선택기] +
  [🔍 통합 검색바]")와 동일한 `flex items-center gap-2` 가로 배치로 바꿨다.
  `LocationHeader`는 이미 `HomeHeader`에서도 같은 방식으로 쓰이고 있어(`shrink-0
  max-w-[45vw]`로 검색바 공간을 침범하지 않도록 이미 설계돼 있음) 별도 스타일
  조정 없이 그대로 나란히 배치됐다. `SpotCategoryFilter`/재검색 버튼 행은
  `HomeHeader`에는 없는 스팟픽 전용 UI라 계속 별도 줄로 아래에 쌓는다(구조는
  그대로 유지, LocationHeader+SearchBar 한 줄만 가로로 통일). 데스크톱 좌측
  사이드바(400px 폭 세로 패널)는 이벤트픽과 애초에 레이아웃 성격이 달라(좁은
  세로 컬럼) 범위에서 제외했다.

### 5. "반경 내 시설이 너무 많습니다" 임계값 200 → 1,000
- `map-explorer.tsx`의 `MARKER_LIMIT`을 200 → 1,000으로 상향.
- `get_nearby_spaces_and_events` RPC의 `LIMIT 201`도 함께 `LIMIT 1001`로 올렸다
  (마커 상한보다 하나 더 받아 "더 많은 결과가 있다"를 판단하는 기존 관례 그대로
  유지, 신규 마이그레이션으로 적용·DB 반영 완료).
- `spec/map/spatial-search.md 3.1`의 문서 값도 200→1,000으로 함께 갱신했다(Spec
  우선 원칙 — 승인된 변경은 Spec에도 반영).

## 검증

### 코드 검증
`npx tsc --noEmit`/`npm run test`(88파일 889건 — 신규/갱신 3파일 총 12건 갱신)/
`npm run build` 통과.

### 실측 검증(실제 DB, 실제 브라우저·모바일 뷰포트)
- Playwright: `/`(이벤트픽)에 FAB 존재 확인, `/calendar`에는 더 이상 FAB가 없음을
  확인(정정 검증).
- Playwright: 이벤트픽 화면에서 "🎪 테마별 행사" 텍스트가 `isVisible()`상 보이지
  않음을 확인(hidden 속성 실제 동작).
- Playwright: "체험 / 농장" 대분류 클릭 → 바텀시트(제목/✕/중분류 칩 "체험"·
  "도시농업"·"자연/과학")가 실제로 슬라이드업되어 뜨는 것을 스크린샷으로 확인.
- Playwright 스크린샷: `/nearby` 모바일 헤더에서 "서울시 중구" 위치 배지와 검색
  입력란이 한 줄에 나란히 배치됨을 확인.
- 실제 PostgREST 호출(anon 키, 서울시청 좌표, 반경 5000m — `/nearby`의 실제 고정
  반경)로 새 RPC가 정확히 1,000건을 반환함을 확인(해당 지역에 1,000건을 초과하는
  후보가 실제로 존재해 상한이 유효하게 트리거됨), 반복 호출 시 응답 시간
  220~340ms(최초 콜드 3s)로 PostgREST 8초 타임아웃 대비 충분한 여유 확인 — 지시서가
  요구한 "인덱스가 받쳐주는 상태에서 정상 동작하는지 검증"을 실측으로 완료.
  스크린샷상 지도에도 실제 클러스터 마커와 "주변 1000건 목록 보기" 문구가 정확히
  반영됨을 확인.

  제외했다(구현 판단, 기록에 명시).
