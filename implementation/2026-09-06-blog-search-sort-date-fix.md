# 네이버 블로그 검색 정렬 기준 sim → date 교체

## 구현 대상
사용자 지시: 어제(2026-09-05) "호박터숯불촌" 검색 결과가 실제 네이버 검색과
다르다는 지적에 이어, 오늘 NAVER API HUB 공식 요청 형식 문서(`query`/`display`/
`start`/`sort`/`format` 파라미터 표)를 직접 제시하며 우리 요청이 맞게 구성됐는지
재확인 요청.

## 구현 일시
2026-09-06

## 확인 및 새로 발견한 것
문서 대조 결과 기존 요청(`query`, `display=3`, `sort=sim`)은 파라미터 이름/형식
모두 스펙과 정확히 일치했다 — 빠지거나 잘못 쓴 파라미터는 없었다.

다만 어제 Decision 021 7항에서 "쿼리 문구를 바꿔도 결과가 달라지지 않아 코드로
교정할 방법이 없다"고 결론지었을 때, 시도한 변형은 전부 `query` 문구뿐이었고
`sort` 파라미터 자체(`sim` vs `date`)는 비교해보지 않았었다 — 이 문서를 다시
보고서야 그 허점을 알아챘다. 같은 요청에서 `sort`만 바꿔 직접 비교했다:

```
sort=sim  → 1위 "99999"(스팸), 2위 무관한 잡글, 이하 무관한 티스토리
sort=date → 1위 "[대구 월성동 맛집 호박터숯불촌 신월성점]..."(2026-09-05),
            2~5위도 전부 실제 그 식당을 다룬 최근(2026-08-31~09-05) 글
```

`sort=sim`만 유독 저품질이고 `sort=date`는 정확했다 — 원인은 우리 요청이 아니라
NAVER API HUB의 `sim` 랭킹 자체였다.

## 변경 사항
- `src/app/api/admin/spot-curations/blog-search/route.ts`: `sort: 'sim'` →
  `sort: SORT`(`'date'`)로 교체. 이 기능의 목적 자체가 "최근 1년 이내 후기가
  있는지" 확인(1년 룰)이라, `date`(최신순)가 오히려 기능 취지에도 더 맞는다는
  점도 함께 고려해 사용자에게 확인 후 반영했다(AskUserQuestion — "date로 완전히
  교체" 선택).
- `src/components/admin/blog-curation-modal.tsx`: 상단 주석의 "정확도순(sort=sim)"
  역사적 인용은 그대로 두고, 실제 파라미터가 바뀌었다는 정정 주석을 추가했다
  (원문 지시를 조용히 지우지 않고 무엇이 왜 바뀌었는지 남김).
- `project/decision-log.md` Decision 021에 8항 추가 — 7항의 결론이 불완전했음
  (정렬 파라미터는 시도하지 않았음)을 정직하게 기록하고 정정.
