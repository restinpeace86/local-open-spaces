# 롯데마트 찜한 강좌 상태 변화 알림 (경량 워치 배치)

## 구현 대상
사용자 지시(2026-10-04): "롯데마트는 왜 알람 기능이 없어? 찜한거에 대하여서는
동일하게 알람해야하는거 아니야?" → "나도 상태 변화 알림이 좋을것 같지만
그경우 일 1회 배치로는 크게 의미가 없어 이경우 좀 자주 가져오던가 해야해" →
"그래... 그럼 이거에 대하여 하루에 한번 업데이트 됩니다 하고. 뭐 상태에 대한
실시간감지는 찜한 것만 가능합니다. 이런식의 알림?" — 승인된 방향: 전체
카탈로그는 하루 1회 그대로, 찜한 강좌만 별도로 자주 재확인해 상태가 좋아지면
푸시.

## 설계 근거
전체 60개 지점 재스캔은 요청 650~700개/15~20분이 든다(다중값 배치 조회가
안 되는 사이트 제약, 2026-10-04 앞선 조사). 이걸 더 자주(예: 매시간) 돌리면
하루 16,000개 이상의 요청이 나가 과도하다. 반면 "찜한 강좌"는 소수(수십~
수백 건)라 그것만 상세 페이지(courseview.do)로 개별 재조회하면 자주 돌려도
부담이 작다 — event-reservation-reminder-push-batch.mjs가 이미 쓰고 있는
"찜(user_bookmarks)을 구독 신호로 재사용" 설계를 그대로 가져왔다.

## 변경 사항
- `scripts/ingest/lottemart-culture-club-status-watch.mjs`(신규):
  1. `user_bookmarks`에서 `lottemart_class_id` distinct 목록 조회.
  2. 각 class_id의 저장된 지점/학기/대상 코드로 `courseview.do` 상세 페이지
     재조회 → `parseDetailPageStatus()`로 현재 상태 판별.
  3. 상태가 바뀌었으면 DB를 항상 최신화(찜한 것만 "실시간에 가깝게" 보여준다는
     취지).
  4. "접수 불가(접수마감/전화문의/현장접수) → 접수 가능(바로신청/대기자신청)"
     전환일 때만(`isNewlyActionable()`) 우수맘 이상 찜한 유저에게 웹 푸시
     발송(event-reservation-reminder-push-batch.mjs와 동일한 발송 로직 재사용).
- **상세 페이지 상태 마크업 — 실측 확인**: 목록 페이지는 `class="btn-status"`,
  상세 페이지는 `class="btn-status-red"`(접수마감 시 finish 접미사)로 CSS
  class명이 다르다. onclick 함수명/현장접수 텍스트 판별 로직은 동일해 재사용
  가능함을 실측으로 확인. 실측 과정에서 실제로 하루 안에 상태가 바뀐 사례
  (전화문의 → 접수마감)도 발견해, "자주 재확인해야 한다"는 전제 자체가
  맞다는 걸 재확인했다.
- `.github/workflows/lottemart-culture-club-status-watch.yml`(신규): 15분
  주기(이벤트 예약 알림의 10분보다 약간 느슨 — 필요시 조정).
- `scripts/ingest/lottemart-culture-club-status-watch.test.mjs`(신규):
  `parseDetailPageStatus`(5개 상태 전부) + `isNewlyActionable`(전환 판정
  6케이스) 단위 테스트.
- `src/lib/community/bookmarks.ts`: 롯데마트 찜도 이제 알람 대상이 생겼으므로
  예약-알람 캡(기존 이벤트+이마트 합산 20개)에 다시 포함시켰다(최초엔 알람이
  없어서 캡 대상에서 뺐었는데, 이번에 알람이 생기면서 캡의 원래 취지가 다시
  적용됨).
- `src/lib/community/bookmarks.test.ts`: 캡 OR 필터 3-way 확장 검증 + 롯데마트
  전용 캡 테스트 2개 추가.
- `src/components/home/lottemart-culture-club-view.tsx`: 목록 상단에 "⏱
  마지막 업데이트 ... · 전체 목록은 하루 1회 갱신돼요 — 찜하면 그 강좌만 더
  자주 확인해 알려드려요" 안내 추가(이마트의 freshness 배너와 동일한 "실시간인
  척하지 않는다" 원칙).

## 검증
- `npx tsc --noEmit` / `npm run test`(266개 파일 2,785개, 신규 18개 포함) /
  `npm run build` 전부 통과.
- `parseDetailPageStatus`를 실제 5개 실측 class_id(각 상태별 1개씩)로 직접
  호출해 전부 올바르게 분류됨을 확인(테스트 fixture 작성 전 실측 선행).

## 특이 사항
- 상태 "악화"(예: 바로신청 → 접수마감) 또는 "불가 상태끼리의 전환"(전화문의 →
  접수마감)은 알림을 보내지 않는다 — DB는 갱신하되 조용히 처리. 사용자가
  "알림 소음"에 대해 별도 지시한 바는 없지만, 알림의 목적("찜한 강좌를 이제
  신청할 수 있게 됐다는 걸 안다")에 비춰 보수적으로 설계했다 — 필요하면
  후속 지시로 "악화도 알려달라"는 요구를 반영할 수 있다.
- 대기자신청 → 바로신청(둘 다 이미 "액션 가능"한 상태 간 전환)도 알림을 보내지
  않는다 — 대기자 신청을 이미 한 사용자에게 "바로신청으로 바뀌었어요"가
  유용할 수도 있지만, 이번 범위에서는 "완전히 막혀 있다가 뚫림"만 다룬다.
