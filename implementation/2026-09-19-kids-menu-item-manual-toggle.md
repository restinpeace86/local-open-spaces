# [스팟 큐레이션 — 메뉴 항목별 키즈메뉴 수동 전환]

## 구현 대상
사용자 후속 제보(2026-09-19, 육담 퇴계점/`naver_place_id=2086036973` 예시):
"애기밥이 메뉴로 있어.. 이건 키즈메뉴로써 안 해놨기 때문에 뱃지를 못 받았는데
이건 키즈메뉴 맞으니깐 내가 수동으로 키즈메뉴 뱃지 주려고 클릭해도 방법이
없다."

## 원인
직전 커밋(`8c8a329`)에서 고친 건 다른 버그였다 — 사용자가 실제로 겪은 문제는
**메뉴 항목 하나하나**("애기밥")에 대해 수동으로 키즈메뉴 여부를 줄 방법이
없다는 것이었다. 확인 결과:
- "🌟 [키즈메뉴] 뱃지" 체크박스는 큐레이션 전체에 붙는 뱃지 하나
  (`curation_badges`)만 켜고 끈다.
- 유저 화면(`detail-modal.tsx:1102-1115`)에서 메뉴 목록에 붙는 ⭐[키즈추천]
  표시는 이 체크박스가 아니라 **메뉴 항목 각각의 `is_kids_menu` 값**을 본다.
- `is_kids_menu`는 자동 파싱(키워드 매칭)으로만 채워지고, 관리자가 특정
  항목 하나를 수동으로 켜고 끌 UI가 전혀 없었다(메뉴 목록에는 "삭제" 버튼만
  존재).

## 구현 일시
2026-09-19

## 코드 변경
`src/components/admin/spot-curations-panel.tsx`:
- `kidsMenuItemOverridesRef`(useRef, 항목 이름 → 수동 전환 값) 추가.
- `handleToggleMenuItemKidsMenu(index)`: 메뉴 항목을 클릭하면 그 항목의
  `is_kids_menu`를 토글하고 override를 기록한다. 항목을 OFF→ON으로 켰고
  전체 뱃지 체크박스를 관리자가 아직 직접 조작하지 않았다면(위
  `kidsMenuManuallySetRef`), 전체 뱃지도 함께 OFF→ON으로 제안한다(기존
  자동 감지와 동일한 정책 적용).
- `applyKidsMenuOverrides(items)`: 이름으로 override를 적용하는 헬퍼.
  `handleParseMenu`/`handleCrawlNaverPlace`의 메뉴 파싱 결과에 모두
  적용해, 재파싱/재크롤링으로 항목이 다시 나타나도 관리자의 수동 판단이
  지워지지 않게 했다 — 직전 커밋에서 전체 뱃지에 적용한 것과 동일한 원칙을
  항목 단위로도 일관되게 적용한 것이다.
- 메뉴 목록 UI: 각 항목을 `<button>`으로 감싸 클릭 시 토글되게 하고
  (삭제 버튼과는 별도 클릭 영역으로 분리), 라벨에 "파싱 후 항목을 클릭하면
  [키즈추천] 표시를 직접 켜고 끌 수 있음" 안내를 추가했다(발견성 문제도
  함께 있었다고 판단).

## 특이 사항
직전 커밋(체크박스 재파싱 되돌림 버그 수정)은 사용자가 실제로 겪던 문제와
다른 버그였다 — 사용자 재현 사례(naver_place_id, 실제 메뉴명)를 구체적으로
받은 뒤에야 진짜 원인(항목별 수동 토글 UI 부재)을 특정할 수 있었다. 이
기능(항목 클릭으로 토글)은 Spec에 없던 새 UI라 AskUserQuestion으로 방식을
먼저 확인받았다(항목 클릭 방식으로 확정).
