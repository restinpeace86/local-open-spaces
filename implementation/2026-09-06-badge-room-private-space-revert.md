# 큐레이션 뱃지 "룸/개별 공간" 재통합 (분리 되돌림)

## 구현 대상
사용자 지시: "아니.. 룸하고 개별공간이 뭔 차이야? 그냥 2는 다시 합쳐줘" —
바로 이전 작업(2026-09-06-only-unmapped-filter-and-badge-corrections.md)에서
"룸 있음"/"개별 공간 있음"으로 분리했던 것을 되돌려달라는 요청. "예약 가능"
추가(3번 항목)는 언급되지 않아 그대로 유지.

## 구현 일시
2026-09-06

## 변경 사항
`src/lib/admin/curation-badges.ts`: `room`("룸 있음")과 `private_space`
("개별 공간 있음") 두 뱃지를 원래의 단일 뱃지 `private_room`("룸/개별 공간
있음")으로 되돌렸다. `reservation_possible`("예약 가능")은 그대로 유지 —
결과적으로 12개(원본) → 14개(1차 정정) → **13개**(재정정, 원본 대비 "예약
가능" 1개만 순증가).

## 검증
- `npx tsc --noEmit` 통과.
- `npm run test`: 115개 파일 / 1220개 테스트 전체 통과 — `curation-badges.
  test.tsx`를 13개 기준(라벨 목록/그룹별 개수 `{이동/편의:4, 식사/아기:5,
  공간/놀이:2, 운영:2}`/`room`·`private_space` 키가 이제 없음)으로 갱신.
- `npm run build` 통과.

## 특이 사항
- 바로 전 커밋에서 분리했다가 이번에 다시 합친 것 — 이런 왕복 자체가 문제는
  아니다: 사용자가 실제로 써보거나 다시 생각해보고 판단을 바꾸는 것은 정상적인
  피드백 과정이고, 각 시점의 판단 근거를 구현 기록에 정직하게 남겨 무엇이 왜
  바뀌었는지 추적 가능하게 하는 것이 중요하다(이번 파일 및
  curation-badges.ts의 "[재정정]" 주석 참고).
