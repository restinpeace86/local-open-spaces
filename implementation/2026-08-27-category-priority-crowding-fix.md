# [카드 순서 우선순위 쏠림 버그 수정]

## 문제 제보
직전 작업(카드 순서 우선순위)을 배포한 뒤 대표가 실제로 확인해보니 "현재 이용 가능"/
"예약 가능" 두 섹션이 전부 "공공키즈카페"로만 채워져 다른 카테고리가 하나도 안 보인다고
제보. "20개 이상이면 20개만 보이고 끝인 거냐"는 질문.

## 근본 원인 (실측 확인)
`is_active=true` 기준 "공공키즈카페" category_min이 265건 존재한다 — 두 섹션의
`limit`(20)보다 훨씬 많다. 직전 구현은 "우선순위대로 전체 정렬 후 limit만큼 자르기"였는데,
앞 우선순위 그룹의 공급이 `limit`보다 많으면 그 카테고리 하나가 전체 노출 자리를 통째로
독점하는 구조적 결함이 있었다 — "앞으로 가면 좋겠다"는 지시를 "그것만 보이게 해달라"로
잘못 구현한 셈이다.

## 수정 (`src/lib/home/get-home-feed.ts`)
`sortByCategoryMinPriority(items, limit)`에 `limit` 파라미터를 추가하고, 앞 우선순위
그룹이 차지할 수 있는 자리를 전체의 절반(`FRONT_TIER_MAX_SHARE = 0.5`)으로 제한했다:
1. 항목을 앞/중간/뒤 세 그룹으로 나눈다(각 그룹 내부는 기존 지역/거리 정렬 순서 유지).
2. 앞 그룹에서 `ceil(limit * 0.5)`개까지만 맨 앞에 배치한다.
3. 못 들어간 앞 그룹 나머지는 완전히 버리지 않고 중간 그룹 뒤·뒤 그룹 앞에 이어붙인다
   (limit 안에 못 들면 자연스럽게 잘리되, 여전히 뒤 우선순위보다는 앞선 취급을 받는다).

이제 앞 우선순위(공공키즈카페류)는 최대 절반까지만 자리를 차지하고, 나머지 절반은
반드시 다른 카테고리로 채워진다.

## 검증
- `npx tsc --noEmit`: clean.
- `npm run test`: 47 파일 513건 통과(신규 1건: 공급이 20건인 공공키즈카페 + 5건인 일반
  카테고리가 섞였을 때 limit=10 결과가 공공키즈카페 최대 5건 + 일반 5건 전체 포함으로
  나오는지 검증 — 쏠림 버그를 그대로 재현했다가 수정 후 통과하는 회귀 테스트).
- `npm run build`: 성공.
- `npm run dev` 로컬 서버 실측: `/api/home/feed` 응답에서 "현재 이용 가능"이 공공키즈카페
  10건(정확히 limit의 절반) + 문화행사/역사/산림여가/공예·취미/공원탐방/도시농업 등 다양한
  카테고리 10건으로 정상 혼합됨을 확인. "예약 가능"도 동일하게 확인.
