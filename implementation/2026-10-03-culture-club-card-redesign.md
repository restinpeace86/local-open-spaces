# 문화센터 카드/레이아웃 재설계 — 실제 이마트 컬처클럽 화면 참고

## 구현 대상
사용자가 `reference/emart culture club.png`(이마트 컬처클럽 PC 화면 캡처)를
근거로 상세 피드백을 줬다(2026-10-03):
- 필터 영역이 고정(sticky)되지 않고 스크롤하면 같이 올라간다.
- 카드: 이미지 좌상단에 상태 뱃지, 텍스트 영역은 소분류(상단, 작게) →
  제목(2줄까지, 넘으면 말줄임) → 가격(+재료비, 작은 글씨) · 우측에 장바구니
  자리(우리는 찜 하트) → 연한 구분선 → 지점/일정. 우리는 지점이 이미
  고정 선택이라 카드에서 빼고, 대신 접수기간을 넣는다.
- 정원은 카테고리 영역(상단 작은 텍스트) 우측에.
- PC 4열 그리드지만 모바일은 2열로.
- 이미지: 리스트는 썸네일 해상도, 상세보기는 상세 해상도로 분리 저장/노출.

## 변경 사항 — `src/components/home/culture-club-tab-view.tsx`
### 1. 필터+리스트 단일 스크롤
기존엔 필터 영역이 `shrink-0`으로 고정되고 리스트만 자체 스크롤했는데,
전체를 하나의 `overflow-y-auto` 컨테이너로 합쳤다(무한스크롤 트리거도 이
컨테이너의 스크롤 기준으로 이동) — 참고 화면처럼 스크롤하면 필터도 같이
올라간다.

### 2. 카드 재설계(`ClassCard`)
- 이미지 영역(`ClassImagePlaceholder`, 정사각형): 좌상단에 상태 뱃지
  (접수중/정원마감→"대기접수 가능"/접수대기, 기존 색상 그대로 재사용).
  **실제 이미지는 아직 없다** — 아래 "특이 사항" 참고.
- 텍스트 영역: `소분류 ................. 정원 N명`(flex justify-between)
  → 제목(`line-clamp-2`) → `가격원 (재료비 N원 포함, 작게)` 좌측·찜
  아이콘(비활성, 아래 참고) 우측 → `<hr>` 연한 구분선 → `접수기간
  YYYY.MM.DD HH:MM ~ YYYY.MM.DD`(register_start_date의 실제 시각 포함,
  오늘 앞서 추가한 register_start_at과 동일 소스) → `일정 요일
  HH:MM~HH:MM`. 지점명은 완전히 제거.
- 요일/카테고리 칩이 하나라도 선택됐을 때만 "↻ 초기화" 버튼이 브랜드 줄
  우측에 나타난다(참고 화면의 "초기화" 버튼 대응).

### 3. 그리드 반응형
`flex flex-col`(1열 리스트) → `grid grid-cols-2 md:grid-cols-4 gap-3` —
참고 화면은 PC 4열이지만 이 앱은 모바일 우선이라 기본 2열, md 이상에서
4열. 광고 자리(`CultureClubAdSlot`)는 `col-span-full`로 감싸 그리드
전체 폭을 차지하도록(실제 콘텐츠는 아직 null).

## 특이 사항 — 이미지, 아직 미해결
사용자가 "리스트는 썸네일 해상도로 저장하고 열었을 때는 상세 해상도로"
요청했지만, 실측 재확인 결과 `emart_culture_club_classes.main_image_bucket`
(`prod-cognitos3-master-imagestoragemaster...`)은 명명 규칙상 AWS Amplify
Storage(Cognito Identity Pool 인증) 전용 버킷으로 보이고, 직접 GET 요청은
여전히 403이다(오늘 다시 실측). 이 방식은 보통 브라우저가 Cognito
자격증명으로 런타임에 서명한 URL을 받아 쓰므로, 버킷/키만으로는 접근
불가능하다 — 이번 세션에서 이미 한 번 차단된 접근(서드파티 JS 번들에서
인증 정보 추출)을 다시 시도하지 않았다(제3장 제5조 추측 금지). 그래서
이번 변경은 플레이스홀더 이미지(회색 박스 + 상태 뱃지)만 넣었고, 실제
이미지 + 썸네일/상세 해상도 분리 저장은 이번 범위에 포함하지 않았다.
사용자가 실제 사이트 브라우저 DevTools에서 동작하는 이미지 URL을 찾아
제공하면(이전 GraphQL API 키를 확보했던 것과 동일한 방식) 그 때 설계를
진행한다.

찜(하트) 아이콘도 레이아웃만 참고 화면과 맞췄고 비활성 상태다 — 이마트
클래스는 아직 `user_bookmarks`의 대상(spot/event) 구조에 들어있지 않아,
실제로 찜 가능하게 하려면 새 target 종류를 추가할지 별도 테이블을 만들지
먼저 정해야 한다(사용자가 "넣으면 되지 않을까"로 제안만 했을 뿐 확정
지시는 아니었음).
