# [7대 대분류 실제 적용 및 /admin/data-grid 활성 데이터 전용 필터 적용]

## 구현 대상
- `is_active = true`인 유효 events(약 3,560건)를 대상으로 7대 대분류(`category_maj`)/36종
  중분류(`category_min`) 체계를 실제 DB에 반영
- `/admin/data-grid` 기본 조회를 `is_active = true`로 고정(이미 직전 작업에서 구현돼 있음을 확인)

## 2. 실제 적용 로직 (`scripts/ingest/lib/category-maj-taxonomy.mjs`, 신규)

`is_active=true`인 이벤트만 대상으로, 기존 `category_min_source`에 따라 다르게 처리한다:
- **MANUAL**: 관리자가 확정한 값이라 절대 건드리지 않는다(보존). 이번 실행 시점 events에는
  MANUAL 행이 0건이라 실질적 영향은 없었지만, 향후를 위한 안전장치로 구현했다.
- **RAW**: SEOUL_YEYAK 원본 MINCLASSNM이 ground truth이므로 제목 키워드로 재추측하지 않고
  "구 카테고리명 → 신 카테고리명" 매핑 테이블로 직접 치환한다(예: 서울형키즈카페→공공키즈카페).
  새 36종에 없는 값(기타/청년정보/단체봉사/전문·자격증/정보통신)은 NULL로 정리한다.
- **RULE 또는 NULL**: 새 36종 키워드 규칙으로 제목을 다시 스캔한다.

## 4. 실측 중 발견해 그 자리에서 수정한 버그 2건 (중요)

### 4.1. "OO문화재단"(기관명) → "역사" 오매칭
1차 실행 직후 결과를 실제로 검수하다가(제6장 검수 원칙 — 화면/데이터를 실제로 확인) "역사"로
분류된 85건 중 58건이 "[마포문화재단]", "[서울문화재단]" 등 **기관명**이었음을 발견했다.
"문화재"라는 키워드가 "문화재단"의 부분 문자열이라 생긴 오탐이다. `역사` 규칙에
`exclude: ['문화재단']`을 추가해 수정하고, 재실행으로 실제 DB의 58건을 바로잡았다(재검증:
"문화재단"을 포함하며 역사로 남은 행 0건 확인).

### 4.2. RAW 행 재매핑의 멱등성 버그
위 4.1 수정을 반영해 **재실행**했을 때, 예상보다 훨씬 큰 폭(추가 189건 감소)으로 매칭
건수가 줄어드는 것을 발견했다. 원인 조사 결과: RAW 행의 "구→신 이름 매핑"이
`row.category_min`(1차 실행이 이미 신규 이름으로 덮어쓴 가변 컬럼)을 조회 키로 썼다 —
2차 실행 시점에는 이 컬럼이 이미 "공공키즈카페"(신규 이름)로 바뀌어 있어 매핑 테이블에
"서울형키즈카페"(구 이름) 키를 찾지 못해 265건이 통째로 NULL로 잘못 지워지는 멱등성
버그였다(실측: `seoul_public_reservation` 소스 중 132건이 원본 MINCLASSNM="서울형키즈카페"
였는데 NULL로 소실됨을 직접 쿼리로 확인).

**수정**: RAW 행의 매핑 키를 `row.category_min`이 아니라 **절대 변하지 않는 원본**
(`raw_data.MINCLASSNM`)으로 바꿨다 — 몇 번을 다시 실행해도 항상 같은 결과가 나오도록
멱등성을 확보했다. 이후 동일 데이터로 두 번 연속 재실행해 완전히 같은 결과(1,992/3,560,
공공키즈카페 265건, seoul_public_reservation 잔여 NULL 73건)가 나옴을 실측으로 재확인했다.
재발 방지를 위해 `category-maj-taxonomy.test.mjs`에 멱등성 회귀 테스트를 추가했다.

이 두 버그 모두 **실제 DB에 반영되기 전에는 시뮬레이션(JS 메모리)에서 드러나지 않았고**,
실제 실행 후 결과를 검수하는 과정에서만 발견됐다 — "구현 완료 전 실제 화면/데이터 확인"
원칙(제5장 제8조)이 실질적으로 데이터 정확성을 지켜낸 사례로 기록해 둔다.

## 5. `/admin/data-grid` 활성 데이터 전용 필터

직전 작업([0순위 우선 요청] 만료 데이터 자동 비활성화)에서 이미 구현·검증 완료된 상태였음을
재확인했다 — `parseIsActiveFilter`(파라미터 없으면 기본 `true`), "✅ 활성 상태(is_active)"
tri-state 토글(기본값 `'true'`, `'all'`/`'false'`로 전환 가능). 추가 코드 변경 없음.
