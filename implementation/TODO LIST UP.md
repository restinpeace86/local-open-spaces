
# [개발 요청] 키즈친화 스팟 서비스 스마트 폴백(Fallback) 아키텍처 구현

우리 서비스(스팟픽)의 프론트엔드 및 백엔드 로직에 '우리 DB 우선 조회 후, 없으면 네이버로 안전하게 토스하는 스마트 폴백 체인'을 구현해 줘.

## 1. 상세 정보 및 화면 노출 폴백 (View Fallback)
- **지도 마커 클릭 / 상세 모달 진입 시:**
  - 1순위: 우리 DB(curated_items 등)에 해당 스팟의 상세 정보(영업시간, 자체 등록된 대표 이미지, 커스텀 큐레이션 텍스트)가 존재하는지 확인.
    - **데이터가 있는 경우:** 우리 자체 디자인의 풍성한 상세 모달/페이지를 렌더링.
    - **데이터가 없는 경우(공공데이터 기본 뼈대만 있는 경우):** 기본 공공데이터 정보(이름, 주소)를 보여주되, 하단/상단에 **[네이버 지도에서 상세정보 및 사진 보기]** 버튼을 배치하여 네이버 지도 검색 결과(`https://map.naver.com/v5/search/{식당이름+주소}`)로 안전하게 새 창 연동(target="_blank").

## 2. 예약(Reservation) 폴백 체인 (Reservation Fallback)
- **유저가 [예약하기] 버튼을 눌렀을 때:**
  - 1순위: 우리 자체 예약/결제 테이블에 해당 스팟용 시스템이 연동되어 있는가?
    - **Yes:** 우리 자체 예약 플로우 진행.
  - 2순위: 연동된 자체 예약은 없지만, 네이버 예약 링크(`naver_booking_url`)가 등록되어 있는가?
    - **Yes:** 네이버 예약 페이지로 즉시 리다이렉트.
  - 3순위 (Fallback): 둘 다 없다면?
    - **Default:** "전화 문의 또는 준비 중인 서비스입니다" 안내 팝업 및 직통 전화번호 연결(tel:) 처리.

이 폴백 로직이 유저 플로우에서 자연스럽게 맞물리도록 프론트엔드 컴포넌트와 데이터 조회 로직을 짜줘.

# [개발 요청] 관리자 전용 '스팟 큐레이션 탭' 및 클립보드 이미지 업로드 구현

관리자 페이지에 기존 1, 2번 관리 메뉴와 분리된 **[스팟 큐레이션] 전용 탭/페이지**를 새로 만들어 줘. 관리자가 최소한의 품으로 데이터를 손쉽게 밀어 넣을 수 있도록 아래 기능을 포함해 줘.

## 1. 관리자 큐레이션 탭 주요 기능
- **스팟 검색 및 선택:** 1,500개의 공공데이터 뼈대 리스트 중에서 특정 스팟을 검색하고 선택해 수정 모드로 진입하는 UI.
- **노출/비노출 토글 (Toggle):** 이상하거나 쓸모없는 데이터는 앱에서 즉시 숨길 수 있는 `is_active` 스위치 버튼.

## 2. 핵심 기능: 클립보드 이미지 'Ctrl + V' 바로 업로드
- 사진을 일일이 다운받아서 업로드하는 노가다를 없애기 위해, 이미지 입력 영역에서 **웹서핑 중 복사한 이미지(Copy Image)를 키보드 `Ctrl + V`로 곧바로 붙여넣을 수 있는 기능** 구현.
- **동작 방식:**
  - 이미지 입력 박스에 포커스가 있거나 마우스가 위치한 상태에서 `paste` 이벤트가 감지되면, 클립보드에 있는 이미지 파일 데이터를 가로챔.
  - 프론트엔드에서 즉시 Supabase Storage(또는 서버 스토리지)로 비동기 업로드 요청을 날림.
  - 업로드가 완료되면 반환된 퍼블릭 URL을 자동으로 이미지 미리보기(Preview)에 띄우고 DB 필드에 세팅해 줌.

## 3. 스마트 텍스트 파서 (영업시간 & 메뉴 일괄 입력)
- **영업시간 일괄 입력란 (Textarea):** 네이버 등에서 긁어온 지저분한 영업시간 텍스트 덩어리를 통째로 붙여넣고 [자동 파싱]을 누르면, 정규식을 통해 영업시간, 브레이크타임, 라스트오더를 각각의 입력 칸에 쪼개서 채워주는 편의 기능.
- **메뉴 일괄 입력란 (Textarea):** "짜장면 7,000원\n짬뽕 9,000원" 형태의 텍스트를 통째로 붙여넣으면 구조화된 메뉴 데이터로 변환해 주는 기능.

# [개발 요청] 관리자 페이지 탭 전환 및 데이터 로딩 최적화 (Lazy Loading 적용)

관리자 페이지의 초기 로딩 속도 저하와 불필요한 대량 데이터 조회를 막기 위해 데이터 fetch 구조를 아래와 같이 전면 수정해 줘.

## 1. 탭 전환 시 자동 데이터 로딩 금지 (Lazy Loading)
- 현재 존재하는 탭들(`open_spaces`, `events`, `raw_ingest_data`, `큐레이션`, `제휴상품`)은 **초기 페이지 진입 시 또는 탭을 누르는 순간 자동으로 데이터를 백그라운드에서 조회(fetch)하지 않도록** 변경해 줘.
- 탭을 클릭했을 때는 빈 뼈대 UI(테이블 레이아웃 및 검색 필터 영역)만 우선 렌더링되도록 처리.

## 2. 'raw_ingest_data' 탭 수동 조회(On-Demand) 방식 적용
- 특히 데이터량이 가장 많은 `raw_ingest_data` 탭의 경우, 화면 진입 시 데이터를 아예 불러오지 않음.
- 상단에 **[조회하기] (Search)** 버튼을 명시적으로 배치하고, **관리자가 이 버튼을 직접 클릭했을 때만** 조건에 맞는 로데이터를 서버에서 가져와 테이블에 뿌려주도록 구현해 줘.

초기 마운트 시 불필요한 대형 쿼리 실행을 막고 관리자 화면이 즉각적으로 뜰 수 있도록 성능을 최적화해 줘.

# [개발 요청] 외부 공공 API 배치 수집 안정성 및 독립 실행(Isolation) 구조 고도화

현재 구축된 공공데이터 수집 배치 스크립트의 안정성을 높이기 위해, 개별 API 에러 격리, 재시도, 데이터 유실 방지 및 스케줄 최적화 로직을 아래와 같이 구현/보완해 줘.

## 1. 개별 API 에러 격리 및 독립 실행 (Isolation)
- `gg_public`이나 `tour_api` 같은 대분류/그룹 루프 안에서 순회할 때, **각각의 개별 API 엔드포인트(예: 문화행사, 축제 등)는 완전히 독립된 개별 `try-catch`로 감싸줘.**
- 특정 API 하나가 타임아웃이나 에러로 터지더라도, 뒤에 있는 다른 API들은 절대 영향을 받지 않고 각각 개별적으로 끝까지 실행될 수 있도록 방어해 줘.

## 2. 넉넉한 타임아웃 및 지수 백오프(Exponential Backoff) 재시도
- 외부 API 호출 fetch/axios 요청 시 타임아웃을 **최소 30초(`30000ms`) 이상**으로 넉넉하게 설정.
- 호출 실패(타임아웃, 5xx 에러 등) 시 즉시 포기하지 않고 총 3회까지 재시도하되, 재시도 간격을 점진적으로 늘려줘 (예: 1차 실패 후 5초 대기, 2차 실패 후 10초 대기).

## 3. 수집 실패 시 기존 데이터 보존 (Stale Data 방어)
- 특정 API 소스 수집이 최종 실패하더라도, 기존 DB에 적재되어 있던 이전 데이터가 유실되거나 비워지지 않고 그대로 유지되도록 업서트(Upsert) 또는 트랜잭션 로직을 안전하게 처리해 줘.

## 4. 관리자 수동 재수집 트리거 기능
- 관리자 페이지 또는 배치 모니터링 영역에서, 실패한 특정 API 소스만 지정해 **[개별 수동 재수집]**을 실행할 수 있는 API 엔드포인트와 버튼 UI를 추가해 줘.

## 5. 크론(Cron) 스케줄 시간 변경 (스탬피드 방지)
- 정각 트래픽 몰림(Stampede 현상)을 피하기 위해, 배치가 실행되는 크론 시간을 정각이 아닌 애매한 분 단위(예: 매일 새벽 3시 43분)로 설정해 줘.

[개발 요청] 스팟픽(SpotPick) AI 맞춤 추천 챗봇 엔진 구현
기존에 구현 완료된 항목들을 제외하고, 유저 경험 극대화와 LLM 비용 최적화에 초점을 맞춘 [플로팅 바텀 시트 형태의 AI 맞춤 추천 챗봇] 기능 구현을 위한 통합 개발 프롬프트입니다.

1. UI/UX 인터페이스 및 진입 방식
플로팅 바텀 시트 (Bottom Sheet FAB): 스팟픽 또는 이벤트픽 화면 우측 하단의 플로팅 버튼(FAB) 클릭 시, 화면 하단에서 스르륵 올라오는 오버레이 대화창으로 구현하여 유저가 기존에 보던 화면의 맥락을 유지하도록 함.

2. LLM 토큰 최적화 원칙 (중요)
불필요한 LLM 토큰 소모를 방지하기 위해, 1~8단계 인터뷰 질문은 정형화된 UI 선택지(버튼형 컴포넌트) 및 프론트엔드 상태 관리로 처리하고, 최종 데이터 필터링 및 요약 답변 생성 시에만 LLM을 최소한으로 호출할 것.

3. 8단계 맞춤 추천 인터뷰 시나리오
When (일자): 오늘 / 내일 / 이번 주 토요일 / 이번 주 일요일 중 선택 (아니오 선택 시 일자 선택 캘린더 제공).

Time (시간대): 점심 전 / 점심 먹고 / 오후 / 저녁 등 선택.

Meal (식사 계획 - Contextual): 시간대와 연동하여 밖에서 식사할 계획인지 질문 ("점심 전에 나가시네요, 밖에서 식사도 함께 하실 예정인가요?").

Transport & Distance (이동 거리): 도보 가능한 가까운 곳 / 차로 10분 이내 / 30분 이내 / 1시간 이상 등 선택.

Weather & Air (날씨 및 미세먼지): AI가 해당 일자/시간의 기상 정보(강수확률, 미세먼지/초미세먼지)를 분석해 먼저 넌지시 보여준 뒤, 야외/실내/둘 다 선택 유도.

Budget (예산): 완전 무료 / 1만 원 이하 / 2~3만 원 이하 / 상관없음 선택.

Kids (아이 정보): 함께 가는 아이 수 및 연령대 입력/선택.

Purpose / Vibe (나들이 성향): 대분류를 부모 친화적 말투로 변환한 선택지 제공 (예: 🏃‍♂️ 신나게 뛰어놀기, 🎨 교육 및 체험, 🌳 힐링 자연 등).

4. 검색 결과 도출 및 예외 처리 (Strict Rule & Performance Optimization)
결과 개수 제한: 조건에 가장 적합한 순서대로 최대 10개만 리스트업.

기준 거리 표시 (성능 최적화 적용):

상위 10개 장소 리스트에는 사용자 위치 기준 해당 장소까지의 거리를 즉시 계산하여 표시 (대상 데이터가 10개로 한정되어 있어 성능 영향 없음).

단, 주변 키즈친화 맛집의 거리 및 상세 정보는 초기 일괄 로딩하지 않고, 유저가 특정 장소를 클릭해 상세 정보를 열 때 불러오는 지연 로딩(Lazy Loading) 방식을 적용하여 서버 부하 방지 (맛집 탐색 시 거리를 조금씩 넓혀가며 탐색).

엄격한 1회성 임계값 완화 (Soft Fallback Limit):

엄격한 조건으로 검색된 결과가 0개일 경우, 딱 1번만 가격이나 거리를 한 단계 살짝 넓혀서 차선책을 재조사.

여기서도 결과가 없으면: 무한정 늘리지 말고 즉시 중단한 뒤, *"차선책까지 가격/거리를 조정하여 찾아보았으나 조건에 맞는 적합한 곳을 찾지 못했습니다"*라고 안내하고 종료.

필수 믹스 룰: 최종 10개 결과 안에 ① 든든한 공공시설/공공장소 1개 이상과 ② 수익화를 위한 제휴 티켓/상품 1개 이상을 자연스럽게 섞어서 노출.
