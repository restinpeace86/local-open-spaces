# [키즈카페 이벤트 ↔ 스팟(open_spaces) 연결]

## 구현 대상
사용자 지시(2026-09-20): "이 스팟에 대하여 현재 공공키즈카페나 서울형키즈카페들은
스팟연결해줄래? 만약 스팟이 딱 맞는게 없으면 유사한 위치 하는게 아니라 그냥
비워둬 수동으로 하게.. 그리고 그럼 이벤트가 들어올때마다 새로운 이벤트에
대하여 스팟연결안해도 되는거야?.. 스팟에 대하여 연결했을때 노출중분류가
아직없는것도 관리자한테 좀 알수있게해줄래?"

## 배경 — 왜 스팟 연결이 필요한가
직전 대화에서 사용자가 지적한 구조적 문제: 공공키즈카페/서울형키즈카페는
events 테이블에만 존재하고 open_spaces(스팟)로는 전혀 존재하지 않는다(실측
확인, 0건). 그래서 "찜"이 물리적 장소가 아니라 매주 갱신되는 예약 레코드
하나에 걸려 있었다 — 스팟 상세페이지, 시설 정보 관리, 향후 확장이 모두
막혀 있는 구조였다.

## 이벤트가 새로 들어올 때마다 다시 연결해야 하는지 — 아니오(실측 확인)
`scripts/ingest/adapters/seoul-yeyak-adapter.mjs`는 `upsertRowsSafeMerge`
(onConflict: external_id)를 쓴다 — 실측으로 확인한 사례: "도봉구 방학1동2호점"
이벤트가 `created_at: 2026-08-25`인데 `updated_at`은 오늘(2026-09-20)까지
계속 갱신되고 있었다(같은 행, 예약기간만 최신화). `space_id`는
`ALWAYS_REFRESH_FIELDS.events`에 없어 한 번 채우면 재수집이 덮어쓰지
않는다 — **한 번만 연결하면 그 시설의 SVCID가 바뀌지 않는 한 다시 연결할
필요가 없다.** (SVCID 자체가 바뀌는 경우는 새 행이 생겨 별도 연결이
필요하지만, 실측상 흔치 않은 경우로 보인다.)

## 매칭 방법 — 좌표만으로는 부족했다
1차로 좌표 50m 이내 단일 후보(37건, 그중 3개 구는 조회 타임아웃으로
누락)를 뽑았으나, 표본을 직접 확인한 결과 거리만으로는 전혀 다른 시설(예:
"노량진2동점(동작키즈카페)" → "벧엘유치원 어린이놀이터", "역촌동점" →
"대한예수교장로회 제일영광교회")이 다수 섞여 있었다 — 정부 시설이 교회/
유치원/도서관 건물 안에 세들어 있는 경우가 많아 좌표만으로는 "우연히
같은 건물"과 "진짜 같은 시설"을 구분할 수 없었다.

사용자 확인에 따라, 143+27건(3개 구 재시도 포함) 전체를 후보 목록과 함께
하나씩 직접 검토해 "이벤트 제목과 스팟 이름이 실질적으로 같은 시설을
가리키는가"만으로 확정했다(추측 금지) — 거리는 참고만 하고 최종 판단
기준으로 쓰지 않았다.

## 코드 변경
`scripts/migrations/2026-09-20-link-kids-cafe-events-to-spots.mjs`(신규,
1회성): 위 검토로 확정한 14쌍(이벤트 제목, 스팟 이름)을 제목/이름으로
정확히 재조회해(오타/ID 착오 방지) `events.space_id`를 연결한다. 조회
결과가 1건이 아니면(중복 이름 등 모호함) 안전하게 스킵하고 경고를 남긴다.

## 실행 결과(2026-09-20, 실제 DB)
14쌍 중 13건 연결 성공(실패 0). 1건("동작구 흑석동점")은 동일 이름의
스팟이 2개 있어 스크립트 자체의 안전장치로 스킵됨(수동 확인 필요).

연결된 13개 스팟 중 **8개는 노출 중분류(`service_category_id`)가 없다** —
스크립트 실행 결과에 명시적으로 나열했다:
- 서울가족플라자(2개 이벤트가 연결됨), 동작키즈카페 신대방2동점, 서울형
  키즈카페 관악구 신사동점, 보라매공원, 중랑실내놀이터 늘푸른공원점,
  신트리공원(서울), 오목공원.

기존 관리자 화면(`SpotServiceCategoryCheck`, raw-data-modal.tsx의
`SpaceLinkEditor` 바로 아래)이 이미 "노출 중분류 없음" 경고 + 그 자리에서
바로 지정하는 UI를 갖고 있다 — 이 스크립트는 그 화면을 거치지 않고 DB에
바로 썼으므로, 관리자가 위 8개 이벤트를 열어서 그 기존 UI로 채우면 된다
(새 UI를 따로 만들지 않음, 제5장 제4조 기존 구조 우선).

## 검증

- `npx tsc --noEmit`/`npm run test`(170개 파일, 2048개 테스트, 변동 없음)/
  `npm run build` 모두 통과(DB 데이터만 바뀌는 스크립트라 앱 코드 변경
  없음).

## 특이 사항 — 남은 작업
- **마포구/도봉구**: open_spaces 조회가 반복적으로 statement timeout이 나
  이 두 자치구의 키즈카페 이벤트는 이번에 확인하지 못했다(원인 미상 — 다른
  24개 자치구는 정상 조회됨). 별도로 재확인이 필요하다.
- **나머지 다수**: 좌표 50m 이내 후보가 있었지만 이름이 일치하지 않아
  의도적으로 비워둔 이벤트가 많다(교회/유치원/도서관 등과 우연히 같은
  건물인 경우) — 관리자가 수동으로 검토해 필요하면 연결해야 한다.
