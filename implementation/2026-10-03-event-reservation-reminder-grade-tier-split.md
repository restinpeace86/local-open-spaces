# 예약 오픈 알림 등급 정책 재개정 — 찜과 분리해 우수맘 이상으로

## 구현 대상
사용자 지시(2026-10-03): "현재 우리 이벤트픽의 찜들에 대하여서는 예약 알림기능
주고 있잖아 이것들은 우수맘? 등급 업해야 사용할 수 있는 기능이고.. 그래서
찜기능에대하여 2개로 분기해서 우수회원들은 예약 알림기능까지.. 그 아래는..
그냥 찜해서 찜한것 마이페이지 같은데서 볼수 있는기능.."

## 사전 확인 — 사용자 인식과 실제 코드 상태 차이
실제 코드를 확인한 결과, 지시 시점의 실제 상태는 사용자가 전제한 것과 달랐다:
[[2026-09-20-event-reservation-reminder-bookmark-redesign]]에서 "알림도
열심맙 이상만"으로 정책이 확정돼 있었다 — 즉 예약 알림은 **찜 자체와 동일한
등급(열심맘/active)**에 걸려 있었고, 우수맘(excellent) 전용은 아니었다. 이번
지시는 "이미 우수맘 전용"이 아니라 **"우수맘 전용으로 새로 분리해달라"**는
등급 정책 재개정으로 처리했다.

## 변경 사항
- **찜(북마크) 자체는 변경 없음**: `BookmarkButton`/`favorites-view.tsx`는 그대로
  `canBookmark`(열심맘/active 이상) 기준 유지 — "그 아래는 그냥 찜해서 찜한것
  마이페이지(=기존 `/favorites`) 같은데서 볼수 있는기능"에 해당하는 부분은
  이미 존재해서 손댈 게 없었다.
- **예약 오픈 알림만 우수맘(excellent) 이상으로 상향**:
  - `src/components/common/event-reservation-reminder-hint.tsx`: 안내 문구
    표시 기준을 `canBookmark` → `canReceivePushNotifications`(이미
    `grades.ts`에 존재하던 우수맘 이상 기준 함수, 재사용 — 신규 함수 생성 없음)
    로 교체.
  - `scripts/ingest/event-reservation-reminder-push-batch.mjs`: 발송 대상
    등급 필터 `ELIGIBLE_GRADES`를 `['active','excellent','power']` →
    `['excellent','power']`로 축소. UI만 바꾸고 발송 배치를 그대로 두면
    열심맘 유저도 실제로는 알림을 받는 불일치가 생기므로 두 곳을 함께 수정.
  - 결과적으로 기존 `mom-pick-push-send-batch.mjs`(우수맘 이상)와 동일한
    등급 문턱으로 통일됐다(우연이 아니라 `canReceivePushNotifications`를
    그대로 재사용했기 때문).

## 검증
- `npx tsc --noEmit` / `npm run test`(256개 파일 2,699개, 두 파일 모두 기존에
  단위 테스트가 없어 회귀 영향 없음) / `npm run build` 전부 통과.

## 특이 사항
- 찜 자체의 등급 문턱(열심맘)과 알림의 등급 문턱(우수맘)이 이제 서로 다르므로,
  열심맘 이상이지만 우수맘 미달인 유저는 이벤트를 찜할 수는 있지만 예약 오픈
  알림 안내 문구는 보이지 않는다(의도된 동작 — "그 아래는 그냥 찜해서 보는
  기능"). 승급 유도 문구("우수맘 되면 알림 받아요" 등 업셀 카피)는 이번
  지시에 포함되지 않아 추가하지 않았다(제3장 제5조 추측 금지) — 필요하면 별도
  지시로 진행.
