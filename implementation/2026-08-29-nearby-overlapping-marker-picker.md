# [스팟픽(/nearby) 겹친 마커(동일 좌표 다건) 클릭 시 목록 표시]

## 배경
사용자 제보: "판교원마을 5단지 (504동 앞)" 위치에서 지도를 줌아웃하면 "3건"이라고
나오는데, 확대해서 자세히 보면 1건밖에 없는 것처럼 보임 — 버그인지 문의.

## 조사 결과
프로덕션 DB(`open_spaces`)를 직접 조회해 확인: "판교원마을 5단지"는 실제로 서로 다른
3개의 놀이터(502동/504동/505동 앞, `external_id`가 각각 다름 —
`LOCALDATA_PLAYGROUND_16258/16259/16260`)로, 데이터 자체는 중복이 아니다. 다만 원본
지방행정 데이터(LOCALDATA_PLAYGROUND)가 개별 놀이터 실측 좌표 대신 아파트 단지
대표 주소 좌표를 그대로 사용해 3건 모두 위경도가 완전히 동일하다(37.3876093,
127.0885267). 그 결과 지도 마커 3개가 정확히 같은 픽셀에 겹쳐 렌더링되어, 목록/카운트는
정확히 "3건"으로 집계되지만 지도에서는 맨 위 마커 1개만 보이고 클릭되는 UX 문제였다.
같은 방식으로 확인한 "판교원마을12단지"(3건 동일 좌표), "판교원마을11단지"(2건)도 같은
패턴이며, 반대로 놀이터별 실측 좌표가 다른 단지(7단지, 8단지 등)는 문제가 없었다 —
데이터 손상이나 파이프라인 중복 적재 버그가 아니라 원본 소스의 좌표 정밀도 한계로 결론.

대표 확인 결과, 처리 방식은 **"마커 클릭 시 겹친 항목 목록을 먼저 보여주고 그중 하나를
선택하면 기존 상세 모달로 이어지는" 방식**으로 확정(좌표를 인위적으로 벌리는 방식이나
현행 유지는 채택하지 않음).

## 구현
1. `src/components/map/kakao-map-view.tsx`: 마커 생성 시 `lat.toFixed(6),lng.toFixed(6)`
   키로 동일 좌표 항목을 그룹핑(`groupsByPosition`). 마커 클릭 시 그룹 크기가 2 이상이면
   신규 `onSelectGroup` 콜백으로 그룹 전체 배열을 전달하고, 1건이면 기존 `onSelectItem`
   그대로 호출(기존 단일 마커 클릭 동작은 변경 없음).
2. `src/components/map/marker-group-modal.tsx`(신규): "이 위치에 N건이 있어요" 헤더 +
   기존 `ItemListPanel` 재사용 목록을 보여주는 모달. 항목 선택 시 상위로 그 항목을 전달.
3. `src/components/map/map-explorer.tsx`: `selectedGroup` state 추가, `KakaoMapView`에
   `onSelectGroup` 연결. 그룹 모달에서 항목을 선택하면 그룹 모달을 닫고 기존
   `DetailModal`을 그 항목으로 연다(`handleSelectFromGroup`).

## 검증

  참조하지 않아 영향 없음 확인
- `npm run build` 통과
- 기존 단일 마커(겹치지 않는 대다수) 클릭 흐름은 변경 없이 그대로 `DetailModal` 직행

## 특이 사항
- 원본 데이터(LOCALDATA_PLAYGROUND)의 좌표 정밀도 한계 자체는 이번 범위에서 수정하지
  않았다(원천 데이터 이슈이며, 재수집/보정은 별도 검토 필요 — 이번엔 UX 레벨에서
  겹침을 해소하는 방식으로 대응).
