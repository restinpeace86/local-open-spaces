# 얼굴 스티커 편집 기능 (맘스픽 글쓰기 사진 업로드)

## 구현 대상
맘스픽 글쓰기(SurveyReviewComposer) 3단계 사진 업로드 시, 클라이언트에서 얼굴을
자동 인식해 스티커를 씌우되 사용자가 클릭으로 직접 확정(추가/제거)할 수 있는
편집 단계를 추가.

## 구현 일시
2026-09-14

## 배경
사용자 지시: "최종적으로 얼굴 인식해서 얼굴에 스티커 합성해줘.. 이에 대하여
사용자가 최종 판단하고.. 클릭으로 이거 얼굴이고 이거 얼굴아니다도 수동으로 할
수 있도록 하는게 나을꺼같은데.." — 자동 얼굴 인식은 참고용 초안일 뿐이고,
최종 확정(아이 얼굴 노출 방지)은 반드시 사용자가 직접 눈으로 보고 결정하도록
설계했다.

## 변경 사항
- `package.json`: `@tensorflow/tfjs`, `@tensorflow-models/blazeface` 추가
  (동적 import로 실제 편집 모달을 열 때만 로드 — 번들 크기에 영향 없음).
- 신규 `src/components/community/face-sticker-editor.tsx`: 사진 1장을 받아
  - 이미지를 표시용 캔버스(최대 420px 폭)에 그리고, 같은 캔버스에서
    blazeface로 얼굴을 인식해 바운딩박스를 얻는다(표시 좌표계와 인식 좌표계가
    동일해 별도 스케일 변환 없이 그대로 사용).
  - 인식된 얼굴에는 기본 스티커(이모지, 6종 중 선택 가능)를 자동으로 씌운다.
  - 캔버스에서 스티커가 있는 자리를 클릭하면 제거("이거 얼굴 아니다"),
    빈 자리를 클릭하면 새로 추가("이거 얼굴이다") — 순수 클릭 토글 방식.
  - "완료"를 누르면 원본 해상도 캔버스에 이미지+스티커를 다시 그려
    `Blob`으로 내보낸다(표시용 캔버스와 원본 해상도 간 스케일만 곱해서 계산).
  - 모델 로딩 실패/얼굴 인식 실패 시에도 수동 클릭으로 스티커를 붙일 수 있는
    안내 문구로 안전하게 대체(fallback).
  - "편집 없이 올리기"(원본 그대로 업로드), "이 사진 취소"(해당 사진 건너뜀)
    옵션도 함께 제공.
- `src/components/community/survey-review-composer.tsx`: `handlePhotoSelect`가
  더 이상 즉시 업로드하지 않고 선택한 파일들을 편집 큐(`editQueue`)에 넣는다.
  큐의 첫 파일을 `FaceStickerEditor` 모달로 보여주고, 확정/건너뛰기 결과만
  `/api/mom-pick/upload-image`로 업로드한 뒤 다음 파일로 진행한다(여러 장
  선택 시 한 장씩 순차 진행). 서버 업로드 API는 변경 없음(File/Blob 모두
  동일하게 처리 가능).
- 테스트: `survey-review-composer.test.tsx`에 `FaceStickerEditor`를
  스텁으로 대체한 뒤 큐 진행 로직(완료/건너뛰기/취소, 다중 파일 순차 진행)을
  검증하는 5개 테스트 추가.

## 검증
- `npx tsc --noEmit` 통과
- `npm run test` 전체 1679개 통과(신규 5개 포함)
- `npm run build` 프로덕션 빌드 성공
- Playwright로 임시 테스트 페이지를 띄워 실제 브라우저에서 확인:
  얼굴 모양 도형을 그린 샘플 이미지 → blazeface가 자동 인식해 🐻 스티커 부착
  → 빈 자리 클릭 시 스티커 수동 추가 → 같은 자리 재클릭 시 제거 → "완료" 클릭
  시 `onConfirm`이 합성된 PNG Blob(15,657바이트)을 정상적으로 전달함을 확인.
  (임시 테스트 페이지/스크립트는 검증 후 삭제, 커밋에 포함되지 않음)

## 후속 수정 (2026-09-14, 사용자 실사용 리포트)
"사진 올리니깐 사진이 엄청 길어지더라? 취소버튼도 안보여... 그래서 뒤로가기
누르니깐 그 사진팝업만 없어지는게 아니고 완전히 빠져나오던데" — 실제 세로
사진(휴대폰 9:16 비율)으로 테스트한 결과 재현되는 버그를 확인하고 수정:
- 원인: 표시용 캔버스 크기 계산이 **가로 폭만** 제한(`MAX_DISPLAY_WIDTH`)하고
  세로 높이는 제한하지 않아, 세로로 긴 사진일수록 모달이 뷰포트보다 훨씬
  길어졌다. 그 결과 "완료"/"이 사진 취소" 버튼이 화면 아래로 밀려나 보이지
  않았고, 사용자가 다른 탈출 수단이 없어 브라우저/앱의 뒤로가기를 눌러
  글쓰기 화면 전체를 빠져나가게 된 것이 실제 원인이었다(팝업만 닫는 로직은
  애초에 없었다 — 버튼이 안 보였을 뿐).
- 수정: ①가로·세로를 함께 제한하도록 표시 크기 계산 수정(`MAX_DISPLAY_HEIGHT`
  추가), ②모달 카드에 `max-h-[85vh]` + 내부 스크롤을 두어 아무리 긴 사진도
  카드가 화면을 벗어나지 않게 함, ③버튼 줄을 스크롤 영역 밖 하단에 항상
  고정(`shrink-0`)해 콘텐츠 길이와 무관하게 항상 보이게 함, ④어두운 배경을
  눌러도 취소되도록(표준 모달 이탈 경로) 추가해, 버튼을 못 찾더라도 안전하게
  빠져나갈 수 있게 했다.
- 검증: 1080×1920(실제 휴대폰 세로 사진 비율) 테스트 이미지 + 390×700(휴대폰
  화면 크기) 뷰포트로 Playwright 재현 — "완료"/"이 사진 취소" 버튼이 뷰포트
  안에 정상적으로 보이고 클릭 가능함을 확인, 배경 클릭 시 정상적으로
  취소(onCancel)됨을 확인.

## 특이 사항
- `npm install` 과정에서 기존에 존재하던 것으로 보이는 무관한 취약점 3건
  (js-yaml, next 16.x RCE, sharp)이 `npm audit`에 표시됨 — 이번 작업이
  새로 유발한 것이 아니라 기존 의존성 트리에 있던 것이며, 특히 Next.js
  메이저 업그레이드는 범위 밖의 리스크가 큰 변경이라 이번 작업에서는
  손대지 않음(별도로 검토가 필요하면 사용자에게 안내 필요).
- 얼굴 인식 모델(blazeface, 약 400KB~1MB) 다운로드는 사용자가 실제로
  편집 모달을 열 때만 발생 — 모바일 환경 첫 로딩 시 수 초 지연이 있을 수
  있음(로딩 중 안내 문구로 표시).
