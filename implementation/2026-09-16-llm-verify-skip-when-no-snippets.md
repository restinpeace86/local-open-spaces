# [LLM 매장 검증: 수집 0건이면 LLM 호출 생략]

## 구현 대상
사용자 지시(2026-09-16, 직전 타임아웃 수정 보고에 대한 지적): "0건이면 LLM 으로
안던지고 그냥 0건이다라고 나와야하는거 아니야 ?" — 직전 검증 중 "라라코스트
부천" 재현 호출에서 수집된 블로그 스니펫이 0건인데도 여전히 Gemini를 호출해
"불일치" 판정을 받아온 것을 사용자가 지적함.

## 구현 일시
2026-09-16

## 원인/판단
수집된 블로그 스니펫이 0건이면 LLM이 분석할 근거 자체가 없어 결과는 항상
결정적으로 "불일치(is_valid_match: false)"가 된다 — 실제로 프롬프트에도 "(수집된
블로그 스니펫 없음)"이라고 명시해 보내고 있었을 뿐, 매번 동일한 결론을 얻기 위해
불필요하게 네트워크 호출(지연 1~수 초, 드물게 타임아웃 위험, API 비용)을 감수하고
있었다. AI는 판단을 보조하는 도구이지(제2장 제5조), 판단할 데이터가 없는
상황에서까지 호출할 이유가 없다.

## 변경 사항
### `src/lib/admin/llm-blog-verification.ts`
`buildNoSnippetsResult(storeName)` 신규 순수 함수 추가 — LLM 호출 없이 결정적인
"불일치/데이터 없음" `LlmVerificationResult`를 즉시 만든다.

### `src/app/api/admin/spot-curations/llm-verify/route.ts`
- 1년 이내 필터링 후 `recentSnippets.length === 0`이면 `buildNoSnippetsResult`
  결과를 즉시 반환하고 Gemini 호출 자체를 생략하도록 수정.
- `GEMINI_API_KEY` 필수 체크를 스니펫 수집 이후, "실제로 LLM을 호출해야 할 때"로
  이동 — 스니펫이 0건이라 애초에 LLM을 안 쓸 상황이면 이 환경변수가 없어도
  정상적으로 "데이터 없음" 결과를 반환할 수 있게 했다(불필요한 실패 경로 제거).

## 검증
- `npx tsc --noEmit`, `npm run test`(전체 1780개, 신규 1개 포함), `npm run build`
  모두 통과.
- 실제 개발 서버에 직전과 동일한 입력("라라코스트 부천")으로 재현 호출 — 수정
  전에는 Gemini 호출까지 거쳐 약 6초가 걸렸으나, 수정 후에는 0.1초 내로 즉시
  동일한 취지의 "데이터 없음" 결과를 반환하는 것을 확인.
