# 롯데마트 문화센터 탭 속도 저하 원인 분석 및 수정

## 구현 대상
사용자 지시(2026-10-04): "내가 문화센터를 이벤트픽화면에서 들어갔었는데...
왜이렇게.. 느려졌지? 느려진것도 원인 분석해봐."

## 원인 분석 (실측)
두 가지 원인을 찾아 둘 다 고쳤다.

### 원인 1: 지점 목록 API가 전체 테이블을 훑고 있었음
`/api/culture-club/lottemart-stores`가 60개 지점명을 뽑으려고
`lottemart_culture_club_classes` 전체 15,101행을 1,000건씩 16번
페이지네이션으로 훑고 있었다(PostgREST 1,000행 기본 제한 때문에 어쩔 수
없이 넣었던 루프 — 2026-10-04 앞선 커밋). 실측 응답 시간 **2.3초**(이마트
지점 API 0.6초 대비 4배). 이 데이터는 사실상 정적이라(지점 신설은 드문
수동 이벤트, 수집 스크립트 자체도 하드코딩된 목록을 씀) 매 요청마다 테이블을
훑을 이유가 없었다.

### 원인 2: 강좌 목록 API에 store_code 인덱스가 없었음
`/api/culture-club/lottemart-classes`가 지점 선택마다 `.eq('store_code',
...)`로 조회하는데, `store_code` 컬럼에 인덱스가 전혀 없어 15,101행 전체를
순차 스캔하고 있었다. 실측 응답 시간 0.67초.

### 체감 지연이 더 컸던 이유
화면 쪽 구조상 지점 목록을 먼저 불러온 뒤에야(그 응답으로 기본 지점을
정하고) 강좌 목록을 불러오는 **순차 구조**라 두 지연이 그대로 더해졌다
(2.3초 + 0.67초 ≈ 3초).

## 변경 사항
- `src/lib/home/culture-club-options.ts`: `LOTTEMART_STORES`(60개 지점
  코드/이름, 정적 상수) 추가.
- `src/app/api/culture-club/lottemart-stores/route.ts`: DB 쿼리를 전부
  제거하고 `LOTTEMART_STORES`를 정렬해 그대로 반환하도록 교체.
- `scripts/migrations/2026-10-04-lottemart-culture-club-store-index.sql`
  (신규, 적용 완료): `(store_code, is_excluded)` 복합 인덱스 추가.

## 검증
- `npx tsc --noEmit` / `npm run test`(269개 파일 2,801개) / `npm run build`
  전부 통과.
- **실제 응답 시간 재측정**(개발 서버, curl):
  - 지점 목록: 2.3초 → **0.07초**(약 32배)
  - 강좌 목록: 0.67초 → **0.18~0.24초**(약 3배, 인덱스 적용 후 안정화된
    수치 — 첫 측정은 Next.js dev 서버 컴파일 캐시 미스로 0.93초가 나왔으나
    재측정 3회 모두 0.18~0.24초로 수렴)
  - **Playwright로 실제 화면 흐름 측정**(문화센터 탭 클릭 → 롯데마트 전환 →
    지점/강좌 목록 로드 완료까지): **587ms**(이전엔 두 API가 순차로
    3초 가까이 걸렸을 것으로 추정).

## 특이 사항
- 이마트 테이블(`emart_culture_club_classes`)도 `store_code` 인덱스가 없는
  건 동일하다 — 다만 테이블이 더 작아서(6,500행, 롯데마트의 약 43%) 체감
  지연이 덜했을 뿐 같은 구조적 약점을 안고 있다. 이번엔 사용자가 롯데마트
  속도만 지적해서 그쪽만 고쳤다 — 이마트도 같이 고칠지는 후속 지시로.
