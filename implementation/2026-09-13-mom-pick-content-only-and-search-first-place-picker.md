## 배경 — 직전 조치의 오해 정정
바로 전 커밋(Step 136)에서 "그냥 새싹맘 유저처럼 맘스픽 화면 동일하게
보여야돼"라는 지시를, guest/not_sprout_yet도 allowed와 똑같이
`SurveyReviewComposer`(장소선택 등 실제 작성 폼)를 메인 화면에 그대로
인라인 노출하는 것으로 구현했다. 이번 지시로 확인된 실제 의도는 "작성 폼
자체가 맘스픽 컨텐츠가 아니니 메인 화면엔 아예 나오면 안 된다"는 것 —
즉 로그인/등급 상태와 무관하게 다뤄야 할 대상은 "문구가 상태를 드러내면
안 된다"는 것이었지 "작성 폼을 항상 보여줘야 한다"는 뜻이 아니었다.

## 변경 사항

### 1. `src/components/community/mom-pick-view.tsx`
메인 화면 상단의 `<SurveyReviewComposer>` 인라인 렌더링(+ 투명 인터셉트)을
완전히 제거하고, 상태와 무관하게 항상 동일한 작은 버튼 하나로 대체했다:
```tsx
<button onClick={() => {
  if (state === 'guest') setIsGuestWritePromptOpen(true);
  else if (state === 'not_sprout_yet') setIsGuideModalOpen(true);
  else setIsFullScreenComposerOpen(true); // allowed: 안내 모달 없이 바로 전체 화면 글쓰기
}}>
  ✍️ 글쓰기
</button>
```
- 버튼 문구는 상태와 무관하게 항상 "✍️ 글쓰기"다(로그인 여부/등급을 드러내지
  않는다는 원칙 유지).
- 메인 화면(`<div className="flex-1 flex flex-col gap-4 overflow-y-auto p-5">`)에는
  이제 헤더 + 이 버튼 + 피드(파워맘·우수맘 추천/인기·우수글/실시간 라이브)만
  남는다 — "맘스픽 컨텐츠만" 요구를 충족한다.
- 실제 작성 폼은 Step 136에서 만든 전체 화면 전환(early return,
  `isFullScreenComposerOpen`/`isGuestWritePromptOpen`)에서만 나타난다 —
  그 부분 구조는 그대로 재사용했다(제5장 제4조).
- `allowed` 상태는 안내 모달 없이 버튼 클릭 즉시 전체 화면 글쓰기를 연다
  (이미 자격을 갖췄으므로 별도 확인 절차가 필요 없음).

### 2. `src/components/community/survey-review-composer.tsx`
장소선택(1단계) 기본값을 검색 모드로 바꿨다. 실측 확인(`get_nearby_spaces_
and_events`, 반경 30km, SPACE/EVENT 각각 별도 RPC 호출):
```
SPACE r=30km: 3840ms(콜드) → 1206ms(웜)
EVENT r=30km: 3095ms(콜드) → 812ms(웜)
```
1~4초가 걸려 "내 주변 인기 스팟"을 기다리는 동안 아무것도 할 수 없었다 —
사용자가 직접 제안한 대안("이름으로 검색이 처음에 나오도록")을 그대로
적용했다:
- `isSearchMode` 기본값을 `false → true`로 변경(폼 초기화 시에도 동일하게
  복원).
- Step 1 UI를 재구성해 `isSearchMode`가 켜져 있으면 이름 검색(`SpotPicker`)만
  보이고, "내 주변 인기 스팟" 목록은 토글("📍 내 주변에서 찾기")을 눌러야만
  나타나게 했다(이전엔 목록이 무조건 먼저 보이고 검색은 추가로 열리는
  구조였다).
- "내 주변 인기 스팟" 백그라운드 조회(`useEffect`)는 그대로 유지한다 — 검색
  모드가 기본이어도 조용히 먼저 받아와 둬서, 토글을 누르면 이미 준비돼 있다.
  DB 쿼리 자체(`get_nearby_spaces_and_events`)의 근본적인 최적화는 이번
  범위에 포함하지 않았다(사용자가 명시적으로 "힘들면"이라는 조건부로 더 쉬운
  대안을 제시했고, 이 RPC는 스팟픽 지도 등 다른 여러 기능이 공유하는 핵심
  RPC라 변경 위험도가 더 크다 — 제3장 제5조 추측 금지, 다음에 이 RPC 자체가
  다시 문제되면 별도로 실측·조치).

## 특이 사항
- `get_nearby_spaces_and_events`(30km 반경, SPACE/EVENT 병렬 호출) 자체의
  지연은 근본 해결하지 않았다 — 이 RPC는 스팟픽 지도 등 여러 화면이 공유하는
  핵심 경로라, 이번처럼 UI 우선순위만 바꿔 체감 지연을 없애는 것으로
  충분하다고 판단했다. 필요하면 이 RPC를 EXPLAIN으로 직접 실측해 인덱스/쿼리
  구조를 별도로 점검할 수 있다.
