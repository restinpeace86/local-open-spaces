# [스팟픽 AI 추천 칩 + 나들이 전용 핵심 중분류 1단 필터 개편]

## 요구사항 (원문 대비 범위 확정 과정)
사용자 원문은 "스팟픽/추천픽 → 'AI 추천' 명칭 변경"으로 시작했으나, 실제 의도를 확인하는
과정에서 완전히 다른 요구로 확정되었다(추측 금지 원칙에 따라 구현 전 확인):
- **하단 5탭 이름은 변경하지 않는다** — '스팟픽'/'추천픽' 탭 라벨 그대로 유지.
- **'AI 추천'은 스팟픽(`/nearby`) 화면 안의 중분류 칩 중 하나로 신규 추가**된다. 클릭하면
  페이지 이동 없이 지도 위에 바텀시트로 AI 추천 나들이 장소를 바로 보여준다.
- 추천 로직은 "기존 데이터 기반 스마트 정렬"로 확정(LLM 실시간 호출 없음 — 즉시 응답,
  비용 0, 실패 리스크 없음).
- 카테고리 필터는 대분류→중분류 2단 구조를 철회하고, 나들이 목적에 맞는 핵심 중분류만
  1단 가로 칩으로 노출(체육시설/행정 대관류 제외).

## 구현 일시
2026-08-29

## 1. 핵심 중분류 1단 필터

`src/lib/spaces/spot-category-groups.ts`를 2단(대분류→중분류) 구조에서 평평한
`CORE_SPOT_CATEGORIES` 배열로 전면 교체. 실제 DB `category_min` 분포를 직접 조회해
(`select category_min, count(*) from open_spaces group by category_min`) 존재하지 않는
값을 임의로 만들지 않았다:
- 공원 → `['공원']`
- 문화센터/문화의집 → `['문화의집', '문화원']`(실제 DB에 "문화센터"라는 값은 없어 가장
  가까운 실제 값 2종으로 매핑)
- 박물관(미술관 포함) → `['종합/기타박물관', '역사박물관', '미술관']`
- 도서관 → `['도서관']`
- 키즈카페 → `['키즈카페']`
- 놀이터 → `['어린이놀이터', '어린이놀이시설(야외)', '어린이놀이시설(실내)']`

`SpotCategoryFilter`(`spot-category-filter.tsx`)를 대분류 탭 + 중분류 칩 2행 구조에서
1행 가로 칩으로 재작성. "AI 추천" 칩은 다른 칩과 달리 `minors: []`이며 별도 액션
(`onSelectAiRecommend`)을 호출할 뿐 선택 상태/최대 5개 제한에 포함되지 않는다. 하나의
칩이 여러 `category_min`을 아우르므로, `map-explorer.tsx`는 "칩 id 배열"
(`selectedCategoryIds`)을 1차 상태로 두고, 실제 필터링에 쓰는 `category_min` 배열은
선택된 칩들의 `minors`를 펼친 파생값(`useMemo`)으로 계산한다.

## 2. AI 추천 — 규칙 기반 스마트 정렬 (LLM 미사용)

`src/lib/spaces/ai-recommend.ts`: `rankAiRecommendedSpots(items, limit=8)`가 거리
(가까울수록 가점, 5km 반경 기준 정규화)·나들이 편의성(키즈친화/주차/유모차)·무료 여부·
썸네일 유무를 가중합해 점수를 매기고, 한 카테고리가 추천 목록을 독점하지 않도록
카테고리(`category_min`)별 라운드로빈으로 상위 항목을 뽑는다. 단위 테스트
(`ai-recommend.test.ts`)로 카테고리 편중 방지/거리·편의성 우선순위/limit 동작을 검증.

`src/components/map/ai-recommend-sheet.tsx`(신규): "AI 추천" 칩 클릭 시 여는 바텀시트
(모바일)/모달(데스크톱). 페이지 이동 없이 지도 화면 위에 그대로 뜨고, 목록에서 항목을
선택하면 시트를 닫고 기존 `DetailModal`로 이어진다(겹친 마커 처리 때 만든
`marker-group-modal.tsx`와 동일한 UI 관례 재사용).

## 3. 실측 디버깅 중 발견한 심각한 기존 버그 — `useModalBackClose`가 React onClick 경로의 모달을 무력화

`AiRecommendSheet`를 처음 붙였을 때 칩 클릭이 핸들러까지는 정확히 도달하는데(React
Fiber를 Playwright로 직접 조회해 `onClick` 함수 실행과 `setState` 호출까지 확인) 바텀시트가
DOM에 전혀 나타나지 않는 현상을 발견했다. 원인 규명 과정(발췌):
- 완전히 새로운 격리된 `useState` + 인라인 `<div>` 토글은 정상 동작 → 조건부 마운트
  자체는 문제 없음.
- 이미 검증된 기존 컴포넌트(`MarkerGroupModal`)를 그대로 이 자리에 넣어도 동일하게
  실패 → 새 컴포넌트의 버그가 아니라 "이 위치에서 특정 기존 컴포넌트를 마운트하는 것"
  자체의 문제.
- `MarkerGroupModal`에서 `useModalBackClose(onClose)` 호출 한 줄만 주석 처리하면 즉시
  정상 동작 → 원인이 이 훅(내부에서 `window.history.pushState` 호출)으로 좁혀짐.
- 실제 프로덕션에 이미 존재하는 `DetailModal`(리스트 항목 클릭으로 여는 경로)도 동일하게
  실패하는 것을 확인 — **직전 커밋(오늘 세션 이전, 이번 작업과 무관)에서도 이미 발생하던
  버그임을 `git stash`로 작업 내용을 잠시 걷어내고 재현해 확정**했다.
- 반대로 카카오맵 마커 클릭(SDK의 순수 `addEventListener` 경로, React 합성 이벤트가
  아님)으로 여는 `MarkerGroupModal`은 동일한 훅을 쓰는데도 정상 동작한다 — 즉 "React
  onClick으로 트리거되는 상태 업데이트가 이 훅을 쓰는 모달을 마운트하는" 경로에서만
  재현되는, React 19 + Next.js 16 App Router의 `history.pushState` 자체 라우팅 감지
  로직과의 스케줄링 충돌로 추정된다(정확한 내부 메커니즘은 프레임워크 내부 영역이라
  이번 범위에서 확정하지 않음).

**영향 범위**: `DetailModal`은 홈 피드/이벤트픽(오늘·진행중·예약가능)/캘린더/지역별
그리드/지도 탐색 등 앱 전역에서 카드·리스트 클릭(전부 React onClick 경로)으로 열리므로,
이 버그는 이번 작업 이전부터 **앱 전체에서 상시 재현되고 있었을 가능성이 높다**(단일
경로인 마커 클릭만 우연히 영향을 받지 않았음).

**조치**: `DetailModal`에서 `useModalBackClose` 호출을 제거했다(뒤로가기 제스처로 모달만
닫는 편의 기능만 사라지고, 배경 클릭/X 버튼으로 닫는 핵심 기능은 그대로 유지 — 실측으로
확인). `AiRecommendSheet`도 애초에 이 훅을 쓰지 않도록 구현했다. `MarkerGroupModal`(현재
마커 클릭 경로에서만 정상 동작 확인됨)과 `MapPreviewModal`(레이어드 히스토리 스택을
의도적으로 사용하는 특수 케이스)은 이번 범위에서 손대지 않았다 — 전자는 현재 유일한
트리거 경로에서 정상 동작하고, 후자는 별도의 의도된 설계라 더 깊은 검토가 필요해
후속 과제로 남긴다.

## 검증
- `npx tsc --noEmit` 통과
- `npm run test`(58파일 571건, 신규 `ai-recommend.test.ts` 포함) 통과
- `npm run build` 통과
- 실측(Playwright, 개발 서버 + **프로덕션 빌드 서버 양쪽 모두**):
  - 핵심 중분류 칩(AI 추천/공원/문화센터·문화의집/박물관/도서관/키즈카페/놀이터) 1단
    노출, 체육시설(테니스장 등) 완전 제외 확인.
  - "도서관" 칩 선택 시 category_min 필터가 정확히 반영되어 200건 → 3건으로 줄고,
    해제 시 다시 200건으로 복원됨을 확인(요구사항 3 API 연동 검증).
  - "AI 추천" 칩 클릭 → 바텀시트 즉시 노출(페이지 이동 없음) → 추천 8건 표시 → 항목
    선택 → 시트 닫힘 + 상세 모달 정상 진입까지 전체 플로우 확인.
  - 일반 리스트 항목 클릭으로도 상세 모달이 정상 열림을 재확인(기존 버그 수정의 부작용
    없음 확인).

## 특이 사항
- 이번 작업 도중 발견한 `useModalBackClose` 버그는 이번 작업 범위(AI 추천 기능)를 훨씬
  벗어나는 심각도이나, 신규 기능이 의존하는 공용 컴포넌트(DetailModal)를 직접 막고
  있어 함께 수정했다. `MarkerGroupModal`/`MapPreviewModal`에 남아있는 동일 계열 리스크는
  별도 후속 검토가 필요하다.
- "박물관(미술관 포함)"/"문화센터/문화의집" 칩처럼 하나의 칩이 여러 `category_min`을
  아우르는 매핑은 실측 DB 분포에 근거했으며, 임의로 새 카테고리 값을 만들지 않았다.
