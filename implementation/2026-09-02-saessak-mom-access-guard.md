# [개발요청] 새싹맘 등급 조건부 권한 제어 및 안내 팝업

## 구현 일시
2026-09-02

## 배경
"맘스픽" 진입 시 비로그인/새싹맘 미달성/새싹맘 이상 3가지 분기를 모달로 안내하는
사용자 상세 요구사항.

## 기존 구현과의 용어 대응 (중요 — 스키마를 다시 바꾸지 않음)
요구사항 원문은 `profiles.tier` 컬럼과 `'seed_mom'` 값을 전제하지만, 이 앱은 오늘
(2026-09-02) **Decision 019**로 이미 다음을 구현·배포해 두었다:
- `profiles.grade` 컬럼(값: `signed_up`/`sprout`/`active`/`excellent`/`power`).
- 첫 글 작성 즉시 `signed_up → sprout`로 자동 승급하는 DB 트리거
  (`promote_to_sprout_on_first_post`, 이미 라이브 적용됨).

요구사항의 "tier='seed_mom'"과 기존 "grade='sprout'(새싹맘)"는 정확히 같은 개념이다.
**임의로 컬럼/값을 다시 만들거나 이름을 바꾸지 않고, 이미 승인·구현된 것을 그대로
사용했다**(제3장 제2조 Spec 우선 — 오늘 이미 확정한 스키마를 같은 날 다른 이름으로
재도입하지 않음). 따라서 "새싹맘 자동 승급 처리" 항목은 **이미 완료돼 있어 이번에
새로 구현하지 않았다** — 실측으로 트리거가 라이브 DB에 존재함을 재확인했다.

## 구현 내용

### `useMomPickAccess` 훅
`useUser()` + `getMyProfile()`을 조합해 `'loading' | 'guest' | 'not_sprout_yet' |
'allowed'` 4가지 상태를 판별한다. 프로필 조회가 실패해도 접근을 잘못 허용하지 않고
`not_sprout_yet`으로 안전하게 처리한다(제5장 제11조 오류 처리 원칙).

### `LoginPromptModal` (Case 1: 비로그인)
기존 카카오/구글 로그인 버튼을 모달 형태로 재구성. "닫기" 시 홈으로 이동.

### `SaessakMomGuideModal` (Case 2: 로그인 + 새싹맘 미달성)
요구사항 문구 그대로("아직 새싹맘 등급이 아니에요!..."), [첫 글 쓰러 가기]/[닫기] 버튼.
**"/write 페이지로 이동" 대신** 같은 화면(`/mom-pick`)에 이미 상시 노출돼 있는
`PostComposer`로 스크롤 이동하는 방식을 택했다 — 이 앱 구조상 별도 글쓰기 페이지가
없고 작성 폼이 이미 같은 화면에 있어(Decision 019), 페이지를 새로 만드는 대신
기존 구조를 그대로 활용했다(제5장 제4조).

### `/mom-pick` 진입 흐름 재구성
"맘스픽 클릭 시" 분기 체크를 이 페이지의 유일한 진입점(`/my`의 링크)에서가 아니라
`/mom-pick` 페이지 마운트 시점에 수행하도록 통일했다 — 이 앱에는 "맘스픽" 전용
메뉴가 하단 탭 등 클릭 이전 단계에 없고 `/mom-pick`이 유일한 진입 경로라, 페이지
진입 직후 제한 콘텐츠가 전혀 노출되지 않고 즉시 모달로 안내되는 것으로 요구사항의
"클릭 시 분기 처리"와 동일한 사용자 경험을 만든다(단일 진입점에 로직을 하나로
모아 이중 관리를 피함).

## 검증
### 코드 검증
`npx tsc --noEmit`/`npm run test`(96파일 957건 — 신규 훅 테스트 4건 포함)/
`npm run build` 통과.

### 실측 검증
- 라이브 DB에 `promote_to_sprout_on_first_post` 트리거가 실제로 존재함을
  `information_schema`/`pg_trigger` 조회로 재확인(새로 만들 필요 없음 확인).
- dev 서버 curl로 `/mom-pick` 200 정상 응답 확인.

## 특이 사항
- Case 1/2 모달의 실제 등장 타이밍(클릭 즉시 vs 페이지 마운트 후)에 대한 체감 차이는
  네트워크 지연이 매우 큰 환경에서만 미세하게 느껴질 수 있다 — 정상적인 상황에서는
  거의 즉시 나타나 요구사항의 의도(제한 콘텐츠 비노출)를 그대로 만족한다.
