# 스팟 상세 "연결된 이벤트" 섹션에 타겟 연령 필터 추가 (Step 127)

## 구현 일시
2026-09-12

## 배경 (사용자 지시 원문)
> "특정 이벤트에 대하여 지금 이제 스팟픽에서도 연결된거 있잖아.. 이 연결된
> 항목중에 저 4개 연령아닌데 나오는게 있나 점검해봐 저 연령 4개 외에 연결되어있어도
> 스팟픽에서 해당 장소 눌ㄾㅓㅓㅆ을때 이벤트 나오면 안되긴해"

("저 4개 연령"은 직전 대화에서 확인한 `EVENT_PICK_TARGET_AUDIENCES`
= `['INFANT', 'KIDS_PRE', 'KIDS_SCHOOL', 'FAMILY']`.)

## 조사 결과
`/api/spots/linked-events`(스팟픽 상세 화면 "🎪 진행 중인 이벤트" 섹션이 호출하는
API, Step 114 개선사항10)는 `space_id`/`is_active=true`/`end_date >= 오늘`만
필터링하고 **`target_audience` 필터가 전혀 없었다** — 반면 이벤트픽의 다른 모든
피드 조회(오늘/알찬 픽/예약 픽/카테고리별 등, `get-home-feed.ts`)는 전부
`EVENT_PICK_TARGET_AUDIENCES`로 걸러진다.

실측 확인(프로덕션): 현재 스팟에 연결되고 활성/미종료인 이벤트 714건 중
- 199건(28%)만 4개 타겟 연령 안에 있음
- 333건(47%)은 target_audience가 NULL
- 182건(25%)은 4개 밖의 값(예: TEEN/YOUTH/ADULT/SENIOR 등 11종 체계의 다른 값)

즉 **714건 중 515건(72%)이 이벤트픽 피드에는 전혀 노출되지 않는데도, 스팟픽에서
연결된 장소를 열면 "진행 중인 이벤트"로 그대로 보이고 있었다** — 사용자가 지적한
바로 그 불일치.

## 변경 사항
- `src/app/api/spots/linked-events/route.ts`: 쿼리에
  `.in('target_audience', EVENT_PICK_TARGET_AUDIENCES)`를 추가해 다른 이벤트픽
  조회들과 동일한 필터를 적용한다(`get-home-feed.ts`에서 이미 export된 상수를
  재사용 — 제5장 제4조).

## 검증
- `npx tsc --noEmit`: 통과.
- `npm run test -- --run`: 135 files / 1584 tests 전체 통과(회귀 없음 —
  `detail-modal.test.tsx`의 "🎪 진행 중인 이벤트" 관련 테스트는 fetch 응답을
  직접 mock하므로 이 서버 사이드 필터 변경과 무관하게 그대로 통과).
- `npm run build`: 성공.
- 이 route.ts 파일은 이 코드베이스의 다른 API 라우트들과 동일하게 별도 유닛
  테스트가 없는 기존 관례를 따른다(라우트 레벨 테스트 파일이 프로젝트 전체에
  하나도 없음을 실측 확인) — 실제 필터 효과는 프로덕션 데이터로 직접 검증했다.

## 특이 사항
- 이 필터가 적용되면 스팟 상세의 "진행 중인 이벤트" 개수가 눈에 띄게 줄어들 수
  있다(714건 중 199건만 남음) — 이는 버그 수정의 정상적인 결과이며, 이벤트픽
  피드와 노출 기준을 일관되게 맞춘 것이다. 4개 밖 타겟 연령이나 미분류(NULL)인
  이벤트는 여전히 관리자 화면(이벤트 블로그 큐레이션 모달의 타겟 연령 선택,
  Step 117)에서 4개 중 하나로 분류하면 다시 노출된다.
