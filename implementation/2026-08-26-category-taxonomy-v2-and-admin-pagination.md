## 1. 신규 Taxonomy Dry-run 시뮬레이션 (실제 DB 반영 없음)

지시대로 DB 스키마 변경(`category_maj` 컬럼 추가 등)과 데이터 UPDATE를 전혀 수행하지 않고,
`events.title`/`source`만 읽어(SELECT) 새 규칙을 애플리케이션 코드(JS) 메모리에서만
테스트했다. 상세 매핑 기준/결과/권고는 `docs/category-taxonomy-7major-dryrun-report.md`에
전부 기록했다 — 요약:

- 지시에 나열된 항목을 세어보면 36종이다(지시문의 "37종"과 1건 차이 — 임의로 항목을
  추가해 맞추지 않고 나열된 그대로 시뮬레이션, 보고서에 명시).
- **전체 매칭률 34.28%(9,050/26,404건), NULL 잔여 65.72%(17,354건).**
- 7대 대분류별 분포: 문화/전시(5,340) > 축제/이벤트(2,353) > 스포츠 대여(504) > 공공
  키즈카페(417) > 배움/클래스(228) > 자연/캠핑(139) > 체험/농장(69).
- "공원탐방"/"농장체험" 2종은 현재 데이터에서 0건 매칭(규칙은 유효, 데이터가 아직 없음).
- 신규/개명 3종(공공키즈카페, 어린이실내놀이터, 지역축제/페스티벌)의 키워드는 **제안**이며
  확정이 아니다 — 특히 "지역축제/페스티벌"은 기존 "문화행사" 키워드에서 `축제`/`페스티벌`을
  분리해 만든 것으로, 이 분리 기준 자체도 검토가 필요하다.
- **실제 UPDATE는 지시대로 실행하지 않았다** — 대표 최종 승인 대기 상태.

## 2. `/admin/data-grid` 표준 페이지네이션 + 가독성 개선 (구현 완료)

### 신규 컴포넌트: `src/components/admin/pagination.tsx`
- `«`(첫 페이지)/`이전`/페이지 번호 버튼(현재 페이지 기준 앞뒤 1개씩 + 양끝, 생략 구간은
  `…`)/`다음`/`»`(마지막 페이지)로 구성된 표준 페이지네이션.
- 생략 부호가 페이지 번호 딱 1개만 대체하는 경우(예: `[1,2,…,4]`)는 어색해 그 번호를 그대로
  펼쳐 보여준다(`[1,2,3,4]`) — 표준 페이지네이션 UX 관례.
- `data-grid-client.tsx`의 기존 이전/다음 버튼 2개를 이 컴포넌트로 교체.

### 가독성 개선 (`data-grid-client.tsx`)
- 테이블 헤더에 `sticky top-0`(그리드 스크롤 시 헤더 고정) + 살짝 진한 폰트/구분선.
- 짝수/홀수 행 교차 배경(zebra striping)으로 행 구분 가독성 향상.
- 행 호버 색을 회색에서 파란 계열로 변경(클릭 가능한 행임을 더 명확히 인지).

## 특이 사항
- 이번 작업에서 `category_maj` 컬럼은 추가하지 않았다(지시의 "필요 시" 조건부 문구를,
  "실제 UPDATE 전에는 스키마도 건드리지 않는다"는 더 보수적인 해석으로 적용 — 이전
  [카테고리 정제 & 어드민 확장] 작업 때도 첫 Dry-run 단계에서는 스키마를 전혀 건드리지
  않았던 것과 동일한 원칙 적용).
- 신규 taxonomy가 승인되면: (1) `events.category_maj` 컬럼 추가, (2) `category_rules`의
  기존 events 규칙 중 새 36종에 없는 것(정보통신/전문/자격증/단체봉사/청년정보/녹화장소)
  처리 방침 결정, (3) 기존에 이미 `category_min_source='MANUAL'`로 수동 확정된 행을
  재분류 시 덮어쓸지 여부 결정이 필요하다 — `docs/category-taxonomy-7major-dryrun-report.md`
  4절에 다음 단계로 정리해 뒀다.
