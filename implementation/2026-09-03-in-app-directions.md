# 인앱 길찾기(카카오모빌리티 자동차 길찾기 API) 구현

## 구현 일시
2026-09-03

## 배경
"이벤트픽에서 스팟 선택 후 '지도에서 보기'를 눌러도 확대/축소 말고는 할 수 있는 게
없다 — 현재 위치 기준 길찾기가 없다"는 지적. 이 프로젝트에는 2026-08-30에 "길찾기가
네이버 지도 앱/웹으로 유저를 내보내던 것"을 명시적으로 없애고 인앱 지도로 대체한
결정이 있어, 사용자에게 먼저 확인했다 — 그 결정의 취지(앱 이탈 없이 위치 확인)를
해치지 않는 선에서, 기존 "지도에서 보기"(MapPreviewModal)는 그대로 두고 그 안에
"길찾기" 액션을 추가하는 방향으로 합의했다. 이어서 어떤 카카오 API를 쓸지(길찾기
API로 데이터만 받아 우리 지도에 직접 그리기 vs 카카오내비 SDK로 나가기)와 그중
어떤 세부 API(자동차/다중경유지/다중출발지/다중목적지/미래운행정보)를 쓸지도
사용자와 함께 확인해 "자동차 길찾기"(단일 출발지·단일 목적지)로 확정했다.

## 구현 내용
1. **`/api/nearby/directions`(신규 API 라우트)**: 카카오모빌리티 자동차 길찾기
   REST API(`https://apis-navi.kakaomobility.com/v1/directions`)를 서버에서만
   호출한다 — `KAKAO_REST_API_KEY`(.env.local에 이미 있던 값, 실측으로 이 API에
   대한 권한이 이미 활성화돼 있음을 확인)를 브라우저에 노출하지 않는다. 응답의
   `sections[].roads[].vertexes`(평탄 `[lng,lat,lng,lat,...]` 배열)를 `{lat,lng}[]`
   순서 목록으로 변환해 반환한다.
2. **`MiniMap`**: 기존 지도 생성 effect는 전혀 건드리지 않고, `route`(출발지 좌표 +
   경로 좌표 목록) prop이 있을 때만 동작하는 완전히 독립된 effect를 추가했다 —
   Polyline(경로선)과 출발지 마커(파란 점)를 그리고 `setBounds`로 출발지~경로 전체가
   보이도록 뷰포트를 맞춘다. route가 나중에(버튼 클릭 후 비동기 응답으로) 채워져도
   지도 자체를 재생성하지 않아 사용자가 이미 조작한 확대/이동 상태를 잃지 않는다.
3. **`MapPreviewModal`**: 지도 하단에 "🧭 현재 위치에서 길찾기" 버튼을 추가했다.
   누르면 `navigator.geolocation`으로 현재 위치를 확인하고(이 앱의 기존 위치
   온보딩과 동일한 패턴 재사용) `/api/nearby/directions`를 호출, 성공하면 거리·
   예상 소요시간을 표시하고 그 경로를 MiniMap에 그린다. 위치 권한 거부/API 실패
   /브라우저 미지원 각각 별도 안내 문구로 처리한다(제5장 제11조 무중단 원칙).

## 타입 선언 확장
이 프로젝트는 Kakao Maps SDK 공식 타입 패키지 없이 실제 쓰는 API 표면만 최소
선언한다(`src/types/kakao.d.ts`) — `Polyline`/`LatLngBounds`/`Map.setBounds`를
새로 추가했다(전부 카카오 공식 API에 실제로 존재하는 것만).

## 테스트 작성 중 발견한 기존 버그
`mini-map.test.tsx`의 카카오 SDK 스텁(`Map: vi.fn(() => ({...}))` 등)이 화살표
함수를 `vi.fn()` 구현체로 쓰고 있었는데, 화살표 함수는 JS 스펙상 `new`로 호출할 수
없다 — `new window.kakao.maps.Map(...)`가 항상 "is not a constructor"로 실패해
컴포넌트가 조용히 'error' 상태로 빠지고 있었다. 기존 테스트들의 단언이 약해서
(loadState와 무관하게 항상 렌더링되는 `role="img"` div의 존재만 확인) 이 버그가
무증상으로 통과되고 있었다 — 이번에 Polyline 호출 여부처럼 더 엄격한 단언을
추가하면서 발견했다. 모든 생성자 스텁을 `function` 표현식으로 바꿔 실제로 `new`가
가능하도록 고쳤다(vitest 자체 경고 메시지가 이 원인을 정확히 안내하고 있었음).

## 검증
`npx tsc --noEmit`/`npm run test`(97파일 996건, MiniMap/MapPreviewModal 신규
테스트 포함)/`npm run build` 통과.

라이브 dev 서버 실측:
- `curl /api/nearby/directions?...`(판교역~인근 좌표)로 우리 API 래퍼가 실제
  카카오모빌리티 응답을 정확히 변환해 반환함을 확인(거리 1991m, 소요 504초, 경로
  41개 좌표).
- 잘못된 좌표(`origin_lat=abc`)를 주면 400과 명확한 에러 메시지를 반환함을 확인.
- 이 API 자체를 직접 카카오모빌리티 엔드포인트에 curl로도 먼저 검증해 REST 키에
  "길찾기 API" 권한이 이미 활성화돼 있음을 확인한 뒤 구현을 진행했다.

**주의(정직한 한계 고지)**: 브라우저 자동화 도구가 없어 실제 위치 권한 팝업 →
클릭 → 지도 위에 그려지는 경로선까지 눈으로 직접 확인하지는 못했다. API 라우트는
실제 카카오모빌리티 서버로 라이브 검증했고, 클라이언트 쪽(geolocation→fetch→
MiniMap route 전달) 흐름은 각 단계를 모킹한 컴포넌트 테스트로 검증했다.
