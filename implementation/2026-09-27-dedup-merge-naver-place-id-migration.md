# 중복 스팟 그룹 병합 시 naver_place_id 자동 이전

## 구현 대상
사용자 지시(2026-09-27, Step 65 후속): "그룹병합한 후에 안보이게 되고
그룹병합후 해서 채우면 보이면 돼. 혹은 둘중에 값 있던 것으로 나머지
그룹병합된것도 채워줘도 되고".

## 배경
Step 65에서 "어뮤즈스파 진주점" 사례를 1건 수동으로 고쳤다 — 그룹 병합 전에
naver_place_id를 저장해둔 행이 나중에 비대표가 되면서, 대표 행에는 값이
없는데 저장이 안 되는(unique 제약) 상태가 됐었다. 이번엔 이 문제를 병합
시점에 자동으로 처리하도록 근본 원인을 고친다.

## 변경 사항
`src/app/api/admin/spot-dedup/apply/route.ts`(그룹 일괄 저장 라우트):
- 멤버 조회에 `naver_place_id` 컬럼을 추가로 select.
- 대표 결정 로직 바로 다음에, "대표가 아직 naver_place_id가 없고 멤버 중
  정확히 하나의 서로 다른 값(distinct)만 존재하면" 그 값을 대표로 이전한다.
- naver_place_id는 `open_spaces`에 unique 제약이 있어 두 행이 동시에 같은
  값을 가질 수 없다 — 그래서 반드시 **원래 값을 갖고 있던(비대표가 될) 행에서
  먼저 비우고, 그다음 대표에 채운다**(순서를 바꾸면 그 사이 두 행이 동시에
  같은 값을 갖는 순간이 생겨 제약을 위반한다).
- 값을 가진 멤버가 둘 이상이고 서로 다른 값이면(진짜 데이터 충돌) 추측으로
  하나를 고르지 않고 그대로 둔다(제3장 제5조 추측 금지) — 이 경우는 관리자가
  직접 확인해야 하는 예외적 상황으로 남긴다.

## 검증
- `src/app/api/admin/spot-dedup/apply/route.test.ts`(신규): 4개 테스트 —
  (1) 비대표 하나만 값을 가지면 대표로 이전되고 비우기가 이전보다 먼저
  실행됨, (2) 대표가 이미 값을 가지면 아무것도 안 건드림, (3) 아무도 값이
  없으면 아무것도 안 건드림, (4) 서로 다른 값을 가진 멤버가 둘 이상이면
  옮기지 않음.
- `npx tsc --noEmit` / `npm run test`(204개 파일 2,379개) / `npm run build`
  모두 통과.

## 특이 사항
- Step 65에서 고친 "저장 실패를 화면에 보여주는" 안전장치는 그대로 유지된다
  — 이번 자동 이전으로 대부분의 경우는 애초에 실패 자체가 안 생기지만, 값을
  가진 멤버가 둘 이상인 충돌 케이스처럼 자동 이전이 스스로 판단하지 않은
  경우엔 여전히 관리자가 직접 채우다가 실패하면 그 에러를 볼 수 있어야 한다.
