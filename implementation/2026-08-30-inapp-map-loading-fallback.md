# [개발 요청] 상세 모달 내 인앱 지도 및 위치 핀 표시 기능 구현

## 요구사항
1. 외부 지도 앱/웹으로 나가는 길찾기/위치 보기 버튼 동작 제거.
2. 상세 모달 내 좌표/주소 기반 인앱 지도(핀 포함) 컴포넌트.
3. 로딩 중 스켈레톤 + 필요시 주소 복사 버튼 등 유저 편의 UI.

## 구현 일시
2026-08-30

## 사전 조사 — 요구사항 1/2는 직전 작업에서 이미 구현돼 있었음

코드를 전수 확인한 결과(`window.open`/`map.kakao.com`/`map.naver.com`/`nmap://` 등
외부 지도 연동 패턴 전체 grep), 요구사항 1(외부 링크 제거)과 2(인앱 지도+핀)는
바로 전 작업["외부 지도 앱 연동 제거 및 '스팟픽' 인앱 지도/위치 표시 기능
구현"](2026-08-30)에서 이미 구현되어 있었다 — `DetailModal`의 조건부 CTA 3번째
옵션이 네이버 지도 딥링크(`<a target="_blank">`)에서 인앱 `MapPreviewModal`(Kakao
Maps SDK, 핀 표시)을 여는 버튼으로 이미 교체돼 있었고, `MiniMap`이 상세 모달
안에 항상 노출되는 콤팩트 인앱 지도로 이미 존재했다. 앱 전체에서 외부 지도 연동
지점은 더 이상 없음을 재확인했다.

**실제로 남아 있던 갭은 요구사항 3(로딩 스켈레톤/실패 폴백)이었다** — 기존
`MiniMap`은 Kakao Maps SDK가 비동기 로드되는 동안 빈 `<div>`만 보여줘 로딩 중인지
실패한 것인지 구분할 수 없었고, SDK 로드 실패(API 키 미설정/네트워크 오류) 시에도
"조용히 무시"만 할 뿐 유저에게 어떤 정보도 보여주지 않았다.

## 변경 내용

### `src/components/map/mini-map.tsx`
- SDK 로딩 상태를 `'loading' | 'loaded' | 'error'`로 명시적으로 관리한다.
- **로딩 중**: 지도와 동일한 크기의 회색 펄스 스켈레톤(다른 스켈레톤 컴포넌트들과
  동일한 CLS 방지 원칙)을 보여준다.
- **로드 실패**: "지도를 불러올 수 없습니다." 안내 + (address prop이 있으면) 주소
  텍스트와 "주소 복사" 버튼을 보여준다(요구사항 3 "필요시 주소 복사 버튼 등을 함께
  배치"). 지도가 아예 없어도 유저가 위치 정보(주소)는 확인할 수 있다.
- 새 `address?: string | null` prop 추가 — 실패 폴백 전용, 지도 자체 렌더링에는
  영향 없음.

### `DetailModal`/`MapPreviewModal`
`item.address`를 `MiniMap`/`MapPreviewModal`에 새로 전달하도록 연결(콤팩트
미니맵/풀스크린 미리보기 모달 둘 다 동일한 실패 폴백을 갖게 됨).

### 부수 발견 및 정리
`src/lib/kakao/directions-url.ts`(`buildKakaoDirectionsUrl`) — 예전에 카카오맵
길찾기 링크를 만들던 유틸인데, 이후 네이버 지도로 전환되면서(Task 9-5-1) 완전히
버려진 채 아무도 참조하지 않는 죽은 코드였다(grep으로 소비처 0건 확인). 이번
작업의 조사 과정에서 발견해 삭제했다.

## 검증

### 코드 검증
- `npx tsc --noEmit` 통과.
- `npm run test`(70파일 703건 — `mini-map.test.tsx` 4건 신규: 로딩 스켈레톤/로드
  성공 시 전환/로드 실패 시 주소+복사 버튼/주소 없을 때 복사 버튼 미노출) 통과.
- `npm run build` 통과.

### 실측 검증
로컬 개발 서버로 `/`, `/nearby` 페이지가 정상 렌더링됨을 확인했다. `MiniMap`은
클릭 상호작용(상세 모달 오픈) 이후에만 클라이언트에서 렌더링되는 컴포넌트라 SSR
응답만으로는 검증되지 않는다 — 이 프로젝트의 기존 관례(jsdom에서 Kakao Maps SDK가
실제로 로드되지 않아 지도 렌더링 자체는 단위 테스트 대상이 아님, `detail-modal.test.tsx`
주석 참고)에 따라 `loadKakaoMapSdk()`를 모킹해 로딩/성공/실패 세 상태 전이를
컴포넌트 테스트로 검증했다.

## 특이 사항
- "이벤트/큐레이션 상세 모달"이라는 지시서 표현 중 "큐레이션" 쪽은 별도 상세
  모달이 없다 — 직전 작업["홈 화면 큐레이션 섹션 추가 및 상단 탭 정리"]에서
  사용자가 명시적으로 "카드 클릭 시 상세 모달 없이 곧바로 booking_url을 새 창으로
  연다"고 확정한 설계라, 이번 지시서만으로 그 결정을 뒤집어 새 모달을 만들지
  않았다. "이벤트" 쪽은 `DetailModal`(스팟/이벤트 공용, 이미 인앱 지도 완비)을
  가리키는 것으로 해석했다.
