# [UI/UX 개발 요청] 홈 화면 큐레이션 섹션 추가 및 상단 탭(네비게이션) 정리

## 요구사항
1. 상단 [홈 / 특가 할인 / 무료 공공] 서브탭 완전 삭제 — 단일 메인 화면으로 정리.
2. "이번 주말 실패 없는 베스트 나들이 픽" 큐레이션 섹션 추가(광고 느낌 제거, 신뢰감
   있는 큐레이션 톤).
3. 배치 위치: "현재 이용 가능" 바로 아래, "예약 가능" 바로 위(샌드위치 구조).
4. 가로 스크롤 슬라이드(컴팩트 카드, 썸네일+타이틀 중심).
5. `event_tickets.booking_url`과 연동, 클릭 시 `target="_blank"`로 외부 브라우저 오픈.

## 구현 일시
2026-08-30

## 0. 사전 확인 — 직전 작업과의 중복 발견 및 사용자 확인

바로 전 작업에서 만든 홈 상단 배너 섹션("🔥 이번 주말 놓치면 후회할 특가", Hero 바로
아래 4개 그리드 카드)이 이번 요구사항 2의 "베스트 나들이 픽" 섹션과 목적(event_tickets
큐레이션, 제휴 링크 연결)이 거의 동일하고 위치도 가까웠다 — 그대로 두면 비슷한
큐레이션 섹션이 화면에 두 번 나오게 되어 지시서 자체의 "UI/UX 간소화" 목표와도
어긋난다. `AskUserQuestion`으로 확인한 결과 **"새 섹션이 기존 배너를 대체"**로
확정 — 기존 배너 섹션(그리드/디테일 모달/전체보기 바텀시트 전체)을 걷어내고 이번
섹션으로 교체했다.

## 1. 상단 서브탭 완전 삭제

`HomeSubTabs`(`src/components/home/home-sub-tabs.tsx`)와 그 사용처를 전부 제거했다.
탭이 사라지면서 다음도 함께 정리했다(탭이 유일한 진입 경로였던 콘텐츠라 탭 삭제와
동시에 도달 불가능해짐):
- "🏷️ 특가·핫딜" 탭의 `deals` 그리드(DealCard/DealDetailModal) — 파일 삭제.
- "🎁 무료·공공" 탭의 무료·공공 피드(`useFreeFeed` 훅의 탭 연동 부분) — home-view.tsx
  에서 해당 렌더 분기와 훅 사용 제거.

**백엔드는 건드리지 않았다**: `deals` 테이블, `/api/deals` 라우트, `event_tickets`
테이블, `/api/home/free-feed` 라우트는 그대로 남아 있다 — 이번 지시서는 프런트엔드
UI/탭 구조에 관한 것이었고, DB 스키마/API 삭제는 명시적으로 요청되지 않아 임의로
진행하지 않았다(제3장 제3조 데이터 구조 변경을 구현 AI가 임의로 결정하지 않음).
프런트엔드 연결만 제거해 지금은 쓰이지 않지만, 필요하면 다른 화면에서 재사용 가능한
상태로 남겨뒀다.

삭제된 파일: `home-sub-tabs.tsx`, `deal-card.tsx`, `deal-detail-modal.tsx`,
`event-ticket-card.tsx`, `event-ticket-banner-card.tsx`, `event-ticket-browse-sheet.tsx`,
`event-ticket-detail-modal.tsx`(0번 항목에서 대체된 구 배너 섹션 전용 컴포넌트 포함) —
전부 삭제 전 다른 소비처가 있는지 `grep`으로 확인 후 진행했다.

## 2~5. "베스트 나들이 픽" 신규 섹션 (`src/components/home/best-pick-slider.tsx`)

- **위치**: "✅ 현재 이용 가능" 섹션과 "📋 예약 가능" 섹션 사이(요구사항 3 그대로).
- **레이아웃**: `overflow-x-auto` + `snap-x` 가로 스크롤(요구사항 4) — 카드 폭
  `w-36`(144px)로 컴팩트하게, 정사각 썸네일 + 2줄 제목 + 장소명만 담백하게 노출.
- **톤**: 할인율 뱃지·"놓치면 후회" 같은 세일즈 문구를 전부 뺐다. 타이틀
  "이번 주말 실패 없는 베스트 나들이 픽" + 서브 텍스트 "에디터가 직접 검증한
  나들이 코스만 엄선했어요."로 신뢰감 있는 큐레이션 톤을 구성했다(요구사항 2).
- **클릭 동작**: 카드 전체가 `<a href={booking_url} target="_blank"
  rel="noopener noreferrer">`다 — 요구사항 5가 "카드 클릭 → booking_url 새 창"을
  명시했고 중간 상세 모달 단계를 언급하지 않아, 직전 배너 섹션과 달리 상세 모달을
  거치지 않고 곧바로 새 창을 연다(더 단순한 상호작용, 컴팩트 슬라이드에 적합).
- **데이터**: 기존 `GET /api/event-tickets`를 그대로 재사용(제5장 제4조 기존 구조
  우선). 탭이 사라져 "탭 선택 시 지연 페칭" 트리거가 없으므로, 마운트 시 곧바로
  한 번 페칭하는 `useBestPicksFeed` 훅을 새로 뒀다("현재 이용 가능"/"예약 가능"과
  동일한 마운트-이펙트 패턴).
- **가변 노출**: 0건이면 섹션 자체를 숨긴다(다른 섹션과 동일한 원칙).

## 검증

### 코드 검증
- `npx tsc --noEmit` 통과.
- `npm run test`(68파일 691건 — 서브탭 삭제 확인, 베스트 픽 마운트 렌더링/직접 링크
  클릭/0건 숨김/섹션 위치 순서 검증 등 신규 테스트 포함) 통과.
- `npm run build` 통과 — 기존 `/api/deals`/`/api/event-tickets` 라우트 모두 정상 유지.

### 실측 검증
로컬 개발 서버 + 시드된 실제 `event_tickets` 데이터로 홈 페이지 SSR 응답을 확인 —
새 섹션 타이틀 "이번 주말 실패 없는 베스트 나들이 픽"과 서브 텍스트는 정상 포함되고,
기존 탭 라벨("🏠 홈"/"🏷️ 특가·핫딜"/"🎁 무료·공공")은 응답에서 완전히 사라졌음을
확인했다. `GET /api/event-tickets`도 정상 동작 확인. 이 세션에는 브라우저 자동화
도구가 없어 실제 화면을 시각적으로 캡처해 확인하지는 못했다 — 대신 컴포넌트 단위
테스트(정확한 렌더 텍스트/링크 속성/DOM 순서 검증)와 API/SSR 레벨 실측으로 대체
검증했다.

## 특이 사항
- `deals`/`event_tickets` 테이블과 `/api/deals`/`/api/home/free-feed` 라우트는
  프런트엔드에서 더 이상 쓰이지 않지만 삭제하지 않았다 — 백엔드 스키마/API 삭제는
  이번 지시서 범위 밖이라(명시적 요청 없음) 임의로 진행하지 않았다. 필요하면 별도
  지시로 정리 가능하다.
- 홈 화면에 있던 검색바(HomeHeader)와 위치 설정 버튼은 이번 지시서가 언급한 "탭"과는
  별개 컴포넌트라 그대로 유지했다.
