# [개선사항 9] 어드민 키즈친화 식당 스팟 큐레이션 관리 UX 개편 (리스트 기반 모달 팝업 입력)

## 구현 일시
2026-09-03

## 배경 조사
기존 "스팟 큐레이션" 탭은 이미 등록된 큐레이션만 목록으로 보여줬고, 신규 등록은 모달을
연 뒤 그 안에서 2글자 이상 타이핑해 `/api/spots/search`로 자동완성 검색해야 했다
(실측 코드 확인) — 요구사항이 지적한 "검색/타이핑 필요" 문제와 정확히 일치했다.

## 구현 내용
1. **후보 목록 우선 노출**: "스팟 큐레이션" 탭을 열면 큐레이션 여부와 무관하게 키즈친화
   식당(category_min='놀이방식당') 전체를 리스트로 먼저 보여준다. 새 엔드포인트를 만들지
   않고 이미 페이지네이션/검색을 지원하는 `/api/admin/data-grid?table=open_spaces&
   category_min=...`를 그대로 재사용했다(제5장 제4조 기존 구조 우선).
   - **실측으로 발견한 버그**: 이 엔드포인트는 `page_size`를 50/100/200 중 하나로만
     받고 그 외 값은 조용히 50으로 대체한다 — 처음 20으로 설정했다가 라이브 curl
     테스트로 발견해 50으로 맞췄다(그대로 뒀다면 클라이언트 페이지 수 계산이 서버 실제
     동작과 어긋났을 것).
2. **큐레이션 여부 뱃지**: 이미 등록된 스팟은 "큐레이션됨"(+ 노출 토글), 아직 없는
   스팟은 "미등록"으로 표시한다. 전체 큐레이션 현황은 마운트 시 한 번만
   (`/api/admin/spot-curations?page_size=5000`) 불러와 spot_id 기준 Map으로 들고
   있는다 — 큐레이션 총량이 후보(1,815건)보다 훨씬 적을 것으로 예상돼 페이지당 조회
   대신 1회 전체 조회가 더 단순하다.
3. **클릭 → 자동 바인딩 모달**: 리스트 항목을 클릭하면 그 스팟이 이미 큐레이션돼
   있으면 수정 모달을, 없으면 그 스팟에 곧바로 바인딩된 등록 모달을 연다 — 두 경우
   모두 모달 안에서 검색할 필요가 전혀 없다.
4. **모달 간소화**: `CurationFormModal`에서 스팟 검색 UI(입력창/디바운스 자동완성/
   mousedown 선택 로직 전체)를 들어냈다. 이제 스팟은 항상 `initial`(수정) 또는
   `presetSpot`(신규, 리스트에서 넘어옴) 중 하나로 이미 정해져 있어, 이름/주소를 정적
   요약 카드로만 보여주고 나머지는 전부 메뉴/시간/이미지/링크 입력에 쓴다.
5. 자유 검색 기반의 "+ 스팟 큐레이션 등록" 버튼은 완전히 제거했다 — 새 리스트 자체의
   검색창(이름/주소)이 그 역할을 대신하므로 두 가지 진입 경로를 유지할 필요가 없었다
   (제2장 제6조 단순함).

## 검증
`npx tsc --noEmit`/`npm run test`(96파일 972건 — 기존 파일 검색 자동완성 테스트 6건을
새 리스트/모달 바인딩 테스트 5건으로 교체)/`npm run build` 통과.

라이브 dev 서버 curl로 실제 데이터 확인:
- `/api/admin/data-grid?table=open_spaces&category_min=놀이방식당` → 1,815건 확인.
- 실제 스팟(`35ca88f6-...`, "신 진짜루") 1건에 curl로 진짜 큐레이션을 생성 →
  `/api/admin/spot-curations?page_size=5000`에 즉시 반영됨을 확인(패널의 상태
  뱃지/토글이 참조하는 정확히 그 응답 경로) → 검증 후 테스트 데이터 삭제.
