# 동네 설정 (지역 선택) 개편

## 구현 대상
사용자 지시(원문): "동네 설정 (지역 선택) 개편 — 무한 로딩/에러 버그 해결 및 약 1초의
자연스러운 로딩 연출 적용. 3가지 명확한 선택지 제공: ① 평소 동네 근처, ② 현재 위치,
③ 다른 지역 바꾸기 (시·군·구 단위 상세 선택 구조)"

대상 파일: `src/components/map/location-onboarding-modal.tsx` (지도/주변 탐색
`MapExplorer`에서 쓰는 "동네를 설정해주세요" 온보딩 모달 — `useUserLocation` 훅을 통해
최초 진입 시와 "동네 변경" 재설정 시 모두 이 모달이 뜬다).

## 구현 일시
2026-09-04

## 변경 사항

### 1. 무한 로딩 버그 수정
`openManualPicker`가 `getSigunguOptions()` 호출 실패를 `.catch(() => {})`로 조용히
삼키기만 하고, 응답 자체가 없이 멈추는 경우(네트워크 지연 등)에 대한 타임아웃이
전혀 없어 `isLoadingOptions`가 영원히 `true`로 남을 수 있었다("목록 불러오는 중..."이
무한정 노출). `withTimeout()`(8초, `SIGUNGU_FETCH_TIMEOUT_MS`)으로 감싸 일정 시간 안에
응답이 없으면 강제로 실패 처리하도록 수정했다.

### 2. 에러 버그 수정 (조용한 실패 → 명시적 에러 + 재시도)
기존에는 조회 실패 시 사용자에게 아무 안내도 없이 "지역을 직접 선택해주세요" 섹션이
빈 채로만 남았다(로딩도 아니고 결과도 아닌 애매한 상태 — 실질적으로 "고장 난 것처럼"
보임). `sigunguErrorMessage` 상태를 추가해 실패 시 구체적인 에러 메시지와 "다시 시도"
버튼을 보여주고, 재시도 시 `loadSigunguOptions()`를 다시 호출한다.

### 3. 약 1초의 자연스러운 로딩 연출
`getSigunguOptions()` 응답이 매우 빠를 때(수십~수백ms) "목록 불러오는 중..."이 눈
깜빡할 새 사라져 오히려 부자연스러웠다. `MIN_LOADING_DURATION_MS`(1000ms)를 두어,
실제 응답이 이보다 빠르면 나머지 시간만큼 로딩 상태를 유지한 뒤 결과/에러를 반영한다
(응답이 이미 1초보다 오래 걸렸다면 추가 지연 없음).

### 4. 3가지 명확한 선택지로 UI 재구성
새 데이터/로직을 추가하지 않고(제5장 제4조 기존 구조 우선) 이미 있던 3가지 경로에
번호가 매겨진 제목을 붙이고 지시된 순서(①→②→③)로 재배치했다:
- **① 평소 동네 근처**: 기존 "동네/주소 검색" 입력(플레이스홀더를 "평소 다니는 동네
  이름이나 주소로 검색"으로 명확화).
- **② 현재 위치**: 기존 "📍 현재 위치로 찾기" GPS 버튼(동작 변경 없음).
- **③ 다른 지역 바꾸기**: 기존 "🗺️ 지역 목록에서 선택" 버튼을 "🗺️ 시·군·구 목록에서
  선택"으로 라벨만 다듬고, 이미 시/도 단위로 그룹핑돼 있던 시/군/구 상세 선택 시트를
  그대로 유지(지시된 "시·군·구 단위 상세 선택 구조"와 일치).

## 특이 사항
- GPS 실패 시 수동 선택 시트를 자동으로 여는 기존 2단계 Fallback 동작(Task 9-1-8),
  중첩 모달 배경 클릭 버블링 방지 포탈 렌더링(2026-09-03), 시/도 그룹핑(개선사항 2-3)은
  모두 그대로 유지 — 라벨/배치만 바꿨다.
- 테스트: `withTimeout` 타이밍 로직을 컴포넌트에서 분리해 export하고 순수 함수로
  fake timer 검증했다 — 처음에는 컴포넌트를 통째로 렌더링한 채 fake timer로 8초
  타임아웃을 흉내내려 했으나, React의 내부 스케줄러가 fake timer와 충돌해 상태
  업데이트가 멈추는 문제를 실측으로 발견해 이 방식으로 바꿨다. 또한 "약 1초 로딩
  연출"이 testing-library의 기본 `findBy` 타임아웃(1000ms)과 정확히 겹쳐 flaky해지는
  것을 발견해, 관련 `findBy` 호출에 `{ timeout: 2000 }`을 명시했다.
- 검증: `npx tsc --noEmit` 통과, `npm run test`(97개 파일/1005개 테스트) 전체 통과,
  `npm run build` 프로덕션 빌드 통과. 브라우저 실기동 확인은 이 환경에 사용 가능한
  브라우저/스크린샷 도구가 없어 수행하지 못했다 — 렌더링 구조는 테스트가 캡처한 전체
  DOM 스냅샷(①②③ 제목과 각 섹션 마크업)으로 대신 확인했다.
