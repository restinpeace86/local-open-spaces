## 1. vh 기준 3분할 → 실제 남은 높이 기준 3분할로 교체
직전 커밋(Step 141)에서 3개 섹션에 `min-h-[28vh]`를 줬는데, `vh`는 뷰포트
"전체" 높이를 기준으로 하는 단위라 `RootLayout`(`src/app/layout.tsx`)의
하단 탭바(`BottomTabs` — 맘스픽/스팟픽/이벤트픽/마이)가 이미 차지하고 있는
공간을 반영하지 못한다. 이 프로젝트에는 이미 똑같은 원인의 문제가 한 번
발견·수정된 적이 있다(`data-grid-client.tsx`, "vh는 화면 전체 뷰포트 기준값이라
전역 하단 탭바가 이미 떼어간 공간을 반영하지 못한다" — 그때는 %로 바꿔
해결했다).

이번엔 %를 하드코딩하는 대신 flex 자체를 이어 붙이는 방법을 썼다:
- `body`(`layout.tsx`)는 이미 `h-dvh flex flex-col overflow-hidden`이고
  `BottomTabs`는 `shrink-0`다 — 즉 페이지 콘텐츠(`MomPickView`의 최상위
  div, 기존부터 `flex-1`)는 이미 "하단 탭바를 뺀 나머지 높이"를 정확히
  받고 있었다.
- `mom-pick-view.tsx`에서 대시보드를 감싸는 두 겹의 wrapper div
  (`<div className="relative">` → `<div className="flex flex-col gap-6">`)에
  각각 `flex-1`을 추가해 그 "나머지 높이"를 그대로 아래로 전달하게 했다.
- 3개 섹션 컴포넌트(`expert-pick-section.tsx`/`trending-pick-section.tsx`/
  `live-pick-section.tsx`)의 `min-h-[28vh]`를 `flex-1`로 교체 — 이제 3개
  섹션은 vh 추측값이 아니라 "실제로 남은 화면 높이"를 정확히 3등분해서
  나눠 가진다(글이 많아 필요한 높이가 더 크면 flexbox 기본 동작대로 자연스럽게
  더 커지고, 전체 페이지 스크롤(`overflow-y-auto`, 기존 그대로)로 넘친다).

## 2. 섹션별 색상 구분
"각 영역별 좀 구분이 되도록.. 색깔로 구분"에 따라 3개 섹션 `<section>` 루트에
각각 테마 색 배경 패널을 둘렀다(`rounded-2xl border ...`):
- 파워맘·우수맘 추천: 골드→퍼플 그라데이션 틴트(`from-amber-50/70
  to-purple-50/70`) + 앰버 테두리.
- 인기 우수글: 오렌지 틴트(`bg-orange-50/50`) + 오렌지 테두리.
- 실시간 라이브: 레드 틴트(`bg-red-50/50`) + 레드 테두리.

테두리가 자연스럽게 "가로줄"(구분선) 역할도 겸해서, 별도의 `<hr>` 요소를 추가로
넣지는 않았다(사용자가 "가로줄.. 아니면 색깔로"라고 양자택일로 제시했고, 색상
패널이 구분선 효과까지 포함한다고 판단).

## 3. 실시간 라이브 정렬 확인(코드 변경 없음)
`getLivePosts()`(`mom-pick-dashboard.ts`)를 다시 확인한 결과, 이미
`.order('created_at', { ascending: false })`로 최신순 정렬 중이었다 — 즉
"가장 최신글이 맨 위로"라는 요구사항은 이전부터 충족되어 있었다(2026-09-02
기획 그대로, Step 140/141에서도 이 정렬 로직 자체는 건드리지 않음). 별도 코드
수정 없이 확인만 하고 넘어간다(제3장 제5조 — 이미 맞는 로직을 추측성으로
다시 만들지 않음).

## 특이 사항
- 실제 기기별 정확한 3등분 비율은 폰트 렌더링/카드 개수에 따라 약간씩 달라질

  flex-1 체인으로 충분히 달성된다.
