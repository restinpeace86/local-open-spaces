# 중복 스팟 그룹 정기휴무일(excluded_weekdays) 통합

## 구현 대상
사용자 지시(2026-09-28): "지금 어린이도서관 관련 중복 스팟 검수 및 매핑으로
동일 장소는 그룹으로 묶었는데 그룹으로 묶으면서 정기 휴관일 같은게 없는쪽이
대표가 되게 묶인게 있는지 확인해주고 .. 정기휴관일 관련하여서도 둘중 하나가
값이 있으면 있는것 기준으로 통합되게 해줘.. 동일한 그룹내 빈쪽에도 동일하게
채워주던가"

## 실측 확인
어린이도서관 그룹 24개 중 대표가 비어있는데 멤버가 값을 가진 그룹이 **2개**
있었다:
- "서구어린이도서관" 그룹: 대표 비어있음, 다른 멤버가 `MON` 보유.
- 주엽어린이도서관 그룹: 대표 비어있음, 멤버 2곳이 `FRI`로 일치하는 값 보유.

## 변경 사항
### 1. 기존 그룹 일회성 백필
`scripts/migrations/2026-09-28-backfill-dedup-group-excluded-weekdays.mjs`
(신규): 어린이도서관 카테고리의 그룹 24개를 스캔해, 그룹 내 non-null
excluded_weekdays/excluded_nth_weekdays 값이 전부 서로 같으면(또는 1건만
있으면) 그 값을 **대표뿐 아니라 그룹 내 비어있는 모든 멤버**에 채운다
(naver_place_id처럼 unique 제약이 없어 대표로만 옮길 필요가 없음 — "같은
물리적 장소면 모든 멤버가 같은 정기휴무 정보를 가져야 자연스럽다"). 서로 다른
값이 섞여 있으면(진짜 충돌) 추측으로 합치지 않고 그대로 둔다.
- 실행 결과: 22건 채움, 충돌 0건. 그룹 5개는 멤버 전원이 비어있어(원본 자체에
  정보 없음) 대상에서 자연히 제외됨(실측 재확인).

### 2. 그룹 병합 라우트 — 향후 재발 방지
`src/app/api/admin/spot-dedup/apply/route.ts`: 멤버 조회에
`excluded_weekdays, excluded_nth_weekdays`를 추가하고, naver_place_id
마이그레이션과 동일한 지점에 병합 로직을 추가했다 — 그룹 멤버들의 값이
전부 일치(또는 1건만 존재)하면 그 값을, 그룹 전체를 한 번에 업데이트하는
배치 UPDATE(`standard_name`/`service_category_id`/`group_id` 등을 이미
`.in('id', spotIds)`로 전원 갱신하던 기존 호출)에 조건부로 포함시킨다. 값을
못 찾거나(전원 비어있음) 충돌이면 그 키 자체를 업데이트 객체에서 뺀다(각 행의
기존 값을 그대로 둠).

## 검증
- `scripts/migrations/2026-09-28-backfill-dedup-group-excluded-weekdays.test.mjs`
  (신규 5개): 한 멤버만 값 있음/여러 멤버 동일값/전원 없음/충돌/nth 필드도 동일.
- `src/app/api/admin/spot-dedup/apply/route.test.ts`(신규 4개): 그룹 전원에
  채워짐, 충돌 시 안 건드림, nth 필드도 동일 동작, 전원 없으면 키 자체를 안 보냄.
- `npx tsc --noEmit` / `npm run test`(214개 파일 2,471개) / `npm run build`
  모두 통과.
- 실제 DB: 22건 백필 완료. 재검증 결과 대표가 비어있는데 그룹 내 어딘가엔
  값이 있는 케이스는 0건(남아있는 대표 5곳의 빈 값은 그룹 전원이 원래부터
  비어있던 경우로 확인).

## 특이 사항
- 이번 백필 스크립트는 사용자가 지목한 어린이도서관 카테고리로 범위를

  그룹에도 같은 문제가 있을 수 있지만, 이번 지시 범위 밖이라 손대지 않았다.

  모든 그룹에 공통 적용된다.
