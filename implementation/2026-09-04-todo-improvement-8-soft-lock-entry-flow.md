# [개선사항8] 맘스픽 미등업 유저 진입 플로우 및 소프트 락 개선

## 구현 대상
`implementation/todo.md` [개선사항8]:
1. 맘스픽 진입 시 곧바로 글쓰기로 강제 이동하지 않고 메인 화면(피드)을 먼저 노출.
2. 미등업(새싹맘 미달성) 유저도 메인 화면 스크롤/탐색은 자유롭게 허용.
3. 안내 모달 "닫기" 시 강제 이동 없이 메인 화면 탐색을 계속할 수 있게 처리.

## 구현 일시
2026-09-04

## 조사 결과
`mom-pick-view.tsx`를 읽어보니, 2026-09-03에 이미 다른 지시(그 시점 todo.md
개선사항 10 — 지금 이 todo.md와는 번호만 같고 다른 문서)로 '게스트'(비로그인)
사용자에 대해서는 "메인 화면 먼저 노출 + 소프트 락" 원칙이 이미 적용돼 있었다.
그런데 그 컴포넌트 상단 주석("guest | not_sprout_yet | allowed 셋 다 같은 레이아웃을
공유한다")은 이미 세 상태 모두를 지원하는 것처럼 적혀 있었지만, 실제 코드의 피드
조회/렌더 조건은 `state === 'allowed' || state === 'guest'`로만 남아 있어
**'not_sprout_yet'(로그인은 했지만 첫 글을 아직 안 쓴 상태)에서는 피드가 영원히
뜨지 않는** 주석-코드 불일치 버그가 있었다 — 정확히 이번 [개선사항8]이 지적하는
문제와 일치한다.

추가로, 미등업 안내 모달(`SaessakMomGuideModal`)의 "닫기" 버튼이
`onClose={() => router.push('/')}`로 배선돼 있어, 닫으면 `/mom-pick`에 머무는 게
아니라 홈('/')으로 강제 이동했다 — "닫으면 메인 화면 탐색을 계속할 수 있어야 한다"는
요구사항과 정반대였다.

## 변경 사항 (`mom-pick-view.tsx`)
1. 대시보드(피드) 조회 effect와 렌더 조건 모두에 `'not_sprout_yet'`을 추가해, 로그인만
   했으면(등급 무관) 메인 피드를 볼 수 있게 했다. `project/decision-log.md`의 "등급
   게이팅 범위"("맘스픽 커뮤니티 피드는 로그인 사용자만 이용 가능") 상위 결정과도
   일치한다 — 등급이 아니라 로그인 여부가 기준이므로 스펙 충돌이 아니다.
2. `SaessakMomGuideModal`의 `onClose`를 `router.push('/')`에서 `setIsGuideModalOpen(false)`로
   바꿔, 닫으면 같은 화면(`/mom-pick`)에서 계속 둘러볼 수 있게 했다. 더 이상 쓰이지
   않게 된 `useRouter` import/변수도 함께 제거했다.
3. 안내 모달이 뜨는 시점(진입/재진입 시 자동 노출)은 그대로 유지했다 — 요구사항
   원문이 트리거 시점으로 "재진입 시"를 명시적으로 포함하고 있어, 기존 동작이 이미
   그 조건을 만족한다(추가 변경 불필요).

## 특이 사항 — 구현하지 않은 부분 (정직하게 기록)
- 요구사항 중 "개별 스팟의 상세 정보를 보려고 터치했을 때" 안내 모달을 띄우는
  트리거는 구현하지 않았다 — 현재 맘스픽 피드 카드(`DashboardPostCard`)는 애초에
  개별 포스트를 열람하는 "상세 화면/모달" 자체가 어디에도 없는 정적 미리보기 카드라
  (탭해도 아무 반응 없음), 이 트리거를 걸 대상이 존재하지 않는다. 새 "포스트 상세"
  화면을 만드는 것은 이번 개선(소프트 락 버그 수정)의 범위를 벗어나는 별도 신규
  기능이라 임의로 만들지 않았다(제7장 제4조 미래 기능 구현 금지) — 향후 포스트 상세
  화면이 추가되면 그 진입 지점에 동일한 게이팅을 적용하는 것을 제안한다.
- `mom-pick-view.tsx`는 이 세션 이전부터 단위 테스트 파일이 없다(useMomPickAccess/
  getMyProfile/fetch 등 의존이 많아 목킹 비용이 큼) — 기존 관례를 따라 새 테스트
  파일을 만들지 않고 tsc/build 통과와 코드 리뷰로 검증했다.
- 검증: `npx tsc --noEmit` 통과, `npm run test`(99개 파일/1059개 테스트) 전체 통과,
  `npm run build` 프로덕션 빌드 통과.
