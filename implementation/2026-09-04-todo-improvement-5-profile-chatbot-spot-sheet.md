## 변경 사항

### 1. 출생년도 드롭박스 (`complete-profile-view.tsx`)
`<input type="number">` 자유 입력을 `<select>` 드롭박스로 전환했다. 하한 연도("초등
6학년 기준")는 학년이라는 상대적 기준에 묶여 있어 `CURRENT_YEAR - 12`로 매년 자동
갱신되게 계산했다(2014를 하드코딩하면 내년부터 기준이 틀어짐). 과거 자유 입력
시절에 저장된, 지금 표준 범위를 벗어난 값(예: 1999)은 목록에 없다고 조용히 다른
값으로 바뀌지 않도록 옵션 맨 앞에 그대로 끼워 넣어 보존한다.

### 2. 봇 추천 단어 필터링 (`weather-reaction.ts`, `summary.ts`)
날씨 기반 제안 문구 2곳("야외 공원이나 놀이터", "야외 공원")에서 "공원"을 제거하고
"야외 나들이"/"야외 이벤트"로 교체했다. 유일한 LLM 호출 지점인 `summary.ts`의
프롬프트에도 "'공원' 단어와 공원을 콕 집어 추천하는 표현을 쓰지 말 것" 규칙을
명시해, LLM이 생성하는 자유 응답에도 같은 원칙이 적용되게 했다.

### 3. 동갑 자녀 멘트 자연화 (`personalization.ts`)
`buildPersonalizedGreeting`이 여러 자녀 나이를 항상 쉼표로 나열하던 것을, 전부
동갑(쌍둥이 포함)인 경우에만 고유어 수 표현으로 묶도록 분기했다("3살, 3살 아이들" →
"3살 두 아이"). 나이가 섞여 있으면(예: 2살, 5살) 기존처럼 나열한다 — 스펙이 명시한
"동갑인 경우"만 다루고, 부분적으로만 겹치는 경우(예: 3살,3살,5살)까지 일반화하는
것은 추측이라 다루지 않았다.

### 4. 지역 선택 검색 필터 (`location-onboarding-modal.tsx`)
챗봇 "다른 지역 바꾸기" → "시·군·구 목록에서 선택"으로 열리는 368건 목록(시/도별로
그룹핑됨, 2026-09-03 기존 구현) 위에 실시간 검색 입력창을 추가했다. 별도 debounce
없이 입력 즉시(`sigungu_name.includes(keyword)`) 필터링하고, 일치하는 지역이 없으면
안내 문구를 보여준다.

### 5. 챗봇 이용 제한 안내 시점 (`ai-chat-sheet.tsx`)
비로그인 사용자의 진입 시점 판정(개선사항8, 2026-09-03)은 이미 구현돼 있었으나,
로그인 사용자의 "후기 미작성으로 인한 이용 제한" 판정은 여전히 8단계 인터뷰를 전부
마친 뒤(`handleVibeConfirm` → `/api/ai-chat/search` 응답)에야 이뤄지는 사각지대였다.
마운트 시점에 `getMyProfile()`로 이미 조회하던 프로필에서 `grade`/
`ai_chat_free_uses_used`를 서버(route.ts)와 동일한 기준(`canUseUnlimitedChatbot`,
`FREE_CHATBOT_USES_BEFORE_SPROUT`)으로 먼저 판정해, 제한에 걸리면 날씨 질문조차
시작하지 않고 곧바로 LIMIT_REACHED 화면(기존 UI가 이미 로그인 여부에 따라 "맘스픽에
첫 후기 남기러 가기"/"로그인하러 가기" CTA를 분기해 보여주고 있었음)을 띄운다.
서버 쪽 최종 판정은 다른 기기/탭에서 그 사이 소진했을 수 있어 이중 방어로 그대로
남겼다(비로그인 분기와 동일한 원칙).

### 6. 스팟픽 중분류 바텀시트 재구성 (`spot-category-filter.tsx`, `map-explorer.tsx`)
기존에는 중분류를 고르면 시트가 즉시 닫히고(`setOpenMajorId(null)`), 대분류 탭
자체가 시트 바깥(화면 전체를 덮는 오버레이 뒤)에만 있어 시트가 열려 있는 동안에는
다른 대분류로 바로 전환할 수 없었다(닫았다가 다시 열어야 함). 이미 이벤트픽
`MajorCategoryGrid`가 검증해 둔 "시트 유지 + 시트 안에 탭을 두고 결과를 그 안에서
갱신" 패턴(2026-09-04 앞선 작업)을 그대로 재사용했다:
- 중분류를 선택해도 더 이상 시트를 닫지 않는다.
- 대분류 탭을 시트 안(상단 고정 영역)에도 두어, 시트를 닫지 않고 바로 다른
  대분류로 전환할 수 있다. 다만 이 안쪽 탭은 라벨을 선택된 중분류 이름으로
  바꾸지 않고 항상 고정 라벨을 쓴다 — 바로 아래 중분류 칩 목록에 이미 선택
  상태가 강조돼 있어, 탭 라벨까지 바뀌면 같은 값이 두 곳에 중복 노출돼 오히려
  혼란스럽기 때문이다(바깥의, 닫혀 있을 때 상시 노출되는 탭은 기존처럼 라벨을
  바꾼다 — 닫힌 상태에서 현재 선택을 한눈에 보여주는 역할은 그대로 유지).
- 스팟픽은 배경이 지도라 시트가 화면 전체를 덮으면 지도/목록 패널을 볼 수 없다 —
  "동적 데이터 연동"이 실제로 체감되도록, 부모(MapExplorer)가 이미 갖고 있는
  필터링된 `visibleItems`를 그대로 props로 내려받아 시트 안(중분류 칩 바로 아래)에
  기존 `ItemListPanel`로 그린다(새 조회 로직 없음, 제5장 제4조).
- 레이아웃: 제목/대분류 탭/중분류 칩 영역을 `shrink-0`으로 스크롤 밖에 고정하고,
  데이터 목록 영역만 `flex-1 overflow-y-auto`로 스크롤되게 해 목록이 길어져도 상단
  선택 영역이 밀리거나 시트 밖으로 잘리지 않는다.

  파일을 만들지 않고 tsc/build 통과와 코드 리뷰로 검증했다. 정직하게 기록한다:
  향후 이 컴포넌트에 회귀 테스트가 필요하다고 판단되면 별도로 제안한다.
- 스팟픽 시트 재구성 과정에서 기존 테스트 2건(`spot-category-filter.test.tsx`의
  "선택 시 자동 닫힘" 테스트, `map-explorer.test.tsx`의 단일 선택 토글 테스트)이
  옛 동작(자동 닫힘)을 전제로 하고 있어 새 동작에 맞게 다시 작성했다 — 두 파일 모두
  새 `data-testid="spot-category-tabs"`(닫혀 있을 때 상시 노출되는 바깥 탭 전용)를
  추가해, 시트가 열려 있는 동안 같은 대분류 라벨이 두 곳(바깥 탭 + 시트 안 고정 탭)에
  동시에 나타나도 테스트가 정확히 어느 쪽을 보는지 모호하지 않게 했다.
