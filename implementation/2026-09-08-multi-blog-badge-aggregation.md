분석 대상에서 제외. 워닝 판정 기준: 탭 제목에 워닝 아이콘이 부착돼 있거나
제목/본문 내에서 필수 지역 키워드를 찾지 못한 블로그."

## 구현 일시
2026-09-08

## 변경 전 구조
`src/lib/admin/use-spot-curation-form.ts`는 활성 탭(`activeTab`)의 블로그
링크 하나만 지연 로딩(탭을 클릭해야 본문을 가져옴)했고, 뱃지 자동 체크도
그 활성 탭의 본문 텍스트 하나만 보고 판단했다 — 지시문이 지적한 "블로그
1의 키워드만 참고하는 구조"가 바로 이것이다.

## 변경 사항
1. **3개 블로그 본문 즉시 로딩**: 검색 결과(`blogItems`)가 도착하면 탭을
   클릭하지 않아도 3개 링크 전부의 본문을 한꺼번에 가져오도록 바꿨다(기존
   "활성 탭만 지연 로딩"에서 "검색 결과 도착 시 전체 즉시 로딩"으로). 자동
   체크가 3개 블로그를 모두 참고하려면 그 본문이 미리 준비돼 있어야 하기
   때문이다. 캐시 키(`bodyByLink`)와 중복 요청 방지 로직은 그대로 재사용해
   이미 시도한 링크는 다시 요청하지 않는다.
2. **워닝 판정 로직 공유화**: 기존에 활성 탭 하나에만 인라인으로 있던
   "지역 키워드 불일치" 판정을 `hasRegionMismatch(title, bodyText,
   regionKeywords)` 함수로 뽑아내, 활성 탭 경고 아이콘(`hasRegionMismatchWarning`)
   과 멀티 블로그 자동 체크 양쪽이 정확히 같은 기준을 쓰도록 통일했다
   (지시문의 "워닝 판정 기준"과 실제 아이콘 표시 기준이 어긋나지 않게 함).
3. **멀티 블로그 종합 자동 체크**: 신규 등록(기존 큐레이션 없음)이고 3개
   블로그 본문 fetch가 모두 정착(성공/실패 무관)된 뒤, 워닝 걸리지 않은
   블로그들의 본문에서만 `matchBadgeKeysFromText`로 뽑은 뱃지 키를 전부
   합집합으로 모아 한 번만 체크한다. 딱 한 번만 실행하는 안전장치
   (`hasAutoCheckedBadges`)는 기존 단일 탭 버전 그대로 유지해, 탭 전환 등
   으로 재실행돼 관리자가 수동으로 해제한 뱃지를 되살리지 않는다.
4. **회귀 방지 가드**: 3개 블로그 전부 크롤링 실패(네이버 블로그가
   아니거나 실패)라 본문을 하나도 못 얻은 경우, 예전처럼 아무것도 건드리지
   않고 그대로 둔다(빈 Set으로 확정 지어 이미 수동 체크한 뱃지를 지워버리는
   사고 방지 — 실제로 이 가드가 없으면 기존 테스트 하나가 이 경쟁 상태로
   깨지는 것을 확인했다).

## 검증
- `blog-curation-modal.test.tsx`에 신규 테스트 추가: 블로그 1(지역명 포함,
  정상)이 '주차 완비'를, 블로그 3(제목에 지역명 포함, 정상)이 '예약 필수'를
  기여하고, 블로그 2(제목/본문 어디에도 지역명 없어 워닝)는 '유모차
  가능'/'수유실 있음' 키워드를 담고 있음에도 집계에서 완전히 제외됨을
  확인.
- 기존 "본문에서 매칭된 키워드 자동 체크" 테스트는 본문에 지역명이 없어
  새 워닝 필터링 로직에 의해 제외되도록 바뀌었던 것을 확인하고, 그
  테스트의 목적(기본 자동 체크 동작 검증)을 그대로 유지하기 위해 픽스처
  본문에 지역명을 포함시켜 갱신했다(동작 회귀가 아니라 새로 요구된
  워닝 필터링이 의도대로 작동한 결과).
- `npx tsc --noEmit` / `npm run test`(1297건) / `npm run build` 전체 통과.

## 특이 사항
- 3개 블로그를 전부 즉시 크롤링하게 되면서 관리자가 탭을 클릭하지 않는
  블로그도 크롤링 API 호출이 발생한다(기존엔 탭을 눌러야만 호출). 지시문이
  명시적으로 "블로그 1,2,3 전체를 종합"하라고 요구해 이 비용 증가는
  요구사항의 직접적인 결과다 — 별도로 승인 없이 범위를 임의로 좁히지
  않았다.
