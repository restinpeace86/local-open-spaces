# 스팟픽 대분류 바텀시트가 '주변 목록 보기' 시트에 가려지는 CSS 스택 컨텍스트 버그 수정

## 구현 대상
사용자가 이전 답변(AI 추천 위치 조정)을 정정하며 재지적: "아니 주변 692건 목록
보기... 이렇게 뜨고 있는데? 이건 AI 추천이 아니고 주변목록이 현재 위치 기준으로
default로 뜨게 되어있는건가? 이것도 하단에서 올라오는 바텀시트로 되어있는데 이거랑
다르게 대분류들도 누르면 또다른 바텀시트가 생기면서 겹쳐.."

## 구현 일시
2026-09-05

## 조사 — 실측으로 확인한 진짜 원인(CSS 스택 컨텍스트)
사용자 지적대로 "주변 N건 목록 보기"는 AI 추천과 무관하다 — `map-explorer.tsx`의
모바일 바텀시트(`h-[112px]` 접힌 상태, `h-[70vh]` 펼친 상태)로, 현재 위치/반경 기준
조회 결과 개수를 상시 보여주는 **항상 렌더링되는 바(자동으로 "뜨는" 것이 아니라
원래 계속 화면에 있는 UI)**다. 문제는 이 바 자체가 아니라, 대분류 탭을 눌렀을 때
열리는 `SpotCategoryFilter`의 바텀시트가 이 바에 가려지는 것이었다.

DOM/CSS 구조를 직접 추적해 원인을 확정했다:
- 모바일에서 `SpotCategoryFilter`는 `map-explorer.tsx`의
  `<div className="md:hidden absolute top-3 ... z-10">`(플로팅 헤더) 안에 중첩
  렌더링된다.
- `position: absolute` + 명시적 `z-index`는 CSS 스택 컨텍스트(stacking context)를
  새로 만든다 — 그 안에 있는 `SpotCategoryFilter`의 바텀시트(`fixed inset-0 z-50`)는
  **그 스택 컨텍스트 안에서만** z-50이지, 문서 전체 기준 z-50이 아니다.
- "주변 N건 목록 보기" 바텀시트는 이 헤더의 형제(DOM상 나중에 위치, 스택 컨텍스트에
  갇혀 있지 않음)로, 마찬가지로 `z-10`이다.
- 두 요소가 최종적으로 비교되는 지점(바깥 스택 컨텍스트)에서는 둘 다 `z-10`로
  동률이라 DOM 순서(나중에 나오는 쪽이 위)로 승부가 갈린다 — "주변 목록 보기"
  바텀시트가 DOM상 더 나중이라 대분류 시트 위로 올라와 버렸다.
- 이는 추측이 아니라 CSS 스펙대로 항상 재현되는 문제이며, 이 프로젝트의 다른
  모달들(`location-onboarding-modal.tsx`, `migrate-to-event-modal.tsx`)도 이미 같은
  이유로 `createPortal`을 써서 우회하고 있었다 — 이번에 처음 발견된 패턴이 아니라
  기존에 검증된 해결책을 아직 적용하지 않은 컴포넌트가 하나 더 있었던 것이다.

## 변경 사항
- `src/components/map/spot-category-filter.tsx`: 대분류 바텀시트(`data-testid=
  "spot-category-sheet"`)를 `createPortal`로 `document.body` 바로 아래에 직접
  렌더링하도록 변경 — 어떤 조상이 스택 컨텍스트를 만들어도 전역 `z-50`이 실제로
  적용된다. 시트의 마크업/로직 자체는 변경 없음(렌더링 위치만 이동).

## 검증
- **버그를 그대로 재현하는 회귀 테스트 추가**: `position: absolute` + `z-index: 10`인
  가짜 조상 안에 컴포넌트를 렌더링한 뒤, 열린 시트가 그 조상의 자손이 아니라
  `document.body`의 직계 자식인지 확인한다(수정 전 코드로는 이 테스트가 실패했을
  것 — 포탈 적용 후 통과 확인).
- `npx tsc --noEmit` 통과.
- `npm run test`: 108개 파일 / 1134개 테스트(기존 1133개 + 신규 1개) 전체 통과 —
  기존 테스트들은 Testing Library가 기본적으로 `document.body` 전체를 대상으로
  쿼리하므로 포탈로 옮겨도 그대로 통과했다(별도 수정 불필요).
- `npm run build` 통과.

## 특이 사항
- **직전 작업(AI 추천 위치 조정)은 이 버그의 직접적인 원인이 아니었다** — 사용자가
  정확히 정정해준 대로, "주변 목록 보기"는 AI 추천과 무관하게 항상 떠 있는 UI이고,
  실제 문제는 대분류 바텀시트의 CSS 스택 컨텍스트였다. 다만 AI 추천 위치 조정 자체는
  (첫 진입 시 오탭 방지라는) 별개의 개선으로 유효하게 남는다.
- **데스크톱은 원래도 영향이 없었다** — 데스크톱의 `SpotCategoryFilter`는 `<aside>`
  (일반 블록, `position`/`z-index` 없음) 안에 있어 스택 컨텍스트를 만들지 않는다.
  이번 버그는 모바일 레이아웃에서만 재현됐다.
- **AiRecommendSheet/DetailModal/MarkerGroupModal은 이미 안전하다** — 이들은
  `map-explorer.tsx`의 최상위 반환문에 형제로 나란히 렌더링돼(스택 컨텍스트를 만드는
  조상에 중첩되지 않음) 애초에 이 문제의 영향을 받지 않는다 — 실제 DOM 구조를 직접
  확인해 추측 없이 확정했다.
