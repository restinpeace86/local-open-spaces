# [어드민 예약 관리 화면 상단 요약 카운트 및 대기(PENDING) 뱃지 강조 폴리싱]

## 요구사항
1. 상단 요약 카드(전체/대기/확정/취소 건수), 대기는 강조 색상.
2. 테이블에서 PENDING 행을 시각적으로 눈에 띄게 강조.
3. 검증 후 커밋/푸시.

## 구현 일시
2026-08-29

## 1. API 확장 (`src/app/api/reservations/route.ts`)

요약 카드는 "전체 예약 현황"(페이지네이션과 무관하게 테이블 전체 기준)이어야 해서,
`GET` 핸들러에 상태별 카운트 3개 쿼리를 추가했다. 전체 행 데이터를 내려받아
애플리케이션에서 세는 대신, `select('id', { count: 'exact', head: true }).eq('status',
X)`(행 데이터 없이 카운트만) 쿼리를 상태별로 병렬 실행한다 — 신청 건수가 늘어나도 비용이
일정하고(인덱스만 스캔), 기존 목록 조회 쿼리와 `Promise.all`로 묶어 왕복 횟수를 늘리지
않는다. 응답에 `statusCounts: { PENDING, CONFIRMED, CANCELLED }`를 추가했다.

## 2. 어드민 뷰 (`src/app/admin/reservations/page.tsx`)

### 상단 요약 카드
`MetricCard` 컴포넌트를 신설해 4개 카드(전체/🔴 신규 대기/확정 완료/취소)를 그리드로
배치했다. "신규 대기"만 `emphasize` 옵션으로 진한 주황 배경 + 흰 글자를 써 나머지
카드(흰 배경)와 확실히 구분되게 했다(요구사항: "눈에 띄는 강조 색상"). 데이터가 아직
없을 때는 숫자 대신 펄스 애니메이션 스켈레톤을 보여준다.

상태 변경(확정/취소) 시 목록을 통째로 다시 불러오지 않고, 방금 바뀐 행의 이전 상태를
기준으로 요약 카드 숫자만 로컬로 즉시 갱신한다(체감 속도 유지 — 기존 PATCH 흐름과 동일한
설계 원칙).

### 테이블 PENDING 행 강조
기존에는 짝수/홀수 행 줄무늬(zebra)만 있었는데, PENDING 행은 그 규칙보다 우선해
`bg-amber-50` 배경 + `border-l-4 border-amber-400`(왼쪽 강조선)을 적용해 스캔 한 번에
"전화 조율이 필요한 건"을 찾을 수 있게 했다. 상태 뱃지도 PENDING만 옅은 파스텔
(`bg-amber-50 text-amber-700`)에서 채워진 진한 색(`bg-amber-500 text-white`)으로 바꿔
확정(연한 초록)/취소(연한 회색)와 명확히 대비되게 했다.

`statusCounts: {"PENDING":1,"CONFIRMED":0,"CANCELLED":0}`가 정상적으로 함께 내려오는
것을 확인. 검증 후 테스트 데이터는 정리 삭제했다.

## 특이 사항
- 상태별 카운트는 현재 페이지의 필터와 무관하게 항상 테이블 전체 기준이다 — 지시서가
  "전체 예약 현황"을 요구했고, 상태별 목록 필터(예: "대기중만 보기") 자체는 이번
  지시서에 없어 구현하지 않았다(제7장 제4조 미래 기능 임의 구현 금지, 필요시 별도 지시로
  진행 가능).
