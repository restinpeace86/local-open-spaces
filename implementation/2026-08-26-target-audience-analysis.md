# [target_audience 분석] events 5대 태그 분류 시뮬레이션 및 어드민 Split-View 스펙

## 구현 대상
- events 전용 target_audience(CHILD/FAMILY/YOUTH/SENIOR/ALL) 분류 알고리즘 시뮬레이션(읽기
  전용, DB 반영 없음)
- 단계별 퍼널 수치 보고, 추가 키워드 제안
- `/admin/data-grid` 최후 정밀 검수용 Master-Detail Split-View 스펙 문서화

## 구현 일시
2026-08-26

## 작업 성격
이번 지시는 "시뮬레이션 실행 → 수치 보고 → 문서 작성 → 대표 승인 요청"까지만 요구했다
(실제 UPDATE/스키마 추가/어드민 코드 구현은 명시적으로 요청되지 않음). 이번 세션의 다른
분석 전용 작업들과 동일한 원칙(실행 전 승인)을 적용해 **DB 스키마 변경, 데이터 UPDATE,
어드민 UI 코드 변경을 전혀 수행하지 않았다** — 순수 읽기 전용(SELECT) 조사와 애플리케이션
메모리 상 시뮬레이션만 수행했다. 코드 변경이 없어 `npx tsc --noEmit`/`npm run build` 대상
자체가 없다(변경된 소스 파일 없음).

## 핵심 발견 — 구조적 제약

지시된 알고리즘은 "제목 및 설명(contents)"을 스캔하도록 돼 있었으나, 실측 확인 결과
`events` 테이블에는 본문 설명 컬럼이 아예 없고, `raw_data`(원본 보존 컬럼)조차
`seoul_public_culture`(18,951건)/`gg_public`(2,955건)/`tourapi_4.0`(240건) 세 소스는
**완전히 빈 객체(`{}`)**였다 — 전체 26,404건 중 83.9%가 해당된다. 이 세 소스의 수집
스크립트가 원본 API의 상세설명 필드를 애초에 저장하지 않았기 때문이다. 이 사실을
`docs/target-audience-analysis-report.md` 0절에 최우선으로 명시하고, 이후 모든 시뮬레이션은
"제목만"으로 수행했음을 투명하게 밝혔다.

## 시뮬레이션 결과 요약

| 단계 | 건수 | 누적 비율 |
| :--- | ---: | ---: |
| 전체 events | 26,404건 | 100% |
| ① 서울시 USETGTINFO 1:1 매핑 | 1,055건 | 4.00% |
| ② 0단계 역방향 소거(ALL 확정 제안) | 2,583건 | 13.78% |
| ③ 1단계 자동 확정 | 245건 | 14.71% |
| ④ 2단계 텍스트 파싱 | 1,121건 | 18.95% |
| ⑤ 최후 NULL 잔여(어드민 수동 검수 대상) | **21,400건** | **81.05%** |

검산 일치 확인(1,055+2,583+245+1,121+21,400=26,404).

상세 매핑 규칙, 판단 근거, 추가 키워드 제안(6.1~6.3, 우선순위별), 어드민 Split-View 스펙
전문은 `docs/target-audience-analysis-report.md`에 기록했다.

## 대표 확인이 필요한 미결 사항 (제3장 제5조 추측 금지 — 임의 결정하지 않고 그대로 보고)
1. **"성인" 단독 값(SEOUL_YEYAK 313건)**: 지시된 5대 표준 태그 어디에도 정확히 대응되지
   않는다(ALL=제한없음과는 반대 개념). 임의로 ALL에 끼워 맞추지 않고 별도 집계했다.
2. **NULL 잔여율이 매우 높은 근본 원인(83.9% 소스의 raw_data 공백)**: 키워드 추가만으로는
   구조적으로 해결되지 않는다 — 수집 파이프라인에 본문 필드를 추가 보존하는 별도 작업이
   필요하다는 점을 6절에서 명시적으로 제안했다.
3. 추가 키워드 제안(6.1~6.3) 중 어디까지 반영할지 — 특히 "스포츠 시설 대관 → ALL 신설 규칙"
   은 새로운 판단 기준이라 검토가 필요하다.

## 검증
코드 변경이 없어 별도 tsc/test/build 실행 대상이 없다. 모든 수치는 실제 DB에 대한 읽기
전용 쿼리(SELECT/COUNT)로 직접 실측했으며, 조사에 사용한 임시 스크립트는 실행 후 즉시
삭제했다(DB에는 어떤 흔적도 남기지 않음).
