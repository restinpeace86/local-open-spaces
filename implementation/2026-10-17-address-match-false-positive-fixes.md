# 네이버 플레이스 주소 매칭 — 지번 주소 오탐 3건 발견/수정 (유아숲체험원 재매칭 중)

## 구현 대상
사용자 지시(2026-10-16): "D:\...\reference\naverplace에 네이버플레이스에서
유아숲체험원으로 검색했을때 나온 리스트들 1페이지부터 5페이지까지 넣어놨어..
상호명과 주소를 보고 우리쪽에꺼랑 매칭을 해." 이 작업을 진행하며 결과를
검수하는 과정에서 `address-match.mjs`의 심각한 오탐 버그 3건을 연속으로
발견/수정했다 — 셋 다 "도로명이 없는 지번 주소 비교" 경로의 같은 근본
원인(공유 접두어가 Dice 유사도를 부풀림)에서 비롯됐다.

## 구현 일시

## 참고 목록 매칭 도구 신규 추가

상호명을 `네이버상호명` 컬럼에 추가로 기록한다(사용자 지시 "상호명을
여기에 맞추어" — 우리 쪽 `명칭` 컬럼은 덮어쓰지 않고 참고용으로 병기).

## 발견/수정한 오탐 버그 3건 (전부 `address-match.mjs`)
이 매칭 결과를 검수하며(사용자가 예로 들었던 "불암산공원" 사례부터 전체
목록 육안 검토까지) 순차적으로 발견했다 — 매번 수정 → 테스트 → CSV 초기화 →
전체 재매칭의 순환을 반복했다:

1. **지번 주소의 동(洞) 이름 무시**: 도로명이 없는 지번 주소(예: "노원구
   공릉동 산223-1")는 둘 다 도로명 추출에 실패해 전체 문자열 Dice 유사도로
   대체되는데, "서울특별시 노원구"라는 공유 접두어가 길어 동 이름이 완전히
   달라도(공릉동 vs 상계동) 0.5를 넘었다 — "불암산공원 유아숲체험원"이
   전혀 다른 산인 "수락산 생태 노원골 유아숲체험원"으로 잘못 매칭됨.
   → 동 이름+번지를 도로명과 동일한 방식으로 먼저 추출해 비교하도록 추가.
2. **시/구까지만 있는 희박 주소**: 네이버 쪽 주소가 "서울특별시 강북구"처럼
   구까지만 있고 동/번지가 전혀 없는 경우가 실제로 있었다("북서울꿈의숲
   유아숲체험원" 등 3곳 실측 확인) — 짧은 쪽의 모든 글자가 긴 쪽에 그대로
   포함돼 Dice가 높게 나와 "오패산 유아숲체험"이 완전히 다른 "북서울꿈의숲
   유아숲체험원"으로 잘못 매칭됨. → 한쪽이라도 너무 짧으면(당시 기준 10자)
   비교 자체를 하지 않고 0 반환.
3. **양쪽 다 길어도 공유 접두어로 오탐**: 2번 수정 후 재검증에서, 양쪽 다
   충분히 길어도("오리로 1102-4, 천왕동" / "개봉동 416-102") 같은
   "서울특별시 구로구"로 시작한다는 이유만으로 여전히 0.5를 넘는 사례를
   발견했다 — "개웃개웃 유아숲체험원"이 "잣절 유아숲체험원"으로 잘못
   매칭됨. **근본 원인 자체를 제거**: Dice 비교 전에 선행 시/도+시/군/구
   토큰(최대 2개)을 떼고 그 뒤쪽(동/번지/상세)만 비교하도록 변경(2번의
   길이 체크는 "접두어를 뗀 뒤"로 이동 — 결과적으로 2번도 이 구조에
   자연히 포함됨).

## 최종 검증 — 같은 우려를 산 2건을 직접 재확인
수정 후 재매칭 결과 중 이름이 크게 달라 보이는 2건("매봉산중구 유아숲체험원"
→"금호산 유아숲체험원", "매봉산 유아숲체험원"(용산구 다산로8-12) →
"응봉공원 유아숲체험장")을 네이버에서 직접 재조회해 주소를 대조한 결과,
**둘 다 주소가 정확히 일치하는 진짜 매칭**이었다(매봉산/금호산, 매봉산/응봉은
같은 산·시설의 다른 통칭으로 보인다) — 이름만 보고 오탐으로 예단하지 않고
주소까지 직접 확인해 정확성을 검증했다.

## 최종 실행 결과 (3개 버그 전부 수정 후)
```
1차(실시간 검색, 3초 간격): matched 14 / notFound 316 / rateLimited 0
2차(참고 목록 300건): matched 2 / stillNotFound 314 / skipped 14
최종: 16/330 매칭(4.8%)
```
수정 전(오탐 포함) 136/330(41%) → 수정 후 16/330(4.8%)로 크게 줄었다 —
이는 매칭 로직이 더 정확해진 결과다. 유아숲체험원은 한 산/공원에 여러
진입로가 공공데이터에 개별 등재되는 경우가 많아(이전 구현 기록
`2026-10-16-forest-experience-naver-place-match.md` 참고), 네이버에
독립 등록된 Place가 없는 경우가 실제로 많다 — 낮은 매칭률 자체는 버그가
아니라 이 카테고리 데이터의 진짜 특성이다.

패턴 보유) — 재실행 불필요.
