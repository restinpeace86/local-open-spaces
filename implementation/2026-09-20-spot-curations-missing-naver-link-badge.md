# [스팟 큐레이션 목록 — 네이버 플레이스 미연동 표시]

## 구현 대상
사용자 지시(2026-09-20): "어.. ID가 있어야지만 사용자가 눌렀을때 해당 ID를
기준으로 1주일 이상지났는지 체크해서 지난거에 대하여 다시 데이터를
가져오던가 할텐데" — `naver_place_id` 저장 버그를 고친 직후, 이 컬럼이 왜
필요한지 사용자가 짚어준 지점을 그대로 조사해 실제 영향 범위를 확인했다.

## 조사 결과 — 기존 372건 중 371건이 이 기능의 사각지대였다
`src/lib/admin/spot-curation-refresh.ts`의 `checkAndRefreshSpotCuration()`은
이미 완성돼 있고(2026-09-20 이전 작업, "1주일 온디맨드 재크롤링"), 유저가
스팟/이벤트 상세를 열 때마다 `detail-modal.tsx`가 `/api/spot-curation-refresh`를
fire-and-forget으로 트리거하는 배선도 정상이었다. 하지만 그 함수 첫 줄이
`if (spotError || !spot?.naver_place_id) return;`라 naver_place_id가 없는
스팟은 애초에 체크 자체를 시작하지 못한다. DB를 직접 조회해 실제 영향을
확인했다: 스팟 큐레이션 372건 중 naver_place_id가 연동된 건 (직전 작업에서
고친 저장 버그 이전에 유일하게 수동 백필됐던) 딸부자 닭갈비 1건뿐이었다 —
즉 이 "1주일 재크롤링" 기능은 사실상 371/372건에서 지금까지 한 번도
작동한 적이 없었다.

## 처리 방향 결정
기존 371건을 자동으로 되살릴 방법은 없다(당시 어떤 네이버 URL로 크롤링했는지
기록이 남아있지 않아 추측으로 채울 수 없음, 제3장 제5조 추측 금지). 사용자에게
세 가지 선택지(① 관리자 화면에 "미연동" 표시만 추가 ② 아무것도 안 함 ③ 다른
방법 조사)를 제시했고, **① 관리자 화면에 "미연동" 표시만 추가**로 확정했다 —
관리자가 우선순위를 잡아 해당 스팟들을 하나씩 다시 열어 "⚡ 데이터 가져오기"로
재크롤링하면 그 시점부터 정상적으로 연동된다.

## 변경 사항
`src/components/admin/spot-curations-panel.tsx`: 스팟 목록의 각 행에서, 이미
큐레이션은 있지만(`curationsBySpotId`에 존재) `open_spaces.naver_place_id`가
없는 경우에만 "🔗 네이버 미연동" 뱃지(amber 색상, 기존 "노출중분류 없음" 뱃지와
동일한 스타일)를 "큐레이션됨" 뱃지 옆에 보여준다. 아직 큐레이션 자체가 없는
"미등록" 행에는 표시하지 않는다 — 그 상태는 "연동이 끊긴" 게 아니라 애초에
아무 작업도 안 한 정상적인 초기 상태이기 때문이다.
