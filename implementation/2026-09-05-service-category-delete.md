# 노출 중분류(service_categories) 삭제 기능

## 구현 대상
사용자 지시: "노출 중분류 기존거 삭제도 가능하도록 해줘... 동물 먹이주기 체험농장하고
자연 체험장 분류하기 어렵네" — 시드 데이터로 들어간 "동물 먹이주기 체험농장"/
"흙/자연 체험장"(농장/체험 대분류)처럼 구분이 애매한 노출 중분류를 관리자가 직접
정리(삭제)할 수 있어야 한다는 지적. 지금까지는 생성(POST)만 가능하고 삭제 기능이
없었다.

## 구현 일시
2026-09-05

## 변경 사항
- `src/app/api/admin/service-categories/route.ts`: `DELETE`(쿼리 파라미터 `id`) 추가.
  `open_spaces.service_category_id`/`spot_dedup_groups.service_category_id` 둘 다 이
  테이블을 FK로 참조하는데 `ON DELETE` 절이 없어(기본값 NO ACTION) 참조 중인 행이
  있으면 그냥 DELETE는 실패한다 — 이 사실을 안전장치로 삼되, 삭제 전에 두 테이블에서
  몇 건이 참조 중인지 먼저 조회해 명확한 이유(몇 건, 어느 테이블)와 함께 409로
  거부한다(원인불명 DB 에러 대신). 참조가 0건이면 정상 삭제하고, 사전 확인 이후에도
  경합 등으로 FK 위반이 나면 마지막 안전망으로 문구를 정리해 돌려준다.
- `src/components/admin/category-mapping-panel.tsx`: "🏷️ 노출 중분류 관리" 섹션의 각
  칩에 삭제(✕) 버튼 추가 — 클릭 시 확인창 → DELETE 호출 → 성공 시 목록에서 즉시
  제거, 실패 시(주로 참조 중 409) 에러 문구를 보여주고 목록은 그대로 둔다.

## 특이 사항
- **"동물 먹이주기 체험농장"/"흙/자연 체험장" 두 항목을 실제로 삭제하거나 통합하는
  것은 이번 작업 범위가 아니다** — 어떤 걸 남기고 어떤 걸 지울지는 콘텐츠/분류
  기준에 대한 판단이라 관리자가 직접 결정할 사안이다(제3장 제5조 추측 금지). 이번엔
  그 판단을 실행에 옮길 수 있는 삭제 기능만 만들었다 — 다만 현재 두 항목 모두
  참조 중인 open_spaces 행이 0건(전체 노출 중분류 매핑이 아직 0건)이라, 지금
  삭제하면 바로 지워진다는 점은 참고할 만하다.
