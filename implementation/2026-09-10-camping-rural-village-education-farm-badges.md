# 캠핑장/체험휴양마을/교육농장 전용 뱃지 + 네거티브(주의/제한) 뱃지 신설

## 구현 대상
사용자 지시: "중분류중 캠핑장과 체험휴양마을 교육농장 3개에 대하여 각각
데이터들 속성들을 확인해 보고 어린이 친화로 사용할 뱃지들 리스트 제안 및
작성해줘. 또 반대로 어린이 포함 가족들이 가지 못하는 뱃지들도 제안해줘.
예. 캠핑장의 네거티브 뱃지.. - 백패킹 / 험지 / 노키즈존 등.. 캠핑장의
포지티브 뱃지 - 방방 트램펄린 미끄럼틀 모래놀이 따뜻한 온수 등등"

## 구현 일시
2026-09-10

## 데이터 속성 확인(실측)
세 노출 중분류에 대응하는 원천 소스의 `raw_data`를 직접 조회해 확인했다.
- **GO_CAMPING**(캠핑장 / 피크닉장): `sbrsCl`(부대시설)/`posblFcltyCl`(가능
  시설)/`themaEnvrnCl`(테마환경)/`animalCmgCl`(반려동물) 등 부대시설 관련
  구조화 필드가 스키마상 존재하지만, 실제 샘플 전수 확인 결과 **거의 항상
  빈 문자열**이었다. 다만 `intro`(소개글) 자유 텍스트에는 "반려동물 출입
  금지", "23시 이후 매너타임", "매점에서 장작/음료 판매" 같은 실제 유용한
  정보가 들어있는 경우가 있었다.
- **RURAL_EXPERIENCE_VILLAGE**(휴양마을)/**RURAL_EDUCATION_FARM**(체험
  농장·농원): 원천 데이터가 훨씬 더 단순해(`telno`/`thema`/`locplc`/
  `exprnCn`/`exprnSe` 등) 구조화된 부대시설 필드 자체가 없다.

**결론**: 구조화 필드 기반 자동 판정은 신뢰할 수 없어(제3장 제5조 추측
금지 — 비어있는 필드로 있다/없다를 단정할 수 없음), 기존 키즈카페/식당과
**동일하게 관리자가 블로그 본문을 붙여넣으면 키워드로 1차 자동 체크되는
방식**을 그대로 따랐다(제5장 제4조 기존 구조 우선).

## 변경 사항
`src/lib/admin/curation-badges.ts` — 기존에 "아직 전용 콘텐츠 없음"으로
`GENERIC_BADGE_OPTIONS`(주차/유모차/수유실/기저귀대/예약 6종)만 적용되던
3개 노출 중분류를 전용 config로 승격했다.

### CAMPING_CONFIG ('캠핑장 / 피크닉장')
- 포지티브(이동/편의, 놀이/편의시설, 캠핑 유형): 주차, 유모차 이용 가능한
  평탄한 부지, **온수 샤워**, 놀이터, **트램폴린/방방**, **미끄럼틀**,
  **모래놀이터**, 물놀이장/계곡 인접, 매점, 글램핑/카라반/온돌 사이트
  (텐트보다 어린 자녀 동반에 편한 캠핑 유형).
- 네거티브(주의/제한): **백패킹 전용**, **험지/고지대**, **노키즈존**,
  전기 미사용 사이트, 반려동물 전용 캠핑장, 계곡 급류/안전펜스 없음.

### RURAL_VILLAGE_CONFIG ('휴양마을')
실측 샘플이 대부분 어촌체험마을(갯벌체험류)이라 그 맥락에 맞춰 구성했다.
- 포지티브: 갯벌체험, 동물 먹이주기, 과일·농작물 수확, 우천 대비 실내
  체험장, 체험 장비(장화/장갑) 제공, 체험 후 세척시설, 숙박 가능.
- 네거티브: 갯벌이 깊어 유아 부적합, **밀물시간 위험**(조수 간만 — 갯벌
  체험 특유의 실질적 위험), 성인 위주 중노동 체험, 오지 마을(교통 불편).

### EDUCATION_FARM_CONFIG ('체험농장·농원')
- 포지티브: 동물 체험/승마, 작물 수확 체험, 요리·만들기 체험(장 담그기
  등, 실측 샘플의 `thema` 필드가 실제로 이런 프로그램이었음), 트랙터 등
  농기구 탑승 체험, 우천 대비 실내 체험장, 미취학 아동 맞춤 프로그램,
  안전 관리 인력 상주.
- 네거티브: 농기계 이동 구간 위험, 벌·모기 등 해충, 계단식 지형(유모차
  이동 어려움), 체력 소모 큰 체험(미취학 제한).

### 네거티브(주의/제한) 뱃지 — 신규 개념이지만 구조 변경 없음
`curation_badges`는 단순 키 배열이라 포지티브/네거티브 뱃지를 DB 스키마
차원에서 구분할 필요가 없다 — "주의/제한"이라는 UI 그룹명으로만 구분해
관리자가 위험 요소를 명확히 체크할 수 있게 했다. 기존 블로그 큐레이션
UI(BlogCurationModal 등)는 `getBadgeGroupsForCategory`/`getBadgeOptionsForCategory`
로 그룹/뱃지를 그대로 순회해 렌더링하므로, 이 두 함수에 새 그룹/뱃지가
포함된 것만으로 UI 쪽 추가 변경 없이 자동 반영된다.
