# 파워맘/우수맘 추천픽 노출 기준을 등급→"채택된 글"로 변경

## 구현 대상
`getExpertPosts()`(맘스픽 메인 "파워맘 추천/우수맘 추천" 섹션)가 상급 등급
작성자의 글을 **내용과 무관하게 전부** 노출하던 것을, 관리자가 실제로
"채택"(`is_adopted=true`)한 글만 노출하도록 변경.

## 구현 일시
2026-09-15

## 배경
사용자 지시: "내가 쓴글 빈약한데 파워만돼서 파워맘 추천픽에 노출됐잖아" —
직전 대화에서 이 계정이 이번 달 글 5개로 파워맘까지 자동 승급됐는데(별도
기록 참고), 정작 그 글 자체는 체크리스트 위주의 짧은 내용이었다. 확인해보니
`getExpertPosts()`가 `profiles.grade in ('excellent','power')`인 작성자의
글을 **글 내용 품질과 무관하게** 전부 가져오고 있었다 — 등급(활동량 기반
게이미피케이션)과 추천픽 노출(품질 큐레이션)이 분리되어 있지 않았다.

## 원인
`mom_pick_posts.is_adopted`는 애초에 spec(2.1)에 "관리자가 우수 후기를
수동으로 채택 지정하는 관리자 전용 액션"으로 정의된 필드인데, 정작
`getExpertPosts()`는 이 필드를 조회 조건에 전혀 쓰지 않고 있었다(등급
필터만 적용). 등급은 "이번 달 몇 개 썼는지"라는 순수 활동량 지표라, 활동이
많다고 해서 그 글의 품질이 보장되지 않는다 — 특히 활동 계정이 적은 초기
단계에서는 "혼자라서 등업"되는 경우도 있어(직전 대화 참고) 격차가 더
두드러진다.

## 변경 사항
- `src/lib/community/mom-pick-dashboard.ts`의 `getExpertPosts()`: 기존
  `.in('author_id', expertIds)`에 `.eq('is_adopted', true)`를 추가 — 상급
  등급 작성자의 글 중에서도 관리자가 채택한 것만 가져온다.
- `src/lib/community/mom-pick-dashboard.test.ts` 신규 작성(이 파일 자체가
  기존에 테스트가 전혀 없었음): is_adopted 필터가 걸리는지, 상급 등급
  작성자가 아예 없을 때 채택 조회 자체를 생략하고 빈 결과를 반환하는지
  2개 테스트로 검증.

## 관리자 채택 기준에 대한 논의 (코드 변경은 아님, 대화 기록)
사용자가 "블로그처럼 화려하지 않은 체크리스트 형식인데 무슨 기준으로
채택해야 할지 모르겠다"고 물어, 이 형식(체크리스트+옵션 소감/사진)에 맞는
실질적 채택 기준을 제안했다: ①사진 첨부 여부/장수, ②자유글이 구체적인가
(빈 말 vs 실제 정보), ③체크리스트를 얼마나 성실히 채웠나(선택 항목까지),
④태그·사진·글의 조합이 일관적/구체적인가. 대략 "사진 1장 이상 + 자유글에
구체적 내용 + 체크리스트 절반 이상 응답"을 최소 기준으로 제안했다 — 이는
관리자 운영 가이드일 뿐 코드로 강제하지 않는다(Spec에 없는 자동 판정 로직을
임의로 만들지 않음, 제3장 제5조).

## 검증
`npx tsc --noEmit`, `npm run test`(전체 1691개, 신규 2개 포함),
`npm run build` 모두 통과. 이 계정(하린맘, 799c25c1...)의 기존 5개 글은 전부
`is_adopted=false`(아직 관리자가 채택한 적 없음)라, DB를 추가로 건드리지
않아도 이 코드 변경만으로 자동으로 추천픽에서 사라진다 — 관리자가 실제로
그 중 한 글을 채택해야 다시 노출된다.
