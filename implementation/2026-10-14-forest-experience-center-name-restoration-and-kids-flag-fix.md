# 유아숲체험원 "구_코드" 이름 복원 + is_kids_friendly 버그 수정

## 구현 대상
사용자가 forestforkids(타인 공유 링크) 기반 조사 중 발견: `open_spaces`의
`category_min='유아숲체험원'` 레코드 중 상당수가 `name`에 원본 소스
(스마트서울맵)의 관리코드("강남구_2011-14" 등)를 그대로 쓰고 있었다.
"하나씩 하기 힘든데" → 정규식 추출 + 카카오 로컬 API 교차검증으로 일괄
복원 진행. 추가로 조사 중 `is_kids_friendly`가 전부 `false`로 들어가
있는 별도 버그도 발견해 같이 수정.

## 구현 일시
2026-10-14

## 조사 — 원인
- `source='smart_seoul_map'`(서울시 스마트서울맵 GIS 테마 레이어, 테마
  "서울, 유아숲 체험시설") 원본 자체가 사람이 읽을 이름 필드가 없고
  관리코드(`COT_CONTS_NAME`, 예: "종로구_1809-04")만 제공한다.
- `raw_data.COT_VALUE_01`(라벨상 "주소")에 종종 괄호로 실제 공원/산
  이름이 끼어 있다(예: "종로구 사직동 산 1-10번지 일대 (인왕산공원)") —
  372건 중 291건이 코드명 패턴, 그중 278건이 괄호 추출로 1차 복원 가능.
- `COT_VALUE_01`의 **주소 부분은 신뢰할 수 없음을 실측으로 확인**
  (강남구_1806-09 사례: COT_VALUE_01엔 "수서동"이라고 돼 있지만, 실제
  좌표를 카카오 역지오코딩하면 "일원동"이 나옴 — 원본 소스 자체의
  오기). 단, 괄호 안 지명 힌트는 이 오류와 무관하게 유효함(실측: 같은
  레코드에서 좌표 기반 카카오 검색도 독립적으로 "대모산"으로 일치).
- 카카오 로컬 "키워드 장소 검색"(`geocodeKeyword`, 기존
  `kakao-geocoder.mjs`에 이미 있던 유틸과 동일 엔드포인트, 이번엔
  좌표+반경 파라미터를 추가해 직접 호출)을 좌표 기반으로 돌리면 더
  신뢰도 높은 결과가 나오는 경우도 있었지만(예: "인왕산 유아숲체험원"
  실제 등록 확인), 등록 자체가 안 된 사이트도 많아(예: 백련산 매바위)
  단독으로는 전체를 커버 못함 — 정규식 추출과 상호 보완.
- `is_kids_friendly`는 `category_min='유아숲체험원'`인 374건(서울 372 +
  타지역 2) **전부 `false`**였다 — 원본의 `COT_KW`("#어린이") 태그가
  54건에만 부분적으로 있었는데, 이 필드가 애초에 `is_kids_friendly`
  반영에 전혀 쓰이지 않고 있었던 것으로 확인(태그 유무와 무관하게
  374건 전부 유아 대상 시설이므로 전부 `true`가 맞음).

## 변경 사항 (DB 직접 반영, 코드 변경 없음)
1. **이름 복원 287건**: 우선순위 카카오(좌표 기반 키워드 검색) > 정규식
   (COT_VALUE_01 괄호 추출, 트레일러 단어 "인근/대피소/내/일대" 제거).
   - 정규식 결과 중 "공원명-세부위치설명" 형태(예: "현충근린공원-달마
     배드민턴장")는 대시 뒤쪽(배드민턴장/아파트동/등산로입구 등 과도하게
     구체적인 설명)을 버리고 대시 앞쪽(실제 공원/산 이름)만 사용.
   - 버그 2건 직접 수정: "도봉구_1909-02"(원본 텍스트 자체가 중첩 괄호
     "둘리근린공원(쌍문공원)"라 단순 정규식이 깨짐) → "둘리근린공원
     유아숲체험원". "성북구_1909-003"(원본에 지명 힌트 없음, 단 동일
     좌표의 sibling 2건 및 DB 내 기존 정상 이름 자매 레코드
     "개운산공원 유아숲체험원"과 완전히 일치) → "개운산근린공원
     유아숲체험원"으로 sibling 대조 확정.
2. **`is_kids_friendly = true` 374건 전체 반영**(category_min='유아숲
   체험원', 지역 무관).
3. **8건은 그대로 유지**(추측 금지, 제3장 제5조): 원본에 지명 힌트가
   전혀 없고 카카오 검색도 안 걸린 7건, 그리고 "서초구_1808-05"(원본이
   가리키는 곳이 아파트 단지 내 경관녹지뿐이라 대체할 "공원명" 자체가
   없음) 1건.

## 검증
- 코드 변경 없이 Supabase `open_spaces` 테이블 직접 UPDATE(287건 이름,
  374건 `is_kids_friendly`)만 수행 — `npx tsc --noEmit`/`npm run test`/
  `npm run build` 대상 코드 변경이 없어 이번 작업 범위에선 해당 없음.
- 적용 후 재조회로 직접 확인: `is_kids_friendly` true=374/false=0,
  코드명 패턴으로 남은 건 정확히 8건(의도한 대로).

## 후속 — 좌표/주소 불일치 전수 검증 및 수정(사용자 지시: "위치주소 좌표랑
정확히 확인한거 맞아?")
이름 복원 작업 중 `location`/`address` 컬럼은 손대지 않았는지, 그리고
그 두 값이 서로 실제로 맞는지 의문이 제기돼 전체 371건(address에서
구 이름 추출 가능한 건)을 카카오 역지오코딩(`coord2regioncode`)으로
좌표 기준 실제 행정구역과 `address` 컬럼의 구를 전부 대조했다.
- 369건 일치, **2건 불일치 발견**(이번 이름 복원 작업과 무관한 기존
  데이터 오류 — name/is_kids_friendly 외 다른 컬럼은 건드리지 않았음을
  이 전수조사로 재확인).
- **"상도공원 유아숲체험원"**: `address`="관악구 성현로 57"였지만
  좌표는 실제로 "동작구 상도동"(이름과도 일치). `raw_data.
  COT_ADDR_FULL_OLD`="동작구 상도동 531-15"를 카카오로 직접 지오코딩
  하면 저장된 좌표와 7m 차이(거의 동일 지점) — **좌표가 맞고 address가
  틀렸던 것**으로 확정, `address`를 "서울특별시 동작구 상도동 531-15"
  로 수정.
- **"북한산도시자연공원 유아숲체험원"**(솔샘로25길 121-50, 괄호 없는
  쪽 레코드만): 저장된 `address`를 구 없이 도로명만으로 카카오에 다시
  질의하면 "서울 성북구 솔샘로25길 121-50"(건물명: "북한산 자연학습장"
  — 이 시설과 정확히 일치)로 나오고, 강북구로 바꿔 질의하면 검색결과
  없음 — **address가 맞고 좌표가 ~55m 밀려 강북구 경계를 넘어간 것**
  으로 확정, `location`을 올바른 지오코딩 좌표(127.006883122195,
  37.6209569764859)로 수정.
- 수정 후 재검증: 371건 전체 좌표↔주소 불일치 0건.

## 특이 사항
- 이 작업은 **코드 스크립트가 아니라 일회성 조사+적용**이다(어린이도서관
  4쌍 병합 선례와 동일한 성격) — 재사용 가능한 스크립트로 남기지
  않았다. 같은 `source='smart_seoul_map'`의 다른 테마(예: 다른 공원
  시설 유형)에도 동일한 "구_코드" 문제가 있을 수 있어 필요하면 같은
  방법론(카카오 좌표검색 우선 + 정규식 폴백 + sibling 주소 대조)을
  재적용할 수 있다.
- `COT_IMG_MAIN_URL`(131건)/`COT_TEL_NO`(52건)/`COT_ADDR_FULL_NEW`
  (158건) 등 추가로 쓸 수 있는 메타데이터가 raw_data에 더 있음을
  확인했으나, 이번 범위(이름 복원 + 어린이 플래그)엔 포함하지 않았다 —
  별도 지시 시 진행.
