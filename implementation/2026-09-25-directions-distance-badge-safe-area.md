# 인앱 길찾기 실제 경로거리 배지가 화면 하단에서 가려지는 문제 수정

## 구현 대상
사용자 지시(2026-09-25): "그럼 지도 들어가는 깊이에 따라 300건 미만이 될때
클러스터 자동풀리는거야?"(질의응답만, 변경 없음)에 이어 "그리고 우리가
길찾기 눌러서 지도들어가서 길찾으면 실제 길찾은거 대로 거리 다시 구할수
있어? ... 실제 길찾기 경로에 대한 거리.." → (기능이 이미 있다고 답변 후)
"아니 실제 경로거리는 보여주는데 그 경로거리가 몇km인지에 대하여 안보여지고
있는데?" (버그 제보)

## 조사
`MapPreviewModal`(`src/components/map/map-preview-modal.tsx`)의 "🧭 현재
위치에서 길찾기" 버튼은 이미 카카오모빌리티 실제 자동차 길찾기 API
(`/api/nearby/directions`)를 호출해 실거리/소요시간을 구하고 있었다(2026-09-03
구현). 실측(Playwright, 운영 서버 대상, 모바일 뷰포트+mock geolocation)으로
직접 재현해보니 `routeSummary`는 정확히 계산되고("🚗 826m · 약 3분") DOM에도
실제로 존재했다 — 데이터/계산 로직 자체는 정상. 문제는 배지의 위치였다:
이 배지가 `absolute bottom-3`(화면 맨 아래에서 12px)로, `fixed inset-0`
전체화면 모달 안에 있었다. 스크린샷으로 확인한 결과 배지가 화면 맨 아래
가장자리에 거의 딱 붙어 있었다 — 실제 모바일 기기의 하단 제스처바/브라우저
주소창 툴바가 그 몇 픽셀을 가릴 수 있는 위치다. 이 프로젝트는 이미 같은
문제를 겪은 다른 고정-하단 UI(`bottom-tabs.tsx`, `add-booking-fab.tsx`)에서
`env(safe-area-inset-bottom)`으로 처리해 온 전례가 있는데, 이 배지에는 그
처리가 빠져 있었다.

## 변경 사항
`src/components/map/map-preview-modal.tsx`: 길찾기 액션 컨테이너의
`bottom-3`를 `bottom-[calc(env(safe-area-inset-bottom)+0.75rem)]`로 변경 —
안전 영역이 없는 기기에서는 기존과 동일한 12px, 있는 기기에서는 그만큼 더
띄워 항상 화면 안에 들어오게 한다. 버튼/로딩 텍스트/거리·소요시간 배지 세
상태 모두 같은 부모 div를 공유해 한 번의 수정으로 전부 적용된다.

## 검증
- `npx tsc --noEmit` / `npm run test`(202개 파일 2,328개, 기존
  `map-preview-modal.test.tsx` 5건 그대로 통과 — className을 직접 검증하는
  테스트가 없어 별도 회귀 테스트를 추가하지 않음, CSS 전용 변경) /
  `npm run build` 모두 통과.
- 실측(운영 서버, Playwright, iPhone 13 뷰포트 + mock geolocation): 실제
  스팟 상세 → 길찾기 → 카카오모빌리티 경로 조회까지 재현, `routeSummary`가
  정확히 계산되고 배지 텍스트("🚗 826m · 약 3분")가 DOM에 존재함을 확인 —
  기능 자체는 이미 정상 동작 중이었고, 이번 수정은 순수 배치(포지셔닝) 문제.

## 특이 사항
- Playwright의 헤드리스 뷰포트는 고정 크기라 실제 모바일 브라우저의 동적
  주소창/제스처바 노출 범위를 재현하지 못한다 — 그래서 이 원인을 스크린샷
  (배지가 화면 맨 아래에 거의 붙어 있음)과 이 프로젝트의 기존 안전영역
  처리 전례로 추론했다. 배포 후 실제 사용자 기기에서 배지가 잘 보이는지
  최종 확인이 필요하면 재보고 요청.
