# events 상세팝업 표준 중분류 수동 선택 드롭다운을 승인 15종으로 제한 (Step 129)

## 구현 일시
2026-09-12

## 배경 (사용자 지시 원문)
관리자의 실제 매일 워킹프로세스 설명:
> "매일 재수집통하여 오늘 등록건에 대하여 EVENTS탭에 가서 리스트 확인해.. 하나씩
> 눌러서 들어가면 상세팝업뜨는데 여기서 표준 중분류... 선택하고 타겟연령
> 선택가능해.. 다만 내용만보고 타겟연령 잘모르겠으면 블로그 큐레이션 열어서
> 블로그 확인하고.. 스팟연결... 하고 스팟연결된 곳에 대하여 노출중분류가
> 없으면.. 노출중분류에 해당 스팟지정해줘.. 이게 기본적인 한 호흡이야...
> 여기에대하여 일단 상세팝업에서 표준 중분류 수동선택하여 저장하는 부분엔
> 우리가 사용하기로 한 중분류들만 나왔으면 해.."

Step 128에서 확정한 "events는 문화/축제·자연/체험·키즈/육아 대분류의 15종만
쓴다"는 정책을 이번엔 **관리자가 상세팝업에서 직접 고르는 드롭다운**에도
반영한다 — Step 128은 자동 분류(배치/키워드 규칙)만 막았고, 사람이 손으로
고르는 이 드롭다운은 여전히 DB에 실제 존재하는 모든 category_min 값(강의실/
테니스장/기타 등 SEOUL_YEYAK 전용 값 포함)을 그대로 보여주고 있었다.

## 변경 사항
- `src/lib/admin/category-min-groups.ts`: `EVENTS_ALLOWED_CATEGORY_MINS` 신규
  export — 새 목록을 하드코딩하지 않고 이미 있는 `EVENTS_GROUPS_STATIC`에서
  "문화/축제"·"자연/체험"·"키즈/육아" 3개 그룹의 minors를 그대로 뽑아 합친다
  (제5장 제4조/제6조 — 같은 15종 목록을 두 곳에 따로 유지하면 나중에 어긋날
  위험이 있어, Step 126~128에서 이미 이 3개 그룹을 정확히 15종으로 맞춰둔 것을
  재사용). 실제로 뽑아보면 문화/축제(6) + 자연/체험(7) + 키즈/육아(2) = 15종,
  사용자가 나열한 목록과 정확히 일치함을 확인했다.
- `src/components/admin/raw-data-modal.tsx`의 `CategoryMinEditor`: `table ===
  'events'`일 때만 드롭다운 옵션을 `EVENTS_ALLOWED_CATEGORY_MINS`로 좁힌다
  (open_spaces는 이 정책과 무관해 기존처럼 전달받은 `categoryMinOptions`
  그대로 사용). **현재 값이 15종 밖이어도(예: SEOUL_YEYAK 행의 "강의실") 그
  값 자체는 옵션에서 지우지 않고 그대로 보여준다** — seoul_public_reservation은
  이미 원천 대/중분류를 그대로 쓰는 별도 정책(Decision 017/024, RAW 소스)이라
  이 드롭다운으로 손대는 대상이 아니고, 있는 값을 안 보이게만 하는 것도 임의
  변경이라 판단해 남겨뒀다(제3장 제5조 추측 금지) — 다만 15종 밖의 "새" 값을
  고를 수는 없다.

## 검증
- `npx tsc --noEmit`: 통과.
- `npm run test -- --run`: 135 files / 1588 tests 전체 통과. 신규 3개
  (`raw-data-modal.test.tsx`):
  1. events 탭: 어떤 categoryMinOptions를 넘겨도 승인된 15종만 옵션으로 보이고,
     승인 밖 값(강의실/테니스장/기타)은 옵션에 없음.
  2. events 탭: 현재 값이 15종 밖이어도(강의실) 그 값 자체는 옵션에 남아있음.
  3. open_spaces 탭: 이 정책과 무관하게 전달받은 categoryMinOptions 그대로 노출.
- `npm run build`: 성공(라우트 목록 변화 없음).

## 특이 사항
- 이 변경은 "새로 선택할 수 있는 값"만 제한한다 — 이미 DB에 15종 밖 값으로 들어가
  있는 SEOUL_YEYAK 행들(강의실/테니스장 등, Step 118/122/126에서 의도적으로
  공공청사·행정/체육시설로 분류해둔 것들)은 전혀 영향받지 않는다. 그 값들은 여전히
  "현재 값"으로 정상 표시되고, 관리자가 굳이 이 드롭다운으로 바꾸려 하지 않는 한
  그대로 유지된다.
