# [대분류/중분류 계층적 탐색 UI] Admin 표준 중분류 필터 개편

## 요구사항
1. `/admin/data-grid`의 표준 중분류(category_min) 필터가 50종 내외로 늘어나 flat하게
   펼쳐지면서 지저분해지는 문제 — 대분류 탭 선택 시 그 하위 중분류만 노출되는 계층적
   탐색 UI로 개편.
2. 프론트엔드가 대분류에 속한 중분류 목록을 가져오고, 중분류 선택 시 해당 항목들을
   누락 없이 가져올 수 있는지 백엔드 쿼리 점검.
3. 검증 후 커밋/푸시.

## 구현 일시
2026-08-28

## 1. 대분류 그룹핑 설계

이 어드민 필터 전용 대분류 그룹핑을 새로 정의했다. 홈 화면 이벤트픽의
`category-maj-meta.ts`(7대 대분류)는 재사용하지 않았다 — 공개 화면에 노출할 항목만 추린
부분집합이라(강당/회의실/청년정보 등 관리 전용·시설 대관류 다수를 의도적으로 제외) 어드민
전체 목록에 그대로 쓰면 다수 항목이 어느 그룹에도 속하지 못해 "누락"이 발생한다(제5장
제4조 기존 구조 우선의 예외 — 목적이 다른 기존 구조를 억지로 재사용하지 않았다).

- `src/lib/admin/category-min-groups.ts`(신규):
  - `open_spaces`용 6개 대분류(체육시설/문화시설/자연·공원/키즈·놀이시설/공공청사 대관/기타).
  - `events`용 7개 대분류(체육시설/문화·축제/자연·체험/키즈·육아/배움·교육/공공청사·행정/기타).
  - `buildCategoryMinGroups(liveOptions, staticGroups)`: 실제 살아있는 옵션만 각 그룹에
    남기고, 정적 정의에 없는 값(신규 카테고리 추가나 인코딩 손상 등 예상 밖 값 포함)은
    전부 '기타'로 합쳐 **절대 누락되지 않게** 한다 — 이 파일을 갱신하지 않아도 새
    카테고리가 조용히 사라지지 않는다.
- 단위 테스트(`category-min-groups.test.ts`, 6건): 그룹 배정, 미정의 값 기타 합류, 빈
  그룹 숨김, open_spaces/events 실제 전체 목록 무손실 배정(각각 50/51종 전수 검증).

## 2. UI 구현
- `src/components/admin/data-grid-client.tsx`: `HierarchicalCategoryMinFilter` 컴포넌트
  신규(기존 `CheckboxMultiSelect`는 target_audience 필터용으로 계속 사용) — 대분류 탭을
  누르면 그 아래에 해당 대분류의 중분류 체크박스만 노출된다. **선택된 중분류는 대분류
  탭을 넘나들어도 그대로 유지**된다(어느 탭에서 선택했는지와 무관하게 `pendingCategoryMin`
  하나로 관리). 대분류 탭에 선택된 개수를 작은 뱃지로 표시해, 지금 보이지 않는 다른
  대분류에도 선택된 항목이 있음을 알 수 있게 했다.
- **아코디언 대신 단일 포커스 탭 방식을 택한 이유**: 이 프로젝트는 이미 홈 화면
  `MajorCategoryGrid`를 아코디언으로 시도했다가 "처음(아이콘 그리드 + 공유 칩 목록)
  방식이 더 낫다"는 명확한 사용자 피드백을 받은 전례가 있다(2026-08-27). 바텀시트는
  데스크톱 지향 어드민 도구(넓은 화면, 마우스 조작)와 어울리지 않는 모바일 패턴이라
  채택하지 않았다 — 요구사항의 "검토" 결과다.
- [Admin 필터 체크박스 렌더링 안정성 확보](2026-08-28, 직전 작업)의 `fetchFailed`/
  `onRetry`/하드코딩 폴백 목록 안전장치를 그대로 이어받았다(폴백 목록도 동일하게 대분류로
  묶여 렌더링됨).

## 3. 백엔드 쿼리 점검 (요구사항 2)

별도 신규 API는 만들지 않았다 — "대분류→중분류" 매핑은 프론트엔드 전용 UI 구성 개념일 뿐,
실제 필터링은 기존과 동일하게 `category_min` 값 자체로 이뤄지므로 이미 검증된 다중 선택
+ NULL 쿼리 메커니즘(`applyMultiValueOrNullFilter`, [행사 데이터 수집/정제 파이프라인 및
홈 피드 필터링 개선] 2026-08-27)을 그대로 재사용한다. 실측으로 "같은 대분류 내 여러
중분류 동시 선택" 쿼리가 정상 동작함을 재확인했다:
- open_spaces `테니스장+축구장+농구장` → 1,186건 정상 응답.
- events `캠핑장+산림여가` → 518건 정상 응답.

## 검증
- `npx tsc --noEmit`: clean.
- `npm run test`: 54개 파일 551건 통과(신규 6건 포함).
- `npm run build`: 성공, 라우트 변화 없음.
- 로컬 서버 실측: `/admin/data-grid` 진입 시 대분류 탭 6개(체육시설/문화시설/자연·공원/
  키즈·놀이시설/공공청사 대관/기타)가 정상 렌더링되고, 기본 활성 대분류("체육시설")의
  중분류만(테니스장/골프장/풋살장/축구장/농구장...) 노출됨을 HTML로 직접 확인 — 나머지
  대분류의 중분류는 화면에 없음(요구사항 "지저분해지지 않도록" 충족).

## 특이 사항
- 이번 작업도 프론트엔드 UI 개편(필터 렌더링 방식 변경)일 뿐 백엔드 쿼리 로직/데이터는
  전혀 건드리지 않았다 — 기존에 이미 검증된 다중 선택+NULL 쿼리 메커니즘을 그대로
  재사용했다.
- 직전 작업에서 발견한 DB 부하 이슈(RPC 동시다발 timeout)는 이번 실측 중에도 일부
  재현됐으나(`get_open_spaces_source_type_options` 등), category_min RPC는 재시도로
  정상 응답했다 — 별도 조치 없이 기존 안전장치가 계속 유효함을 확인했다.
