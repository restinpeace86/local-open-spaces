# 글쓰기 전체화면 제목 "첫 글 쓰기" 오표기 수정

## 구현 대상
맘스픽 전체 화면 글쓰기(`isFullScreenComposerOpen`)의 헤더 제목이 항상
"✍️ 첫 글 쓰기"로 고정되어 있던 문제 수정.

## 구현 일시
2026-09-14

## 배경
사용자 지시: "이거 제목이 왜 첫글쓰기야 ? 난 여러번째 글쓰기 중인데.."

## 원인
`mom-pick-view.tsx`의 이 전체화면은 두 경로로 열린다.
1. `not_sprout_yet`(새싹맘 미달성) 유저가 안내 팝업의 "첫 글 쓰러 가기"를
   누른 경우
2. `allowed`(이미 새싹맘 이상) 유저가 평소 "✍️ 글쓰기" 플로팅 버튼을 누른
   경우(`handleWriteClick`의 else 분기)

두 경로 모두 동일한 화면을 열지만 헤더 제목은 "1"번 경로만 염두에 두고
"✍️ 첫 글 쓰기"로 고정되어 있어, 이미 여러 번 글을 쓴 유저에게도 매번
"첫 글 쓰기"라고 표시되는 오류였다.

## 변경 사항
- `src/components/community/mom-pick-view.tsx`: 헤더 제목을 "✍️ 첫 글 쓰기"
  → "✍️ 글쓰기"로 변경(플로팅 버튼의 aria-label "글쓰기"와도 톤을 맞춤).
- `src/components/community/mom-pick-view.test.tsx`: 4곳의 기대값을
  "✍️ 글쓰기"로 갱신.

## 검증
- `npx tsc --noEmit`, `npm run test`(전체 1679개), `npm run build` 모두 통과.

## 특이 사항 — 별도로 확인 중인 이슈
같은 사용자 리포트에 포함된 "사진 올리려고 사진첩 찾아보다가 어느 순간
닫으면 글쓰기가 맨 처음(1단계)으로 돌아가 있다"는 이슈는 이번 커밋에
포함하지 않았다. 코드 리뷰로는 `SurveyReviewComposer`가 리마운트될 경로가
`isFullScreenComposerOpen`이 false→true로 바뀌는 경우뿐이라 원인을 확정할
수 없었고(파일 선택 자체는 별도 상태 변경을 만들지 않음), 유력한 가설은
①모바일 브라우저가 네이티브 사진 선택 UI로 오래 머무는 동안 메모리 회수
목적으로 웹뷰 자체를 재로드하는 OS 차원의 동작(JS로 직접 막을 수 없음),
②이 전체화면 자체가 애초에 뒤로가기/네비게이션 이탈에 대한 보호가 없어서
(이번 세션에서 다룬 얼굴 스티커 모달과 별개로, 더 상위인 전체화면 전환
자체가 원래부터 보호되지 않았음) 실수로 페이지를 벗어났다가 돌아온 경우다.
Playwright로는 네이티브 OS 파일 선택기 자체를 재현할 수 없어 실사용 기기
정보(iOS/Android, 브라우저 종류) 확인 후 재조사 필요.
