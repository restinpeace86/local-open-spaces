# 표준중분류 미지정 → LLM 분류 결과 검토 후 실제 이관(1차, 8개 카테고리)

## 구현 대상
사용자 지시(2026-09-30): "미지정_분류결과.csv 여기있는데이터는 표준중분류가
미지정인 데이터들이야.. 이 중에서 C열의 표준중분류가 체험휴양마을,
교육농장, 놀이방찜질방/스파, 어린이도서관, 공공키즈카페, 전시실,
어린이박물관, 테마파크 이렇게 된 것들에 대하여 각각 우리가 가지고 있는
표준중분류니깐 이에 맞춰서 미지정 -> 각각의 표준중분류로 DB에서 데이터
이관해줘. 다 이관하고나면 CSV파일에서 해당 row들에 대하여 삭제해. 그외에
매칭한 것들은 일단 냅둬."

## 실측 확인
1. 사용자가 이전 세션에서 생성한 `미지정_분류결과.csv`(LLM 1차 분류 결과)를
   직접 검토·일부 수정한 상태였다(원본 1,920행 → 이번 작업 시작 시점
   1,852행으로 68행 감소, CP949로 재저장됨 — Excel에서 직접 편집한 것으로
   보임). 지정된 8개 표준중분류에 해당하는 행을 뽑은 결과 **총 33건**
   (체험휴양마을 10 / 교육농장 11 / 놀이방찜질방·스파 6 / 어린이도서관 1 /
   전시실 1 / 어린이박물관 1 / 공공키즈카페 2 / 테마파크 1).
2. **카테고리 존재 여부 확인 및 사용자 판단(AskUserQuestion)**: '공공키즈
   카페'와 '테마파크'는 open_spaces 표준중분류 체계에 아직 존재하지
   않았다(DB 직접 조회로 0건 확인, `category_rules`에도 미등록 — 공공키즈
   카페는 events 테이블 전용 분류였고 테마파크는 어디에도 없었음). 사용자
   지시는 "각각 우리가 가지고 있는 표준중분류"라고 전제했지만 실측과
   달라, 새 표준중분류를 임의로 만들지 않고(제5장 제3조 임의 판단 금지)
   사용자에게 확인했다 — 결과: **공공키즈카페(2건) → 기존 '키즈카페'로,
   테마파크(1건) → 기존 '관광명소'로 대체 이관** 확정.
3. 33건을 category_min IS NULL 대표 행 2,164건과 이름+주소로 대조했다.
   **32건은 단일 후보로 안전 매칭**됐고, **1건은 모호**했다 —
   "농협경제지주(주) 안성팜랜드"(경기도 안성시 공도읍 대신두길 28)
   주소에 "농협경제지주(주) 안성팜랜드"와 "제이에스 산업개발(주)" 두
   후보가 있어, CSV가 적어낸 이름과 정확히 일치하는 전자만 포함하고
   후자(같은 부지의 다른 사업자로 보임)는 제외했다(제3장 제5조 추측 금지).
4. 노출중분류(service_category_id) 매핑 요청이 이번 지시에 없어 표준중분류
   /category_min_source만 변경하고 노출중분류는 건드리지 않았다(박물관_기타
   배치와 동일한 원칙).

## 특이 사항
사용자가 이미 검토/편집한 CSV를 그대로 입력으로 사용했다(재생성하지
않음) — 원본 LLM 출력과 행 수·일부 분류값이 달라져 있었던 것은 사용자의
사전 수동 검토 결과로 판단하고 그 상태를 신뢰했다. '공공키즈카페'/
'테마파크' 2개 값은 신규 표준중분류 생성 여부가 이번 지시에 명시돼 있지
않아 임의로 새 카테고리를 만들지 않고 먼저 확인했다 — 이 판단이 어긋났을
경우를 대비해 별도 표준중분류로 만들어야 한다면 이번 세션의 기존
패턴(category_rules 등록 + category-min-groups.ts 등 3개 분류체계 파일
갱신)을 따라야 한다.
