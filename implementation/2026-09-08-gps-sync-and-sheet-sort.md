# 실시간 위치 싱크(GPS Sync 팝업) + 바텀시트 GPS 거리순 정렬(10km)

  반경 10km 제한.
- 3. 실시간 위치 싱크(GPS Sync 팝업): "사전에 설정한 동네와 현재 실제 GPS
  위치 간에 유의미한 차이가 감지될 경우.. '현재 위치({동네 이름})로 위치를
  변경할까요?' 팝업.. 수락 시 기본 위치 설정을 GPS 기준으로 업데이트."

## 구현 일시
2026-09-08

## 설계
두 기능 모두 "사용자의 실시간 GPS 좌표"가 필요해 공통 훅으로 뽑았다(제5장
제4조 기존 구조 우선 — 기존 `LocationOnboardingModal`의 `navigator.
geolocation.getCurrentPosition` + `reverseGeocodeAddress` + `extractSigunguName`
패턴을 그대로 재사용).

- `src/hooks/use-live-gps-position.ts`(신규): 마운트 시 1회
  `getCurrentPosition`을 호출해 `{lat, lng} | null`을 반환한다. 사용자가
  명시적으로 요청한 동작이 아닌 백그라운드 조회라 실패/거부 시에도 에러를
  던지지 않고 조용히 null을 유지한다(제5장 제11조).
- `src/hooks/use-gps-sync-check.ts`(신규): 위 훅의 좌표와 현재 설정된
  "동네"(`configuredCenter`) 사이 거리를 `haversineDistanceMeters`(기존
  유틸 재사용)로 계산해, 2km 이상 차이 나면 역지오코딩 후 `{동네 이름}`을
  채운 제안(`suggestion`)을 채운다. **"유의미한 차이"의 구체적 임계값은
  지시문에 명시되지 않아**, 동/읍/면 하나를 넘는 이동만 감지하고 같은
  동네 안 이동에는 반응하지 않는 보수적 기본값(2km)을 채택했다(제3장
  제5조 — 근거 없는 정밀한 숫자 대신 판단 기준을 코드에 명시). 한 세션당
  한 번만 평가하고(재확인 없음), 역지오코딩 실패 시 팝업 자체를 띄우지
  않는다(이름을 추측으로 채우지 않음).
- `src/components/map/gps-sync-modal.tsx`(신규): "현재 위치({동네 이름})로
  위치를 변경할까요?" 팝업 — `LocationOnboardingModal`과 동일한 바텀시트형
  레이아웃 재사용.
- `map-explorer.tsx`: 위 훅/모달을 연결. 수락 시 기존 `handleConfirmLocation`
  (동네 재설정과 동일 로직 — 드래그/재검색 임시 기준점도 함께 초기화)을
  그대로 호출한다.
- 바텀시트 GPS 거리순 정렬: `mobileSheetItems`(새 파생값)를 만들어, 실시간
  GPS 좌표가 있으면 `visibleItems`(기존 지도/데스크톱 목록, effectiveCenter
  기준 5km 그대로 유지)를 GPS 기준 실거리로 재계산 → 10km 초과 제외 → 거리순
  정렬 → `distance_meters`를 GPS 기준 값으로 덮어써 모바일 바텀시트에만
  전달한다. **검색 모드(전국구 서버사이드 텍스트 검색)는 이 재정렬에서
  제외**했다 — 이름으로 콕 짚어 찾는 검색 결과를 GPS 10km로 임의로 잘라내면
  사용자가 찾던 항목이 사라지는 회귀가 되기 때문이다. GPS를 못 가져오면
  (권한 거부 등) 기존 `visibleItems`로 조용히 폴백한다.

## 관련 스킵: 노출 중분류 기준 카테고리 전환 (개선사항3-1 첫 문장)
`todo.md`가 지시한 "대분류/중분류를 다 걷어내고 노출 중분류 기준으로"는
구현하지 않고 스킵(보류) 처리했다. 실측(`select count(*), count(service_category_id)
from open_spaces`) 결과 전체 142,118건 중 `service_category_id`가 채워진
행은 3,982건(2.8%)뿐이다. 지금의 `category_min` 기반 "핵심 중분류" 칩
필터(2026-08-28~29에 명시적으로 확정된 시스템)를 이 값으로 전면 교체하면
전체 스팟의 97.2%가 모든 카테고리 필터에서 사라지는 즉각적이고 심각한
회귀가 된다. 지시문에는 "매핑 안 된 스팟을 어떻게 처리할지"에 대한 언급이
없어, 임의로 폴백 설계를 만들지 않고(제3장 제5조 추측 금지) 스킵했다.
todo.md 본문에 상세 사유와 재개 선행조건(커버리지 확대 또는 폴백 방식을
정한 신규 Decision)을 기록했다. (반경 컷오프 폐지 스킵은 이미 Step 68에서
별도 기록·커밋·알림 완료.)

## 특이 사항
- 데스크톱 좌측 패널(`aside`)은 이번 변경 대상이 아니다 — 지시문이 명시적으로
  "하단 바텀시트 리스트"(모바일 전용 UI)라고 특정했다.
- GPS 좌표를 얻으면(권한 허용 시) 페이지 진입마다 항상 한 번 조용히 조회한다
  — 이전에는 위치 온보딩 버튼을 눌러야만 GPS를 요청했지만, 이번 두 기능
  (동기화 감지 + 바텀시트 정렬) 모두 명시적으로 "실시간/현재 GPS"를
  요구해 불가피하다. 브라우저 권한 프롬프트는 최초 1회만 뜨고 이후에는
  캐시된 권한 상태를 따른다(브라우저 표준 동작).
