# [스팟 큐레이션 — 키즈메뉴 뱃지 수동 해제 유지 버그 수정]

## 구현 대상
사용자 버그 제보(2026-09-19): "스팟 큐레이션에서 키즈메뉴 선택된거 수동 변경
가능하다고 적혀있는데 수동변경 안되던데? 자동체크 이후에?"

## 구현 일시
2026-09-19

## 원인
`handleParseMenu`(⚡ 자동 파싱 버튼)와 `handleCrawlNaverPlace`(⚡ 데이터
가져오기 버튼)는 메뉴에서 키즈메뉴 키워드가 매칭될 때마다 무조건
`setHasKidsMenuBadge(true)`를 호출했다. 관리자가 체크박스를 직접 클릭해
수동으로 해제해도, 이후 메뉴 텍스트를 수정해 다시 파싱하거나(같은 매칭이
여전히 존재) 재크롤링하면 값이 다시 `true`로 되돌아가 수동 해제가
무의미해졌다 — 라벨의 "수동 변경 가능" 문구와 실제 동작이 어긋나는 조용한
버그였다.

jsdom 기반 재현 테스트를 여러 번 시도했으나("자동 파싱 → 체크박스 클릭"
단발 시나리오, 기존 저장된 curation을 열어 해제하는 시나리오 등) 모두
실패했고, "체크 → 수동 해제 → (메뉴를 조금 바꿔서) 재파싱" 시나리오에서만
재현에 성공했다 — 단발 클릭이 아니라 재파싱이 트리거인 게 핵심이었다.

## 코드 변경
`src/components/admin/spot-curations-panel.tsx`:
- `kidsMenuManuallySetRef`(useRef) 추가 — 관리자가 체크박스를 한 번이라도
  직접 조작했는지 기록한다.
- 체크박스 `onChange`에서 이 ref를 `true`로 세팅.
- `handleParseMenu`/`handleCrawlNaverPlace`의 자동 체크 로직에
  `!kidsMenuManuallySetRef.current` 조건을 추가해, 관리자가 한 번이라도
  수동 조작한 뒤에는 재파싱/재크롤링이 값을 되돌리지 않도록 했다.

기존 "OFF→ON 방향으로만 자동 제안" 정책 자체는 그대로 유지했다(매칭이 전혀
없다고 자동으로 뱃지를 끄지는 않음) — 이번 수정은 "관리자의 명시적 판단이
있었다면 그 이후의 모든 자동 로직보다 우선한다"는 원칙만 추가한 것이다.
