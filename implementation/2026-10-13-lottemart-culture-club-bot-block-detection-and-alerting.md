# 롯데마트 문화센터 봇 차단 감지 + Discord 알림 추가

## 구현 대상
사용자 지시(2026-10-13): "현재 문화센터 강좌가.. 롯데마트가 가져오기
실패하는것같은데 봇차단 같은거로 .. 확인하고 대처방안 마련해봐"

## 구현 일시
2026-10-13

## 실측 확인 — 지금 시점엔 봇 차단 증거를 찾지 못했다
- `pipeline_logs`를 확인한 결과 최근 롯데마트 관련 배치(`LOTTEMART_CULTURE_
  CLUB`/`_PING`/`_DETAIL`) 전부 `status: OK`, 에러 없음.
- Windows 작업 스케줄러(`LocalOpenSpaces-LottemartBatch`/
  `-LottemartDetailFetch`)의 "마지막 결과"도 0(정상 종료), 최근 실행도
  문제 없이 끝났다.
- **직접 재현 시도**: 60개 지점 × 3개 대상(target=2/3/4) = 180개 조합을
  실제 사이트에 다시 요청해봤다 — 전부 HTTP 200, 응답시간 50~260ms로
  일정(느려지거나 타임아웃 없음), 캡차/보안문자/차단 관련 문구 전혀
  없음. 그 뒤 전체 범위(60지점×3대상×2학기=360조합 + 페이지네이션)로
  실제 수집 스크립트를 `--dry-run`으로 끝까지 돌려도 1,931건을 정상
  수신하며 끝까지 완료됨(에러 0건).

**결론**: 지금 이 순간 봇 차단이 실제로 발생 중이라는 증거는 없다.

## 하지만 실측으로 발견한 진짜 문제 — 방어 자체가 없었다
롯데마트 스크립트 3개(`lottemart-culture-club.mjs`/`-detail.mjs`/
`-ping.mjs`)를 다른 7개 브랜드(이마트/AK플라자/롯데백화점 등)와
비교해보니, 유독 롯데마트만:
1. **봇 차단 감지 로직이 전혀 없었다** — `<tr>`이 0건이면 사이트
   정책이 바뀌었든 차단됐든 무조건 "진짜 0건"으로 간주해 조용히
   넘어간다. 이 상태로 실제 차단이 발생하면, 멀쩡히 열려있던 강좌들이
   `markFallenOutRowsAsUnavailable`에 의해 전부 "접수불가"로 잘못
   갱신될 수 있다.
2. **메인 수집 루프가 try/catch 밖에 있었다** — `fetchAllForCombo`가
   던지는 에러(네트워크 오류 등)가 `postPipelineLog`/Discord 알림을
   전혀 거치지 않고 CLI 진입점까지 그대로 올라가, 작업 스케줄러가
   리다이렉트하는 로그 파일에만 남았다. 사용자가 그 로그 파일을 직접
   열어보지 않으면 실패 사실 자체를 알 수 없었다.
3. **Discord 알림이 성공/실패 모두 전혀 없었다** — 롯데백화점(2026-
   10-09)에 이미 적용한 "차단 의심되면 사용자가 바로 알 수 있게"
   관례가 롯데마트엔 아예 빠져 있었다.

이 셋이 합쳐지면: 실제로 차단이 발생해도 **아무도 모른 채 데이터만
조용히 망가지는** 구조였다 — 사용자가 "실패하는 것 같다"고 느낀 게
지금 당장의 증거는 아니었지만, 그런 일이 생겨도 알 방법이 없었다는
지적은 정확했다.

## 변경 사항 — `scripts/ingest/lottemart-culture-club.mjs`
1. **봇 차단 감지(실측 기준)**: 180개 조합을 직접 조회해 확인한 "진짜
   0건" 응답의 정확한 모양(공백/탭/줄바꿈만 있는 빈 템플릿, 실측
   27바이트)을 기준으로 `looksLikeSuspiciousEmptyResponse(html, trCount)`
   함수를 추가했다. `<tr>`이 0건인데 응답 내용이 비어있지 않으면(차단/
   공지 페이지가 `<tr>` 없이 내려온 경우) 이상 응답으로 간주해
   `fetchAllForCombo`가 에러를 던진다. 차단 페이지의 구체적인 문구를
   추측하지 않고, 실측으로 확인된 "정상이면 반드시 이래야 한다"만
   기준으로 삼았다(제3장 제5조).
2. **수집 루프를 try/catch로 감쌈**: 실패 시 `postPipelineLog(FAILED)`
   + Discord 알림 후 재throw.
3. **Discord 알림 추가**(다른 브랜드와 동일한 관례): 수집 루프 실패,
   upsert 실패, 최종 성공 — 3곳 모두 알림이 가도록 추가.

## 특이 사항
- 같은 구조적 공백(차단 감지 없음, Discord 알림 없음)이 `lottemart-
  culture-club-detail.mjs`(상세수집)와 `lottemart-culture-club-ping.mjs`
  (상태 핑)에도 그대로 있다 — 이번엔 사용자가 지적한 "강좌 가져오기"에
  가장 직접적인 메인 리스트 수집 스크립트만 고쳤다. 나머지 둘도 같은
  방식으로 보강할지는 별도 확인이 필요해 이번 범위에 포함하지 않았다.
- 지금은 차단이 없다는 걸 실측으로 확인했을 뿐, 사이트 정책이 나중에
  바뀌어 실제로 차단되면 이번에 추가한 로직이 그때 처음으로 작동하게
  된다 — 차단 자체를 미리 막는 게 아니라 "차단되면 바로 알게" 하는
  대처다.
