# 블로그 검색 — 지역명 접미사 제거가 실패하는 경우의 폴백 자동 재검색

## 구현 대상
사용자 지시: "모심갈비가 지역명이 인천광역시 남동구인데 모심갈비에 남동을
붙여서 모심갈비 남동으로 찾으면 안나와.. 모심갈비 남동구는 나오고 ..."

## 구현 일시
2026-09-07

## 원인
지금까지의 스마트 검색 쿼리 규칙은 "노원구"→"노원"처럼 시/군/구 접미사를
떼야 검색 성공률이 높다는 사용자 실측(2026-09-07 초반)을 근거로 **항상**
접미사를 뗐다. 그런데 이번에 사용자가 정반대 사례를 실측으로 제시했다 —
"남동구"는 접미사를 떼면("남동") 오히려 검색이 안 되고, 접미사를 유지해야
("남동구") 검색된다. 즉 **어느 지역명은 접미사를 떼야, 어느 지역명은
접미사를 유지해야 검색이 잘 되는지는 지역마다 다르다** — 미리 정해진
사전이나 규칙 없이는 어느 쪽이 맞는지 알 수 없다(제3장 제5조 추측 금지).

## 변경 사항
접미사를 하나로 고정하는 대신, **1차 쿼리가 실패하면 자동으로 한 번만
폴백 쿼리로 재검색**하도록 바꿨다.
- `src/lib/admin/naver-blog-search.ts`: `buildFallbackBlogQuery(name,
  sigunguName)` 신규 — 1차 쿼리(접미사 제거)와 달리 시/군/구 원본 토큰을
  그대로 유지한 쿼리를 만든다(예: "모심갈비 남동구"). 상호명이 "점"으로
  끝나는 경우(애초에 지역명을 안 씀)나 애초에 접미사가 없던 경우(1차와
  동일)는 폴백을 만들지 않는다(`null`).
- `src/lib/admin/use-spot-curation-form.ts`: `runSearch`가 이제
  `{ hasNoResults }`를 반환한다(기존 호출부는 반환값을 그냥 무시하면 되므로
  영향 없음). 마운트 시 최초 검색이 `hasNoResults: true`를 받으면
  `buildFallbackBlogQuery`로 딱 한 번 자동 재검색한다(무한 재시도 방지 —
  이 최초 마운트 시점 검색에만 적용, "다시 검색" 버튼 등 다른 수동 재검색
  경로는 그대로 둠).

## 검증
- `src/lib/admin/naver-blog-search.test.ts`: `buildFallbackBlogQuery` 신규
  4건(접미사 유지 폴백 생성, "점" 케이스는 폴백 없음, sigungu_name 없으면
  폴백 없음, 접미사가 애초에 없으면 폴백 없음).
- `src/components/admin/blog-curation-modal.test.tsx`: 신규 1건 — 1차
  쿼리("모심갈비 남동")가 결과 없음을 반환하면 자동으로 폴백 쿼리("모심갈비
  남동구")로 재검색해 결과가 나타나는지, 검색 API가 정확히 2번(1차+폴백)만
  호출되는지 확인.
- `npx tsc --noEmit` / `npm run test`(115개 파일, 1283개 테스트) /
  `npm run build` 전체 통과.

## 특이 사항
- 이 폴백은 마운트 시 자동 최초 검색에만 적용된다 — 검색 API 호출은 실패
  시에만 최대 1회 추가되므로(사용자가 이전에 명시한 "크롤링/API 호출량 증가
  우려"와 달리, 이건 블로그 본문 크롤링이 아니라 검색 API 호출 1회일 뿐이라
  비용이 매우 낮다), 기존에 정한 "추가 크롤링 없음" 원칙과 상충하지 않는다.
