# 롯데마트 지점 지오코딩

## 구현 대상
문화센터 통합 화면에 "본인 위치 기준으로 가까운 것부터" 정렬을 넣기 위한
선행 작업. 이마트 지점(64개)은 이미 `open_spaces`에 지오코딩돼 있어 거리순
정렬이 바로 가능했지만, 롯데마트 지점(60개)은 지점명만 하드코딩돼 있고
좌표가 전혀 없었다(2026-10-04 당시 "이번 범위 아님"으로 남겨둔 부분).
사용자 확인(2026-10-07, AskUserQuestion): "롯데마트 60개 지점 먼저
지오코딩(추천)".

## 변경 사항
- `scripts/ingest/lottemart-culture-club-stores.mjs`(신규): 기존
  `emart-culture-club-stores.mjs`와 동일한 패턴(카카오 로컬 키워드 장소
  검색 → `open_spaces`에 `category_min='대형마트문화센터'`로 upsert,
  이마트와 **같은 category_min을 공유**해 기존 "가까운 순" RPC
  (`get_nearby_spaces_and_events`)를 추가 변경 없이 그대로 재사용할 수
  있다).
- `external_id` 접두사 `LOTTEMART_STORE_{storeCode}`.

## 실측으로 발견/수정한 버그
최초 쿼리(`"롯데마트 {지점명}점"`)로 돌려보니 60개 중 52개가 "검색 결과
없음"이었다 — `lottemart_culture_club_classes.store_name`이 이미 "고양점"
처럼 "점"을 포함하고 있는데 거기에 "점"을 또 붙여 "고양점점"이라는 잘못된
쿼리가 됐던 것(직접 Kakao API를 여러 포맷으로 테스트해 원인 확정). "점"을
다시 붙이지 않도록 고치자 **60개 전부 정확히 매칭**됐다(MAXX 지점은
"롯데마트맥스"로 별도 처리).

## 검증
- 실제 카카오 API로 60개 전부 지오코딩 성공 확인(실패 0건) — 매칭된
  장소명/주소가 전부 "롯데마트 {지점명}" 형태와 실제 지역에 맞는 주소로
  합리적임을 눈으로 확인.
- 실제 `open_spaces` upsert 완료 후 직접 조회해 60건 전부 정상 저장 확인
  (`LOTTEMART_STORE_455` → "롯데마트 고양점" 등).
- `npx tsc --noEmit` / `npm run test`(275개 파일 2,859개, 신규 6개 포함) /
  `npm run build` 전부 통과.

## 특이 사항
- 이마트와 category_min을 공유하므로, 이 작업의 부수 효과로 롯데마트
  문화센터 지점도 스팟픽(지도) 화면에 자동으로 노출된다 — 의도치 않은
  범위 확장이 아니라 기존 구조 재사용의 자연스러운 결과(제5장 제4조).
