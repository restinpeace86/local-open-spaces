## 변경 사항
- `src/components/map/search-bar.tsx`: 텍스트 입력, 300ms debounce 후 상위로 키워드 전달, 입력 지우기 버튼
- `src/components/map/category-filter.tsx`: "전체" + 표준 카테고리 8종(PARK/SPORTS/CULTURE/FESTIVAL/EXHIBITION/PERFORMANCE/POPUP/RESERVATION) 단일 선택 칩. `category-meta.ts`에 `CATEGORY_FILTER_OPTIONS` export 추가
- `src/components/map/empty-state.tsx`: "검색 결과가 없습니다" + "필터 초기화" 버튼
- `src/components/map/map-explorer.tsx`: `keyword`, `category` 상태 추가. 필터링 우선순위:
  - 특정 카테고리 선택 시: 상시시설 토글과 무관하게 해당 카테고리만 필터링 (spec 2.3 "선택 시 지도 위 마커와 리스트가 즉시 동기화되어 렌더링" 요건 충족 — 토글에 막혀 결과가 안 보이는 상황 방지)
  - "전체" 선택 시: 기존 레이어 정책(EVENT 기본 On, SPACE는 토글) 유지
  - 키워드는 이름(name) 부분 일치, 대소문자 무시, 위 필터 결과에 추가 적용
  - 필터링 결과 0건 + 원본 데이터는 있음 → EmptyState 노출, "필터 초기화"로 키워드/카테고리만 초기화(반경/토글은 유지)
  - 데스크톱 좌측 패널과 모바일 플로팅 헤더 양쪽에 검색바/카테고리 칩 배치 (spec 2.1 위치 규칙)

## 특이 사항
- **카테고리 필터와 레이어 토글의 상호작용을 의도적으로 분리**: spec 2.2(레이어 토글)와 2.3(카테고리 필터)이 각각 독립 규칙으로 문서화되어 있지만, 문자 그대로 독립시키면 "상시 시설 보기"가 꺼진 상태에서 SPACE 계열 카테고리(공원/체육시설/문화기반시설)를 선택했을 때 사용자가 원인을 알 수 없이 결과가 0건으로 보이는 UX 결함이 생김. 특정 카테고리 선택을 레이어 토글보다 우선시켜 "선택 시 즉시 동기화되어 렌더링됨"이라는 spec 2.3의 명시적 요건을 실제로 충족시킴
- 카테고리 칩은 단일 선택으로 구현 (spec의 "다중/단일 선택 UI" 문구가 양쪽을 허용하나, 다중 선택 시 조합 로직이 복잡해지고 사용자가 명시한 예시("전체, 공원, 문화공간, 공공예약 등")도 단일 선택 패턴에 부합해 단순한 쪽을 선택함)
- 10km 초과 시 광역 그리드 뷰 전환 안내(spec 2.2 하단)는 이번 범위에서 제외 — 반경 선택 UI 자체가 최대 10km로 제한돼 있어 해당 시나리오(줌 아웃으로 10km 초과)가 아직 발생하지 않음, 다음 단계 후보로 `implementation/todo.md`에 유지
