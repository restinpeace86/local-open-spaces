# 문화센터 통합검색 — 아이 연령+위치 기본 필터, 카드 레이아웃 재설계

## 구현 대상
- `/api/culture-club/search`: `age_months`(연령 겹침 OR 필터), `lat`/`lng`
  (거리순 정렬), `q`(강좌명 텍스트 검색) 파라미터 추가.
- `get_culture_club_store_coordinates()` RPC: 문화센터 지점(현재 124개,
  이마트 64 + 롯데마트 60) 좌표 일괄 조회.
- `culture-club-tab-view.tsx`: 로그인 + 온보딩 정보가 있으면 자동으로
  적용되는 "1차 기본 필터" 2종(아이 연령/위치)과, 사용자가 직접 입력·
  제출하는 텍스트 검색창, 썸네일-좌측 가로형 카드로 레이아웃 재설계.

## 구현 일시
2026-10-07

## 변경 사항
1. **기본 필터 2종(사용자가 아무 조건도 안 걸어도 자동 적용)**
   - 아이 연령: `profiles.birth_years`/`birth_months`로 계산한 개월 수
     기준, 자녀가 2명 이상이면 "첫째/둘째..." 스위처로 전환 가능.
   - 위치: `useUserLocation()`의 `center`(미설정 시 서울시청 기본값)를
     항상 `lat`/`lng`로 실어 보내 거리순으로 정렬.
2. **2차 조건(사용자가 선택)**: 기존 브랜드/요일/카테고리(이마트)·대상
   (롯데마트) 필터는 그대로 유지. 강좌명 텍스트 검색을 새로 추가했는데,
   입력할 때마다 조회하지 않고 "조회" 버튼 제출 시에만 반영한다.
3. **카드 레이아웃**: 세로(이미지 위) 그리드 카드 → 참고 화면
   (`reference/moonsen_mobile.png`/`moonsen_pc.png`)처럼 썸네일이 좌측에
   있는 가로형 리스트 카드로 전환. 참고 화면엔 없는 연령 범위/브랜드 뱃지/
   거리(`distance_meters`→"0.7km"/"650m")를 추가로 보여준다.
4. **거리순 정렬 — 백엔드**: `culture_club_classes`는 좌표가 없어
   `store_code`로 `open_spaces`를 가리킨다. 지점이 124개뿐이라 RPC로
   전부 가져와 Node.js에서 메모리 조인 후 거리로 정렬한다. PostgREST가
   `.limit()`을 아무리 크게 줘도 응답을 1,000건으로 자르는 기존 이슈
   때문에 `.range()`를 병렬로 나눠 호출해 우회했다(실측으로 "가장 가까운
   지점"이 틀리게 나오는 버그를 발견해 수정).

## 특이 사항
- 아이 정보가 없거나 비로그인이면 연령 배너 자체를 생략한다(추측 금지).
- 거리 정렬 안전상한(`DISTANCE_SORT_FETCH_SAFETY_CEILING = 5000`)은 현재
  규모(약 2만여 행)에서 실제로 걸릴 일은 없는 방어선이다.
- 검증: `npx tsc --noEmit` / `npm run test`(2869건) / `npm run build`
  모두 통과. 개발 서버에서 `/api/culture-club/search`를 실제 curl로
  호출해 연령+위치 조합(거리순 정렬, 청계천 ~3.9km 1위 확인) 및 텍스트
  검색("트니트니" 조회 결과 확인)이 기대대로 동작함을 확인했다.
