# [가격 파싱: 숫자 금액을 "무료" 추정보다 항상 우선]

## 구현 대상
사용자 보고(2026-09-16, "트레저헌터 in 진안" 이벤트 가격 큐레이션): 소스1(블로그)
카드가 "💰 참가비 무료"라고 요약해서 보여주는데, 정작 같은 카드의 연령/구간
목록에는 "얼리버드 2,000원 / 사전등록 4,000원 / 현장구매 5,000원"이라는 실제
유료 구간이 함께 떠서 서로 모순돼 보임 — "이건 어떻게 적으면돼?"라는 질문.

## 구현 일시
2026-09-16

## 원인
직전에 추가한 "라벨+무료" 인식(3순위, 예: "관람료는 전액 무료")이 우선순위상
"라벨 없는 대상어+금액"(기존 2순위)보다 먼저 검사됐다. 이 이벤트의 실제 블로그
본문은 긴 글 안에 서로 무관한 두 가지 요금 정보가 섞여 있었다:
- 메인 참가 패스(유료): "참가 패스 요금\n얼리버드 2,000원 / 사전등록 4,000원 /
  현장구매 5,000원"
- 완전히 별개인 부가 이벤트(무료): "2) 무료 야간 특별 미션: 나이트헌터...
  참가비: 무료"

`.match()`는 텍스트에서 처음 성공하는 매치를 그대로 반환하는데, "참가 패스
요금" 뒤에는 표 형식(줄바꿈)이 끼어 있어 라벨+무료 정규식이 매칭에 실패하고,
정규식 엔진이 계속 스캔하다 뒤쪽의 완전히 무관한 "참가비: 무료"에서 성공해
버렸다 — 메인 요금이 명확한 숫자로 존재하는데도 무관한 "무료" 추정이 이겼다.
`priceTiers`(구간 파싱, parsePriceAgeTiers)는 별도 로직이라 이 문제 없이 3개
구간을 정확히 잡아서, 결과적으로 요약(priceText)과 구간 목록이 서로 모순돼
보이는 화면이 나왔다.

## 변경 사항
### `src/lib/admin/parse-price-from-text.ts` / `scripts/ingest/adapters/lib/price-parser.mjs`
우선순위를 재정렬했다: **1) 라벨+숫자 → 2) 라벨 없는 대상어+숫자 → 3) 라벨+"무료"**
(기존은 1 → 1.5(라벨+무료) → 2 순서였음). 텍스트 어디든 실제 숫자 금액이 있으면
그 증거가 "무료" 추정보다 항상 우선하도록 했다 — 긴 블로그 글처럼 여러 소주제를
함께 다루는 텍스트에서, 뒤쪽의 무관한 "라벨: 무료" 문구가 앞쪽의 진짜 메인 요금을
가리는 일을 막는다. 완전히 무료인 이벤트(숫자가 텍스트 어디에도 없는 경우, 예:
"관람료는 전액 무료")는 순위가 바뀌어도 그대로 정확히 잡힌다(숫자가 없으니 1/2
순위가 실패하고 3순위로 자연스럽게 넘어감).

## 검증
- `npx tsc --noEmit`, `npm run test`(전체 1790개, 신규 2개 포함), `npm run build`
  모두 통과.
- 실제 이벤트("트레저헌터 in 진안")로 재현 호출 — 수정 전 `priceText: "참가비
  무료"`(모순)이던 것이 수정 후 `priceText: "얼리버드 2,000원 사전등록
  4,000원"`으로, `priceTiers`(3개 구간)와 더 이상 모순되지 않게 확인.
- 신규 회귀 테스트: 메인 참가비(숫자 유료)와 별개 부가 이벤트("참가비: 무료")가
  한 텍스트에 함께 있을 때 숫자가 이기는지 검증.

## 사용자 질문에 대한 직접 답변
"최종 가격 텍스트"에는 실제 메인 참가 방식인 패스 요금 3구간을 그대로 적으면
된다 — 예: `얼리버드 2,000원 / 사전등록 4,000원 / 현장구매 5,000원`. "야간
특별 미션"은 그 패스와 무관한 별도 무료 부가 프로그램이라, 메인 가격 텍스트에
섞어 적으면 오히려 헷갈린다 — 필요하면 "추가 메모" 칸에 "야간 특별 미션(나이트
헌터)은 별도로 무료"라고 덧붙이는 정도면 충분하다. "최종 연령 기준"은 이
이벤트에는 연령별로 가격이 나뉘는 게 아니라(구매 시점별 구분) 해당 사항 없다.
