## 변경 사항
### 1. 공개 API (`src/app/api/spot-curations/route.ts`)
- `child_fee`/`guardian_fee`(Step 71에서 추가한 컬럼)를 select에 추가해
  상세 모달의 가격 표시에 쓸 수 있게 했다.
- `curation_badges` + `open_spaces(service_categories(category_name))`
  중첩 조인을 추가해, 서버에서 뱃지 키(예: `kc_trampoline`, 카테고리마다
  의미가 다름)를 사람이 읽을 라벨(`badge_labels: string[]`)로 미리
  변환해 내려준다 — 클라이언트가 원본 키를 그대로 보여주면 안 되므로
  (카테고리 무관하게 해석 불가) `resolveCurationCategoryId`/
  `getBadgeOptionsForCategory`(기존 admin 뱃지 config를 그대로 재사용,
  제5장 제4조)로 서버에서 미리 라벨을 확정한다.

### 2. `src/components/map/marker-preview-card.tsx`
- 마운트 시(`item.id` 기준) `/api/spot-curations`를 한 번 호출해 `image_url`/
  `badge_labels`를 가져온다. 큐레이션이 없거나 조회 실패하면 기존처럼
  카테고리 색상 아이콘으로 조용히 폴백한다(제5장 제11조).
- 대표 이미지가 있으면 아이콘 대신 실제 이미지를 보여주고, 핵심 뱃지는
  카드 폭 제약을 고려해 최대 2개까지만 작은 칩으로 보여준다.

### 3. `src/components/map/detail-modal.tsx`
- `SpotCuration` 타입에 `child_fee`/`guardian_fee` 추가, `formatEntranceFee()`
  신규(있는 필드만 이어붙임 — `formatCuratedHours`와 동일한 "추측 금지"
  원칙).
- 신규 "가격" 행 추가: 큐레이션에 입장료가 있으면 그대로, 없지만 공공
  데이터로 이미 무료임을 아는 경우(`item.is_free === true`)는 "무료입장",
  둘 다 모르면 지시받은 문구("가격 정보 업데이트 준비 중입니다 ⏳")를
  보여준다. `is_free`를 확인 없이 "준비 중"으로 잘못 표시하면 실제로는
  아는 정보를 숨기는 셈이라 신뢰도 유지라는 취지에 오히려 어긋나 이 분기를
  추가했다.
- "메뉴" 행은 이제 메뉴가 없어도 숨기지 않고 지시받은 문구("상세 메뉴
  정보는 순차적으로 추가될 예정이에요")를 보여준다.
- "운영시간" 행의 최종 폴백을 범용 `NO_INFO_TEXT`에서 지시받은 전용 문구
  ("영업시간 정보는 순차적으로 추가될 예정이에요")로 바꿨다(주소 등 다른
  필드의 `NO_INFO_TEXT`는 그대로 유지 — 가격/메뉴/영업시간처럼 큐레이션에
  의존하는 정보만 이 톤으로 바꾼다는 지시 범위를 지켰다).

## 특이 사항
- 마커 프리뷰 카드가 이제 스팟마다 가벼운 조회를 한 번 추가로 하지만
  (예전엔 "별도 네트워크 요청 없이"가 의도적 설계였음), 이번 지시가
  실제 대표 이미지/뱃지를 명시적으로 요구해 불가피한 트레이드오프다 —
  단건 조회(`.maybeSingle()`)라 부담은 크지 않다.
- 가격/메뉴 행은 카테고리와 무관하게 모든 공간(이벤트 제외) 상세에서
  항상 보인다 — 지시문이 "MVP 단계에서 가격이나 메뉴 데이터가 아직
  채워지지 않은 스팟의 경우"라고 일반적으로 표현해 특정 카테고리로
  좁히지 않았다.
