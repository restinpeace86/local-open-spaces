## 설계 원칙
- `DetailModal`은 스팟(SPACE)/이벤트(EVENT) 양쪽을 공유하는 대형 컴포넌트라, 이벤트
  분기 전체를 새 8단 구조로 새로 작성하고 **스팟 분기는 100% 그대로 보존**했다
  (제5장 제4조 기존 구조 우선 — 스팟 쪽 회귀 위험을 원천 차단).
- 기존에 이벤트에서만 보여주던 정보(연령대상, 사전예약필요 경고, 예약 마감일)는 8단
  스펙에 명시된 섹션은 아니지만 임의로 없애지 않고(제5장 제3조 기능 삭제 금지)
  2단(뱃지)·5단(예약기간) 근처에 자연스럽게 재배치했다.
- 새로 필요한 값(예약 기간)은 Step 109에서 이미 만든 `formatReservationPeriod`를,
  진행 상태 뱃지는 기존 `getEventStatus`(event-status.ts, event-card/calendar-view가
  이미 쓰는 함수)를 그대로 재사용했다 — 새 판별 로직을 만들지 않았다.

## 변경 사항
### `src/components/map/detail-modal.tsx`
- `getEventStatus`/`EventStatus`, `formatReservationPeriod` import 추가. 더 이상
  쓰지 않는 `formatDDay`(D-day 뱃지, 새 구조에서 진행 상태 뱃지로 대체)는 제거.
- `eventStatusPillClass(tone)` 신규 — 2단 진행 상태 뱃지 색상(calendar-view.tsx의
  텍스트 전용 statusColorClass와 시각 요구가 달라 별도로 둠).
- `currentImageIndex` state 신규(1단 이미지 슬라이드 위치, item.id 변경 시 0으로 리셋).
- `eventImages`(현재는 thumbnail_url 1장뿐이라 0~1건 배열 — 다중 이미지 데이터가
  없어 지어내지 않는다, 제3장 제5조), `eventStatus`, `eventReservationPeriod` 계산값 추가.
- `return` 문을 `{isEvent ? (...) : (...)}`로 분기:
  - **이벤트 분기(신규)**: `flex flex-col overflow-hidden` 컨테이너 + 스크롤 가능한
    본문(`flex-1 overflow-y-auto`) + `shrink-0` 고정 푸터로 8단 CTA를 실제로
    "하단 고정"시켰다. ✕ 닫기 버튼은 이미지 유무와 무관하게 항상 같은 위치에 뜨도록
    모달 우상단에 떠 있는 원형 버튼으로 옮겼다(이미지가 최상단 전체 폭을 차지하는
    구조에서 기존처럼 패딩 안에 두면 이미지가 있을 때만 어색하게 밀림).
    1단 이미지 슬라이드는 배열 길이가 1 이하면 화살표/점을 숨긴다(실질적으로 현재는
    항상 이렇게 동작 — 다중 이미지 소스가 생기면 그대로 활성화된다).
    3단 거리는 **spotPickCard 여부와 무관하게** 정확한 좌표가 있으면 항상 탭 가능한
    버튼(요구사항 "탭 시 곧바로 인앱 길찾기")으로 바뀌었다(기존엔 spotPickCard일 때만).
    8단 CTA는 기존 `cta`(Task 9-6-11의 공공예약/할인예매/지도길찾기 3분류)를 그대로
    재사용하되 버튼 하나만 렌더링한다(이벤트는 원래도 `secondaryAction`이 항상
    null이라 실질적 동작 변화는 없음) — 셋 다 없으면(좌표도 없는 극히 드문 경우)
    안내 텍스트로 대체.
  - **스팟 분기**: 기존 JSX를 그대로 옮기되 `isEvent` 삼항 조건들(이제 항상 거짓)을
    제거해 코드를 단순화했을 뿐, 렌더링 결과는 완전히 동일하다.
