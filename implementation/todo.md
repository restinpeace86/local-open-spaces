1. **GitHub `todo.md` 기반 작업 수행**: 본 문서에 명시된 Task 목록과 세부 작업 지시를 최우선 가이드라인으로 삼아 순차적으로 작업을 진행한다.

   - 기존 Spec 문서 (`spec/`), Decision Log (`project/decision-log.md`), 또는 기존 모듈과 구조적/논리적 충돌이 발생하는 경우, 절대로 무리하게 코드를 수정하지 말고 즉시 **[스킵 (보류)]** 처리한다.
3. **스킵 처리 시 필수 기록 사항**:
   - 충돌로 인해 작업을 스킵할 경우, 해당 Task 하단에 **① 상세 스킵 사유**를 명확히 기록한다.
   - 해당 Task를 재개하기 위해 **② 선행되어야 할 작업**(예: 신규 Decision 기록 필요, Spec 문서 선행 수정 필요 등)을 구체적인 가이드로 명시한다.
4. **원격 문서 갱신 반영 및 동기화**:
   - 원격 저장소의 `project/decision-log.md` (Decision 010) 및 `spec/map/spatial-search.md` (2.2 레이어 분리) 변경 내역을 확인하고, 충돌이 해소된 상태에서 안전하게 다음 Task를 진행한다.
5. **결과 업데이트 및 정합성 유지**:
   - 작업 완료 시 관련 테스트/빌드를 검증하고 `todo.md` 내 체크박스(`[x]`) 및 진행 상태를 최신화한다.

- 현재 스팟 큐레이션에서 네이버 플레이스에 등록된 이름을 읽어오기에 더 정확한 이름이고 해당 이름으로 블로그로 큐레이션 검색이 정확도가 더 높을 것으로 보여지기에 변경 필요
- **요구사항:**

  2. 만약 블로그 검색용 키워드가 별도 컬럼(`search_keyword` 등)으로 분리되어 있다면, 스팟 정보 수정 시 노출 이름과 함께 검색 키워드도 자동으로 업데이트되도록 연동 로직을 보완해주세요.
  3. 현재 블로그로 큐레이션에서 검색시 뒤에 시군구를 넣고 있는데 해당로직은 제외해주고 정확히 스팟의 노출 이름 반영되면 해당 노출 이름으로 검색하도록 할 것
  4. 노출 이름 수동 수정 (원본 상호명: 조마루감자탕) 쪽도 변경 반영되지 않고 있음

  2. 스팟 큐레이션에서 입력된 뱃지가 유실되지 않고 블로그 키워드 뱃지와 정상적으로 병합되거나(혹은 의도에 맞게 갱신되도록) 데이터 흐름과 상태 관리 로직을 수정해주세요.

[개선사항 5] # PMS / 파트너 센터 이메일(ID/PW) 로그인 및 회원가입 기능 추가

## 1. 개요
- 현재 카카오/구글 소셜 로그인만 지원하는 PMS 로그인/온보딩 화면에, **이메일 및 비밀번호(ID/PW) 기반의 로그인과 회원가입 기능**을 추가합니다.
- Supabase Auth를 활용하여 기존 소셜 로그인 계정과 동일하게 인증 및 온보딩 플로우로 연동합니다.

## 2. 구현 요구사항
1. **UI / UX 구성 (로그인 페이지):**
   - 기존 소셜 로그인(카카오/구글) 버튼들과 함께 **[이메일로 로그인] / [이메일로 회원가입]**을 선택할 수 있는 탭 또는 토글 UI를 추가해주세요.

2. **Supabase Auth 연동 로직:**
   - **로그인 (`signInWithPassword`):** 입력받은 이메일과 비밀번호로 인증 후 대시보드로 이동.
   - **회원가입 (`signUp`):** 이메일/비밀번호로 새 계정 생성 후, 기존 소셜 로그인 직후와 동일하게 **농장 정보 입력(온보딩) 화면**으로 자연스럽게 진입하도록 연결.
3. **유효성 검증 및 에러 처리:**
   - 이메일 형식 검증, 비밀번호 자릿수/유효성 체크.
