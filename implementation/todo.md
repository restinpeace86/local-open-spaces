### 6. 지도 마커 팝업/카드와 상세 카드(Detail View) UI 일원화

### 7. 상세 카드 내 네이버 블로그 후기 및 캐싱 로직 (API 호출 최적화)
- **요구사항:** 상세 카드 내 네이버 블로그 후기를 노출하되, 매번 페이지를 열 때마다 외부 Search API를 호출하지 않도록 **10일 주기 캐싱(TTL) 로직**을 구현해 주세요.
- **DB 요구사항:**
  - 스팟별로 최대 3개의 블로그 링크(`blog_urls`)와 마지막 갱신 일시(`blog_updated_at`)를 저장할 수 있는 필드가 필요합니다.
  - 무조건 가져온 url을 저장하는게 아니고 관리자 화면에서 사용하는 블로그 큐레이션과 동일하게 가져온 url의 신뢰도 검증을 먼저해서 신뢰성 있는 블로그 url만 저장합니다.
  - 신뢰도 검증은 해당 조건으로 검색 + 주소가 제목이나 내용등에 포함되어있을 경우를 말함 (쁠로그 큐레이션에서 이와 같은 조건으로 워닝표시함)
- **조회 및 갱신 로직 (Cache-Aside):**
  - 상세 카드를 열 때 다음 조건을 체크해 주세요:
    1. `blog_urls`가 비어있거나 부족한 경우 OR
    2. 마지막 갱신일(`blog_updated_at`)로부터 **10일이 경과**한 경우
  - **위 조건 중 하나라도 해당할 때만:** 네이버 블로그 Search API를 호출하여 최신 URL을 가져와 DB를 갱신(Upsert)한 뒤 리턴해 주세요.
  - **조건에 해당하지 않는 경우 (10일 이내):** 외부 API 호출 없이, DB에 저장된 캐시 데이터를 즉시 내려주어 로딩 속도를 최적화하고 API 비용을 절약해 주세요.
  - 검색 결과가 0건인 스팟은 해당 영역을 숨김 처리해 주세요.
 
[개선사항3] [스팟픽] 상세 카드(Detail View) 최종 UI 컴포넌트 스펙
컴포넌트 배치 순서와 각 영역별 동작 규칙은 다음과 같습니다.

1. [최상단 헤더] 대표 이미지 영역 (Carousel / Single)
동작 방식:
- 등록된 이미지가 있는 경우: 최상단 대표 이미지 노출 (추후 다중 이미지 슬라이드 확장이 가능하도록 구조화).
- 등록된 이미지가 없는 경우: 해당 영역 전체를 숨김(Gone) 처리하여 레이아웃이 어색하게 비지 않도록 처리.

2. [이미지 하단] 뱃지 영역
동작 방식:
- 구형 레거시 뱃지('키즈*액티비티' 등)는 완전히 배제.
- 해당 카테고리(식당/캠핑/체험 등)에 맞는 정상적인 맞춤형 뱃지 목록만 컴팩트하게 노출.

3. [뱃지 하단] 상호명 및 & 인터랙티브 거리 및 길찾기 영역 (우측, 예: 🧭 1.2km ›) 👉 여기를 누르면 즉시 길찾기 실행!
좌측: 상호명 (Bold 메인 타이틀)
우측: 현재 내 위치 기준 직선거리 (예: 1.2km)
 - 동작 방식: 현재 거리 클릭 시 서비스 내에 구현되어 있는 인앱 길찾기 API를 정상 호출하여 내 위치 기준 길안내 실행.
 - 해당 거리 누르면 길 찾기가 될 거라는걸 직관적으로 알수 있게 노출할 것

5. [상호명 하단] 네이버 블로그 후기 바로가기 (동적 버튼)
동작 방식:
앞서 논의한 10일 주기 캐싱(TTL) 로직이 적용된 blog_urls 데이터를 활용.
저장된 URL 개수(최대 3개)에 맞춰 동적으로 버튼 노출 (예: 블로그 1, 블로그 2, 블로그 3).
터치 시 해당 블로그 원문 링크로 인앱/아웃바운드 연결. URL이 없으면 영역 숨김.
다만 네이버 블로그로 넘어가서 읽은 후 뒤로가기 눌렀을때 우리앱의 현재 상태, 블로그로 넘어가기 전 상태로 다시 In 될 수 있어야 함.

6. [블로그 하단] 기본 상세 정보 영역
포함 정보: 상세 주소, 운영시간, 가격, 대표 메뉴 등 핵심 스팟 정보.

7. [정보 하단] 예약 버튼 (조건부 렌더링)
동작 방식:
스팟별 DB에 외부 예약 링크(네이버 예약 등)가 존재하는 경우에만 버튼 노출 및 해당 링크 연결.
예약 링크가 없는 경우: 뜬금없는 "간편 예약" 버튼이 뜨지 않도록 버튼 영역을 완전히 숨김 처리.
