## 🚨 자율 실행 및 작업 진행 지침 (Strict Execution Rules)

1. **GitHub `todo.md` 기반 작업 수행**: 본 문서에 명시된 Task 목록과 세부 작업 지시를 최우선 가이드라인으로 삼아 순차적으로 작업을 진행한다.
2. **충돌 발생 시 즉시 스킵 (Skip on Conflict)**:
   - 기존 Spec 문서 (`spec/`), Decision Log (`project/decision-log.md`), 또는 기존 모듈과 구조적/논리적 충돌이 발생하는 경우, 절대로 무리하게 코드를 수정하지 말고 즉시 **[스킵 (보류)]** 처리한다.
3. **스킵 처리 시 필수 기록 사항**:
   - 충돌로 인해 작업을 스킵할 경우, 해당 Task 하단에 **① 상세 스킵 사유**를 명확히 기록한다.
   - 해당 Task를 재개하기 위해 **② 선행되어야 할 작업**(예: 신규 Decision 기록 필요, Spec 문서 선행 수정 필요 등)을 구체적인 가이드로 명시한다.
4. **원격 문서 갱신 반영 및 동기화**:
   - 원격 저장소의 `project/decision-log.md` (Decision 010) 및 `spec/map/spatial-search.md` (2.2 레이어 분리) 변경 내역을 확인하고, 충돌이 해소된 상태에서 안전하게 다음 Task를 진행한다.
5. **결과 업데이트 및 정합성 유지**:
   - 작업 완료 시 관련 테스트/빌드를 검증하고 `todo.md` 내 체크박스(`[x]`) 및 진행 상태를 최신화한다.

[개선사항 1] 당신은 Next.js App Router, TypeScript, 그리고 Supabase를 활용한 웹 서비스 개발에 능숙한 시니어 풀스택 엔지니어입니다.

현재 우리 서비스의 이벤트픽 화면에서 제휴상품등록한것들이 '이번주말 실패없는 베스트 나들이 픽'에 다 노출되던 기존 방식을 갈아엎고,  **상품의 성격(기간한정 특가 vs 상시 티켓)에 따라 노출 위치와 큐레이션 전략을 이원화**하려고 합니다.

아래 기획 철학에 맞추어 Supabase 쿼리 로직과 프론트엔드 컴포넌트 구조를 리팩토링해 주세요.

### [핵심 기획 철학 및 노출 위치]

1. **기간한정 특가 / 월별 특가 상품 (Time-limited Deals):**
   - **대상:** 10월 특가, 기간 한정 특가, 시즌 할인 등 이벤트 운영 기간은 아니지만 가격에 대한 기간 마감이 존재하는 시한적 제휴 상품 (`end_date`가 명시된 상품). <- 관리자 화면에 구현된 마이리얼트립 제휴 상품 탭의 팝업에서 기간 입력
   - **노출 위치:** 메인 화면의 핵심 영역인 **[이번 주말 실패 없는 베스트 나들이 픽] (기존 제휴 상품 노출 영역)**에 배치.
   - **타이틀 변경:** **[이번 주말 실패 없는 베스트 나들이 픽] 제목에 대하여 [엄선된 기간 한정 특가 픽] 으로 변경 , 부제도 현재 '에디터가 직접 검증한..' 이거인데  '아이와 함께 가기 좋은 한정기간 추천 픽만 모았어요' 이거로 바꿔줘
   - **특징:** 유저의 이목을 끄는 강력한 핫딜/추천 성격으로 다루며, 지정된 종료일(`end_date`)이 지나면 자동으로 피드에서 내려가거나 마감 처리되도록 구현. (이미 구현되어있음. 다시 확인만해.. start_date도 있을 경우는 start_date 지나야 노출 시작해야하는것도 같이 확인해)
   - **프리뷰카드:**: 텍스트 영역에 가격 / 장소 / 기간 등에 대한 정보가 다른 영역이랑 비슷한 구조로 나와야함

2. **상시 티켓 / 스테디셀러 상품 (Evergreen Tickets):**
   - **대상:** 키즈카페 등 기간 마감 없이 연중무휴 언제나 구매·예약 가능한 상시 제휴 상품 (`end_date`가 없거나 상시 노출로 설정된 상품).
   - **노출 위치:** 메인 피드 맨 **[하단 영역 (상시 픽 / Evergreen Zone)]**에 별도로 분리하여 고정 노출.
   - **제목 선정:** [타이틀] 🧸 언제 가도 좋은 상시 추천 픽 . [부제] 마감 걱정 없이, 아이와 언제든 떠날 수 있는 스테디셀러 티켓
   - **특징:** 타임라인의 흐름을 해치지 않고, 언제든 든든하게 받쳐주는 스테디셀러 스토어 형태로 배치.
   - **프리뷰카드:**: 텍스트 영역에 가격 / 장소 등에 대한 정보가 다른 영역이랑 비슷한 구조로 나와야함

 
### [요구 사항]

1. **데이터 페칭 및 분기 로직 (Supabase / Server Actions):**
   - 제휴 상품 테이블(또는 통합 상품 테이블)에서 데이터를 가져올 때, `end_date`의 유무(또는 플래그)를 기준으로 **'기간한정 특가군'**과 **'상시 티켓군'**으로 데이터를 나누어 쿼리하거나 필터링하는 유틸 함수/훅 작성.
2. **프론트엔드 메인 피드 컴포넌트 구조 개편:**
   - 상단 히어로/큐레이션 영역: 기간한정 특가 상품들만 엄선하여 렌더링.
   - 최하단 영역: 상시 티켓 상품들을 모아 보여주는 [언제나 가기 좋은 상시 혜택 픽] 섹션 추가.
   - 만료된 기간한정 특가는 화면에 노출되지 않도록 날짜 비교(`current_date <= end_date`) 예외 처리 포함.

---

당신은 Next.js App Router, TypeScript, 그리고 TailwindCSS를 활용한 프론트엔드 개발에 능숙한 시니어 풀스택 엔지니어입니다.

현재 우리 서비스의 제휴 상품 UX를 개선하여, **메인 피드의 '프리뷰 카드'를 클릭했을 때 곧바로 외부 링크로 이동하는 대신, 내부 상세 뷰(모달 또는 슬라이드 오버 바텀시트, 혹은 동적 상세 페이지)를 거쳐 상품 정보를 충분히 확인한 뒤 외부 구매 링크로 이동하는 구조**로 개편하려고 합니다.

아래 요구사항에 맞춰 컴포넌트 구조와 인터랙션 로직을 구현해 주세요.

### [핵심 유저 플로우]
1. 메인 피드(타임 특가 픽 / 상시 픽)에서 상품 카드 클릭
2. 우리 서비스 내부의 **상세 정보 뷰** 오픈 (상품 상세 내용, 기간, 위치, 가격 등 확인)
3. 하단 고정 CTA 버튼 클릭 시 마이리얼트립 원본 제휴 링크로 아웃링크 이동 (`target="_blank"`)

### [상세 뷰 (Detail View) 필수 구성 요소]
1. **상단 이미지 및 뱃지 영역:**
   - 대표 이미지 갤러리 (또는 단일 대표 썸네일)
   - 상품 성격에 따른 뱃지 필요한가 ? 제안할 것
2. **타이틀 및 가격 정보:**
   - 상품명 (Title)
   - 최종 판매가 (Price) 및 할인 관련 안내 텍스트
3. **핵심 메타데이터 (Quick Info Box):**
   - 📍 **위치 정보:** 연동된 장소/주소 정보
   - ⏰ **이용/예약 기간:** `start_date` ~ `end_date` (기간 한정 상품인 경우 명시)
   - 👶 **타겟 포인트:** "아이와 함께 가기 좋은 곳" 관련 에디터 노트나 요약 코멘트
4. **상세 설명 영역:**
   - API로 가져온 상품 상세 소개 텍스트 및 이미지 그대로 사용 / 주의사항 (다만 , 현재 관리자화면에서 봤을때 상기와 같이 되어있는데 상세 설명을 보는 영역이 좀 좁아보이는 느낌이 나는데 이를 고려할것.. 상세보기할때는 상세 정보 뷰에서 해당 영역을 좀 길게 잡아서 사용자 경험을 헤치지 않도록.)
5. **하단 고정 CTA (Call to Action) 버튼:**
   - `[예매하러 바로가기 ↗]` 버튼 (전체 너비 고정, 클릭 시 새 창으로 원본 링크 연결 및 안전한 `rel="noopener noreferrer"` 처리)

### [출력 요구]
- 위 요구사항을 만족하는 상세 뷰 컴포넌트(모달 또는 상세 페이지 형태 중 모바일 웹에서 직관적인 구조)의 TypeScript + TailwindCSS 코드를 작성해 주세요.
