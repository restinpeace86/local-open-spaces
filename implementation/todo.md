유저용 이벤트 상세 화면 내 '큐레이션 블로그' 연동 구조
데이터 파이프라인 (Admin ➡️ DB ➡️ User)

관리자 화면에서 블로그 후보 3개 중 체크하여 저장한 URL들이 해당 이벤트 데이터의 필드(예: curated_blog_urls)에 안전하게 저장됩니다.

유저 상세 화면에서의 노출 (Conditional Rendering)

위치: 6단 상세 설명 아래쪽, 또는 지도 미니맵 위쪽에 [방문 후기 / 추천 블로그] 형태의 깔끔한 카드 리스트로 배치합니다.

조건부 노출: 만약 관리자가 저장한 블로그 URL이 단 1개도 없다면 해당 섹션 전체를 통째로 숨김(Gone) 처리하여 빈 화면이 뜨지 않도록 깔끔하게 방어합니다.

유저 인터랙션

유저가 상세 페이지를 보다가 큐레이션된 블로그 카드를 탭하면, 인앱 브라우저(또는 외부 브라우저)로 부드럽게 연결되어 생생한 현장 후기나 사진을 바로 확인할 수 있습니다.

현재 데이터 파이프라인에서 상시성 스팟(`open_spaces`)과 시한성 이벤트(`events`)의 원천 데이터 수집 및 라우팅 로직을 이분법적으로 명확하게 분리하고, 기존에 섞이거나 크로스되던 모호한 로직을 깔끔하게 정리(Refactoring)해 주세요.

### 📌 핵심 요구사항

1. **엄격한 이분법적 수집 라우터 (Ingestion Router) 구축**
   - 원천 데이터의 속성(운영 기간 유무 등)을 기준으로 수집 단계에서부터 데이터가 완전히 갈라져서 적재되도록 라우팅 로직을 수정해 주세요.
   - **시한성/기간성 데이터 (시작일·종료일 존재):** 무조건 `events` 테이블로만 적재.
   - **상시성/고정 시설 데이터 (기간 없음, 연중 상시):** 무조건 `open_spaces` 테이블로만 적재.
   - 서로 무분별하게 크로스되거나 섞여 들어가는 기존의 모호한 쿼리/로직은 전면 차단하고 제거해 주세요.

데이터 수집 파이프라인에서 '서울시 공공서비스 예약' 등에서 수집되는 공공 대관 및 예약형 시설/프로그램 데이터가 잘못 적재되고 있는 라우팅 경로를 수정해 주세요.

### 📌 수정 요구사항

1. **'서울시 공공예약' 소스 데이터의 라우팅 변경**
   - 수집처가 '서울시 공공서비스 예약'이거나, 핵심 운영 방식이 '대관/사전 예약제'인 공공 체육시설·프로그램 데이터는 `open_spaces`(상시 스팟)가 아닌 **`events` (시한성 이벤트/예약 픽) 테이블로 강제 라우팅**되도록 수정해 주세요.
   - 현재 체육시설 대분류와 축구장, 농구장 등의 시설 대관 예약관련 seoul_public_reservation 원천 데이터 관련 open_spaces에서 보이고 있는데 evnets쪽으로 이관해주세요
2. **기존 잘못 적재된 데이터 마이그레이션/차단**
   - 이미 `open_spaces`에 섞여 들어간 공공 예약/대관 데이터들을 식별하여 `events` 쪽으로 올바르게 재배치(또는 마이그레이션)하고, 앞으로는 원천 소스 및 속성 기준으로 두 영역이 완전히 분리되어 적재되도록 정비해 주세요.

[개선사항 10]
시한성 이벤트(`events`)와 상설 스팟(`open_spaces`)을 파이프라인 단계에서는 분리하되, 데이터 모델과 UI 상에서 유기적으로 연결(양방향 링킹)될 수 있도록 구조를 구현해 주세요.

### 📌 핵심 요구사항

1. **데이터 모델링 (FK 링킹)**
   - `events` 테이블에 `open_spaces`를 참조할 수 있는 외래키 컬럼(`open_space_id`)을 추가해 주세요.
   - 이벤트 수집 시 장소 매칭 로직을 두어, 일치하는 상설 스팟이 있으면 자동 매칭하고, 매칭되는 스팟이 없는 경우 관리자가 수동으로 스팟을 지정하거나 신규 등록하여 연결할 수 있도록 관리자 툴 플로우를 지원해 주세요.

2. **유저 화면 양방향 연동**
   - **Event ➔ Spot:** 이벤트 상세 화면의 장소/위치 영역을 탭했을 때, 연결된 `open_spaces` 상세 페이지로 이동할 수 있도록 연동해 주세요.
   - **Spot ➔ Event:** 상설 스팟(`open_spaces`) 상세 페이지 내에, **현재 해당 장소에서 진행 중이거나 예정된 시한성 이벤트(`events`) 목록**을 실시간으로 조회하여 보여주는 섹션을 추가해 주세요. (진행 중인 이벤트가 없는 경우 해당 섹션은 숨김 처리)
