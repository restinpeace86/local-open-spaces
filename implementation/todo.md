[개선사항 2] 이마트 컬처클럽과 롯데마트 문화센터의 강좌 데이터에서 제각각인 연령 표기를 파싱하여, 최종적으로 데이터베이스에 정형화된 정수 컬럼인 `minAge`와 `maxAge`에 '총 개월 수(Months)' 단위로 적재하는 파싱 함수 및 유틸리티를 구현해줘.

파싱은 반드시 아래의 '2단계 파이프라인'을 거치도록 설계해줘.

### [2단계 연령 정규화 파이프라인]

#### Step 1: '세' 및 '년생' 표현을 표준 출생 연도로 1차 정규화
원문 문자열의 형태에 따라 다음과 같이 처리할 것:
1. '세' 표기 (예: "6세", "6~7세"):
   - 한국의 문센/키즈 프로그램은 '출생 연도(연나이)' 기준임.
   - 기준 연도(예: 현재 연도 2026년 또는 강좌 개시 연도)를 기준으로 `기준 연도 - 나이 = 출생 연도`로 치환할 것.
   - 예: 2026년 기준 '6세' -> 2020년생. '6~7세' -> 2019~2020년생.
2. '년생' 표기 (예: "2020~23년생", "(17~22년생A)"):
   - 명시된 출생 연도 범위 그대로 유지할 것 (예: 2020년생 ~ 2023년생).
3. '개월' 표기 (예: "13~26개월", "(37~55개월/c)"):
   - 개월 수 단위 데이터는 Step 1을 거치지 않고 바로 Step 2로 전달할 것.

#### Step 2: 출생 연도 또는 개월 수를 최종 '개월 수(Months)' 범위로 환산하여 적재
- 출생 연도로 변환된 데이터(또는 원본 개월 수 데이터)를 바탕으로, 해당 강좌를 들을 수 있는 아이들의 총 개월 수 범위를 계산하여 `minAge`(최소 개월 수)와 `maxAge`(최대 개월 수) 정수형 컬럼에 각각 매핑할 것.
- 예외 처리: 파싱할 수 없는 포맷이거나 정보가 없는 경우 에러를 내지 말고 `null` 처리하는 방어 코드 포함.

### [목표 DB 스키마 구조]
파싱된 결과는 아래의 공통 규격으로 출력되어야 함:
1. `startDate` (Date, YYYY-MM-DD)

### [마트별 원문 데이터 패턴 및 파싱 규칙]

#### 1. 롯데마트 문화센터 파싱 규칙
- **원문 예시 1 (일정/요일/시간):** `2026.09.12 (토) 17:20~18:00`
  * `startDate`: `2026.09.12` -> `2026-09-12`
  * `days`: `(토)` -> `['SAT']`
  * `startTime` / `endTime`: `17:20`, `18:00`으로 분리
- **원문 예시 2 (수강료/회차 필드):** `3회 18,000원`
  * `totalSessions`: 숫자 `3` 추출
  * `round`: 롯데마트는 별도 차수 표기가 없으므로 `null` 처리

#### 2. 이마트 컬처클럽 파싱 규칙
이마트는 제목이나 기간 필드에 차수와 회차, 기간이 섞여 있는 경우가 많음.
- **원문 패턴 예시 A:** `[3차-11/6~11/27] 4회, 신체놀이 짐짐펀 ... (금)`
  * `round`: `3차`에서 숫자 `3` 추출 (`round = 3`)
  * `startDate` / `endDate`: `11/6~11/27` -> 현재 연도(예: 2026년)를 붙여 `2026-11-06`, `2026-11-27`로 변환
  * `totalSessions`: `4회`에서 숫자 `4` 추출 (`totalSessions = 4`)
  * `days`: `(금)` 또는 `금` -> `['FRI']`
- **원문 패턴 예시 B:** `월 15:40 ~ 16:20` + 강좌 기간 필드 `20261012 ~ 20261123`
  * `round`: 표기 없으므로 `null`
  * `startDate` / `endDate`: `20261012` -> `2026-10-12`, `20261123` -> `2026-11-23`
  * `days`: `월` -> `['MON']`
  * `startTime` / `endTime`: `15:40`, `16:20`으로 분리
