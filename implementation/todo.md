[개선사항5] 사용자 글쓰기 [스팟 검색 및 신규 장소 처리] 최종 플로우 스펙 (ex. 첫글쓰기 등)
입력 조건 및 최적화 (Debounce)

유저가 장소 검색창에 3글자 이상 입력 시 검색 시작.

매 글자마다 API가 폭주하는 것을 막기 위해 디바운스(0.3초 지연)를 적용하여 마지막 키워드 입력 직후에만 쿼리 수행.

2단계 검색 구조 (Cache-Aside / Fallback)

1단계 (내부 DB 우선 조회): 중분류 상관없이 우리 스팟 DB 전체를 대상으로 키워드 매칭 검색.

2단계 (외부 API Fallback): 우리 DB에 검색 결과가 없거나 부족한 경우, 자동으로 네이버/카카오 로컬 API를 호출하여 외부 장소 리스트를 함께 노출.

미등록 장소 선택 시 예외 처리 (Auto-Upsert)

유저가 외부 지도 API 결과에서 원하는 장소를 탭하는 순간, 해당 장소의 기본 정보(상호명, 주소, 좌표 등)가 우리 DB에 자동으로 안전하게 복사(Upsert)되어 스팟으로 등록.

등록과 동시에 해당 스팟이 선택된 상태로 자연스럽게 다음 글쓰기 단계로 진입.

   - 선택된 장소의 고유 ID(`spot_id`)가 제휴 상품 데이터와 1:1로 안전하게 매핑되어 저장되어야 합니다.

   - 사용자가 보는 '스팟픽' 지도 화면에서, `spot_id`가 매핑되어 있고 '노출 활성화'된 제휴 상품이 존재하는 스팟인 경우, 일반 마커와 차별화된 **특별 마커(예: 특가 마커, Hot 마커 등)**로 시각적으로 강조되어 렌더링되도록 구현해 주세요.
   - 유저가 해당 마커나 상세 카드로 진입했을 때 연동된 제휴 상품/링크로 자연스럽게 연결될 수 있도록 백엔드 및 프론트엔드 연계 구조를 잡아주세요.
