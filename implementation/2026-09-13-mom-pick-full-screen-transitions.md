# 맘스픽 메인 화면 항상 동일하게 노출 + 로그인/첫글쓰기 완전한 화면 전환

## 구현 대상
사용자 지시(2026-09-13):
> 아직 로그인 유저든 비로그인 유저든 맘스픽으로 하단 버튼 눌러서 가면 맘스픽의
> 메인화면만 보여야돼... 로그인하러가기라던가 첫글쓰기 같은거 보이면 안돼..
> 그냥 새싹맘 유저처럼 맘스픽 화면 동일하게 보여야돼.
> 그리고 여기서 뭔가 누르려고 하면그때 비로그인 유저는 로그인 인증화면으로
> 완전 전환되는거고 로그인했는데 첫글 아직 안쓴 유저는 첫글쓰기로 완전히
> 화면이 전환되어야해.
> 지금은 첫글쓰기할때 아래 맘스픽 화면 메뉴가 같이나옴.. 공존이 아니고
> 글쓰기 화면으로 완전히 전환되어야해.

## 구현 일시
2026-09-13

## 변경 전 상태(문제)
- `MomPickView`의 글쓰기 영역이 상태별로 서로 다른 문구를 노출했다:
  - `guest`: "✍️ 로그인하고 후기 남기기" 버튼
  - `not_sprout_yet`: "✍️ 첫 글 쓰고 맘스픽 시작하기" 버튼
  - `allowed`: 실제 `SurveyReviewComposer`(장소선택 등 실제 작성 폼)
  → 로그인/등급 상태가 화면에 그대로 드러나 있었다(요구사항: 보이면 안 됨).
- `guest`가 글쓰기를 시도하면 `LoginPromptModal`(반투명 배경의 하단 시트
  모달)이 떴다 — 뒤의 맘스픽 화면과 하단 탭이 함께 비쳐 보였다.
- `not_sprout_yet`이 안내 모달의 "첫 글 쓰러 가기"를 누르면 같은 `/mom-pick`
  페이지 안에서 `SurveyReviewComposer`를 그 자리에 드러내고(reveal)
  스크롤만 했다 — 헤더/피드/하단 탭이 계속 함께 보였다(공존).

## 변경 사항

### 1. `src/components/community/mom-pick-view.tsx`
- **글쓰기 영역을 상태 무관 동일하게**: `guest`/`not_sprout_yet`/`allowed`
  전부 `<SurveyReviewComposer>`를 그대로 렌더링한다(장소선택 1단계 포함,
  `allowed`가 보던 것과 완전히 동일). `guest`/`not_sprout_yet`에는 이미
  피드 영역에 쓰던 것과 동일한 "투명 인터셉트 레이어" 패턴을 그대로 적용해,
  실제 클릭만 가로챈다(기존 서로 다른 문구의 소프트월 버튼은 제거).
- **완전한 화면 전환(early return)**: `isFullScreenComposerOpen`/
  `isGuestWritePromptOpen` 상태가 켜지면, 컴포넌트가 헤더·배너·글쓰기·피드
  전체를 반환하지 않고 그 화면(글쓰기 전용 화면 / `LoginPromptModal`)만
  단독으로 반환한다 — CSS로 배경 위에 덮어씌우는 방식이 아니라, 그 상태일 땐
  아예 그 화면만 DOM에 존재한다. 이렇게 해야 "완전 전환"이라는 요구와
  접근성(배경 콘텐츠가 여전히 포커스/스크린리더에 잡히는 문제) 둘 다
  만족된다. `RootLayout`이 하단 탭을 모든 페이지에 항상 렌더하지만, 이
  화면은 `fixed inset-0`(z-[100])이라 시각적으로 그 영역까지 전부 덮는다 —
  별도 `/mom-pick/write` 라우트를 새로 만들지 않고도(제5장 제4조 기존 구조
  우선) "화면 전환"처럼 동작한다.
- `isComposerRevealed`/`composerRef`(inline reveal + scrollIntoView) 로직은
  전부 제거 — 더 이상 필요 없다.
- `SaessakMomGuideModal`의 "첫 글 쓰러 가기"는 이제 `isFullScreenComposerOpen`을
  true로 바꾼다(기존 안내 모달 자체는 그대로 유지 — 작은 카드형 확인 단계로
  남긴다, 사용자 지시가 이 단계 자체의 제거를 요구하지는 않음).

### 2. `src/components/community/login-prompt-modal.tsx`
반투명 배경 + 하단 시트(bottom-sheet) 모달에서 **불투명(bg-white) 전체 화면**
(`fixed inset-0 z-[100] flex flex-col`)으로 바꿨다. 뒤의 화면이 전혀 비치지
않고, 상단에 닫기(✕) 버튼만 남긴다. `LoginPromptModal`은 이 화면(mom-pick-view)
에서만 쓰여(다른 소비처 없음) 이 컴포넌트 자체의 의미를 "로그인 완전 전환
화면"으로 바꿔도 안전하다.

### 3. `src/components/community/saessak-mom-guide-modal.tsx`
동작은 그대로(작은 안내 카드)이고, 파일 상단 주석만 "같은 화면 안에서
reveal"이라는 더 이상 사실이 아닌 설명을 "전체 화면 전환으로 이어진다"로
수정했다.

    확인.
  - guest가 로그인 레이어를 눌러도 헤더/피드 없이 전체 화면 로그인 화면만
    보임을 확인.
- `npm run build`: 성공.

## 특이 사항
- 별도 `/mom-pick/write`, `/login` 같은 새 라우트는 만들지 않았다 — 기존
  구조(같은 컴포넌트 안에서 상태에 따라 반환 트리를 바꾸는 것) 위에서
  "완전 전환"을 구현했다. URL(`/mom-pick`)은 화면 전환 중에도 바뀌지 않는다
  — 사용자 지시가 URL 변경을 요구하지는 않았고, 뒤로가기 버튼으로 직접 이
  화면을 벗어나는 것도 요구되지 않아 추측으로 라우팅을 추가하지 않았다
  (제3장 제5조). 필요하면 후속으로 논의.
