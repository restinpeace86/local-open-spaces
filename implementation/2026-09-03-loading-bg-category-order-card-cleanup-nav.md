## 1. 로딩 화면 배경색 보정
Pillow로 `reference/loading/loading_image.gif` 배경을 직접 픽셀 측정한 결과 순백
(#ffffff)이 아니라 `#fcfcff`(252,252,255)였다(이번 세션 초반 GIF 투명화 작업 때도
동일 값을 확인한 바 있음). GIF는 반투명을 지원하지 않아 투명화 후에도 안티앨리어싱
경계의 미세한 잔여 픽셀이 원래 배경색에 가깝게 남을 수 있는데, 페이지 배경이 순백이면
그 경계가 옅게 도드라져 보인다. `app/loading.tsx`와 `bottom-tabs.tsx`의 전환 오버레이
(GIF가 노출되는 두 곳 전부)의 배경을 `#fcfcff`로 맞췄다 — 앱 전체 배경(globals.css)은
그대로 두고 GIF가 보이는 화면에만 국소 적용했다(요청 범위를 넘는 전역 톤 변경 방지).

## 2. 이벤트픽 대분류 그리드 최상단 배치
`home-view.tsx`의 "카테고리별 행사"(MajorCategoryGrid, 자연/캠핑·공공 키즈카페 등 7대
대분류) 섹션을 "예약 가능" 아래(화면 맨 아래 근처)에서 "오늘의 추천 행사"(오늘 마감/
오늘 한정 뱃지가 뜨는 Hero Carousel)보다 앞으로 옮겨 화면의 첫 콘텐츠 섹션으로 만들었다.
실제 필터링 로직(`selectedMaj`/`selectedCategory`/`handleSelectMaj`/`selectCategory`)은
전혀 바꾸지 않았다 — 렌더링 위치만 이동했다.

## 3. 카드 뱃지/높이 정리 (EventCard)
실측으로 두 가지 순수 중복을 발견해 제거했다:
- `showReservationAlert`("🚨 오늘 예약 마감")는 `status.label === '오늘 마감'`일 때만
  뜨는데, 그 값 자체가 이미지 위 오버레이(상태 뱃지)로 항상 이미 노출되고 있었다 —
  같은 정보를 문구만 바꿔 텍스트 영역에 한 번 더 보여주던 중복이라 제거.
- `reservationTag`("사전예약필요"/"예약불필요·현장방문")는 DetailModal에 이미 동일
  정보가 있어(detail-modal.tsx) 카드에서 빼도 정보 손실이 없다 — 목록 카드는 "고를지
  판단할 핵심 정보"만, 나머지는 상세 화면에서 보도록 역할을 분리했다.

남은 뱃지 중 무료/유료(is_free)·실내/야외(facility_type)는 이미지 하단 좌/우
오버레이로 옮겼다 — 이미지 영역은 오버레이 개수와 무관하게 높이가 고정(flex-[4])이라
텍스트 영역 줄 수(=카드 높이)에 영향을 주지 않는다. 텍스트 영역에는 접수 상태
(booking_status)·키즈 대상 뱃지만 남아 최대 2개로 줄었다. 정보를 삭제한 게 아니라
"이미지 오버레이(항상 무료)" / "상세 화면(예약 안내)" / "텍스트 영역(핵심 2개)"으로
재배치한 것이라 어떤 정보도 사라지지 않았다.

## 4. 하단 내비게이션 "찜" 탭 제거
사용자가 "찜된 데이터는 마이페이지 안에서 보도록 할 것"이라며 기존 규칙(Decision 019가
찜을 하단 탭으로 활성화한 것)과 상충해도 진행해 달라고 명시적으로 지시해 그대로
따랐다. `/favorites` 화면 자체와 `ENABLE_USER_BOOKMARK` 플래그는 삭제하지 않았다 —
"카테고리"(/region) 탭을 하단에서만 뺐던 기존 선례와 동일하게, 화면은 남기고 진입
경로만 없앴다. "마이페이지 안에서 찜 보기" 기능은 아직 구체적으로 지시되지 않아
임의로 설계하지 않았다(추측 금지) — 별도 지시가 오면 진행한다. 탭이 5개→4개로 줄어
그리드도 `grid-cols-5` → `grid-cols-4`로 맞췄다.

## 5. (후속) 카드 세로 높이 축소
3번 작업 직후 사용자 후속 지시: "뱃지를 이미지 쪽으로 옮겼으면 카드 높이도 줄여라 —
지금 여백이 너무 많다." 무료/유료·실내야외 뱃지가 이미지 오버레이로 옮겨가며 텍스트
영역(flex-[6])에 남은 실제 콘텐츠(제목 2줄+장소+기간+최대 2개 뱃지)가 기존 컨테이너
높이가 확보해주던 공간보다 확연히 적어져 하단에 빈 여백이 생긴 것이 원인이었다.
`ReservationOpenSlider`(현재 이용 가능/예약 가능 슬라이더, EventCard를 고정 높이
래퍼로 감싸는 유일한 소비처)의 래퍼 높이를 `h-64`(256px) → `h-56`(224px)으로 32px
줄였다 — 이미지:텍스트 4:6 비율(event-card.test.tsx가 고정 검증)은 그대로 유지한
채 전체 카드 높이만 축소했다. 스켈레톤(`ReservationOpenSliderSkeleton`)도 동일하게
맞춰 Layout Shift가 생기지 않게 했다. 다른 EventCard 소비처(홈 카테고리 그리드/검색
결과 그리드/전체보기 시트/지역 도감)는 애초에 고정 높이 래퍼가 없어(CSS Grid가
콘텐츠 기준으로 자연스럽게 높이를 정함) 뱃지 이동만으로 이미 자동으로 낮아졌다 —
별도 수정이 필요 없었다.
