# open_spaces → 노출 중분류(service_category_id) 대량 매핑 기능

## 구현 대상
사용자 지시(2026-09-05): "이제 노출 중분류가 스팟픽에서 나타나도록 할꺼야.. 현재
open_spaces에서 이 노출 중분류 매핑할 수 있도록 개선해줘. 그리고 대량의 데이터도
한꺼번에 노출중분류로 할 수 있는 것도."

## 구현 일시
2026-09-05

## 조사 — 기존 매핑 경로의 한계 (실측 확인)
개선사항10(2026-09-04)의 "중복 스팟 그룹핑" 탭은 `service_category_id`를 채우는
유일한 경로였는데, **2건 이상 중복 의심 그룹에만 적용 가능**하다(`groupDedupCandidates`가
`members.length >= 2`인 그룹만 반환). 실측 확인 결과:
- 현재 `service_category_id`가 채워진 행: **0건**(라이브 DB 직접 조회).
- 미분류(`service_category_id is null`) 상태에서 원본 `category_min`별 건수:
  `어린이놀이터` 57,692건, `공원` 25,531건, `기타` 20,121건, `어린이놀이시설(야외)`
  9,474건 등 — 대다수가 중복이 아닌 대량의 단일 행이라, 기존 그룹 기반 매핑
  경로로는 사실상 아무것도 매핑할 방법이 없었다.

이 실측을 근거로, "그룹 여부와 무관하게 원본 중분류 하나를 통째로 노출 중분류에
매핑"하는 새 경로가 필요하다고 판단했다(추측이 아니라 실제 데이터 분포에 근거).

## 변경 사항

### 신규 API — `POST/GET /api/admin/open-spaces/bulk-category-mapping`
`category_min` 값 하나(또는 미분류 `NULL`, 전용 예약값 `__NULL__`로 지정 —
`data-grid-client.tsx`의 `NULL_FILTER_TOKEN`과 동일한 관례)를 기준으로
`service_category_id`를 일괄 반영한다. id 목록을 주고받지 않고 서버에서
`WHERE category_min = X [AND service_category_id IS NULL]`로 직접 UPDATE해
수만 건 단위(실측: 최대 57,692건)도 안전하게 처리한다.
- `GET`: 미리보기 — 실제로 적용하지 않고 대상 건수만 `count: 'exact', head: true`로
  집계해 반환.
- `POST`: 실제 적용 — `.update({...}, { count: 'exact' })`로 갱신된 행 전체를
  응답으로 돌려받지 않고 건수만 받는다(몇만 건짜리 행 전체를 페이로드로 돌려받는
  것은 불필요하게 무겁다).
- `only_unmapped`(기본 true): 이미 `service_category_id`가 채워진 행은 건드리지
  않는다 — 실수로 이미 검수된 매핑을 덮어쓰는 사고를 방지. 필요하면 명시적으로
  꺼서 재매핑도 가능.
- 이 대량 경로는 `spot_dedup_groups` 이력 테이블에 기록하지 않는다 — 그룹 단위
  이력과 목적이 다르고(원본 category_min 값 자체가 "무엇을 기준으로 일괄
  매핑했는지"를 이미 충분히 설명한다), 몇만 건짜리 `member_spot_ids` 배열을 매번
  쌓는 것은 실익 없이 테이블만 비대해진다.

### `spot-dedup-panel.tsx` — "🗂️ 노출 중분류 대량 매핑" 섹션 신규
"노출 중분류 관리"와 "중복 의심 그룹" 사이에 새 섹션을 추가했다: 원본 중분류
선택(→) 노출 중분류 선택 + "미매핑만 대상" 체크박스 + 미리보기(대상 건수 확인)
+ 일괄 매핑 적용(실행 전 `window.confirm`으로 확인, 대상 건수를 함께 안내). 원본
중분류 옵션은 새 API를 따로 만들지 않고 `data-grid-client.tsx`가 서버 렌더링
시점에 이미 `get_category_min_options` RPC로 조회해 둔 `filterOptions.open_spaces.
categoryMins`를 그대로 prop으로 내려받아 재사용했다(제5장 제4조 기존 구조 우선).

- 단위/컴포넌트 테스트(신규 4개, `spot-dedup-panel.test.tsx`): 원본 중분류 미선택

## 특이 사항 (정직하게 기록)
- **실제 대량 매핑(POST 적용)은 라이브로 실행하지 않았다** — 몇만 건 단위로 되돌리기
  어려운 실제 데이터 변경이라, 관리자가 노출 중분류 목록을 먼저 정리한 뒤 직접
  판단해 실행할 몫으로 남겼다. GET 미리보기에 해당하는 count 조회 로직은 이미
  검증된 것과 동일한 `.eq()/.is()` 조합이라 별도 재확인 없이도 신뢰할 수 있다고
  판단했다.
- **"노출 중분류가 스팟픽에서 나타나도록"(사용자 발언의 궁극 목표)는 이번 범위에
  포함하지 않았다** — 사용자 메시지를 "지금 할 일: 매핑 개선/대량화" + "앞으로의
  목표: 스팟픽 노출"로 해석해, 이번엔 명시적으로 요청된 매핑 인프라만 구현했다.
  스팟픽 화면(`spot-category-filter.tsx`/`map-explorer.tsx`)이 `category_min`이
  아니라 `service_category_id` 기준으로 필터링하도록 바꾸는 작업은 자연스러운
  다음 단계로, 별도 요청 시 진행을 제안한다.
- 대량 매핑은 원본 `category_min` 단위로만 동작한다 — "검색어/출처 등 다른 조건을
  조합한 대량 매핑"은 이번 범위에 포함하지 않았다(사용자가 예시로 든 것도
  "노출 중분류로 대량 매핑"이었지 복합 필터 조합은 아니었음 — 필요 시 별도 확장 제안).
