# 스마트 검색 쿼리 — 상호명이 이미 "[지역명]점"인 경우 지역명 중복 방지

## 구현 대상
사용자 지시: "현재 임성근국가공인진갈비 김포점 해당 이름으로 가게이름이
되어있는데 굳이 여기에 김포를 뒤에 붙여서 임성근국가공인진갈비 김포점
김포로 네이버 search api에 호출중인거 같더라.. 이 경우는
임성근국가공인진갈비 김포 이렇게 조회 호출하도록 해."

## 구현 일시
2026-09-07

## 원인
[[2026-09-07-blog-self-healing-and-text-normalization]]에서 만든
`buildSmartBlogQuery(name, sigunguName)`가 상호명 뒤에 무조건 지역 핵심명을
붙이기만 했다 — "상호명 자체가 이미 지역명을 포함하고 있는 경우"를 고려하지
않아, "임성근국가공인진갈비 김포점"처럼 이름 자체에 지역명("김포")과
지점 접미사("점")가 이미 들어있는 상호에도 지역명을 또 붙여
"임성근국가공인진갈비 김포점 김포"라는 중복 검색어를 만들고 있었다. 이는
원래 todo.md의 예시("쿠우쿠우 명월점"과 같이 되었을 경우 쿠우쿠우 명월로
검색)에서 다루던 바로 그 사례인데, 실제 구현 시 이 분기 처리를 빠뜨렸다.

## 변경 사항
`src/lib/admin/naver-blog-search.ts`의 `buildSmartBlogQuery`: 상호명이 이미
`"[지역명]점"`으로 끝나면(예: "OO 김포점") 지역명을 추가로 붙이지 않고
`"점"`만 뗀다(→ "OO 김포"). 그 외의 경우는 기존처럼 상호명 뒤에 지역명을
붙인다.

## 검증
- `src/lib/admin/naver-blog-search.test.ts`에 2건 추가: "임성근국가공인진갈비
  김포점" + "경기도 김포시" → "임성근국가공인진갈비 김포"(사용자가 제시한
  실제 사례 그대로), "김포공항한식뷔페"(지역명은 포함하지만 "점"으로 끝나지
  않는 경우) + "경기도 김포시" → "김포공항한식뷔페 김포"(기존 동작 유지 —
  이 경우는 중복이 아니므로).
- `npx tsc --noEmit` / `npm run test`(115개 파일, 1268개 테스트) /
  `npm run build` 전체 통과.

## 2026-09-07 후속 재수정 — "점" 매칭 기준을 지역명 일치에서 무조건으로 완화
사용자 재지적: "이유있는감자탕 상인월성점처럼.. 상호명에 +점으로 끝나면
지역명 붙이지 말고.. 그대로 상인월성으로 점만 빼고.. 지역명은 추가하지말고..
이유있는감자탕과 같이 +점으로 안끝나면 이유있는감자탕 달서 같이 붙여줘"

위 1차 수정은 "상호명이 [추출한 지역명]+점으로 끝날 때만" 점을 뗐는데,
"상인월성"은 시군구 핵심 지역명("달서")과 전혀 무관한 지점명(동 이름)이라
이 조건에 걸리지 않아 여전히 "이유있는감자탕 상인월성점 달서"라는 중복
검색어가 만들어졌을 것이다. 규칙을 단순화했다 — **상호명이 "점"으로
끝나기만 하면**(지역명과 일치 여부 무관) 지역명을 아예 붙이지 않고 "점"만
떼고, "점"으로 끝나지 않을 때만 지역명을 붙인다.

### 재검증

  달서구" → "이유있는감자탕 상인월성"(달서와 무관해도 점만 뗌), "이유있는감자탕"
  (점 없음) + "대구광역시 달서구" → "이유있는감자탕 달서".
