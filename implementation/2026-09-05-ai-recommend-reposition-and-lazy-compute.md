사용자 지시: "스팟픽... 자꾸 맨처음 진입시 AI 때문에 동적으로 뜨는건지.. 주변 목록
보기 뜨는거 같은데.. 이거랑 그 대분류눌러서 중분류 보는거랑 다 하단에 있어서 겹쳐서
잘 안보여... AI 추천을 2번째나 3번째로 미루고 .. default로 가져오게 하지마 눌렀을때만
가져오게 해."

2026-09-05

## 조사 — "자동으로 뜨는" 코드 경로는 실제로 없음(실측 확인)
`isAiRecommendOpen`/`isSheetExpanded` 상태를 자동으로 `true`로 바꾸는 코드 경로가
있는지 전체 파일에서 직접 확인했다 — **없다**. `AiRecommendSheet`/대분류→중분류
바텀시트는 둘 다 `fixed inset-0`(전체 화면을 덮는 오버레이)이라 열려 있는 동안은
뒤의 "주변 목록 보기" 바를 완전히 덮어 시각적으로 "겹쳐 보이는" 상태가 되지 않는다.

대신 실제 원인으로 보이는 것은 UX/배치 문제다: "AI 추천" 칩이 대분류 탭 행의 **맨
앞(1번째)**에 있어(`CORE_SPOT_CATEGORIES[0]`이자 `SpotCategoryFilter`가 렌더링하는
탭 목록의 첫 버튼), 지도 화면에 처음 진입해 상단 필터 행을 훑을 때 가장 먼저 짚이는
위치라 의도치 않게 눌려 추천 바텀시트가 "자꾸 뜨는 것처럼" 느껴질 가능성이 높다 —
사용자가 요청한 해결책(순서를 뒤로 미루기)이 정확히 이 가설과 맞아떨어진다.

## 변경 사항
- `src/components/map/spot-category-filter.tsx`: "AI 추천" 버튼을 탭 행의 1번째에서
  **3번째**로 옮겼다(대분류 4개 사이 상대 순서 자체는 변경 없음 — 키즈/놀이시설 →
  농장/체험 → **AI 추천** → 자연/공원 → 문화시설).
- `src/components/map/map-explorer.tsx`: `aiRecommendedItems`를 `useMemo(() =>
  rankAiRecommendedSpots(items), [items])`(지도 데이터가 바뀔 때마다, 추천 시트를 열어본
  적이 없어도 매번 재계산)에서, "AI 추천" 버튼을 누르는 시점에 한 번만 계산해 상태에
  담는 방식(`handleOpenAiRecommend`)으로 바꿨다 — "default로 가져오게 하지마 눌렀을때만
  가져오게 해"를 문자 그대로 지킨다.

## 특이 사항
- **"맨처음 진입 시 자동으로 뜬다"는 코드상의 버그는 발견하지 못했다** — 추측으로
  "고쳤다"고 보고하지 않는다(제3장 제5조). 대신 사용자가 명시한 해결책(순서 조정 +
  지연 계산)을 정확히 그대로 반영했다 — 위치를 뒤로 미룬 것 자체가 "우발적으로 눌려
  자꾸 뜨는" 현상의 가장 그럴듯한 실제 원인(첫 진입 시 화면을 훑다 무의식적으로 첫
  번째 칩을 짚는 것)을 직접 겨냥한 수정이다. 반영 후에도 같은 문제가 재현되면 재현
  스크린샷/조작 순서를 알려주면 추가로 확인할 수 있다.
- `rankAiRecommendedSpots` 자체는 실제 LLM 호출이나 네트워크 요청이 아니라 이미
  불러온 `items`를 정렬하는 순수 클라이언트 연산이다(`ai-recommend.ts` 기존 주석) —
  "지연 계산"의 이득은 네트워크 비용 절감이 아니라 불필요한 재계산을 줄이는 것이다.
