# [마이리얼트립 상품 → 우리 스팟 역방향 매칭 (소거법)]

## 구현 대상
사용자 지시(2026-09-16): "몇백개의 키즈카페중에 마이리얼트립에 있는건 46개 ?
어쨌든 키즈카페말고도 등록해야할텐데 - 어떻게 하는게 가장 편한 방법일까?" →
"한번에 일괄 후보 뽑아두는게 낫지 예를들어 키즈카페 46개 역으로보면
마이리얼트립에서 나온 46개에 대하여 우리쪽 연결하고 그 연결한건 안나와서
내가 연결했다는걸 인지할수 있는것이다 그럼 빠르게 만들고 없어진거확인하고
그다음거하고 한건 사라지고.. 그렇게 소거법으로 가야하지 않을까?"

## 구현 일시
2026-09-16

## 문제 인식
우리 DB의 스팟(수백 개)마다 마이리얼트립을 검색하는 기존 방식은, 실제로
마이리얼트립에 상품이 있는 스팟이 극소수(예: "키즈카페" 검색 전국 46건)라
비효율적이다. 반대로 마이리얼트립 상품(적은 수) 쪽에서 시작해 각각에 맞는
우리 스팟을 찾아 연결하면, 이미 연결된 건 눈에 보이게 표시해 "소거법"으로
남은 것만 처리해 나갈 수 있다.

## 변경 사항
### 백엔드
- `GET /api/admin/spot-myrealtrip-link/by-gids?gids=g1,g2,...`: 주어진 gid
  목록 중 이미 어떤 스팟과 연결된 것이 있는지 한 번에 조회(스팟명까지 join).
- 기존 `POST /api/admin/spot-myrealtrip-link`(스팟 상세에서 승인할 때 쓰던
  것과 동일한 엔드포인트)를 그대로 재사용 — 호출 방향만 반대(스팟 상세 →
  마이리얼트립 검색이 아니라, 마이리얼트립 검색 → 스팟 선택)일 뿐 저장하는
  데이터 구조는 동일해 백엔드 변경이 필요 없었다.

### 관리자 UI (`MyRealTripSearchPanel`)
- 검색 결과가 나올 때마다 해당 gid들의 연결 상태를 조회해, 이미 연결된
  카드에는 "✅ {스팟명}에 연결됨" 배지를 표시(초록 테두리)하고, 상단에
  "(연결됨 N건)"으로 진행 상황을 보여준다.
- 상세 모달에 "🔗 우리 스팟과 연결" 버튼 추가 — 클릭하면 기존
  `SpotPicker`(우리 DB 스팟 검색, `spot-picker.tsx` 그대로 재사용, 제5장
  제4조)로 스팟을 골라 연결한다. 연결 시점에 마이링크가 자동 생성되어
  저장되고(위 POST 엔드포인트 내부 로직 그대로), 성공하면 해당 카드가 즉시
  "연결됨"으로 바뀐다(소거).
- 기존 "🔗 제휴 상품으로 등록"(curated_items 마케팅 목록에 등록)과는 완전히
  별개 기능으로 나란히 둔다 — 하나는 "마케팅 상품 목록에 올리기", 다른 하나는
  "이 스팟의 상세 화면에 구매 버튼 붙이기"로 목적이 다르다.

## 검증
- `npx tsc --noEmit`, `npm run test`(전체 1842개, 신규 3개 포함), `npm run build`
  모두 통과(`/api/admin/spot-myrealtrip-link/by-gids` 라우트 정상 등록 확인).
- 실제 스팟/gid로 재현: 연결 → `by-gids` 조회 시 정확히 그 gid만 연결됨으로
  반환(다른 gid는 제외됨) 확인 → 연결 해제 → 재확인까지 확인. 테스트 데이터는
  정리했다.
