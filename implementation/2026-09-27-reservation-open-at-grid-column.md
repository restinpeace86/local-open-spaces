# events 그리드에 "예약 오픈 알림"(next_reservation_open_at) 컬럼 표시

## 구현 대상
사용자 지시(2026-09-27): "현재 이벤트쪽에 공공키즈카페랑 서울형키즈카페는
규칙에 의하여 예약일자가 들어가있는걸로 아는데 그규칙이 어떻게 되지? 여기에
대하여 관리자 화면에서 좀 볼수있도록 해줘.."

## 배경
`next_reservation_open_at`은 이미 존재하는 컬럼이고(2026-09-20
[[2026-09-20-event-reservation-open-reminder-push]]), `EVENTS_COLUMNS`가
select도 하고 있었지만, 그리드 목록에는 컬럼으로 노출되지 않았다 — 관리자가
행마다 상세 팝업(`raw-data-modal.tsx`의 `ReservationOpenAtEditor`)을 열어야만
값을 볼 수 있었다.

## 규칙 설명(사용자 질문에 대한 답)
- `next_reservation_open_at`은 **어댑터가 자동으로 계산하지 않는다** —
  서울시가 자치구별 그룹(권역) 구성을 시기별로 바꿔온 전례가 있어(2026-04
  공지문과 2026-09 공지문의 그룹 구성이 서로 다름), 코드에 규칙을 하드코딩하면
  서울시가 또 바꾸는 순간 조용히 틀린 값이 나갈 위험이 있다고 판단해
  관리자가 상세 팝업에서 직접 입력하는 방식으로 확정했다([[2026-09-20-event-reservation-open-reminder-push]]).
- 최초 값은 실제 서울시 공지문을 반영한 1회성 시드 스크립트로 채웠다:
  - `서울형키즈카페`(야외 팝업형 9건): 2026-09 공지문(오감/체험/모험/성장
    4개 그룹, 21개 자치구) → 월요일 10/12/14/16시 KST.
  - `공공키즈카페`(동네 상설 지점 268건): 2026-04 공지문(그룹1~4, 25개
    자치구 전역) → 화요일 09/11/13/15시 KST. `sigungu_name`이 없는 133건은
    자치구를 특정할 수 없어 스킵.
- 이후 회차는 관리자가 매주 직접 `ReservationOpenAtEditor`로 갱신해야
  한다(자동 반복 계산 없음) — 이번에 실측 확인한 결과 **두 카테고리 전부
  마지막 시드(9/20~9/22) 이후로 한 번도 갱신되지 않아 현재는 전부 과거
  값으로 남아있고, 알림도 나가지 않는 상태**였다. 이번 컬럼이 바로 이 문제를
  한눈에 보여준다.

## 변경 사항
`src/components/admin/data-grid-client.tsx`:
- events 탭 전용 컬럼 "예약 오픈 알림" 추가(접수상태 컬럼 다음, 수정/적재일
  컬럼 이전).
- 값 표시 규칙: `MM/DD(요일) HH:mm` 포맷 + 상태 뱃지 — 지금 시각보다 미래면
  녹색 "예정", 과거(또는 지금)면 빨간색 "지남"(다음 회차 갱신을 놓쳤다는
  신호), 값이 없으면 회색 "미설정".

## 검증
- `src/components/admin/data-grid-client.test.tsx`(신규 4개): 미래 값→"예정",
  과거 값→"지남", null→"미설정", open_spaces 탭에는 컬럼 자체가 안 보임.
- `npx tsc --noEmit` / `npm run test`(206개 파일 2,399개) / `npm run build`
  모두 통과.

## 특이 사항
- 이번 변경은 표시만 추가했다 — 값을 자동으로 다시 계산하거나 갱신하는
  로직은 추가하지 않았다(기존 설계 결정 유지). 관리자가 이 컬럼으로 "지남"
  상태를 보고 직접 다음 회차 시각을 입력해야 알림이 다시 나간다.
- 사용자가 함께 물어본 "찜해두면 예약 오픈 10분 전에 알림 가는지"는 이미
  구현돼 있다([[2026-09-20-event-reservation-reminder-bookmark-redesign]]):
  이 이벤트를 찜(`user_bookmarks`)한 열심맘 등급 이상 유저에게, 10분마다
  도는 배치가 `next_reservation_open_at`이 지금부터 5~15분 사이인 이벤트를
  찾아 웹 푸시를 보낸다(GitHub Actions cron 특성상 "정확히 10분 전"이 아니라
  "약 5~15분 전"). 다만 이 알림도 `next_reservation_open_at`이 미래 값으로
  채워져 있어야만 작동하므로, 지금처럼 전부 "지남" 상태면 알림도 나가지
  않는다 — 이번 컬럼이 바로 그 전제조건을 관리자가 직접 확인할 수 있게 해준다.
