# [마이리얼트립 검색: 도시가 실제 검색에 반영되지 않던 버그 수정]

## 구현 대상
사용자 지적(2026-09-16): "도시를 서울로 한 상태에서 검색해도 서울하고 무관한
상품들이 많이 나오는데?"

## 구현 일시
2026-09-16

## 원인
공식 검색 API(`POST /v1/products/tna/search`)에는 애초에 `city` 파라미터가
없다 — `city`는 `categories` API(1단계, 카테고리 값 확보용)에만 쓰이는
파라미터다. 화면의 "도시" 입력칸이 검색 요청 바디에 전혀 포함되지 않아,
`category: "kids"`로 필터링해도 인천/대전/심지어 해외(도쿄) 상품까지 섞여
나오는 것을 실측으로 재현 확인했다.

## 변경 사항
### `src/components/admin/myrealtrip-search-panel.tsx`
검색 시 "도시" 값을 키워드 앞에 자동으로 합쳐서 보낸다(`buildEffectiveKeyword()`):
```
도시="서울", 키워드="키즈 체험" → 실제 전송 keyword: "서울 키즈 체험"
```
키워드에 이미 도시명이 포함돼 있으면 중복으로 붙이지 않는다. 화면에도 이
동작을 정직하게 안내하는 문구를 추가했다 — "완전한 위치 필터는 아니라
무관한 지역 상품이 일부 섞일 수 있습니다."

## 검증 및 한계(정직하게 기록)
- `keyword: "서울 키즈 체험"` (도시+구체적 키워드 조합) → 실측 결과가 서울
  위주로 크게 개선됨을 확인(뮤지컬 알사탕/국립중앙박물관 도슨트/궁궐투어 등).
- 다만 `keyword: "서울 체험"`처럼 도시+매우 일반적인 단어 조합은 여전히
  인천/대전 상품이 섞여 나오는 것도 함께 확인했다 — 이는 마이리얼트립 검색
  API 자체가 키워드 연관도 기반 매칭이지 엄격한 AND/지역 필터가 아니기
  때문이다. 이번 수정은 "도시가 검색에 전혀 반영 안 되던" 버그는 확실히
  고쳤지만, API 자체의 fuzzy 매칭 특성상 완전한 지역 필터링은 클라이언트
  쪽에서 보장할 수 없다(문자열로 제목에 도시명이 없는 상품을 강제로 걸러내는
  것은 실제로 관련 있는 상품까지 잘못 없앨 위험이 있어 임의로 하지 않았다 —
  제3장 제5조 추측 금지).

## 검증
- `npx tsc --noEmit`, `npm run test`(전체 1828개, 신규 2개 포함), `npm run build`
  모두 통과.
- 실제 API로 재현: "서울 키즈 체험"은 크게 개선, "서울 체험"은 여전히 일부
  무관한 결과가 남음을 확인(위 한계 섹션 참고).
