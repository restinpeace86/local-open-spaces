# events 그리드에 예약 오픈 알림 "규칙" 참고표 추가

## 구현 대상
사용자 지시(2026-09-27): "어 맞아 규칙에 대하여 지금 이전에 공지문대로 한거
그거를 관리자 화면에 어딘가에서 볼수있게해달라는거야.." — 직전에 추가한
"예약 오픈 알림" 컬럼은 각 행의 현재 값만 보여줄 뿐, 그 값이 어떤 규칙
(서울시 공지문)으로 나온 건지는 여전히 `implementation/`문서와 1회성
시드 스크립트 안에만 있었다는 지적.

## 변경 사항
`src/components/admin/data-grid-client.tsx`:
- `RESERVATION_OPEN_RULE_REFERENCE` 상수 추가 — 이미 두 1회성 시드
  스크립트(`2026-09-20-seed-gonggong-kids-cafe-next-reservation-open-at.mjs`,
  `2026-09-20-seed-seoul-kids-cafe-next-reservation-open-at.mjs`)에
  하드코딩돼 있던 `DISTRICT_OPEN_HOUR_KST` 매핑표를 그대로 옮겨 화면
  참고용으로만 노출한다(새 계산 로직 추가 아님).
- events 탭에 "▾ 예약 오픈 알림 규칙 보기(공공키즈카페/서울형키즈카페)"
  토글 버튼 추가(기존 "상세 필터 더보기"와 동일한 UI 관례) — 펼치면
  두 카테고리 각각의 공지문 시행일/요일/그룹별 시각/자치구 목록을 보여준다.
  "자동으로 다시 계산되지 않으며 서울시가 규칙을 바꾸면 이 표도 관리자가
  함께 갱신해야 한다"는 안내문도 함께 표시.

## 검증
- `src/components/admin/data-grid-client.test.tsx`(신규 2개): open_spaces
  탭에는 토글이 안 보임, events 탭에서 토글을 펼치면 두 카테고리 규칙표가
  보이고 다시 접으면 사라짐.
- `npx tsc --noEmit` / `npm run test`(206개 파일 2,401개) / `npm run build`
  모두 통과.

## 특이 사항 — 사용자의 두 번째 질문에 대한 실측 답변
"공공키즈카페 원천데이터가 들어오면 매번 예약일자 있고 자동으로 다음
예약 오픈시각이 업데이트 되지 않나?"라는 질문에 실측으로 확인한 결과는
**아니다**였다:
- `seoul-yeyak-adapter.mjs`는 이미 `공공키즈카페`/`서울형키즈카페`를
  `isManualOnlyKidsCafeCategory`로 명시적으로 자동 동기화 대상에서
  제외하고 있다(RCPTBGNDT가 이 두 카테고리에서 "다음 예약 오픈 시각"과
  같은 의미인지 확인된 바 없다는 이유, 제3장 제5조 추측 금지).
- 실제 DB 값으로 재확인: 공공키즈카페 행의 `raw_data.RCPTBGNDT/RCPTENDDT`는
  "2026-08-25 ~ 2026-09-07"(2주 접수기간) 그대로였고, 이 값은 지금(9/27)
  기준 이미 3주 전에 끝난 값인데도 `updated_at`은 "2026-09-26"으로 최근에
  재수집이 있었음을 보여준다 — 즉 **소스 API 자체가 이 필드를 주기적으로
  갱신해주지 않는다(정적인 최초 등록 기간에 가깝다).** 코드의 기존 판단
  (자동 동기화 제외)이 실측으로도 맞았음을 재확인했다.
- 결론: 지금 구조(관리자가 매주 직접 `ReservationOpenAtEditor`로 갱신)를
  유지해야 하고, 이번에 추가한 "예약 오픈 알림" 컬럼(지남/예정/미설정
  뱃지)이 그 갱신을 놓쳤는지 확인하는 유일한 수단이다.
