# [수기 예약 입력 간편화 + 일간/주간/월간 노출 검증]

## 구현 대상
직전 작업(네이버 예약 호환 수동 예약 등록 폼)에 대한 사용자 후속 요청(2026-09-21):
"이 필드들을 간편하게 입력하는법이없나? 그리고 여기서 source는 화면에
안보여도 될거같고 자동으로 manual 고정 저장이니.. 그리고 여기서 등록한게
일간 주간 월간 화면 3개에 잘 나타나는지도 확인해봐."

## 1) source 화면 노출 — 이미 원하는 대로 되어 있음(변경 없음)
확인 결과 `AddBookingFab`에는 애초에 `source`를 고르는 입력 필드가 없다 —
항상 서버 액션(`createBooking`)이 `'manual'`로 고정 저장한다. 다만 예약
목록 카드(`BookingCard`)에는 "수기 등록"/"네이버 예약" 채널 뱃지가 표시되는데,
이건 폼의 입력 필드가 아니라 목록에서 출처를 구분하는 표시라 다른 항목이라
AskUserQuestion으로 확인했다 — **"뱃지처럼해서 보여줘 수기등록인지 네이버
예약인지"** → 그대로 유지, 변경 없음.

## 2) 일간/주간/월간 3개 화면 노출 검증 — 실측 완료
임시 스크립트(`scripts/tmp-verify-manual-booking-views.mjs`, 검증 후 삭제)로
운영 DB에 임시 auth 유저 + `partners` 행을 만들고 `source='manual'`,
`product_name`/`total_price` 채운 테스트 예약을 삽입한 뒤, 세 화면(`today/
weekly/monthly` page.tsx)이 실제로 쓰는 것과 동일한 select/필터 쿼리를
그대로 재현해 조회했다. 결과: **세 화면 모두 정상 조회됨**(일간: 전체
필드 포함 조회됨 / 주간: 그룹핑 대상 목록에 포함됨 / 월간: 해당 날짜 집계에
포함됨). 세 쿼리 어디에도 `source`로 걸러내는 조건이 없어, 애초에 네이버
건과 수기 등록 건이 항상 함께 조회되는 구조였다. 테스트 데이터/임시 계정은
검증 직후 모두 삭제했다.

## 3) 입력 간편화
### 결제 금액 — 천 단위 콤마 자동 포맷
`src/lib/partner/format-price.ts`(신규, `format-phone.ts`와 동일한 관례):
`formatPriceInput`(입력 중 표시용, "50000"→"50,000")과 `parsePriceInput`
(제출 시 콤마 제거 후 숫자로 복원, 빈 값이면 `null`)로 분리했다.
`AddBookingFab`의 결제 금액 입력을 `type="number"`에서 `type="text"
inputMode="numeric"`으로 바꾸고(콤마 포함 문자열을 보여줘야 해서 number
타입은 쓸 수 없음), 우측에 "원" 단위를 시각적으로만 보여준다.

**접근성 이름 버그 발견 및 수정**: 처음엔 다른 필드들처럼
`<label>결제 금액(선택)<input/><span>원</span></label>` 구조로 짰더니,
`<span>원</span>`이 label의 자손이라 label의 접근성 이름(텍스트 매칭에
쓰이는 값)이 "결제 금액(선택)원"이 되어버려 `getByLabelText('결제
금액(선택)')`가 못 찾는 실제 테스트 실패로 드러났다(`aria-hidden`만
추가하는 시도는 testing-library의 텍스트 매칭 로직이 존중하지 않아
효과 없었음, 실측 확인). 최종적으로 이 필드만 `htmlFor`/`id` 명시적
연결 구조로 바꿔("원" 스팬이 label의 자손이 아니게) 해결했다 — 다른
필드는 wrapping label 구조 그대로 유지(변경 범위 최소화).

### 상품명 — 최근 등록 이름 자동완성
`AddBookingFab`에 `recentProductNames?: string[]` prop 추가, 네이티브
`<datalist>`로 자동완성 후보를 제공한다(별도 라이브러리/드롭다운 컴포넌트
없이 HTML 표준 기능만 사용 — 제5장 제4조). `src/app/partner/(tabs)/
today/page.tsx`에서 이 파트너가 등록한 최근 예약 50건 중 `product_name`이
있는 값만 뽑아 중복 제거해 전달한다(RLS가 이미 본인 것만 걸러주므로
`partner_id` 필터 불필요, 업체당 상품/객실 종류가 몇 개 안 되는 소규모
사업 특성상 최근 50건이면 충분).

  6개, `add-booking-fab.test.tsx`에 콤마 포맷/자동완성 후보 렌더 테스트
  2개 추가).
- `npm run build` 통과.
- 실측(운영 DB): 위 "2) 일간/주간/월간 3개 화면 노출 검증" 절 참고.

## 특이 사항
- `total_price` 입력을 `type="number"`에서 `type="text"`로 바꿨지만
  `inputMode="numeric"`을 유지해 모바일에서는 여전히 숫자 키패드가 뜬다 —
  실제 기능 손실 없음.
- 상품명 자동완성은 "이 파트너의 최근 50건"만 훑는 단순 구현이라, 상품
  종류가 매우 많은 업체(예: 객실 50종 이상의 대형 숙박업)에서는 자주 쓰는
  이름이 최근 목록에서 밀려날 수 있다 — 지금 이 서비스가 타겟하는 소규모
  농장/체험형 파트너 규모에서는 문제되지 않을 것으로 판단했으나, 필요하면
  "전체 고유 상품명" 방식으로 바꿀 수 있다.
