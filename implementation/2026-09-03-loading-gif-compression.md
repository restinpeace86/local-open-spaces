# [개발요청] 로딩 GIF 최대 경량화

## 구현 일시
2026-09-03

## 배경
직전 작업(로딩 이미지 교체)에서 원본 GIF가 3.1MB로 커서 사용자에게 압축을 권장했고,
사용자가 "최대한 경량화해서" 지금 바로 교체해달라고 요청.

## 구현 내용
Pillow(Python)를 설치해 직접 압축 파이프라인을 짜서 적용했다(이 환경에 gifsicle/
ffmpeg/ImageMagick 등 GIF 전용 압축 도구가 없어 Pillow로 대체 — `pip install Pillow`).

- **해상도 축소**: 480×270 → 112×63. 실제 화면에 h-24(96px 정사각형 박스, object-
  contain) 크기로만 표시되므로, 그 2배(레티나 대응) 수준이면 충분하다고 판단.
- **프레임 감소**: 64프레임 → 22프레임(원본 3프레임 중 1개만 남기고, 남은 프레임의
  duration을 3배로 늘려 체감 재생 속도는 유지). 로딩 인디케이터는 초당 프레임이
  매끄러울 필요가 없다.
- **팔레트 축소**: 256색 → 32색(전체 프레임에 공통 적응 팔레트 적용). 원본이 그라데이션
  없는 플랫 컬러 일러스트라 색상 수를 크게 줄여도 육안 차이가 거의 없음을 실제
  프레임을 640px로 확대해 직접 확인했다.
- 결과: **3,157,115 bytes → 60,317 bytes (약 52배 축소)**.

### 압축 전 검토
여러 압축 강도를 시도하며 매번 실제 표시 크기(96px 박스)로 축소한 미리보기를 직접
눈으로 확인해, 화질 저하가 실사용 크기에서 인지되지 않는 선까지만 공격적으로
압축했다(3배 확대한 이미지에서는 약간의 디더링 노이즈가 보이지만, 실제 표시
크기에서는 보이지 않음을 확인).

## 검증
### 코드 검증
정적 자산 교체만이라 코드 변경은 없음 — `npm run build` 통과만 재확인.

### 실측 검증
- Pillow로 재오픈해 프레임 수(22)/크기(112×63)/loop 설정이 의도대로 저장됐는지 확인.
- dev 서버 curl로 `/loading/loading_image.gif`가 60,317 bytes로 정상 서빙됨을 확인.

## 특이 사항
- 압축에 쓴 임시 스크립트(`compress_gif*.py`)는 세션 스크래치패드에만 있고 저장소에는
  커밍하지 않았다(1회성 변환 도구, 재사용 필요 시 재작성 가능한 간단한 스크립트).
- 원본(비압축) GIF는 `reference/loading/loading_image.gif`에 그대로 남아있다(사용자가
  직접 넣어둔 원본 자산 — 삭제하지 않음).
