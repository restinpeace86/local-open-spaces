# 공간 탐색 및 반경 검색 스펙 (spec/map/spatial-search.md)

## 1. 개요
본 문서는 `local-open-spaces` 서비스의 지도 탐색 인터페이스와 데이터 렌더링 규칙을 정의한다. 수만 건 이상의 방대한 공공 데이터를 안정적으로 처리하고, 사용자에게 쾌적한 탐색 경험을 제공하기 위한 최적화 정책을 포함한다.

---

## 2. 반경 선택 및 데이터 렌더링 정책

### 2.1. 탐색 범위 (Radius Selector) — (Updated by Decision 022, 023)
- **노출 중분류 미선택 시 (기본 화면):** 지도는 사용자의 설정 위치 기준 고정
  반경(5km) 내 데이터만 조회한다(1km/5km/10km 선택 UI는 2026-08-26에 이미
  삭제됨 — 5km 고정값만 남아 있다).
- **노출 중분류 선택 시 (Decision 023):** 반경 컷오프는 적용하지 않는다
  (5/10/20/30km 등의 반경으로 마커를 자르지 않는다). 다만 선택한 노출
  중분류(`service_categories`)에 매핑된 스팟 중 **사용자가 설정한 현재 위치가
  속한 광역(도/광역시) 단위**의 데이터만 지도/리스트에 노출한다.
  - **경기 ↔ 서울은 서로 포함**한다(경계 생활권 반영 — 예: 판교원로 68은
    경기도 성남시 분당구이므로 경기 + 서울 데이터를 함께 노출). 그 외 광역은
    자기 자신만 노출한다(예: 강릉 = 강원도만).
  - 현재 위치의 광역을 판별할 수 없으면 필터를 걸지 않는다(안전 폴백).
  - RPC(`get_spots_by_service_category`)는 그대로 두고 클라이언트
    (`map-explorer.tsx` + `src/lib/spaces/province.ts`)에서 광역 필터를 적용한다
    — 노출 중분류당 매핑 건수가 적어(Decision 022 실측 최대 2,304건) 부담이 없다.
  - 지도 스케일에 따른 마커 클러스터링(3.1 참고)은 이 경우도 동일하게 적용된다.
- **하단 바텀시트 리스트 전용 반경 (지도 광역 필터와 독립):** 하단 바텀시트에
  표시되는 결과 리스트/건수는 지도 마커의 도 단위 필터를 **적용하지 않고**,
  사용자가 5km/10km/20km 중 선택한 반경 내에서 (실시간 GPS가 없으면 설정 위치
  기준) 거리순으로 정렬해 보여준다(2026-09-08 사용자 지시 / 2026-09-10 Step 93로
  GPS 미허용 시 폴백 수정 / 2026-09-10 사용자 지시로 "바텀시트는 반경 설정이
  따로 있으니 도 단위 사전 필터 없이 반경 기준" 확정 — Decision 023). 바텀시트는
  이미 반경으로 지역이 좁혀지므로 도 경계에 걸친 인접 스팟(예: 평택에서 10km인
  천안 스팟)도 선택 반경 안이면 포함된다. 이 반경 선택은 지도 마커 렌더링에는
  영향을 주지 않는다.

### 2.2. 서비스 레이어 및 지도 탐색 정책 (Updated by Decision 010)
지도 가독성과 목적별 탐색 경험을 극대화하기 위해 상시 공간과 시한성 이벤트를 독립된 서비스 레이어로 분리하여 관리한다.

- **스팟픽 (`/nearby`) - 상시 공간 전용 지도**:
  - `/nearby` 지도는 상시 공간(`open_spaces`) 전용 지도 탐색 레이어로 작동한다. 
  - 기존의 지도 내 이벤트 레이어 토글 방식을 폐지하고, 상시 공간의 5대 카테고리 필터링 및 줌 레벨별 계층 클러스터링을 최우선 제공한다.
  - 파란 원 Overlay 및 고정 반경 칩을 제거하고 실시간 `panTo` 위치 연동을 적용한다.
  - **마커 인터랙션 (2026-09-10 사용자 지시로 개정 — 기존 "화면 고정 프리뷰
    카드 2단계" 폐지):** 프리뷰 카드는 **마커 좌표에 앵커된 오버레이**로 떠서
    지도를 움직이면 마커와 함께 이동한다(화면 중앙/하단 고정 금지). PC(호버
    가능 기기)는 **마커에 마우스를 올리면 프리뷰가 뜨고, 클릭하면 상세 카드**
    로 바로 진입한다. 모바일(터치)은 첫 탭에 프리뷰, 같은 마커 재탭에 상세
    카드. 좌표가 겹친 여러 건은 기존대로 선택 목록(MarkerGroupModal) 우선.
    리스트 항목 클릭은 항상 상세 카드 바로 진입.

- **이벤트픽 (`/events/today`) - 시한성 행사 피드**:
  - 축제, 팝업, 예약 마감 임박 행사 등 시한성 이벤트(`events`)는 지도 상의 토글 레이어가 아닌 별도의 **'이벤트픽' 피드 화면**으로 완전히 이관한다.
  - 오늘 마감 / 당일 한정 이벤트를 엄격하게 피딩하여 유저의 행사 집중도를 높인다.

## 3. 방대한 데이터 처리를 위한 성능 최적화 원칙

### 3.1. 렌더링 개수 제한 (Marker Limit & Clustering) — (Updated by Decision 022)
- **최대 마커 개수:** 데이터가 1,000개를 초과할 경우(반경 기반이든 노출
  중분류 기준 전국 조회든 동일하게 적용) **최상위 1,000개 마커만 우선
  렌더링**한다(2026-09-01 사용자 지시로 기존 200개에서 상향). 반경 기반
  조회는 거리순(사용자 중심점 기준)으로 자르고, 노출 중분류 전국 조회는
  정렬 기준점이 없어 서버가 반환한 순서대로 자른다 — 실측 결과(2026-09-08)
  노출 중분류당 매핑 건수가 최대 2,304건(표준 중분류 최대 57,692건 대비
  훨씬 적음)이라 이 상한 정책이 그대로 안전하게 작동한다.
- **초과 안내:** 1,000개 이상의 시설이 존재할 경우 하단 토스트(Toast)로
  안내한다 — 반경 기반 모드는 *"반경 내 시설이 너무 많습니다. 지도를
  확대하거나 범위를 좁혀 상세히 탐색하세요."*, 노출 중분류 전국 조회
  모드는 *"선택하신 중분류에 해당하는 시설이 너무 많습니다. 지도를
  확대해 세부 지역을 살펴보세요."*
- **클러스터링(Clustering):** 데이터가 밀집된 경우 Kakao Map SDK의 클러스터러를 사용하여 인접한 마커들을 묶어 렌더링 부하를 줄인다. 이 정책은 반경 기반/노출 중분류 전국 조회 두 모드 모두 동일하게 적용된다(변경 없음).

  CREATE INDEX idx_events_location ON public.events USING GIST(location);
