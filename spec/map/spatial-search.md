# 공간 탐색 및 반경 검색 스펙 (spec/map/spatial-search.md)

## 1. 개요
본 문서는 `local-open-spaces` 서비스의 지도 탐색 인터페이스와 데이터 렌더링 규칙을 정의한다. 수만 건 이상의 방대한 공공 데이터를 안정적으로 처리하고, 사용자에게 쾌적한 탐색 경험을 제공하기 위한 최적화 정책을 포함한다.

---

## 2. 반경 선택 및 데이터 렌더링 정책

### 2.1. 탐색 범위 (Radius Selector)
- **제공 옵션:** `1km`, `5km`, `10km` (기본값: `5km`)
- **정책:** 10km를 초과하는 탐색은 무분별한 서버 부하 방지를 위해 제한하며, 단일 반경 검색 모드를 기본으로 한다.

### 2.2. 데이터 레이어 토글 (Layer Toggle Policy)
데이터 렌더링 부하를 최소화하고 지도 가독성을 높이기 위해 상시 시설과 시한성 정보를 분리하여 관리한다.
- **시한성 정보 (`events`):** 지도 접속 시 기본 활성화(On). 축제, 팝업, 예약 마감 임박 행사 등 지금 당장 확인할 가치가 있는 정보를 우선 노출한다.
- **상시 시설 (`open_spaces`):** 기본 비활성화(Off). 지도 상단/측면의 **[상시 시설 보기] 토글 버튼**을 통해 사용자가 능동적으로 활성화할 때만 렌더링한다.

---

## 3. 방대한 데이터 처리를 위한 성능 최적화 원칙

### 3.1. 렌더링 개수 제한 (Marker Limit & Clustering)
- **최대 마커 개수:** 특정 반경 내에 데이터가 200개를 초과할 경우, 거리순(사용자 중심점 기준)으로 **최상위 200개 마커만 우선 렌더링**한다.
- **초과 안내:** 200개 이상의 시설이 존재할 경우, *"반경 내 시설이 너무 많습니다. 지도를 확대하거나 범위를 좁혀 상세히 탐색하세요."* 라는 안내 메시지를 하단 토스트(Toast)로 제공한다.
- **클러스터링(Clustering):** 데이터가 밀집된 경우 Kakao Map SDK의 클러스터러를 사용하여 인접한 마커들을 묶어 렌더링 부하를 줄인다.

### 3.2. PostGIS 공간 인덱스 및 쿼리 최적화 (Decision 002)
- 모든 공간 데이터 테이블은 `location` 컬럼에 **GIST 공간 인덱스**를 필수 적용한다.
  ```sql
  CREATE INDEX idx_open_spaces_location ON public.open_spaces USING GIST(location);
  CREATE INDEX idx_events_location ON public.events USING GIST(location);
