# AI 데이터 정제 및 자동 태깅 규칙 (spec/data/ai-rule.md)

## 1. 개요

본 문서는 `local-open-spaces` 서비스의 7대 공공 API 수집 파이프라인에서 가져오는 비정형 텍스트(장소 설명, 행사 개요 등)를 정제하고, 서비스 표준 카테고리 및 태그로 자동 분류하기 위한 AI 파이프라인 규칙을 정의한다.

모든 AI 활용은 **데이터 수집 및 정제 보조 용도로만 한정(Decision 005)**하며, 생성형 대화나 가짜 정보 생성을 방지하기 위해 엄격한 파싱 규칙을 따른다.

> **SSOT 안내 (Decision 008):** 서비스 모토·UI 카테고리·뱃지 정책의 최상위 기준 문서는 `docs/spec.md`이다. 본 문서 3.1/3.2의 DB 원본 카테고리는 유지되며, `docs/spec.md`가 정의하는 5대 UI 카테고리는 3.3의 매핑 레이어로 대응한다.

---

## 2. AI 파이프라인 역할 및 처리 범위

1. **비정형 텍스트 정제 (Text Cleaning):**
   - 공공 API 응답에 포함된 불필요한 HTML 태그, 특수문자, 중복 공백 제거
   - 요약된 설명 텍스트에서 핵심 키워드 추출
2. **표준 카테고리 자동 태깅 (Category Tagging):**
   - 수집된 원본 텍스트를 분석하여 서비스 정의 표준 카테고리 중 하나로 매핑
3. **예약 마감일 파싱 (Reservation Date Parsing):**
   - "매월 1일부터 선착순 마감", "행사 전일 18시까지" 등 비정형 텍스트로 된 예약 마감 일정을 표준 ISO 시각(`reservation_end_date`) 데이터로 변환

## 3. 표준 카테고리 분류 규칙

### 3.1. 열린 공간 (`public.open_spaces`) 표준 카테고리
- `PARK`: 근린공원, 어린이공원, 수변공원 등
- `SPORTS`: 공공체육시설, 축구장, 테니스장, 다목적 체육관 등
- `CULTURE`: 도서관, 미술관, 박물관, 문화회관 등

### 3.2. 시한성 이벤트/행사 (`public.events`) 표준 유형 (`event_type`)
- `FESTIVAL`: 지역 축제, 문화 제전
- `EXHIBITION`: 미술 전시, 박람회, 역사 전시
- `PERFORMANCE`: 야외 공연, 음악회, 연극
- `POPUP`: 단기 팝업스토어, 체험 행사
- `RESERVATION`: 지자체 공공서비스예약 시설/프로그램

### 3.3. UI 표시 카테고리 매핑 (신규, Decision 008)
`docs/spec.md`의 "가성비 놀거리 서비스" 규약은 사용자 화면에 노출할 **5대 핵심 카테고리**(체험·클래스 / 야외·자연 / 전시·박물관 / 공연·축제 / 키즈·액티비티)를 정의한다. DB의 `category`/`event_type` 원본값은 3.1/3.2의 세부 분류를 그대로 유지하고(Upsert·수집 파이프라인 영향 없음), 화면 노출 시에만 아래 매핑을 거쳐 5대 카테고리로 묶어 보여준다.

| UI 표시 카테고리 | 매핑되는 원본 `category`/`event_type` |
| :--- | :--- |
| 🌳 야외·자연 | `PARK` |
| 🏛️ 전시·박물관 | `CULTURE`, `EXHIBITION` |
| 🎪 공연·축제 | `FESTIVAL`, `PERFORMANCE` |
| 🎡 키즈·액티비티 | `SPORTS`, `POPUP`, `RESERVATION` |
| 🎨 체험·클래스 | (신규 소스 전용 — 마트 문화센터 특강 등 보완 수집 데이터에서만 발생. 기존 7대 공공 API 데이터에는 해당 없음) |

- **상태: 제안됨 (코드 미반영)** — 이 매핑은 문서상 정리이며, 프론트엔드 카테고리 필터/RPC/마커 색상 로직(`category-meta.ts` 등)에는 아직 반영되지 않았다. 실제 반영은 Decision 008에 따라 별도 구현 작업으로 진행한다.
- 매핑에 없는 원본 카테고리가 향후 추가되는 경우, 임의로 5대 카테고리 중 하나에 끼워 맞추지 않고 이 표를 먼저 갱신한 뒤 반영한다 (4.1 예외 처리 원칙 준용).

## 4. 예외 처리 및 가이드라인

1. **분류 불확실성 대응:**
   - AI가 카테고리를 명확히 판별하기 어려운 경우, 임의로 생성하지 않고 기본값(`ETC` 또는 `GENERAL`)으로 분류한 뒤 수집 로그에 경고를 남긴다.
2. **면책 조항 및 신뢰성 확보:**
   - AI는 데이터 파싱 및 태깅 도구로만 작동하며, 사용자를 상대로 한 실시간 챗봇이나 직접적인 답변 생성 기능은 배제한다 (Decision 005 준수).

## 5. Parental Checkpoint & Feature Tagging Rules (AI 정제 파이프라인)

### 5.1. Extraction Sources
- Primary Source: 원본 공공 API의 `description`(상세설명), `use_target`(이용대상), `fee_info`(요금안내) 텍스트

### 5.2. Tagging Logic & Fallback Rules
1. `is_kids_friendly` (boolean)
   - `true`: `use_target` 또는 `description`에 '어린이', '유아', '키즈', '아이', '가족', '영유아' 키워드 포함
   - `false`: 위 키워드가 없거나 연령 제한(예: 성인 전용)이 명시된 경우

2. `has_parking` (boolean)
   - `true`: `description`에 '주차', '주차장', '파킹' 포함 및 '주차 불가'가 아닌 경우
   - `false`: 언급이 없거나 '주차 불가'가 명시된 경우

3. `stroller_accessible` (boolean)
   - `true`: `description`에 '유모차', '휠체어', '베리어프리', '엘리베이터' 언급 시
   - `false`: 언급이 없는 경우

4. `facility_type` (text)
   - '실내': '실내', '체육관', '박물관', '미술관', '전시관' 키워드 판단
   - '야외': '야외', '실외', '공원', '광장', '체험장' 키워드 판단
   - '복합' (Default): 두 특성이 모두 포함되거나 판별이 불분명한 경우 기본값 적용

5. `target_age_group` (text)
   - 명시된 대상 연령대 추출 ('영유아', '초등', '전연령' 등)
   - 불분명한 경우 `null` 처리

6. `booking_status` (text, events 전용)
   - 행사 일정 및 접수 정보 기반 ('오늘방문', 'D-1 마감임박', '주말예약', '접수중') 판단
   - 불분명한 경우 `null` 처리

7. `is_free` 오탐 방지 (Decision 008, `docs/spec.md` 3.2)
   - 요금 정보가 텍스트가 아닌 포스터 이미지로만 제공되는 경우, 이미지 OCR로 '무료'/'0원' 키워드를 우선 파싱한다 (OCR 파이프라인 미착수 — `implementation/todo.md` 참고).
   - 요금 정보가 원본 데이터에 전혀 없고 제공기관이 국공립/공공기관인 경우, `is_free: true`를 기본 추정값으로 채택한다 (일반 민간 시설에는 이 Fallback을 적용하지 않는다 — 근거 없는 무료 추정으로 인한 정보 오류 방지).

### 5.3. Decision 005 / Decision 008 Guardrail Compliance
- 텍스트 내 객관적 근거가 불명확할 경우 임의 추측을 금지하며 무조건 기본값(`false`, `'복합'`, 또는 `null`)을 부여한다.
- 단, `is_free`의 국공립 시설 Fallback(5.2-7)은 예외적으로 명시 승인된 추정 규칙이며, 다른 필드에는 이 예외를 확대 적용하지 않는다.

## 6. 메인 히어로 슬라이더 (Hero Slider) 큐레이션 및 추천 규칙

메인 페이지 상단 히어로 슬라이더는 유저의 시선이 가장 먼저 닿는 영역으로, 유저의 현재 위치(또는 설정 지역) 기준 **"오늘/이번 주말 당장 아이와 방문할 수 있는 실시간 행사·이벤트"**를 최우선 큐레이션하여 제공한다.

### 6.1 데이터 추출 및 타겟팅 조건 (Filtering & Scoring)
히어로 슬라이더에 노출되는 항목은 `events`(행사) 테이블과 `open_spaces`(장소) 테이블이 결합된 데이터로, 아래 우선순위에 따라 최대 5~7개를 동적으로 선별한다.

1. **위치 적합성 (Location Constraints)**
   * 유저의 현재 위치(GPS) 또는 설정 지역 기준 **반경 15km 이내(차로 30분 이내 거리)** 장소에서 열리는 행사를 최우선 노출한다.
   * 내 위치 반경 내 유효 행사가 부족할 경우 동일 시/군/구 ➔ 동일 광역시/도 순으로 영역을 확장한다.

2. **일정 실시간성 (Temporal Priority)**
   * **1순위 (Today)**: `start_date <= TODAY` AND `end_date >= TODAY` (오늘 실제 진행 중인 행사/팝업)
   * **2순위 (Upcoming Weekend)**: 오늘이 평일인 경우, 바로 다가오는 주말(토/일) 개최 예정 행사 (`D-1`, `D-2` D-Day 표기)
   * **3순위 (Ongoing Special)**: 이번 주 내 운영되는 시즌 특설 시설 (임시 물놀이장, 썰매장 등)

3. **가성비 및 육아 편의성 가산점 (Weight Scoring)**
   * **무료/가성비 우대**: `is_free = true` 또는 저렴한 공공 대관 행사에 가산점 부여.
   * **3대 육아 뱃지우대**: `has_parking = true` (주차 편의) 및 `stroller_accessible = true` (유모차 용이) 항목 우대.

### 6.2 UI/UX 표출 표준 (Display Standard)
히어로 슬라이더 각 카드는 부모가 방문 여부를 3초 안에 판단할 수 있도록 아래 메타데이터 스펙을 엄격히 준수한다.

* **D-Day 및 상태 뱃지**: `[🎉 오늘 진행 중]`, `[🔥 이번 주말 시작]`, `[💰 무료 입장]`
* **헤드라인 타이틀**: 행사명 + 장소명 (예: *2026 어린이 물총 축제 @ 평화의 광장*)
* **위치 및 거리 표기**: 유저 위치 기준 실시간 거리 및 이동 시간 (예: *내 위치에서 3.2km · 차로 10분*)
* **육아 편의 아이콘 뱃지**: 🅿️ 주차 가능 | 👶 유모차 가능 | 🛝 키즈 친화
