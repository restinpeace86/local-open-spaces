## 0. 확정된 범위 (사용자 지시 원문)
- **포함(MVP)**: 5단계 등급 체계 전체, 등급별 권한 게이팅, 찜(북마크), 좋아요/채택
  카운트, **푸시 알림**(우수맘 이상).
- **제외(이번 범위 밖)**:
  - 커피 쿠폰(기프티콘) 실물 리워드 — "직접 줄 것"이므로 자동 발급/연동 로직 없음.
    파워맘 달성 시 관리자에게 알 수 있는 표시만 남기면 충분(자동 지급 API 불필요).
  - 네이버 블로그 검색 API 기반 "블로그 아웃링크 프리뷰" — 추후 별도 Spec.

## 1. 등급 체계 및 권한 매트릭스

| 등급 | 달성 조건 | 부여 권한 |
| :--- | :--- | :--- |
| 비로그인(Visitor) | 앱 접속 시 기본 상태 | 스팟픽/이벤트픽 지도·리스트 탐색, AI 챗봇 **1회** 체험 |
| 🌱 새싹맘 | 소셜 로그인 + 첫 스팟 방문 후기(마이크로 리뷰) 또는 체크리스트 1회 작성 | 맘스픽 커뮤니티 피드 열람, AI 챗봇 **무제한** |
| 🌿 열심맘 | 월 2회 이상 후기/글쓰기 | 찜(북마크) 기능, 내 리뷰에 대한 좋아요 반응 확인 |
| 🌳 우수맘 | 월 5회 이상 후기/글쓰기 (또는 채택·좋아요 누적 기여도) | 맞춤형 조건(연령/성향/지역) 기반 **일일 푸시 알림**, 피드 상단 우선 노출 + 뱃지 |
| ✨ 파워맘 | 우수맘 중 월간 채택 수 상위 N명(정원제, 기본 10명 — 3-6 참고) | 메인/주간 베스트 스포트라이트 카드 노출, 레전드 뱃지. **리워드(커피 쿠폰)는 수동 지급 — 시스템 범위 밖** |

## 2. 데이터 모델 (신규 테이블 제안)

기존에 커뮤니티/리뷰/찜 관련 테이블이 전혀 없어(이 프로젝트는 지금까지 공간·행사
카탈로그 + 방금 도입한 인증만 있었음) 아래를 신규로 제안한다. `profiles`(2026-09-02
도입)와 마찬가지로 전부 `auth.uid()` 기반 RLS를 적용한다.

### 2.1 `public.mom_pick_posts` (후기/체크리스트/설문형 리뷰 — "글쓰기 활동"의 실체)
- `id uuid pk`, `author_id uuid references auth.users(id)`,
  `spot_id uuid references open_spaces(id) null` (연결된 스팟, 체크리스트만 쓰고
  특정 스팟과 무관할 수도 있어 nullable),
  `event_id uuid references events(id) null`(**2026-09-04 추가** — [설문형 스마트
  리뷰 폼] 1단계 "내 주변 인기 스팟" 피커가 이벤트픽 데이터도 포함하므로, 사용자가
  스팟이 아니라 이벤트를 골랐을 때의 참조 대상. `user_bookmarks`가 이미 spot_id/
  event_id 중 하나만 채우는 동일한 패턴을 쓰고 있어 그대로 재사용한다 — 제5장
  제4조. `spot_id`와 `event_id`가 동시에 채워지는 것은 막지만(`check (spot_id is
  null or event_id is null)`), 과거 체크리스트 글처럼 둘 다 null인 경우는 계속
  허용한다),
  `post_type text check (post_type in ('micro_review','checklist','survey_review'))`
  (**2026-09-04 개정** — 기존 두 값은 과거 데이터 렌더링용으로 유지, 새 글쓰기 화면은
  `survey_review` 하나만 만든다. 아래 3-4·3-5 참고),
  `content text`, `like_count int default 0`,
  `is_adopted boolean default false`, `adopted_at timestamptz null`,
  `adopted_by uuid references auth.users(id) null` (**확정**: "채택"은 좋아요 수와
  무관한 별도 개념 — 어드민이 우수 후기를 수동으로 "채택" 지정하는 관리자 전용
  액션이다. 어드민 화면에 후기 목록 + "채택" 토글 버튼이 필요하다. 우수맘/파워맘
  산정 시 "채택 수"는 이 컬럼의 카운트를 쓴다),
  `created_at timestamptz default now()`.
- **`survey_review` 전용 컬럼(2026-09-04 추가, 아래 3-4가 정의하는 2단계 설문
  문항과 1:1 대응, 전부 nullable — post_type이 다르면 사용하지 않음):**
  - `age_groups text[]` — 2단계 "몇 세 아이와 가기 좋았나요"(다중 선택). 허용값:
    `영유아`/`미취학`/`초등저`/`초등고`.
  - `visit_environment text check (visit_environment in ('outdoor','indoor','mixed'))`
    — "방문 환경"(단일 선택). outdoor=탁 트인 야외, indoor=쾌적한 실내, mixed=복합.
  - `satisfaction_points text[]` — "가장 만족스러웠던 점"(다중 선택). 허용값:
    `parking`(주차 편리)/`stroller`(유모차 이동 수월)/`not_bored`(아이가 지루해하지
    않음)/`good_value`(가성비 좋음).
  - `duration_type text check (duration_type in ('short','half_day','full_day'))`
    — "체류 시간"(단일 선택). short=1~2시간, half_day=반나절(3~4시간),
    full_day=종일.
  - `weather_tags text[]` — "날씨/상황별 맞춤 태그"(다중 선택). 허용값:
    `rainy_day`(비 오는 날 좋음)/`hot_day`(더위 피하기 좋음)/`mild_season`(가을·봄에
    최고)/`energy_burn`(체력 소모형).
  - `infra_tags text[]` — "영유아 부모 필수 인프라"(다중 선택). 허용값:
    `nursing_room`(수유실/기저귀 갈이대)/`food_available`(간식·식사 가능)/
    `clean_restroom`(화장실 가까움/깨끗함).
  - `companion_type text check (companion_type in ('family','friends_group'))` —
    "방문 형태"(단일 선택). family=엄마·아빠와 단둘이(소가족), friends_group=친구네
    가족과 동반.
  - `photo_urls text[]` — 3단계 사진 업로드(선택, 여러 장 허용). Supabase Storage
    공개 버킷(`mom-pick-post-images`, `spot-curation-images`와 동일한 기존 관례 —
    2026-09-01) URL 배열.
  - 배열/체크 컬럼은 전부 "선택하지 않음"을 빈 배열(`{}`)로, 라디오형(단일 선택)
    컬럼은 "선택하지 않음"을 `NULL`로 표현한다 — 둘 다 필수 응답으로 강제하지
    않는다(요구사항 원문이 "선택지들을 터치"라고만 했지 전부 필수라고 명시하지
    않았고, 3단계 자유글처럼 설문도 비워도 저장 자체는 막지 않는 편이 이탈을 줄인다).
- RLS: 누구나 SELECT(커뮤니티 피드는 로그인 사용자에게 공개, 단 API 라우트 레벨에서
  "새싹맘 이상"만 호출 가능하도록 게이팅 — RLS 자체는 "본인 작성 글만 수정/삭제"만
  강제), INSERT/UPDATE/DELETE는 `auth.uid() = author_id`만. `is_adopted`/
  `adopted_at`/`adopted_by` 갱신은 일반 사용자 정책에서 제외하고 서비스 역할(어드민
  API 라우트)에서만 갱신한다(기존 어드민 화면들과 동일한 "서비스 역할 전용 쓰기"
  패턴 — 제5장 제4조 기존 구조 우선).

### 2.4 등급 산정 — 테이블이 아니라 "계산값"으로 제안
`profiles`에 `grade` 컬럼을 두고 값을 캐싱하되, 실제 산정은 `mom_pick_posts`/
`mom_pick_likes`를 매일 배치(기존 `scripts/ingest/run-daily.mjs`류 오케스트레이터에
새 스텝 추가하는 방식 — 제5장 제4조 기존 구조 우선)로 집계해 갱신하는 것을 제안한다.
매 요청마다 실시간 집계하면 비용이 커지고, "월 2회/5회"라는 기준 자체가 실시간성을
요구하지 않기 때문이다.

**확정: 산정 주기는 달력월 기준(매월 1일 00시 리셋), 강등은 즉시 적용(당월 실적만
반영, 유예 없음)이다.** 즉 "이번 달 1일~오늘" 사이 `mom_pick_posts` 작성 건수로
열심맘(2건)/우수맘(5건) 조건을 매일 재계산하며, 월초 리셋 시점에는 조건을 다시
채울 때까지 새싹맘으로 즉시 내려간다(3-7 참고).

### 2.5 푸시 알림 인프라(우수맘 이상, MVP 포함)
기존 `spec/notification/notification-settings.md`의 알림은 **로컬스토리지 기반
인앱 벨 알림**(앱을 열어야 갱신)이라 "매일 아침/주말에 앱을 안 열어도 오는 푸시"
요구사항을 충족하지 못한다 — 이번 요구사항은 브라우저 Web Push API가 필요한
별개의 인프라다:
- `public.push_subscriptions`: `user_id`, `endpoint`, `p256dh`, `auth_key`,
  `created_at` — 브라우저의 `PushSubscription` 객체를 그대로 저장.
- 신규 서비스 워커(`public/sw.js`) + 클라이언트 구독 플로우(알림 권한 요청 →
  `pushManager.subscribe()` → 서버에 구독 정보 저장).
- 서버: VAPID 키 쌍 발급(`web-push` 패키지) 필요 — **확정**: 구현 단계에서 직접
  생성해 `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`로 `.env.local`에 등록하고, Vercel
  프로덕션에도 동일하게 수동 등록이 필요함을 구현 기록에 남긴다(외부 계정 가입이
  필요 없는 순수 키 생성이므로 코드 내에서 직접 처리 가능).
- 발송 스케줄: "매일 아침/주말" — 기존 배치 오케스트레이터(`run-daily.mjs`) 직후
  또는 별도 GitHub Actions 워크플로(기존 3시간 주기 날씨 배치와 동일한 패턴)로
  우수맘 이상 사용자의 저장된 필터와 신규 스팟/이벤트를 매칭해 발송.

### 2.6 [2026-09-04 추가] "내 주변 인기 스팟" 피커 — 데이터 소스와 랭킹 기준
[설문형 스마트 리뷰 폼] 1단계가 보여주는 후보 목록의 범위와 정렬 기준을 명시한다.

- **범위(대상 거리)**: 사용자의 설정 위치 기준 반경 **30km** 이내.
- **대상 분류(요구사항 원문 그대로)**: 공공/대형 어린이 공원(단순 동네 놀이터
  제외) / 체험형 박물관·미술관·과학관 / 키즈카페·실내 놀이터 / 캠핑장·자연휴양림 /
  지자체 주관 체험 행사·프로그램(이벤트픽) / 아이 동반 특화 문화 공간(도서관
  어린이실 등). 기존 `category_min` taxonomy(`spot-category-groups.ts`)로
  대응하면 SPACE 쪽은 `공원`/`종합·기타박물관`/`역사박물관`/`미술관`/`과학관`/
  `키즈카페`/`어린이놀이시설(실내)`/`캠핑장`/`자연휴양림`/`도서관`이고, EVENT 쪽은
  현재 진행 중이거나 예정인 이벤트픽 데이터 전체다(이벤트는 상시 카탈로그가 아니라
  이미 "행사/프로그램" 성격만 존재하므로 별도 category_min 제한을 추가로 걸지
  않는다).
- **"운영진이 직접 검증/큐레이션한 스팟 리스트"의 해석**: 이 프로젝트에는
  `spot_curations`라는 이름의 테이블이 이미 있지만, 그 테이블은 "키즈친화 식당"
  (놀이방식당) 전용으로 좁게 설계돼 있어(메뉴/영업시간 등 그 목적에 특화된 컬럼만
  가짐, 2026-09-01) 이 문맥의 "검증/큐레이션"과 대상 범위가 다르다. `open_spaces`
  전체가 이미 공공데이터 정제 파이프라인(수집→지오코딩→정규화)을 거친 자산이므로,
  "검증/큐레이션한 스팟 리스트"는 `spot_curations` 테이블 참조가 아니라 **위
  대상 분류로 좁혀진 `open_spaces`/`events`** 그 자체로 해석한다(추측이 아니라
  기존 테이블의 실제 설계 목적을 근거로 내린 판단 — 문자 그대로 `spot_curations`를
  요구했다면 현재 그 테이블에 이 대상 분류와 겹치는 행이 사실상 없어 피커가 항상
  빈 결과만 반환하게 된다).
- **랭킹("위치 기반 + 플랫폼 내 인기 순")**: 이 프로젝트에는 조회수 등 별도
  인기도 집계가 없다 — 없는 지표를 지어내지 않고(추측 금지), 이미 존재하는 실제
  신호만 쓴다. 기본 정렬은 거리 오름차순(기존 `get_nearby_spaces_and_events` RPC의
  KNN 정렬을 그대로 재사용)이며, 그중 `mom_pick_posts`에 이미 리뷰가 1건 이상
  달린 스팟/이벤트를 동일 거리대 안에서 우선 노출한다(순수 거리 정렬 앞에 "이미
  검증된 인기 스팟"을 살짝 끌어올리는 경량 신호 — 새 집계 배치나 신규 컬럼을
  요구하지 않는다).

## 3. 확정된 결정 (사용자 답변, 2026-09-02)

1. **"채택"의 정의**: 좋아요 수와 무관한 별도 개념. **관리자가 어드민 화면에서
   수동으로 "채택" 지정**한다(`mom_pick_posts.is_adopted`/`adopted_at`/
   `adopted_by`). 우수맘/파워맘 산정의 "채택 수"는 이 컬럼 기준.
2. **VAPID 키 발급**: 구현 단계에서 직접 생성해 환경변수로 등록한다(외부 계정
   가입 불필요, 순수 키 생성).
3. **등급 재산정 주기**: 달력월 기준(매월 1일 리셋). 월간 누적 작성 건수로 판단.
4. **[2026-09-04 개정] 글쓰기 폼 구조: "설문형 스마트 리뷰"(3단계 위저드).**
   기존 "마이크로 리뷰(별점+한줄 텍스트)" 입력 형태는 새 글쓰기 화면에서 더 이상
   제공하지 않는다(과거 데이터는 `post_type='micro_review'`로 계속 보존·조회 가능).
   새 글쓰기 화면은 아래 3단계 하나만 제공한다:
   - **1단계 — 장소 선택**: 타이핑 없이 "내 주변 인기 스팟" 목록(위 2.6)에서 탭
     한 번으로 스팟 또는 이벤트를 선택(검색으로 직접 찾기도 가능, 기존
     `SpotPicker`/`/api/spots/search` 재사용). 선택 결과는 `spot_id` 또는
     `event_id` 중 하나에 저장된다.
   - **2단계 — 설문**(2.1에 정의한 `survey_review` 전용 컬럼 7종에 1:1 대응):
     연령대(다중)/방문 환경(단일)/만족 포인트(다중)/체류 시간(단일)/날씨 태그
     (다중)/영유아 인프라(다중)/동반 형태(단일). 전부 선택 사항(빈 값 허용).
   - **3단계 — 자유글 + 사진**: `content`(자유 텍스트, 길이 제한 없음 — 마이크로
     리뷰의 80자 제한과 달리 "네이버 블로그처럼 길게도 짧게도" 쓸 수 있어야 한다는
     요구사항 원문에 따름) + `photo_urls`(선택, 여러 장).
   `post_type='survey_review'`로 저장한다.
5. **[2026-09-04 개정] 체크리스트 단독 화면 폐지.** 기존 "전 스팟 공통 체크리스트"
   입력 형태(별도 탭)도 새 글쓰기 화면에서 제공하지 않는다 — 그 5항목이 다루던
   정보(주차/수유실 등)는 위 4항의 "영유아 인프라"/"만족 포인트" 설문 문항으로
   대체·흡수됐다. 과거 데이터는 `post_type='checklist'`로 계속 보존·조회 가능하며,
   `checklist_answers` 컬럼과 `CHECKLIST_ITEMS` 상수도 그 과거 데이터 렌더링을 위해
   삭제하지 않는다.
6. **파워맘 선발**: "상위 1%" 대신 **월간 정원제(기본 10명, 관리자 설정 가능)**.
   `profiles.grade`와 별개로, 매월 배치에서 우수맘 중 당월 채택 수 상위 N명을
   선정한다. N은 하드코딩하지 않고 관리 가능한 설정값(예: 기존 feature-flag류
   패턴 또는 간단한 설정 테이블/환경변수)으로 둔다(제5장 제6조 하드코딩 최소화).
7. **강등 정책**: 즉시 강등 — 당월 실적만 반영한다(유예 기간 없음). 매월 1일 배치
   시점에 지난달 실적이 아니라 "이번 달 누적 실적"으로 등급을 재계산하므로,
   월초에는 조건을 다시 채울 때까지 새싹맘(로그인 완료 이력은 유지)으로 표시된다.

## 4. 이번 초안이 다루지 않는 것(명시적 비목표)

- 네이버 블로그 검색 API 연동("블로그 아웃링크 프리뷰") — 추후 별도 Spec.
- 어드민 화면에서의 등급/신고/제재 관리 UI(콘텐츠 모더레이션) — 이번 초안엔 없음,
  필요 시 별도 확인.
