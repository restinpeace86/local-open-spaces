# 📋 [통합 명세서] 가성비 놀거리 서비스 (Spec & Data Pipeline)

## 1. 서비스 정의 & 핵심 모토
- **모토**: "오늘/이번 주말, 아이·가족과 가성비 있게(0원~1만 원) 뭐 하고 놀지?"
  - **주요 타겟 (Primary Target)**: 
- **20·30·40대 젊은 부부** 및 **유아·어린이·초등학생 자녀를 둔 가족 단위**
- **핵심 가치**: 
  - 80% 이상의 안정적인 공식 API 중심 데이터 수집
  - 사전 예약 없이 '오늘/주말 당일 즉시 출발 가능한 장소' 위주 우선 추천
  - 야놀자 스타일의 직관적인 카테고리/큐레이션 뷰 제공

---
### 0. 명세 관리 및 AI 변경 권한 규약 (Spec Change Governance)
- **AI 임의 변경 전면 금지**: AI(개발 주체)는 별도의 명시적 지시 없이 `spec.md`에 정의된 범위/기능/로직을 임의로 변경, 오버라이딩, 삭제, 축소할 수 없다.
- **대표 지시 기반 확장 허용**: 대표(사용자)가 직접 지시하거나 승인한 요구사항에 대해서는 `spec.md`의 기존 명세를 확장, 개정, 변경 및 추가 반영하는 것을 전적으로 허용한다.
- **명세 우선 처리**: 코드 구현 중 `spec.md`와 상충되는 부분이 발생하거나 명세의 확장이 필요할 경우, 대표의 지시에 맞춰 `spec.md`를 우선 갱신한 후 코드를 수리한다.

### 0-2. 카테고리 정제/합치기(Merge) 작업에 대한 명세 예외 및 확장 규약
- **단계적 정제(Phase-based Clean-up) 허용**: 현 단계의 "원천 중분류 1:1 전체 펼침 노출"은 전수 데이터 검증을 위한 1차 수집/노출 스펙이며, 추후 진행될 **카테고리 통합/합치기/그룹핑/통합 UI 적용 작업은 본 `spec.md` 명세에 위반되지 않는 정상적이고 정당한 확장 단계**로 간주한다.
- **AI 변경 거부 방지**: AI는 "기존 spec.md에 중분류 전체 노출로 적혀있다"는 이유로 차후 지시될 카테고리 합치기, 그룹핑, 정제 작업에 대해 명세 상충을 이유로 작업 수정을 거부할 수 없다. 대표(사용자)의 통합 지시가 있을 경우 해당 중분류 매핑/그룹핑 로직을 즉시 스펙 및 코드에 반영한다.

# 이벤트픽 메인 페이지 사양 및 데이터 파이프라인 스펙 (Events Main Spec)

## 1. 이벤트픽 화면 노출 3대 기본 전제 조건 (AND 조건)
화면에 노출되는 모든 이벤트 데이터는 반드시 아래 3가지 조건을 모두 충족해야 합니다.
1. **활성화 상태**: `is_active = true` (`false`인 데이터는 매일 배치를 통해 자동으로 배제됨)
2. **타겟 연령대**: `INFANT`, `KIDS_PRE`, `KIDS_SCHOOL`, `FAMILY`, `ALL` 중 하나
3. **중분류 유효성**: 중분류(`category_mid` 등)가 `NULL`이 아닌 것 (정상 분류 완료된 데이터)
4. 특정 중분류 항목의 화면 노출 제외(필터링) 정책
- **기본 원칙**: 데이터 수집 및 표준 중분류(`category_min`) 정제 단계에서는 데이터 손실 방지와 전수 수용을 위해 원천 값을 그대로 유지한다. 단, 실제 사용자에게 제공되는 **홈 피드, 이벤트픽, 검색, 카테고리별 조회 등 모든 화면(UI) 및 조회 API 쿼리 레벨**에서는 아래 항목들을 렌더링 대상에서 제외(필터링)한다.
- **화면 노출 제외 대상 중분류 (`category_min`) 목록**:
  1. `단체봉사`
  2. `청년정보`
  3. `정보통신`
  4. `전문/자격증`
- **적용 범위**: 
  - `src/lib/home/get-home-feed.ts` 내의 모든 이벤트픽 및 피드 조회 쿼리에서 `category_min NOT IN ('단체봉사', '청년정보', '정보통신', '전문/자격증')` 조건을 적용하여 강제 배제한다.

## 4. 데이터 정제 및 백필/시뮬레이션 실행 로직 (연령대 및 1단계 중분류)
* **레거시 백필**: `source=null` 및 `raw_data` 공백인 구버전(`SEOUL_RESERVATION_*`) 데이터 중 라이브 API SVCID 매칭 건들은 이미 실제 DB에 `source` 및 `raw_data` UPDATE 반영 완료.
* **원천 필드 우선 탐색 (2단계 연령 및 1단계 중분류 공통)**: 
  * 백필된 `raw_data` 내부의 연령/분류 관련 원천 필드(`USE_TRGT`, `target_age_group`, `USETGTINFO`, `MINCLASSNM` 등 API 소스별 상이한 필드)를 폭넓게 스캔.
  * 텍스트 파싱에 앞서 이 원천 필드 값들을 최우선으로 분석하여 10대 세분화 타겟 태그(`INFANT`, `KIDS_PRE`, `KIDS_SCHOOL`, `FAMILY`, `TEEN`, `YOUTH`, `ADULT`, `SENIOR`, `ALL`, `FACILITY`)로 1:1 매핑 시도.
  * 원천 필드 값이 비어있는 경우에만 텍스트 파싱 단계 진입.
* **활성 데이터 기준 Dry-run 시뮬레이션 (`is_active = true`)**: 매일 배치를 통해 갱신되는 활성 데이터 집합을 대상으로 원천 필드 우선 탐색과 10대 분류 체계를 적용하여 Dry-run 시뮬레이션을 수행하고 `NULL` 잔여 최소화 검증.

## [신규] 공공데이터 ETL 파이프라인 & 가공 규약 (Data Pipeline Spec)

### 1. 기본 원칙 & 타겟팅 전제
- **핵심 타겟층**: 20·30·40대 젊은 부부 및 유아·어린이·초등학생 자녀를 둔 가족 단위.
- **원본 보존 원칙**: 수집 단계에서는 원천 데이터의 속성을 드롭/가공/변형하지 않고 100% 무오염 원본 그대로 DB에 전수 적재(Ingest First)한 후, 후속 단계를 통해 정제·가공을 진행함.
- **테이블 분리 적재**:
  - `spaces` (공간/시설): 체육시설, 공간시설, 장소대여, 키즈카페 등
  - `events` (이벤트/행사): 문화체험, 교육강좌, 공연, 전시, 체험프로그램 등

### 2. 수집 및 Paging Loop 규약
- **수집 범위**: 서울시 공공예약 API 4대 대분류 (`문화체험`, `교육강좌`, `체육시설`, `공간시설`) 전수 수집 (`진료복지` 제외).
- **Paging Loop 순회**:
  - API 첫 응답의 `list_total_count` 기반으로 1,000건 단위(`START_INDEX` ~ `END_INDEX`) 인덱스를 자동 증가시키는 루프(Loop)를 실행하여 전체 데이터를 단 1건의 잘림 없이 전수 순회 수집함.
- **무중단 예외 처리 (Graceful Parsing)**:
  - 수집 루프 내 항목(item) 1건 단위로 Item-level `try-catch`를 적용.
  - 특정 건의 파싱 에러(잘못된 날짜, 특수문자, 필수값 누락 등) 발생 시 해당 항목 ID와 에러 원인만 로그(`logger.error`)에 기록하고 `continue`로 건너뛰어 전체 배치 다운(Crash)을 방지함.

### 3. Null-safe 적재 및 중복 데이터 병합 (Merge) 규약
- **Null-safe 무조건 적재 (Drop 0건)**:
  - 주소/위치 좌표, 이용 요금(`PAYATNM`), 예약 URL(`SVCURL`) 등이 비어있거나 누락되어 있어도 수집 거부/패스하지 않고 `NULL` 처리하여 DB에 무조건 100% 적재함.
  - 중복 데이터 외 항목 누락을 이유로 데이터를 드롭(Drop)하는 행위 전면 금지.
- **원천 식별 정보 (`source`)**:
  - 원천 수집처 구분을 위해 `source` 컬럼(예: `seoul_public_reservation`)을 필수 적재.
- **`SVCID` 기반 중복 병합 (NULL Merge)**:
  - 동일한 고유 서비스 ID(`SVCID`) 중복 건 수집 시 1건으로 통합(UPSERT).
  - 기존 데이터의 컬럼이 `NULL`이고 새로 수집된 건에 값이 존재하는 경우, 실데이터가 존재하는 값으로 해당 컬럼을 병합(`COALESCE` / 조건부 Update)하여 적재함.

### 4. 일간 파이프라인 정밀 로깅 규약 (`docs/pipeline-log.md`)
- **실행 회차별 섹션 생성**:
  - 매일 배치 수집 실행 완료 시 `docs/pipeline-log.md`에 `## [YYYY-MM-DD HH:mm] Batch Log` 신규 섹션을 자동 생성 및 기록.
- **API별 정밀 리포팅 메트릭 필수 포함**:
  1. API 구분 및 서비스명 (`ListPublicReservation...`)
  2. 원천 총 데이터 건수 (`list_total_count`)
  3. 실제 호출/가져온 건수 (`Fetched Count`)
  4. DB 적재 성공 건수 (`DB Inserted/Updated Count`)
  5. 중복 제외 및 NULL 병합 건수 (`Deduplicated/Merged Count`) 및 대상 API명
  6. 파싱/적재 에러 건수 (`Error Count`) 및 원인별 상세 내역 (예: 날짜 포맷 오류 N건 등)
