## 2. 시뮬레이션 A — 이미 승인된 0순위 규칙(`MINCLASSNM`) 재적용

`seoul_public_reservation`의 `MINCLASSNM`은 이미 "원본이 표준 중분류를 직접 갖고 있으면 곧바로
RAW로 태깅한다"는 규칙이 **승인·구현되어 있다**(`scripts/ingest/adapters/seoul-yeyak-adapter.mjs`
186행, `scripts/migrations/2026-08-26-category-rules-engine.sql` 4절). 새 판단이 아니라 기존
승인 규칙을 그대로 재적용하는 시뮬레이션이다.

### 실측 결과
- 이 소스의 현재 `category_min` NULL 잔여 **1,096건 전수가 `MINCLASSNM` 값을 실제로 보유**하고
  있음을 확인했다(예: `교육체험` 158건, `산림여가` 144건, `기타` 84건, `공원탐방` 72건,
  `강의실` 57건, `다목적실` 56건, `회의실` 50건, `녹화장소`/`민원 등 기타` 각 48건 등).
- `MINCLASSNM` 값을 그대로 `category_min`에 채우는 시뮬레이션을 적용하면 **이 1,096건이 전부
  해소**된다 (해소율 100%, 이 소스 한정).
- 이미 `category_min_source='RAW'`로 채워진 917건은 `raw_data.MINCLASSNM`과 **불일치 0건**으로
  기존 RAW 백필의 무결성을 재확인했다.
- 반면 `category_min_source='RULE'`(제목 텍스트 키워드 매칭)로 채워진 778건 중 **401건
  (51.5%)은 `MINCLASSNM` 값과 최종 `category_min` 값이 완전히 동일**했다(예: `테니스장` 152건,
  `축구장` 34건, `캠핑장` 32건, `농구장` 26건, `풋살장` 26건, `족구장` 23건, `산림여가` 17건,
  `야구장` 13건 등). 이는 원천 필드를 0순위로 먼저 참고했다면 텍스트 매칭 없이도 즉시 분류될
  수 있었던 건들이, 실제로는 RULE 엔진에 의존해 (우연히 같은 결론에 도달)했다는 뜻이다.

### 결론(사실 확인, 원인 조사는 범위 밖)
승인된 "0순위 원천 필드 우선 탐색" 설계가 `is_active=true` 최신 데이터의 상당수(NULL
1,096건 + RULE로 우회 도달한 401건)에는 실제로 적용되지 않은 상태임을 실측으로 확인했다.
이 갭의 근본 원인(배치 실행 시점/코드 배포 시점 차이 등) 규명은 이번 Task(Dry-run
시뮬레이션) 범위 밖이라 임의로 조사·수정하지 않았다 — 사실 관계만 투명하게 보고한다.

## 3. 시뮬레이션 B — `CODENAME`(seoul_public_culture) 활용 잠재력 (제안, 승인 대기·미적용)

### 현재 방식의 한계 실측
`seoul_public_culture`는 `category_min`을 오직 제목 텍스트 키워드 매칭(RULE)으로만 채우며,
`CODENAME`(장르) 원천 필드는 전혀 참고하지 않는다. 이미 RULE로 채워진 148건을 `CODENAME`별로
교차 분석한 결과, 하나의 장르가 서로 다른 중분류로 산발적으로 흩어지는 현상을 확인했다:

| CODENAME | 실제 매칭된 category_min (건수) |
| :--- | :--- |
| `교육/체험` | 교양/어학(11), 역사(10), 전시/관람(7), 미술제작(5), 지역축제/페스티벌(2), 공예/취미(1), 어린이실내놀이터(1), 문화행사(1) — **8종으로 분산** |
| `전시/미술` | 전시/관람(33), 전시실(10), 미술제작(4), 역사(3), 공예/취미(2) — **5종으로 분산** |
| `콘서트` | 문화행사(7), 공연장(5), 전시실(2), 전시/관람(1), 광장(1) |
| `클래식` | 지역축제/페스티벌(8), 문화행사(2), 공연장(2) |

일치율(RULE 최종값 == CODENAME 원문)은 **0/148(0.0%)**다 — 애초에 `CODENAME`(예: "콘서트")과
`category_min` 표준값(예: "문화행사")이 문자열 자체가 다르므로 당연한 결과이며, 이는
"CODENAME을 그대로 복사"가 아니라 "CODENAME→표준 중분류 매핑표"가 필요함을 보여준다.

### 제안 매핑(초안, 미확정)
```
연극/무용/국악/클래식/콘서트/뮤지컬·오페라/독주·독창회/영화  → 문화행사
축제-*(문화/예술, 기타, 전통/역사, 시민화합, 자연/경관, 관광/체육) → 지역축제/페스티벌
전시/미술  → 전시/관람
교육/체험  → 교육체험
기타       → (매핑하지 않음, NULL 유지)
```

### 시뮬레이션 결과
위 제안 매핑을 NULL 잔여 278건에 적용하면 **270건 해소**(기타 8건은 매핑 대상에서 제외해
NULL 유지). **이 매핑은 승인 대기 상태이며 실제 반영하지 않았다** — `category_rules` 등
공식 규칙에 아직 없는 신규 판단이므로 대표 승인 없이 임의 확정하지 않는다(제3장 제4조
추측 금지).

## 4. 부적합/보류 판정

- **`gg_public`의 `CATEGORY_NM`**: 값이 "전시/교육/행사/공연" 4종뿐으로 `category_maj`(대분류)
  수준의 성긴 정보다. 중분류(`category_min`) 1:1 매핑에는 정보량이 부족해 이번 제안에서
  제외했다(활용 시 오히려 부정확한 중분류가 대량 생성될 위험).
- **`tourapi_4.0`의 `cat1~3`/`lclsSystm1~3`**: TourAPI 표준 서비스 분류 코드(예:
  `EV030400`)이나, 이번 스캔에서는 공식 코드-한글명 매핑표를 확보하지 못했다. 코드를 임의로
  해석해 매핑하면 추측 금지 원칙에 위배되므로, 이번 시뮬레이션에서는 매핑을 시도하지 않았다
  (잔여 9건, 현재도 RULE로 231건이 이미 잘 분류되어 있어 영향 적음). 향후 진행 시 TourAPI
  공식 문서의 분류 코드표 확보가 선행되어야 한다.
- **`source=(null)` 53건**: `raw_data` 자체가 없는 구버전 잔존 행. 원천 필드 활용이 구조적으로
  불가능한 기존 known gap이다.

## 6. 대표 승인 요청 사항

1. **[즉시 반영 가능, 새 판단 아님]** `seoul_public_reservation`의 `MINCLASSNM` 0순위 RAW
   태깅이 실제 데이터에 왜 누락되었는지 원인 조사 및 재적용 여부 — 기존에 이미 승인된 규칙의
   재현 문제이므로 별도 신규 승인 없이도 다음 단계로 진행 가능해 보이나, DB 실제 UPDATE는
   이번 Task 범위(Dry-run) 밖이라 대표 확인 후 별도 Task로 진행 요청.
2. **[신규 승인 필요]** `seoul_public_culture`의 `CODENAME`→표준 중분류 제안 매핑(3절) 확정
   여부.
3. **[보류 확인]** `gg_public`(CATEGORY_NM 부적합), `tourapi_4.0`(공식 코드표 미확보) 두 건은
   이번 단계에서 보류하는 것에 대한 승인.
