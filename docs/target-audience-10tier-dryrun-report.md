## 1. 레거시 소스 실데이터 백필 (실제 DB 반영)

### 1.1 문제
2026-08-27 8대 체계 Dry-run(`docs/target-audience-8tier-dryrun-report.md` 5절 미결 4번)에서
발견된 이슈: `events.external_id LIKE 'SEOUL_RESERVATION_%'`이고 `source IS NULL`인
2,544건은 `raw_data`도 완전히 비어 있어(Decision 017 전면 재작성 이전, 구버전
`seoul-public-reservation.mjs` 어댑터가 적재한 행) 0순위(원천 필드)/1단계(카테고리) 판정이
원천적으로 불가능했다.

### 1.2 복구 방법 (추측 없이 정확한 키 매칭만 사용)
실측 확인: `external_id`가 `SEOUL_RESERVATION_<SVCID>` 형태로 SVCID를 그대로 보존하고
있고, 동일 SVCID가 `reservation_url`의 `rsv_svc_id=` 쿼리스트링에도 남아 있다. 서울시
예약 통합 API(`tvYeyakCOllect`)를 현재 시점 기준 전수 재수집(페이징, 2,925건)해 SVCID가
**정확히 일치**하는 행만 `source='seoul_public_reservation'`/`raw_data=<API 원본>`으로
채웠다 — 제목/날짜 유사도 등 추측성 매칭은 전혀 쓰지 않았다(제3장 제4조 추측 금지).
기존 행의 `id`/`external_id`는 그대로 두고 `source`/`raw_data` 두 컬럼만 UPDATE했다
(신규 어댑터가 쓰는 `SEOUL_YEYAK_` 접두로 바꾸면 신규 어댑터의 upsert 대상과 물리적으로
같은 행이 중복 생성될 위험이 있어 원천적으로 피함).

### 1.3 결과
| 구분 | 건수 |
| :--- | ---: |
| 백필 대상(legacy, source=null) | 2,544건 |
| **백필 성공(source/raw_data 실제 UPDATE)** | **2,322건 (91.3%)** |
| 백필 불가(라이브 피드에서 이미 사라짐 — 서비스 종료/만료) | 222건 (8.7%) |

222건은 공공 API가 과거 스냅샷을 제공하지 않는 구조적 한계로 복구 불가능하다 —
추측으로 채우지 않고 `source`/`raw_data` 모두 `NULL`로 그대로 남겼다.

### 1.4 스코프 관련 투명 공개
지시문은 `SEOUL_RESERVATION_*` 패턴만 명시했다. 조사 중 `source IS NULL`인 다른 접두
(`TOUR_API_` 13건, `SEOUL_YEYAK_` 32건, 합계 45건)도 발견했으나, 지시문에 명시되지 않은
범위라 **임의로 확장하지 않고 이번 백필에서 제외**했다(제3장 제4조 추측 금지). 별도 승인
필요 시 후속 작업으로 분리 제안한다.

## 2. 10대 분류 체계 알고리즘 — 지시문과 시뮬레이션 사이의 차이 (투명 공개)

지시문은 10개 태그 정의(`FACILITY`="캠핑장, 주민센터 다목적실, 영화촬영 등 시설·장비 대관
전용", `ADULT`="성인 단독")와 3단계 퍼널(0순위 원천 필드 → 1단계 카테고리/FACILITY 판정 →
2단계 텍스트 파싱)만 지정했고, 태그별 구체적 키워드는 지정하지 않았다. 8대 체계 때와
동일하게 **이번 시뮬레이션 전용 잠정 규칙**을 새로 정의했다 — 전부 제안 단계이며 확정이
아니다.

### 2.1 0순위 + 2단계 공용 키워드 매핑 (8대 체계 승인 대기 규칙 재사용 + ADULT만 신설 추가)
| 태그 | 키워드 |
| :--- | :--- |
| INFANT | 영아, 영유아, 신생아, 젖먹이 |
| KIDS_PRE | 유아, 미취학, 유치원 |
| KIDS_SCHOOL | 어린이, 초등학생, 초등, 아동 |
| FAMILY | 가족 |
| TEEN | 청소년, 중학생, 고등학생, 중고생 |
| YOUTH | 청년 |
| **ADULT (신설)** | **성인** |
| SENIOR | 어르신, 시니어, 실버, 노인 |
| ALL | 전연령, 전 연령, 남녀노소, 누구나, 제한없음 |

0순위는 `USETGTINFO`/`USE_TRGT` 원천 필드에, 2단계는 `title`+`description`에 동일 표를
적용한다. 0순위는 8대 체계와 동일하게 쉼표/괄호 분리 토큰이 **전부 하나의 태그로 합의될
때만** 매핑 성공으로 인정한다.

### 2.2 1단계: 카테고리/FACILITY 판정 — FACILITY 신설로 인한 재배정 (투명 공개)
8대 체계 리포트 1.1절은 스포츠 시설 대여 16종(테니스장/체육관 등)을 "공간 대관이라 나이
제한 개념 자체가 없음"이라는 근거로 `ALL`에 잠정 배정했었다. 10대 체계는 이 근거와
의미적으로 완전히 일치하는 `FACILITY` 태그가 신설됐으므로, **같은 근거를 그대로 유지한 채
태그명만 새 체계에 맞게 재배정**했다(추측이 아니라 원래 근거의 논리적 귀결):

- **FACILITY**: 스포츠 시설 대여 16종(테니스장/풋살장/축구장/체육관/골프장/농구장/족구장/
  야구장/다목적경기장/배드민턴장/탁구장/배구장/수영장/운동장/피클볼장/스포츠) +
  지시문이 명시한 캠핑장/다목적실/영화촬영 계열과 실측 확인된 동일 성격의
  `MINCLASSNM`(회의실, 강의실, 강당, 주민공유공간, 녹화장소) — 총 23종.
- **KIDS_PRE**: 공공키즈카페/어린이실내놀이터/서울형키즈카페(시설명 자체로 영유아~미취학
  대상 명확, 8대 체계와 동일 근거).
- **YOUTH (신규 발견)**: 청년공간 — 이번 백필로 `raw_data.MINCLASSNM`이 복구되며 실측으로
  새로 발견한 카테고리. 시설명 자체가 청년 대상임이 명확하다.

### 4.3 제안 — 고효율 추가 키워드 (전부 제안 단계, 확정 아님)
1. **숫자 나이 임계값 파싱(신규 제안, 중간 신뢰도)**: `\d+세\s*이상`/`\d+세이상` 패턴을
   추출해 8~13세는 `KIDS_SCHOOL`, 14~19세는 `TEEN`, 20세 이상은 `ADULT`로 매핑하는 규칙을
   추가하면 UNRESOLVED_TOKEN 상위 6개 토큰(약 27건)을 추가로 해소할 수 있을 것으로
   예상된다. 다만 "미성년자는 보호자 동반 필수" 같은 조건부 문구는 나이 임계값이 아니라
   동반 조건이라 별도 처리 필요 — 정밀 규칙은 승인 후 설계.
2. **8대 체계 리포트 4.2절 제안(`키즈`/`중고등`/`학생`)**: 여전히 미승인 상태로 이번에도
   적용하지 않았다. 승인 시 `KIDS_SCHOOL`/`TEEN` 잔여를 추가로 줄일 수 있다.
3. **`여성`/`장애인`/`국가유공자` 등 인구 속성**: 연령 체계와 별개 축이므로 10대 태그로
   흡수하는 대신, 필요하다면 별도 컬럼/체계 신설을 검토해야 한다(이번 범위 밖, 대표 결정
   필요).

## 5. 대표 확인이 필요한 미결 사항 (제3장 제5조 추측 금지 — 임의 결정하지 않고 보고만 함)

1. **1단계 FACILITY 재배정(2.2절) 채택 여부**: 8대 체계 때 `ALL`로 뒀던 스포츠 시설
   대여 16종을 10대 체계에서 `FACILITY`로 재배정한 것이 타당한지 확인 필요.
2. **2.1절 ADULT 키워드("성인") 및 공용 키워드 표 채택 여부**: 8대 체계와 동일하게
   미승인 잠정 규칙이다.
3. **4.3절 숫자 나이 임계값 파싱 규칙 신설 여부**: 반영 시 NULL 잔여를 추가로 줄일 수
   있으나 정밀 설계와 승인이 필요하다.
4. **4.3절 "여성/장애인/국가유공자" 등 비-연령 인구 속성 처리 방침**: 10대 체계 밖의
   문제라 별도 결정 필요.
5. **1.4절 스코프 외 발견(`TOUR_API_`/`SEOUL_YEYAK_` 소스=null 45건) 백필 필요 여부**:
   이번 지시 범위 밖이라 백필하지 않았다 — 후속 작업으로 분리할지 결정 필요.
6. **실제 반영 여부**: 승인 시 `events.target_audience`/`target_audience_source` 컬럼
   신설 마이그레이션 → 실제 UPDATE 실행 → `/admin/data-grid` 10대 태그 드롭다운 반영
   순서로 후속 진행 필요.
