## 0. 선행 분석과의 관계

수행됐다:

- `implementation/2026-08-27-backfill-contents-pipeline.md`(2026-08-27, description 백필
  후 title+description 재검증)

이번 지시(`implementation/todo.md`)는 태그 체계를 **8대**(`INFANT/KIDS_PRE/KIDS_SCHOOL/
FAMILY/TEEN/YOUTH/SENIOR/ALL`)로 세분화하고, 원천 필드 동적 탐색을 0순위로 승격한
새로운 알고리즘 사양이다. 기존 5대 체계 결과를 재사용하지 않고 8대 체계 기준으로
전체를 처음부터 재시뮬레이션했다.

## 1. 알고리즘 구현과 지시문 사이의 차이 — 투명 공개 (추측 금지 원칙)

지시문은 0순위(원천 필드)와 0단계(역방향 소거)의 키워드는 구체적으로 명시했지만,
**1단계(카테고리 특화 상속)와 2단계(텍스트 파싱)에서 8개 태그 각각에 어떤 중분류/키워드를
매칭할지는 구체적으로 명시하지 않았다.** 이 부분을 임의로 비워두면 시뮬레이션 자체가
불가능하므로, 아래 기준으로 **이번 시뮬레이션 전용 잠정 규칙을 새로 정의**했다 — 전부
**제안 단계이며 확정이 아니다.** 실제 반영 여부/키워드 수정은 대표 승인 후 결정한다.

### 1.1 1단계(카테고리 특화 상속) 잠정 규칙
`scripts/ingest/lib/category-maj-taxonomy.mjs`의 기존 36종 중분류 중, 이름 자체로
연령 제한 개념이 없거나(시설 대관) 대상이 명백한 것만 사용했다(기존
`docs/target-audience-analysis-report.md` 6.1에서 이미 제안됐던 논리와 동일):
- **ALL**: 테니스장/풋살장/축구장/체육관/골프장/농구장/족구장/야구장/다목적경기장/
  배드민턴장/탁구장/배구장/수영장/운동장/피클볼장/스포츠 (16종 — 공간·시설 대관이라
  나이 제한 개념 자체가 없음)
- **KIDS_PRE**: 공공키즈카페/어린이실내놀이터 (영유아~미취학 대상임이 시설명 자체로 명확)

### 1.2 2단계(텍스트 파싱) 잠정 키워드
| 태그 | 키워드 |
| :--- | :--- |
| INFANT | 영아, 영유아, 신생아, 젖먹이 |
| KIDS_PRE | 유아, 미취학, 유치원 |
| KIDS_SCHOOL | 어린이, 초등학생, 초등, 아동 |
| FAMILY | 가족 |
| TEEN | 청소년, 중학생, 고등학생, 중고생 |
| YOUTH | 청년 |
| SENIOR | 어르신, 시니어, 실버, 노인 |
| ALL | 전연령, 전 연령, 남녀노소, 누구나, 제한없음 |

우선순위는 위 표 순서(INFANT→...→ALL)대로 첫 매칭을 채택했다. 0단계 소거 대상(
`excludedFromKidFamily = true`)인 행은 INFANT/KIDS_PRE/KIDS_SCHOOL/FAMILY 매칭을
건너뛰고 TEEN/YOUTH/SENIOR/ALL만 시도한다(지시문 그대로 — 소거는 "키즈/가족 대상에서만"
배제이지 전체 배제가 아님).

## 2. 0순위: 원천 필드 동적 탐색 결과

실측으로 `raw_data` 키 전수를 스캔한 결과, 연령 관련 필드는 아래 2개 소스에만 존재했다
(그 외 `tourapi_4.0`/`gg_public`/레거시 `seoul_public_reservation`(source=null,
`SEOUL_RESERVATION_*`, 1,717건, `raw_data` 완전 공백)에는 연령 관련 원천 필드 자체가
없음을 확인):

| 소스 | 건수 | 원천 필드 |
| :--- | ---: | :--- |
| `seoul_public_reservation`(SEOUL_YEYAK) | 1,123건 | `USETGTINFO` |
| `seoul_public_culture` | 426건 | `USE_TRGT` |

두 필드 모두 쉼표 다중 나열 + 괄호 부연설명이 섞인 자유 텍스트라, 괄호 제거 후 쉼표
분리한 모든 토큰이 **하나의 8대 태그로 완전히 합의될 때만** 1:1 매핑 성공으로 인정했다.

**"성인" 단독/복합 값 처리 (미결, 대표 결정 필요)**: `USETGTINFO`/`USE_TRGT`에 "성인"만
단독으로 나오는 값(226건)은 지시된 8대 태그 어디에도 정확히 대응하지 않는다 — `ALL`(제한
없음)과는 반대 개념(아동 제외)이므로 임의로 끼워 맞추지 않았다. 5대 체계 때와 동일한
미결 이슈이며, 이번에도 그대로 별도 집계만 하고 넘겼다.

## 4. NULL 잔여 제목 빈도 분석 및 추가 키워드 제안 (전부 제안 단계, 확정 아님)

NULL 잔여 1,797건의 제목 토큰 빈도 상위: `목공체험`(94), `천왕산`(57), `숲길`(52),
`도봉구`(45), `성인`(45), `치유의`(42), `주민센터`(39), `양천구`(39), `3층`(34),
`한강공원`(30), `호수`(29), `서울숲`(28), `문화실험공간`(28), `호수랩`(27),
`석촌호수`(26), `난지캠핑장`(26), `산림치유`(26), `단체`(26), `영화촬영`(24) 등.

### 4.1 높은 신뢰도 제안 — "시설/공간 대관"류 → ALL 확장
위 빈도 상위 단어 대부분(`주민센터`, `다목적실`(제목에 자주 등장), `한강공원`, `난지캠핑장`,
`영화촬영`, `치유센터`)은 **개인/단체가 특정 시간대의 공간·장비를 예약하는 게시물**이며,
1절에서 이미 적용한 "스포츠 시설 대관 → ALL" 규칙과 정확히 같은 성격이다. 아래 카테고리
확장을 제안한다:
- `다목적실`, `주민센터`, `자치회관`, `문화실험공간`, `캠핑장`, `야영장`, `치유센터`,
  `산림치유`, `영화촬영` → **ALL**(공간/장비 대관 게시물은 나이 제한 개념이 구조적으로 없음)
- 근거: 레거시 `SEOUL_RESERVATION_*` NULL 잔여 1,010건 중 상당수가 이 패턴에 해당할 것으로
  보이나(제목 샘플 확인 기준), 정확한 반영 건수는 추가 승인 후 재시뮬레이션이 필요하다
  (추측 금지 — 개략 방향만 제안).

### 4.2 중간 신뢰도 제안 — 세분화 보강
| 태그 | 추가 제안 키워드 | 근거 |
| :--- | :--- | :--- |
| KIDS_SCHOOL | `키즈` | 5대 체계 분석(2026-08-26 보고서 6.2)에서 이미 195건 발견된 안전한 키워드 |
| TEEN | `중고등`, `학생`(단, "대학생"/"수강생" 등과 겹칠 위험 있어 단순 부분일치보다 문맥 제한 필요 — 검토 요청) | 청소년 관련 게시물 중 "학생" 단독 표기 케이스 보강 |

### 4.3 낮은 확신 — 검토 필요
- `성인`이 제목에 단독 등장하는 45건: 0순위와 동일한 미결 이슈("성인"은 8대 태그 밖).
  이 45건이 0순위의 226건("성인" 원천필드)과 얼마나 겹치는지는 이번 분석 범위 밖이며,
  근본적으로 "성인"을 8대 체계의 어떤 값으로 볼지(신규 태그 신설 vs `NULL` 유지) 결정이
  선행돼야 한다.

## 5. 대표 확인이 필요한 미결 사항 (제3장 제5조 추측 금지 — 임의 결정하지 않고 보고만 함)

1. **"성인" 처리 방침**: 원천 필드/제목에서 "성인" 단독으로만 등장하는 경우(0순위 226건 +
   텍스트 45건, 중복 포함 가능) 8대 태그 어디에도 없다. `ALL`로 볼지, 9번째 태그(예:
   `ADULT`)를 신설할지, `NULL` 유지할지 결정 필요.
2. **1단계/2단계 잠정 규칙(1.1/1.2절) 채택 여부**: 지시문에 명시되지 않아 이번 시뮬레이션
   전용으로 새로 정의한 규칙이다 — 그대로 채택할지, 수정할지 확인 필요.
3. **4.1절 "시설 대관 → ALL" 확장 적용 여부**: 반영 시 레거시 소스의 NULL 잔여를 크게 줄일
   것으로 예상되나 정밀 재시뮬레이션은 승인 후 진행.
4. **레거시 `SEOUL_RESERVATION_*`(1,717건, source=null) 소스 정체성**: `source` 컬럼이
   비어 있고 `raw_data`도 비어 있다 — `seoul-public-reservation.mjs`(Decision 017 이전
   구버전 어댑터)로 수집된 것으로 추정되나, 이 소스에 대한 `source`/`raw_data` 백필이
   필요한지는 이번 작업 범위 밖이라 별도 결정 필요(target_audience 정제와는 별개 이슈).
